继承、多态与抽象类

Posted on 2026-09-19，8 min read

前面几章学会了用类封装数据、用构造方法初始化对象，但真实项目里的类很少彼此孤立：Programmer 和 Hr 都是员工，Dog 和 Cat 都是动物。如果每个类都把姓名、编号、work() 从头写一遍，代码会重复到无法维护。本章要解决的就是这个问题：用 extends 复用父类成员，用方法重写改造父类行为，用 super 调用父类版本。再进一步，用多态写出“一处编写、多处适配”的代码，最后用抽象类把“只有声明、没有实现”的方法固定成契约。阅读前请确保已经掌握 this、构造方法和访问权限；文中示例都可在 JDK 8 及以上直接编译运行。

一、为什么需要继承：is-a 关系与 extends 格式

继承解决的是“多个类存在共同成员”的重复问题。做法是把共性抽取到一个父类（也叫超类、基类），再让子类（派生类）通过 extends 直接拥有这些成员。判断该不该用继承只有一条标准：子类“是一个”父类，即 is-a 关系。程序员是员工，所以 Programmer extends Employee 成立；员工配有电脑，但“员工不是一个电脑”，这种 has-a 关系应该写成成员变量，而不是继承。

继承带来三点收益：复用父类代码；把共性缺陷集中到一处修复，提升可维护性；让父类引用可以指向子类对象，这正是下一节多态的前提。代价是耦合变强——父类一改，所有子类都会受影响，所以抽取父类要克制，不要为了省几行代码硬造继承关系。

格式为 class 子类名 extends 父类名 {}。有两点必须记住。第一，Java 的类只支持单继承，一个类只能有一个直接父类，但支持多层继承（A extends B，B extends C）。第二，父类的私有成员和构造方法都不能被子类继承：私有成员依然会随对象一起分配空间，但子类无法直接访问，只能通过父类提供的 public/protected 方法间接使用；构造方法则只能用 super 调用。

class Employee {
    protected String name;
    protected String id;

    public Employee(String name, String id) {
        this.name = name;
        this.id = id;
    }

    public void work() {
        System.out.println("员工号为" + id + "的" + name + "员工，正在处理日常工作");
    }
}

class Programmer extends Employee {
    private String language;

    public Programmer(String name, String id, String language) {
        super(name, id);          // 必须在第一行：先初始化父类成员
        this.language = language;
    }

    @Override
    public void work() {          // 重写：方法名、参数列表与父类一致
        System.out.println("员工号为" + id + "的" + name
                + "员工，正在用 " + language + " 写代码");
    }

    public void debug() {
        super.work();             // 显式调用父类被重写掉的版本
        System.out.println("顺便修了一个 Bug");
    }
}

public class ExtendsDemo {
    public static void main(String[] args) {
        Programmer p = new Programmer("李雷", "T001", "Java");
        p.work();    // 走子类重写后的版本
        p.debug();
    }
}

再强调一次对象创建的顺序：new 时先在堆中为子类对象（连同父类成员变量）分配空间并赋默认值，然后子类构造方法进栈，第一件事就是调用父类构造方法；接着依次执行成员变量显式初始化、构造代码块和构造方法体。所以子类对象自始至终只有一个，父类成员只是被放在同一块空间里一起初始化。

二、方法重写与 super：子类如何改造父类行为

当父类的方法实现满足不了子类需求时，就在子类中写一个“格式相同”的方法把父类版本覆盖掉，这就是方法重写（override），也叫覆盖、复写。重写要点可以概括为“签名相同、权限不降、返回类型兼容”，具体有三条：

  • 签名相同：方法名和参数列表必须完全相同；
  • 返回类型兼容：返回类型必须相同，或者（Java 5 起）是父类返回类型的子类型，这叫协变返回；
  • 权限不降：访问权限不能比父类更严格——父类是 public，子类就不能写成 protected。

建议永远加上 @Override 注解，一旦签名写错，编译器会立刻报错，而不是默默变成一个新方法。

要特别纠正一个常见误解：静态方法不能被重写。父类和子类出现同名同参的静态方法时，只是子类方法把父类方法“隐藏”了，运行期按引用的编译类型决定调用哪一个；在静态方法上加 @Override 会直接编译失败。重写针对的是实例方法，只有实例方法才有多态效果。

super 是父类成员的访问标识，注意它不是一个对象引用，而 this 才是当前对象的引用。它有三种用法：super.成员变量 访问被子类同名变量遮蔽的父类字段；super.方法名(参数) 调用父类被重写的方法；super(参数) 在子类构造方法第一行调用父类构造方法。当父类没有无参构造方法时，子类必须显式写 super(参数)，否则编译不通过。this(...) 和 super(...) 都要占据构造方法第一行，因此同一个构造方法里只能二选一。若用 this(...) 转调本类其他构造方法，隐式的父类构造调用会转移到那个被调用的构造方法中，父类数据依然会被初始化。

三、多态：父类引用指向子类对象

多态指同一个对象在不同时刻表现出不同形态，在 Java 中的代码体现就是“父类型引用指向子类对象”（接口类型引用指向实现类对象）。它成立的三个前提是：存在继承或实现关系；子类重写了父类方法；用父类引用指向子类对象。多态最大的价值是解耦：方法参数写成父类型，就能接收任意子类对象，以后新增子类无需修改这段代码。

多态的成员访问规则要分编译期和运行期：编译期一律看左边（父类型），父类里没有的成员直接报错；运行期则只有非静态方法看右边（真实子类对象），成员变量和静态方法都看左边。换句话说，字段没有多态，只有被重写的实例方法有。

class Worker {
    public void work() {
        System.out.println("工作者在工作");
    }
}

class Hr extends Worker {
    @Override
    public void work() {
        System.out.println("招聘英才");
    }
}

class Coder extends Worker {
    @Override
    public void work() {
        System.out.println("用代码改变世界");
    }

    public void study() {          // 子类特有方法，父类型引用调不到
        System.out.println("学习新技术");
    }
}

public class PolyDemo {
    public static void testWorker(Worker w) {   // 参数写成父类型
        w.work();                               // 运行期绑定到真实子类
    }

    public static void main(String[] args) {
        Worker w1 = new Hr();      // 向上转型：子类型赋给父类型，自动完成
        Worker w2 = new Coder();
        testWorker(w1);
        testWorker(w2);

        Worker w = new Coder();
        // w.study();              // 编译错误：父类型中没有 study()
        if (w instanceof Coder) {  // 先判断，再强转
            Coder c = (Coder) w;   // 向下转型：父类型赋给子类型，必须强转
            c.study();
        }
    }
}

多态的弊端是父类型引用看不到子类特有功能，解决办法是向下转型。把子类引用赋给父类引用叫向上转型，可以自动完成。把父类引用赋给子类引用叫向下转型，必须强制写 (子类名)；如果被转型的对象本来就不是该类型，运行时会抛出 ClassCastException（类型转换异常），所以强转前应当用 instanceof 判断。变量 instanceof 类名 返回布尔值，表示左边对象是否是右边类型的实例。JDK 16 起还支持模式匹配写法 if (w instanceof Coder c)，判断通过时直接完成声明和赋值，代码更紧凑。

四、抽象类与 final：把“不具体”的行为定成契约

有时一个类“有哪些行为”是明确的，但“怎么实现”说不清：动物都会吃和叫，但吃法、叫声各不相同。这种只有声明、没有方法体的方法就叫抽象方法，格式是 访问修饰符 abstract 返回值类型 方法名(参数列表);——注意它连大括号都不能有。一个类里只要存在抽象方法，这个类就必须声明为 abstract class，否则编译失败。抽象类不能实例化，必须由子类继承；子类若没有实现全部抽象方法，那它自己也只能是抽象类。

抽象类可以拥有构造方法，而且必须有——它不给自己创建对象，而是供子类创建对象时初始化父类成员。抽象类中允许没有抽象方法，此时它的唯一作用就是禁止实例化。但抽象方法不能与 final、private、static 组合：final 方法不允许重写，private 方法子类访问不到；而 abstract static 本身就是非法的修饰符组合，编译直接报错。

abstract class Animal {
    protected String name;

    public Animal(String name) {     // 抽象类有构造方法，供子类调用
        this.name = name;
    }

    public abstract void eat();      // 抽象方法：没有方法体，连大括号都没有
    public abstract void say();

    public void sleep() {            // 抽象类中也可以有具体方法
        System.out.println(name + "在睡觉");
    }
}

class Dog extends Animal {
    public Dog(String name) {
        super(name);
    }

    @Override
    public void eat() {
        System.out.println(name + "吃骨头");
    }

    @Override
    public void say() {
        System.out.println(name + "汪汪叫");
    }
}

final class MathUtils {
    public static final double PI = 3.1415926;   // final 变量就是常量
    private MathUtils() {}                       // 工具类不允许实例化
}

public class AbstractDemo {
    public static void main(String[] args) {
        // Animal a = new Animal("x");   // 编译错误：抽象类不能实例化
        Animal a = new Dog("旺财");        // 抽象类多态
        a.eat();
        a.say();
        a.sleep();
    }
}

final 是“最终”的意思，可以修饰类、方法和变量：修饰类表示不能被继承（如 String）；修饰方法表示不能被子类重写；修饰变量表示只能赋值一次，成为常量。final 修饰引用类型变量时，锁住的是地址值而不是对象内容——final List<String> list 仍然可以 add，只是不能再指向另一个集合。常量通常在定义时赋值，也可以在构造方法中赋值。

五、常见坑与小结

坑一：在构造方法中调用可被重写的方法。父类构造方法执行时，子类的成员变量还没有显式初始化，此时动态绑定到子类方法，读到的只会是默认值。下面代码会依次输出“父类构造方法”“Son.show(), a = 10, b = 0”“子类构造方法”“Son.show(), a = 10, b = 20”，b = 0 就是典型的“半成品对象”现象。构造方法里应只调用 private 或 final 的方法，或者干脆不要在构造期依赖子类状态。

class Father {
    protected int a = 10;

    public Father() {
        System.out.println("父类构造方法");
        show();       // 坑：构造方法中调用了可被重写的方法
    }

    public void show() {
        System.out.println("Father.show(), a = " + a);
    }
}

class Son extends Father {
    private int b = 20;

    public Son() {
        System.out.println("子类构造方法");
        show();
    }

    @Override
    public void show() {
        System.out.println("Son.show(), a = " + a + ", b = " + b);
    }
}

public class InitOrderDemo {
    public static void main(String[] args) {
        new Son();
    }
}

坑二：把重载当成重写。重载（overload）是同一个类中方法名相同、参数列表不同，与返回值类型无关，也不能用返回值类型区分；重写发生在父子类之间，要求签名一致。二者英文分别是 overload 和 override，面试常考。

坑三：重写时缩小访问权限或返回类型不兼容。这都会直接编译报错；忘了写 @Override 时，签名差一个字母就会变成一个无关的新方法，父类旧逻辑仍在被调用。

坑四：不判断就向下转型。只要有可能不是目标类型，就先 instanceof，否则线上就是 ClassCastException。

坑五：为了复用硬造继承。is-a 不成立时应改用组合（把对象作为字段）；此外子类定义与父类同名的成员变量并不会“重写”父类字段，而是遮蔽，父类字段依然存在、依然占空间，这种写法极易出错，应尽量避免。

小结：继承通过 extends 复用共性，前提是 is-a 关系；Java 类只支持单继承，但可以多层继承，私有成员与构造方法都不被继承。方法重写要求签名相同、权限不降、返回类型兼容，只有实例方法能重写。多态由“父类引用指向子类对象”产生，成员变量和静态方法看左边，被重写的实例方法看右边；访问子类特有功能要先 instanceof 再向下转型。抽象类用 abstract 声明，不能实例化，专门为子类提供契约，且不能与 final、private、static 组合；final 则用于关闭继承、重写和二次赋值。把这四件工具连起来，就具备了设计类层次的基本能力，下一章将继续看接口如何补足单继承的短板。
