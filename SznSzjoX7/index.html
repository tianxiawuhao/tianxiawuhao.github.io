MinIO 是基于 Apache License v2.0 开源的对象存储服务，具备 S3 兼容接口、部署轻量、单机即可运行的特点，适合存放图片、视频、日志、备份数据和容器/虚拟机镜像等非结构化数据，单个对象最大可达 5 TiB。需要注意的是：2021 年之后 MinIO 采用 AGPLv3 许可，2023 年之后的版本彻底移除了 minio gateway 网关模式，也移除了旧版管理 API，因此新版安装与迁移的用法和老教程差别很大，本文以 RELEASE.2023+ 的 minio/minio 镜像为准。

minio 搭建

单机部署

拉取镜像并启动（新版必须显式指定 --console-address，否则控制台会随机监听一个端口，无法稳定映射）：

docker pull minio/minio:latest

docker run -d --name minio --restart=always \
  -p 9000:9000 -p 9001:9001 \
  -e "MINIO_ROOT_USER=admin" \
  -e "MINIO_ROOT_PASSWORD=admin12345" \
  -v /opt/minio/data:/data \
  -v /opt/minio/config:/root/.minio \
  minio/minio server /data --address ":9000" --console-address ":9001"

几点必须注意：

  • --address 是 S3 API 的监听端口，--console-address 是 Web 控制台端口，两者不能混用；老版本只有一个 9000 端口同时承担两者。
  • MINIO_ROOT_USER / MINIO_ROOT_PASSWORD 取代了旧的 MINIO_ACCESS_KEY / MINIO_SECRET_KEY；密码长度不能少于 8 位，否则容器启动即报错退出。
  • 容器内的凭据保存在 /data/.minio.sys 中，挂载出来的 /data 必须持久化，否则重启后桶和用户全部丢失。
  • 启动后浏览器访问 http://IP:9001 登录控制台；http://IP:9000 只提供 S3 API，直接打开会返回 AccessDenied，这是正常现象。
  • 生产环境请在 9000/9001 前加反向代理并配置 HTTPS，控制台不建议直接暴露到公网。

如果不使用 Docker，可直接用官方二进制并以 systemd 托管：

# 下载并安装二进制
wget https://dl.min.io/server/minio/release/linux-amd64/minio
chmod +x minio && mv minio /usr/local/bin/minio

# 数据目录与运行用户
mkdir -p /data/minio && useradd -r minio -s /sbin/nologin || true
chown -R minio:minio /data/minio

# /etc/default/minio
MINIO_VOLUMES="/data/minio"
MINIO_OPTS="--address :9000 --console-address :9001"
MINIO_ROOT_USER=admin
MINIO_ROOT_PASSWORD=admin12345

# /etc/systemd/system/minio.service（片段）
[Unit]
Description=MinIO
After=network-online.target

[Service]
User=minio
Group=minio
EnvironmentFile=-/etc/default/minio
ExecStart=/usr/local/bin/minio server $MINIO_OPTS $MINIO_VOLUMES
Restart=always
LimitNOFILE=65536

[Install]
WantedBy=multi-user.target

systemctl daemon-reload
systemctl enable --now minio
systemctl status minio --no-pager

分布式部署与磁盘要求

分布式模式按纠删码（Erasure Coding）工作，硬性约束如下：

  • 最少 4 个节点（或 4 块盘），否则无法组成纠删码集合；
  • 每个节点上的磁盘数量必须一致，例如 4 节点 × 4 盘、4 节点 × 8 盘；
  • 单机多盘同样可以用大括号展开：minio server /data{1...4} 等价于 4 个纠删码集合；
  • 建议节点间时间同步（NTP）、内网万兆互联，卷必须是本地盘或块设备，不支持 NFS/CIFS 等网络文件系统；
  • 纠删码默认按 4+4 冗余（可容忍一半盘损坏），盘数越少冗余比例越高、可用容量越低。
# 4 节点 × 4 盘，在任一节点上执行同一条命令
export MINIO_ROOT_USER=admin
export MINIO_ROOT_PASSWORD=admin12345
minio server http://192.168.1.{11...14}/data{1...4} \
  --address ":9000" --console-address ":9001"

# docker-compose.yml（4 节点分布式的最小可用示例，数据目录需按节点改路径）
services:
  minio1:
    image: minio/minio:latest
    command: server http://minio{1...4}/data{1...4} --console-address ":9001"
    environment:
      MINIO_ROOT_USER: admin
      MINIO_ROOT_PASSWORD: admin12345
    volumes:
      - /mnt/disk1:/data1
      - /mnt/disk2:/data2
      - /mnt/disk3:/data3
      - /mnt/disk4:/data4
    networks: [minio-net]
  # minio2 / minio3 / minio4 同理，仅卷路径不同
networks:
  minio-net:
    driver: bridge

分布式集群扩容可以直接在命令里增加节点，MinIO 会自动重平衡数据；但缩容不被支持，规划容量时要留足余量。

mc 客户端配置

mc 是 MinIO 官方命令行客户端，所有运维操作（建桶、配额、策略、迁移）都靠它完成。它用 alias（别名）保存服务端地址和凭据，配置文件默认位于 Linux 的 ~/.mc/config.json、Windows 的 %USERPROFILE%\mc\config.json。

# 下载安装（Linux）
wget https://dl.min.io/client/mc/release/linux-amd64/mc
chmod +x mc && mv mc /usr/local/bin/mc

# 配置两个别名：旧集群与新集群
mc alias set oldminio http://10.0.0.11:9000 admin '旧集群密码'
mc alias set newminio http://10.0.0.22:9000 admin '新集群密码'

# 校验连通性
mc admin info oldminio
mc admin info newminio
mc alias list

# 常用浏览命令
mc ls oldminio                  # 列出所有桶
mc ls --recursive --summarize oldminio/model-file-bucket
mc du oldminio/model-file-bucket
mc stat oldminio/model-file-bucket/xxx.bin

换机器迁移时，把 ~/.mc/config.json 直接拷贝过去即可复用全部别名。注意 mc alias set 后的 provider 字段对新版 MinIO 固定为 s3，旧教程里的 mc config host add 命令已废弃，改名为 mc alias set。

数据迁移

MinIO 官方推荐的迁移工具有两种：官方客户端 mc 的 mirror 命令，以及第三方的 rclone。前者对 MinIO 兼容性最好、支持桶策略与原数据一起搬；后者支持的存储后端更多，适合跨云厂商迁移。

mc mirror 迁移

# 1) 先预演，确认要传输与删除的对象清单（不实际写入）
mc mirror --dry-run --overwrite oldminio/model-file-bucket newminio/model-file-bucket

# 2) 正式迁移：保留元数据，只覆盖目标端不同的对象
mc mirror --preserve --overwrite --summary \
  oldminio/model-file-bucket newminio/model-file-bucket

# 3) 持续增量追平（适合业务不停机的平滑切换，Ctrl+C 结束）
mc mirror --watch --preserve --overwrite \
  oldminio/model-file-bucket newminio/model-file-bucket

# 4) 迁移完成后校验：无输出表示两边完全一致
mc diff oldminio/model-file-bucket newminio/model-file-bucket

关于「断点续传」需要澄清：mc mirror 不提供跨进程的断点续传。它的续传能力来自两层机制：一是幂等的重跑——中断后重新执行同一条命令，已传输且大小/ETag 一致的对象会被直接跳过，相当于从断点继续；二是分片上传（multipart）——大对象被切成多个 part 上传，同一进程内的网络抖动会自动重试该 part。因此对大目录的迁移，建议按桶或按前缀拆分多次执行，把单次中断的损失降到最小。

如果两个集群长期共存、需要双向同步，可以用服务端复制，数据不经过客户端中转，速度更快：

# 在旧集群上把 newminio 加为远端目标，再批量复制桶
mc admin replicate add oldminio newminio
mc replicate add oldminio/model-file-bucket --remote-bucket newminio/model-file-bucket

Rclone 安装

Rclone 是一个命令行程序，用于管理云存储上的文件，是云供应商 Web 存储接口的功能丰富的替代品。超过 40 种云存储产品支持 rclone，包括 S3 对象存储、商业和消费者文件存储服务以及标准传输协议，广泛用于 Linux、Windows 和 Mac。

curl https://rclone.org/install.sh | sudo bash

网络不通时建议先下载压缩包再上传到服务器：

# 下载文件
wget https://downloads.rclone.org/v1.57.0/rclone-v1.57.0-linux-amd64.zip
# 解压文件
unzip rclone-v1.57.0-linux-amd64.zip
# 给一下执行权限
chmod 0755 ./rclone-v1.57.0-linux-amd64/rclone
# 拷贝到 /usr/bin/ 后可直接使用 rclone 命令（注意路径不要写错）
cp ./rclone-v1.57.0-linux-amd64/rclone /usr/bin/
# 删除压缩包
rm -rf ./rclone-v1.57.0-linux-amd64.zip

Windows 版本可直接从 官网下载页或 GitHub Releases 获取。

Rclone 配置

rclone config          # 进入交互式配置选项，进行添加、删除、管理网盘等操作
rclone config file     # 显示配置文件路径，一般配置文件在 ~/.config/rclone/rclone.conf
rclone config show     # 显示配置文件信息

一个配置文件里可以用 [name] 段保存多份配置，下面是新旧 MinIO 集群的写法。新版 MinIO 的 provider 写作 Minio，region 可留空，endpoint 必须带上 http:// 或 https://：

[oldminio]
type = s3
provider = Minio
env_auth = false
access_key_id = admin
secret_access_key = 旧集群密码
region = cn-east-1
endpoint = http://10.0.0.11:9000
location_constraint =
server_side_encryption =

[newminio]
type = s3
provider = Minio
env_auth = false
access_key_id = admin
secret_access_key = 新集群密码
region = cn-east-1
endpoint = http://10.0.0.22:9000
location_constraint =
server_side_encryption =

Rclone 迁移示例

# 场景：把阿里云 MinIO 的数据迁移到腾讯云 COS
# aliyun / tencent 为配置文件中的段名，wechat-root-files 为桶名，files 为桶内前缀
# -n 预演，确认无误后去掉
rclone sync -n aliyun:wechat-root-files/files tencent:sj-data-testwechat-1307267266/files -P --transfers=200

# -P 显示实时传输进度
# --transfers=N 并行文件数，默认为 4；小内存机器建议调小，比如 128M 的机器设为 1
# --checksum 用 md5 判断差异，源和目标都是对象存储时推荐开启
rclone sync --checksum aliyun:wechat-root-files/files tencent:sj-data-testwechat-1307267266/files \
  -P --transfers=16 --s3-chunk-size=64M --log-file=/var/log/rclone-migrate.log --log-level=INFO

# 删除指定前缀下的文件（先加 -n 预演，确认清单再执行）
rclone delete tencent:sj-data-testwechat-1307267266/wechat-root-files -P --transfers=100

这里同样强调「脚本要能直接跑」的前提：sync 会删除目标端多出来的文件，首次执行前务必用 -n 预演；--transfers 也不是越大越好，并发过高会拖垮带宽或触发对端限流。

常用功能选项

rclone copy    # 复制
rclone move    # 移动，若需在移动后删除空源目录，加上 --delete-empty-src-dirs
rclone sync    # 同步：使目标目录与源目录一致，会删除目标端多出的文件
rclone delete  # 删除路径下的文件内容
rclone purge   # 删除路径及其所有文件内容
rclone mkdir   # 创建目录
rclone rmdir   # 删除目录
rclone rmdirs  # 删除指定路径下的空目录；加 --leave-root 则不删除根目录
rclone check   # 检查源和目的地址数据是否匹配
rclone ls      # 列出指定路径下的所有文件以及文件大小和路径
rclone lsl     # 比上面多一个显示上传时间
rclone lsd     # 列出指定路径下的目录
rclone lsf     # 列出指定路径下的目录和文件

常用参数

-n = --dry-run                  # 测试运行，查看 rclone 实际会做哪些操作
-P = --progress                 # 显示实时传输进度
--cache-chunk-size SizeSuffix   # 块大小，默认 5M；越大上传越快，内存占用也越高
--cache-chunk-total-size SizeSuffix  # 块在本地磁盘可占用的总大小，默认 10G
--transfers=N                   # 并行文件数，默认 4；小内存 VPS 建议设为 1
--config string                 # 指定配置文件路径，宝塔面板等环境下常用
--s3-provider Other --max-backlog N  # sync/copy/move 时使用，占用约 N 倍 KB 内存
--buffer-size=SIZE              # 加速 sync/copy/move 的内存缓冲区
--bwlimit UP:DOWN               # 上传/下载限速，单位 b|k|M|G
--size-only                     # 仅文件大小变化才同步，可能漏掉内容改变的文件，不推荐
--checksum                      # 通过 md5 判断文件是否变化；两端都是对象存储时推荐
--update --use-server-modtime   # 通过 mtime 判断变化，只有本地 mtime 较新才上传
--fast-list                     # 批量列目录（1000 个文件 1 次 API 调用），1 个文件约耗 1k 内存
--no-traverse                   # 目标端文件较多时直接查找目标文件，而非遍历列表
--max-age                       # 只上传最近修改的文件
--s3-no-head                    # 上传后不再用 HEAD 校验，可减少请求数
--s3-upload-cutoff              # 超过该值使用分片上传，默认 200M，最大 5G
--s3-disable-checksum           # 不计算 md5
--s3-upload-concurrency         # 同时上传的分片数，默认 4；少量大文件时调大可提升带宽
--s3-chunk-size                 # 分片大小，默认 5M
--s3-max-upload-parts           # 分片数上限，默认 10000
--s3-force-path-style           # 默认 true，MinIO 等自建 S3 需要保持 true
--s3-v2-auth                    # 默认 false，旧签名算法才需要开启
--s3-list-chunk                 # 每次 list 返回的 key 数量，默认 1000

桶策略与权限

新版 mc 中旧的 mc policy 命令已被 mc anonymous 取代，桶的访问策略只有三种：none（私有，默认）、download（匿名可读）、public（匿名可读可写，生产环境不要使用）。

# 查看当前策略
mc anonymous get newminio/model-file-bucket
# 允许匿名下载（常用于静态资源桶）
mc anonymous set download newminio/model-file-bucket
# 恢复为私有
mc anonymous set none newminio/model-file-bucket

# 桶配额与版本控制
mc quota set newminio/model-file-bucket --size 500Gi
mc version enable newminio/model-file-bucket

# 子账号与策略：只给某个桶的读写权限
mc admin user add newminio appuser 'AppUserPass123'
mc admin policy create newminio readwrite-model /tmp/readwrite-model.json
mc admin policy attach newminio readwrite-model --user appuser

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:GetObject", "s3:PutObject", "s3:DeleteObject", "s3:ListBucket"],
      "Resource": [
        "arn:aws:s3:::model-file-bucket",
        "arn:aws:s3:::model-file-bucket/*"
      ]
    }
  ]
}

迁移场景里最容易踩的坑是：数据搬完了但桶策略没搬，应用访问对象时报 AccessDenied。切换到新集群后，记得用 mc anonymous get 逐个核对策略，或直接用 mc mirror --preserve 迁移后再统一重设。

日志与进度

# rclone 有 4 个日志级别：ERROR、NOTICE、INFO、DEBUG，默认只输出 ERROR 和 NOTICE
# -q  仅 ERROR
# -v  输出 ERROR、NOTICE、INFO，推荐
# -vv 输出 ERROR、NOTICE、INFO、DEBUG
# --log-level LEVEL 显式指定级别

# 输出日志到文件（Error/Info/Debug 及标准错误都会写入）
rclone sync -v --log-file=/var/log/rclone-sync.log oldminio:bucket newminio:bucket

# 也可以用系统重定向
rclone sync -v oldminio:bucket newminio:bucket > ~/DRIVEX.log 2>&1
