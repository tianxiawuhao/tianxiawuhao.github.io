LoRA_PEFT

Posted on 2025-02-18，4 min read

一、从 LoRA 到 PEFT 库

前一篇《LoRA（Low-Rank Adaptation）》从原理出发，用纯 PyTorch 从零实现了低秩旁路与训练脚本。理解原理之后，工程上并不需要自己维护这套代码：Hugging Face 的 peft 库把 LoRA、QLoRA、Prefix Tuning 等参数高效微调（PEFT）方法统一成一套极薄的 API，本节的实战脚本就基于它编写。

需要先厘清两个容易混淆的概念：

  • LoRA 是方法：固定基座权重 \(W_0\)，只训练低秩增量 \(\Delta W = \frac{\alpha}{r}BA\)，因此可训练参数与优化器状态降低若干个数量级。
  • PEFT 库是封装：它负责按配置把低秩旁路注入到指定层、冻结其余参数、统计可训练参数量，以及保存/加载/合并适配器。库里不止 LoRA 一种方法，同一套接口也能切换到 QLoRA 与软提示。

本节在此基础上再叠加 QLoRA：用 4-bit 量化存放冻结的基座、用 LoRA 训练适配器。两者的分工可以用一句话概括——LoRA 决定「训练哪些参数」，QLoRA 决定「冻结的基座以什么精度存放」，二者正交，可以同时使用。

二、关键超参数怎么选

2.1 秩 r 与缩放系数 lora_alpha

秩 r 是低秩矩阵的中间维度，直接决定新增参数量与表达能力，常用 8～64；任务与基座差异越大、数据越多，可以适当取大。lora_alpha 是缩放系数，真正进入前向计算的是 alpha / r（与主文中 \(h = W_0x + \frac{\alpha}{r}BAx\) 完全一致）。实践中常把 lora_alpha 取成 r 的 2～4 倍，等价于缩放倍数 2～4；若想保持缩放不变而只提高秩，可以按比例同步放大 alpha。

2.2 target_modules：该加在哪里

target_modules 决定旁路注入到哪些线性层，是最需要按模型结构确认的参数。名称必须是模型里真实的模块名，可通过 print(model) 查看：

  • LLaMA / Qwen2 / DeepSeek 系列：["q_proj", "k_proj", "v_proj", "o_proj"]，需要更强拟合时再加 MLP 的 gate_proj、up_proj、down_proj。
  • BLOOM 系列：["query_key_value"]。
  • ChatGLM 系列：["query_key_value"] 或按版本使用 ["q_proj", "v_proj"]。

只挂 q_proj、v_proj 是最省显存的最小配置；把注意力输出层与 MLP 一并覆盖，通常能换到更好的效果，代价是适配器体积和显存上升。

2.3 lora_dropout 与 bias

lora_dropout 作用在旁路输入上，是 LoRA 层唯一的正则化手段，小数据集常用 0.05～0.1，数据充足时可设为 0。bias 取 "none" 表示不训练任何偏置，这也是 LoRA 论文的默认设置；"all" 会训练全部偏置，"lora_only" 只训练 LoRA 层的偏置，二者都会额外增加少量可训练参数，一般没必要开启。

三、与 QLoRA 组合：4-bit 量化训练

QLoRA 的完整流程只需三个动作：

  1. 4-bit 加载基座：load_in_4bit=True，量化类型用 NF4，计算时反量化到 bf16。
  2. 准备量化训练：prepare_model_for_kbit_training(model) 会冻结全部基座参数、把 LayerNorm 等层提升到 fp32 以保证数值稳定，并打开输入梯度以便配合梯度检查点。
  3. 注入 LoRA 适配器：get_peft_model(model, peft_config) 按配置挂载旁路，之后只有适配器参数可训练。

顺序不能颠倒：必须先用 prepare_model_for_kbit_training 处理量化模型，再调用 get_peft_model 注入适配器。另外，开启梯度检查点后要设置 model.config.use_cache = False，否则会收到关于 use_cache 的警告甚至报错。

四、完整实战脚本

下面以 DeepSeek-R1 的 1.5B 蒸馏版为例，演示「4-bit 基座 + LoRA 适配器」的全流程。换用其它模型时，只需修改模型名、数据集名与 target_modules。

# 环境依赖（需提前安装）
# pip install torch transformers datasets peft accelerate bitsandbytes

import torch
from transformers import (
    AutoTokenizer,
    AutoModelForCausalLM,
    TrainingArguments,
    Trainer,
    DataCollatorForLanguageModeling
)
from peft import LoraConfig, get_peft_model, prepare_model_for_kbit_training
from datasets import load_dataset

# ===================== 配置参数 =====================
MODEL_NAME = "deepseek-ai/DeepSeek-R1-Distill-Qwen-1.5B"  # 示例取 R1 的蒸馏小模型便于本地微调；如需原版 R1（671B）请改用官方加载方式
DATASET_NAME = "your_dataset"          # 数据集名称或本地路径
OUTPUT_DIR = "./deepseek-r1-lora-finetuned"
BATCH_SIZE = 2                         # 根据 GPU 显存调整
MAX_LENGTH = 1024                      # 单条样本截断长度，不超过模型的上下文窗口
NUM_EPOCHS = 3
LEARNING_RATE = 3e-5

# LoRA 配置
LORA_R = 16
LORA_ALPHA = 64                        # 缩放系数 alpha / r = 4
LORA_DROPOUT = 0.05
TARGET_MODULES = ["q_proj", "v_proj"]  # 关键参数！需根据实际模型结构调整

# ===================== 模型加载（QLoRA 第 1 步）=====================
tokenizer = AutoTokenizer.from_pretrained(MODEL_NAME)
model = AutoModelForCausalLM.from_pretrained(
    MODEL_NAME,
    load_in_4bit=True,                  # 4-bit 量化存放基座，节省显存
    device_map="auto",                  # 多卡/单卡自动切分
    torch_dtype=torch.bfloat16,         # 反量化后的计算精度
    attn_implementation="flash_attention_2"  # 需本机 flash-attn 可用，否则删掉此行
)

# 处理特殊 token：pad 复用 eos，避免 padding 位置参与 loss
if tokenizer.pad_token is None:
    tokenizer.pad_token = tokenizer.eos_token

# 量化训练准备（QLoRA 第 2 步）
model = prepare_model_for_kbit_training(model)
model.config.use_cache = False          # 配合梯度检查点，必须关闭 KV cache

# ===================== LoRA 配置（QLoRA 第 3 步）=====================
peft_config = LoraConfig(
    r=LORA_R,
    lora_alpha=LORA_ALPHA,
    lora_dropout=LORA_DROPOUT,
    target_modules=TARGET_MODULES,      # 关键配置项！
    bias="none",
    task_type="CAUSAL_LM",
    modules_to_save=["lm_head"]         # 输出层随适配器一起保存；未扩充词表时可省略
)

model = get_peft_model(model, peft_config)
model.print_trainable_parameters()
# 输出形如：trainable params: 2,293,760 || all params: 1,783,985,152 || trainable%: 0.1286
# 说明：trainable params 只统计 LoRA 旁路（及 modules_to_save）的参数，不含 4-bit 冻结权重

# ===================== 数据处理 =====================
def format_function(examples):
    # 根据任务构造 prompt，示例：
    texts = [
        f"<|System|>\n你是一个AI助手\n<|User|>\n{query}\n<|Assistant|>\n{answer}"
        for query, answer in zip(examples["query"], examples["answer"])
    ]
    return {"text": texts}

dataset = load_dataset(DATASET_NAME)
if "test" not in dataset:
    dataset = dataset["train"].train_test_split(test_size=0.02, seed=42)
dataset = dataset.map(format_function, batched=True)

def tokenize_function(examples):
    return tokenizer(
        examples["text"],
        max_length=MAX_LENGTH,
        padding="max_length",
        truncation=True,
        add_special_tokens=True
    )

tokenized_dataset = dataset.map(tokenize_function, batched=True)

# ===================== 训练配置 =====================
training_args = TrainingArguments(
    output_dir=OUTPUT_DIR,
    num_train_epochs=NUM_EPOCHS,
    per_device_train_batch_size=BATCH_SIZE,
    gradient_accumulation_steps=8,       # 模拟更大 batch size：有效 batch = 2 × 8 = 16
    learning_rate=LEARNING_RATE,
    bf16=True,                           # 4-bit 基座的推荐精度；无 bf16 支持时用 fp16=True
    optim="paged_adamw_8bit",            # QLoRA 推荐的 8-bit 分页优化器
    logging_steps=20,
    save_strategy="steps",
    save_steps=500,
    eval_strategy="steps",               # 新版 transformers 参数；旧版请写 evaluation_strategy
    eval_steps=300,
    report_to="tensorboard",
    gradient_checkpointing=True,         # 显存优化
    gradient_checkpointing_kwargs={"use_reentrant": False},  # 开启 dropout 时必须
    ddp_find_unused_parameters=False
)

trainer = Trainer(
    model=model,
    args=training_args,
    train_dataset=tokenized_dataset["train"],
    eval_dataset=tokenized_dataset["test"],
    data_collator=DataCollatorForLanguageModeling(tokenizer, mlm=False),
)

# ===================== 开始训练 =====================
trainer.train()
model.save_pretrained(OUTPUT_DIR)        # 只保存适配器与 modules_to_save 权重（数十 MB）
tokenizer.save_pretrained(OUTPUT_DIR)

五、适配器的保存与加载

model.save_pretrained(OUTPUT_DIR) 保存的是适配器权重 adapter_model.safetensors 与配置 adapter_config.json，而不是完整的基座；这也是 LoRA 多任务部署的基础——同一份基座配多个适配器目录即可切换任务。

推理时用 PeftModel.from_pretrained 把适配器挂回基座。有两点必须注意：

  • 基座 ID 记录在配置里：adapter_config.json 的 base_model_name_or_path 保存了训练时的基座名称，加载时基座要与之一致，否则权重对不上。
  • 精度与量化设置保持一致：适配器是在 4-bit 基座上训练的，推理时同样用 load_in_4bit=True 加载基座最稳妥；若要用全精度基座，则应先合并再保存完整模型。
# ===================== 推理测试 =====================
from peft import PeftModel

base_model = AutoModelForCausalLM.from_pretrained(
    MODEL_NAME,
    load_in_4bit=True,                   # 与训练时保持一致
    device_map="auto",
    torch_dtype=torch.bfloat16
)
model = PeftModel.from_pretrained(base_model, OUTPUT_DIR)
model.eval()

prompt = "<|System|>\n你是一个AI助手\n<|User|>\n如何学习机器学习？\n<|Assistant|>\n"
inputs = tokenizer(prompt, return_tensors="pt").to(model.device)

with torch.no_grad():
    outputs = model.generate(
        **inputs,
        max_new_tokens=256,
        temperature=0.7,
        do_sample=True
    )
print(tokenizer.decode(outputs[0], skip_special_tokens=True))

六、合并为可独立部署的模型

如果要交付一个独立的模型目录，可以把适配器合并回基座权重，得到结构上与原始模型完全相同、推理时不引入额外延迟的模型：

from peft import PeftModel

# 合并前请用全精度（非 4-bit）基座加载，4-bit 权重无法直接合并
base_model = AutoModelForCausalLM.from_pretrained(MODEL_NAME, torch_dtype=torch.bfloat16)
model = PeftModel.from_pretrained(base_model, OUTPUT_DIR)
model = model.merge_and_unload()         # 把 (alpha/r)·BA 加回 W0，并移除 LoRA 分支

MERGED_DIR = "./deepseek-r1-merged"
model.save_pretrained(MERGED_DIR)
tokenizer.save_pretrained(MERGED_DIR)
# 注意：合并会丢失适配器与基座的分离性，无法再单独切换/回退适配器；
# 若仍需多任务热插拔，请保留 adapter 目录而不做合并。

# ===================== 未合并时的多适配器切换 =====================
from peft import PeftModel

model = PeftModel.from_pretrained(base_model, "./adapter-domain-a")
model.load_adapter("./adapter-domain-b", adapter_name="domain_b")
model.set_adapter("domain_b")            # 用哪个适配器，由这一行决定

七、常见坑与调参建议

  • target_modules 写错：模块名不存在时 get_peft_model 会直接报错；写成了别的层名却恰好存在，则可能只训练了无关参数，表现是 loss 不降。
  • 忘记关闭 use_cache：与梯度检查点同时开启会报错或告警。
  • 4-bit 基座与 fp16 混用：量化模型的参数已是 bf16/fp16 计算路径，训练精度建议统一为 bf16=True；老卡不支持 bf16 时再用 fp16。
  • 数据太少、轮数太多：LoRA 参数虽少也会过拟合，优先观察验证集 loss，必要时降低 r、提高 lora_dropout。
  • 学习率取值：LoRA 常用 1e-4～3e-4，比全参数微调高一个量级；本例的 3e-5 偏保守，适合数据量较小、希望稳定收敛的场景。
  • 合并前先脱离量化：merge_and_unload 需要非量化基座，否则应先反量化或重新加载全精度权重。
