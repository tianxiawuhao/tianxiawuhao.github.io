Java 教程

常用类库

Posted on 2026-09-19，5 min read

写 Java 程序，大部分时间都在调用 JDK 已经写好的类：拼接字符串、把输入的 "18" 变成数字、算两个日期相差几天、对浮点数取整。这些类的集合就是常用类库（API）。本章挑出出场率最高的几个家族——String 与 StringBuilder、八种基本类型的包装类、所有类的祖先 Object、数学工具 Math、日期时间类——讲清它们各自解决什么问题、有哪些必须记住的坑。适合已经会写类和方法、能看懂简单泛型语法的读者。示例基于 JDK 8 及以上，版本差异会单独标注。

一、String：不可变的字符串

String 的第一个关键性质是不可变：对象一旦创建，内容就再也不能被修改。看上去能改的 replace、substring、toUpperCase 其实都返回一个新对象，原对象纹丝不动。这样设计是因为字符串常被共享：常量池里同一份字面量会被无数处引用，若允许改动就会互相污染；不可变还带来线程安全、hashCode 可缓存等好处，这也是 String 常被选作 HashMap 键的原因。

由此引出两个高频问题。第一，比较内容必须用 equals，== 比较的是引用地址。字面量 "hello" 会被放进字符串常量池复用，所以字面量之间 == 常常为真；而 new String("hello") 会在堆上另开内存，== 立即为假——一旦字符串来自输入、拼接或文件，这种「巧合」就彻底失效。若担心空指针，用 Objects.equals(a, b) 更安全。

第二，不要在循环里用 += 拼接。每次 += 都新建一个 String 并整体复制旧内容，循环 n 次的总代价是 O(n²)。需要澄清的是，单独一句 a + b + c 编译器会优化成一次 StringBuilder 拼接，所以「加号一定慢」并不准确；问题出在跨迭代的反复创建。

几个细节也常被绊住：下标从 0 开始，substring(begin, end) 含 begin 不含 end；split 的参数是正则表达式，按字面量竖线或点号分割要写 "\\|"、"\\."；JDK 9 起字符串内部改用紧凑字节数组存储，「字符串就是一个 char 数组」的说法已不符合实现。

二、StringBuilder：可变的字符缓冲区

反复修改字符串就该换成 StringBuilder。它内部维护一个可扩容的字符数组，append、insert、reverse 直接改缓冲区并返回自身，所以能链式书写 sb.append("a").append(1)。要注意 length() 是已存字符数，capacity() 是缓冲区容量，容量不足会自动扩容并复制旧内容：无参构造的容量在 JDK 8 中是 16，JDK 9 后为 16 或「初始字符串长度 + 16」，能预估长度时用 new StringBuilder(1024) 可减少扩容。

public class StringBuilderDemo {
    public static void main(String[] args) {
        System.out.println(join(new int[]{1, 2, 3}));   // [1, 2, 3]

        StringBuilder sb = new StringBuilder("helloworld");
        sb.reverse();
        System.out.println(sb.toString());              // dlrowolleh
    }

    // 用 StringBuilder 拼接，避免循环里反复创建 String
    public static String join(int[] arr) {
        StringBuilder sb = new StringBuilder();
        sb.append("[");
        for (int i = 0; i < arr.length; i++) {
            if (i > 0) {
                sb.append(", ");
            }
            sb.append(arr[i]);
        }
        return sb.append("]").toString();
    }
}

StringBuffer 的 API 与它几乎相同，区别是所有方法都加了 synchronized，线程安全但更慢。结论：单线程一律用 StringBuilder，只有确实需要多线程共享同一缓冲区时才考虑 StringBuffer。

三、包装类：基本类型与对象之间的桥

八种基本类型不是对象，不能放进集合、不能调用方法、也无法表示「没有值」，于是每种都有一个对应的包装类：byte→Byte、short→Short、int→Integer、long→Long、float→Float、double→Double、char→Character、boolean→Boolean。它们主要做三件事：字符串转基本类型（Integer.parseInt("18")）、基本类型转字符串（String.valueOf(18)）、提供常量与工具方法（Integer.MAX_VALUE）。从 JDK 5 起两者可自动转换：自动装箱（Integer i = 10;，编译器调用 Integer.valueOf(10)）与自动拆箱（int n = i;，调用 i.intValue()）。

Integer a = 127, b = 127;
Integer c = 128, d = 128;
System.out.println(a == b);        // true，命中 -128~127 的缓存
System.out.println(c == d);        // false，超出缓存范围
System.out.println(c.equals(d));   // true，比较内容才可靠

Integer mayBeNull = null;
// int x = mayBeNull;              // 自动拆箱，运行时报 NullPointerException
int y = mayBeNull == null ? 0 : mayBeNull;
System.out.println(y);             // 0

上面的输出暴露了两个陷阱：Integer.valueOf 会缓存 −128 到 127 的对象，区间内 == 恰好为真，超出就变成两个新对象，因此包装类的比较永远用 equals；包装类引用还可以为 null，直接参与运算会因自动拆箱触发空指针。

四、Object、Math 与日期时间

Object 是所有类的根父类，所以参数写成 Object 就能接收任意对象。它有三个方法值得关注：toString() 决定对象被打印时的样子，默认是「类名@十六进制哈希」，调试时几乎一定要重写；equals(Object) 默认仍是 ==；重写 equals 就必须同时重写 hashCode 并满足「equals 为真则哈希相同」，否则对象存进 HashSet 或当作 HashMap 的键会出现「存进去却查不到」。

Math 全是静态方法：abs 取绝对值，ceil/floor 取上取整与下取整，pow(a, b) 求幂，sqrt 求平方根（别和立方根 cbrt 混淆），max/min 求最值，random() 返回 [0.0, 1.0) 的随机数，生成 [min, max] 整数写成 min + (int) (Math.random() * (max - min + 1))。Math.round 参数为 double 时返回 long，规则是「加 0.5 后向下取整」，所以 Math.round(-1.5) 得 -1 而非 -2。

日期时间 API 分两代。旧的 Date + Calendar + SimpleDateFormat 坑很多：Calendar 的月份从 0 开始（1 月是 0），Date.getYear() 返回「年份减 1900」，SimpleDateFormat 不是线程安全的，多线程共用一个实例会解析出错误结果。JDK 8 引入的 java.time（LocalDate、LocalDateTime、Duration 等）全部不可变、线程安全，新代码应当优先使用；只有对接老接口需要 java.util.Date 时才做转换。

import java.time.LocalDate;
import java.time.LocalDateTime;
import java.time.format.DateTimeFormatter;
import java.time.temporal.ChronoUnit;

public class DateTimeDemo {
    public static void main(String[] args) {
        LocalDate today = LocalDate.now();
        LocalDate birthday = LocalDate.of(2000, 1, 1);
        System.out.println(ChronoUnit.DAYS.between(birthday, today)); // 活了几天

        // 模式串里 MM 是月份、mm 是分钟，别写反
        DateTimeFormatter fmt = DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss");
        String text = LocalDateTime.now().format(fmt);
        System.out.println(LocalDateTime.parse(text, fmt));
    }
}

若不得不使用旧 API，请至少守住三条：Calendar 取月份后自行加 1，SimpleDateFormat 不要作为静态共享字段，模式串里 MM 与 mm 分清。

五、小结

本章几条主线的共同线索是「什么时候复用、什么时候新建」。String 不可变因而可以安全共享，代价是修改就得新建，于是有了 StringBuilder；基本类型轻量但不是对象，于是有了包装类，代价是缓存造成的 == 假象与拆箱空指针；Object 的默认实现按地址与哈希判断，重写时要成对处理；Math 是纯静态工具；日期时间上，新的 java.time 用不可变换来了线程安全。记住三条纪律即可避开大部分坑：比较内容用 equals、循环拼接用 StringBuilder、日期时间优先 java.time。下一章进入集合框架，equals 与 hashCode 的约定将成为理解 HashMap 去重与查找的关键。
