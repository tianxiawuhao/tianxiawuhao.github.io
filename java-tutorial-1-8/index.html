Java 教程

常用类库

Posted on 2026-09-19，6 min read

写 Java 程序，真正花在「自己写逻辑」上的代码其实不多，大部分时间都在调用别人写好的类：拼接字符串、把用户输入的 "18" 变成数字、算出两个日期相差几天、对浮点数取整。这些随手可用的类就是 JDK 提供的常用类库（API）。本章挑出其中出场率最高的几个家族——String 与 StringBuilder、八种基本类型的包装类、所有类的祖先 Object、数学工具 Math、日期时间类——讲清它们各自解决什么问题、有哪些必须记住的坑。适合已经会写类和方法、能看懂简单泛型语法的读者。文中示例基于 JDK 8 及以上，标注了 JDK 8 与 JDK 17 的差异之处。

一、String：不可变的字符串

String 是 Java 中使用频率最高的类，它的第一个关键性质是不可变：对象一旦创建，里面的字符内容就再也不能被修改。看上去能改的 replace、substring、toUpperCase，实际上都是返回一个新对象，原对象纹丝不动。

为什么要把字符串设计成不可变？因为它太常被共享了：字符串常量池里同一份字面量会被无数处引用，如果把其中一处改了，其他地方就跟着遭殃。不可变还带来了天然线程安全、hashCode 可以缓存（这也是 String 当 HashMap 键的首选原因）等好处。

由此引出两个最常见的问题。第一，比较内容必须用 equals，而不是 ==。这里的 == 比较的是引用地址，两个内容相同的字符串完全可能是两个不同对象。Java 会把字面量 "hello" 放进字符串常量池复用，所以字面量之间 == 常常为真，而 new String("hello") 会在堆上另开一块内存，== 立即为假；一旦字符串来自外部输入、拼接或读取文件，字面量比较的「巧合」就彻底失效。要比较内容，请写 s1.equals(s2)；如果 s1 可能为 null，把确定非空的那个放在前面，或使用 Objects.equals(s1, s2)。

第二，不要在循环里用 += 拼字符串。每次 += 都会生成一个新的 String 并把旧内容整体复制过去，循环 n 次的总代价是 O(n²)。需要说明的是，单独一句 a + b + c 编译器会优化成一次 StringBuilder 拼接，所以「加号一定慢」是不准确的；真正的问题在于跨循环迭代的反复创建。

此外还有几个高频细节：String 下标从 0 开始，substring(begin, end) 包含 begin、不包含 end，charAt(index) 越界会抛 StringIndexOutOfBoundsException；判断前缀后缀用 startsWith/endsWith；split 的参数是正则表达式，所以按字面量 "|"、"." 分割时必须写成 "\\|"、"\\."。新版 JDK 中字符串内部用紧凑的字节数组加编码标记存储（JDK 9 起），「字符串就是一个 char 数组」的旧说法已经不符合实现。

二、StringBuilder 与 StringBuffer

既然 String 不可变，那反复修改的场景就需要一个可变的字符容器，这就是 StringBuilder。它内部维护一个可扩容的字符数组，append、insert、reverse 都直接在缓冲区上改动，并且返回自身，因此可以链式调用：sb.append("a").append(1).append(true)。

它有两个容易混淆的度量：length() 是已存字符数，capacity() 是缓冲区当前容量，容量不足时会自动扩容（通常是「原容量 × 2 + 2」，并把旧内容复制过去）。无参构造的容量在 JDK 8 中是 16，JDK 9 之后改为 16 或「初始字符串长度 + 16」，所以不要依赖具体数字，能预估长度时用 new StringBuilder(1024) 减少扩容。

public class StringBuilderDemo {
    public static void main(String[] args) {
        int[] arr = {1, 2, 3};
        System.out.println(join(arr));          // [1, 2, 3]

        // StringBuilder 与 String 的互转
        StringBuilder sb = new StringBuilder("helloworld");
        sb.reverse();
        String reversed = sb.toString();        // dlrowolleh
        System.out.println(reversed);
    }

    // 用 StringBuilder 拼接，避免循环里反复创建 String
    public static String join(int[] arr) {
        StringBuilder sb = new StringBuilder();
        sb.append("[");
        for (int i = 0; i < arr.length; i++) {
            if (i > 0) {
                sb.append(", ");
            }
            sb.append(arr[i]);
        }
        return sb.append("]").toString();
    }
}

StringBuffer 与 StringBuilder 的 API 几乎完全相同，区别是前者所有方法都加了 synchronized，线程安全但更慢。结论很直接：单线程拼字符串一律用 StringBuilder，只有确实需要多线程共享同一个缓冲区时才考虑 StringBuffer。

三、包装类：基本类型与对象之间的桥

Java 的八种基本类型不是对象，所以不能放进集合、不能调用方法、不能表示「没有值」。每种基本类型都有一个对应的包装类：byte→Byte、short→Short、int→Integer、long→Long、float→Float、double→Double、char→Character、boolean→Boolean。

包装类主要干三件事：把字符串转成基本类型（Integer.parseInt("18")）、把基本类型转成字符串（String.valueOf(18) 或 Integer.toString(18)）、提供常量与工具方法（Integer.MAX_VALUE、Integer.compare）。从 JDK 5 起，基本类型与包装类之间可以自动转换，称为自动装箱（Integer i = 10;，编译器实际调用 Integer.valueOf(10)）与自动拆箱（int n = i;，实际调用 i.intValue()）。

自动装箱带来两个陷阱。一是 valueOf 会缓存 −128 到 127 的 Integer 对象，这区间内 == 恰好为真，一旦超出（例如两个 128）就变成两个新对象，== 为假——包装类的比较永远用 equals。二是包装类引用可能为 null，把它直接参与运算会触发 NullPointerException。

Integer a = 127, b = 127;
Integer c = 128, d = 128;
System.out.println(a == b);          // true，命中缓存
System.out.println(c == d);          // false，超出缓存范围
System.out.println(c.equals(d));     // true，比较内容才可靠

Integer mayBeNull = null;
// int x = mayBeNull;                // 运行时抛 NullPointerException（自动拆箱）
int y = mayBeNull == null ? 0 : mayBeNull;   // 先判空再拆箱
System.out.println(y);               // 0

四、Object、Math 与日期时间

Object 是所有类的根父类，即使不写 extends，每个类也间接继承它，所以「方法参数写 Object，就能接收任意对象」。它有三个方法值得每个类关注：toString() 决定对象被打印或字符串拼接时的样子，默认输出「类名@十六进制哈希」，调试时几乎一定要重写；equals(Object) 默认仍是 ==，想让两个内容相同的对象「相等」必须重写；重写 equals 就必须同时重写 hashCode，并保证「equals 为真则 hashCode 相同」，否则对象放进 HashSet 或作为 HashMap 的键会出现「存进去却查不到」的诡异现象。

Math 类全是静态方法，直接类名调用即可。abs 取绝对值，ceil 取不小于参数的最小整数，floor 取不大于参数的最大整数，pow(a, b) 求 a 的 b 次幂，sqrt 求平方根（注意别与立方根 cbrt 混淆），max/min 求最值，random() 返回 [0.0, 1.0) 的随机数。要生成 [min, max] 内的整数，写成 min + (int) (Math.random() * (max - min + 1))。特别提醒 Math.round：它返回 long（参数为 float 时返回 int），规则是「加 0.5 后向下取整」，所以 Math.round(-1.5) 的结果是 -1 而不是 -2。

日期时间 API 分新旧两代。旧的 java.util.Date + SimpleDateFormat + Calendar 能用的坑很多：Calendar 的月份从 0 开始（1 月是 Calendar.JANUARY，即 0），Date 的 getYear() 返回的是「年份减 1900」，SimpleDateFormat 不是线程安全的，多个线程共用一个实例会解析出错乱结果。JDK 8 引入的 java.time 包（LocalDate、LocalDateTime、Instant、Duration）全部不可变且线程安全，新代码应优先使用；只有在对接老接口、需要 java.util.Date 时才做转换。

import java.time.LocalDate;
import java.time.LocalDateTime;
import java.time.format.DateTimeFormatter;
import java.time.temporal.ChronoUnit;

public class DateTimeDemo {
    public static void main(String[] args) {
        LocalDate today = LocalDate.now();
        LocalDate birthday = LocalDate.of(2000, 1, 1);
        System.out.println(ChronoUnit.DAYS.between(birthday, today));  // 活了几天

        // 格式化与解析：月份用 MM（大写），分钟用 mm（小写）
        DateTimeFormatter fmt = DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss");
        LocalDateTime now = LocalDateTime.now();
        String text = now.format(fmt);
        LocalDateTime parsed = LocalDateTime.parse(text, fmt);
        System.out.println(parsed);
    }
}

如果不得不用旧 API，请至少记住三点：Calendar 的月份要 -1、SimpleDateFormat 不要定义为静态共享字段、模式串里 MM 是月份而 mm 是分钟。

五、小结

本章的几条主线其实都围绕同一个判断：什么时候复用，什么时候新建。String 不可变因而可以安全共享，代价是修改就得新建，于是有了 StringBuilder；基本类型轻量但不面向对象，于是有了包装类，代价是缓存的 == 假象与拆箱空指针；Object 的方法默认用「地址」和「哈希」判断，重写时要成对处理；Math 是纯粹的静态工具；日期时间上，新的 java.time 用不可变换来了线程安全，应当优先选择。

把三条纪律记住就能避开大部分坑：比较内容用 equals 而不是 ==；循环拼接用 StringBuilder；处理日期时间优先 java.time，宁可多写两行也不要用共享的 SimpleDateFormat。下一章我们将进入集合框架，那里 equals 与 hashCode 的约定会成为理解 HashMap 去重与查找的关键。
