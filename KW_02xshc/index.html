docker 宿主机定时清除容器的运行日志

Posted on 2022-01-17，3 min read

一般 docker 容器都是最小化安装，systemd、cron 这类定时任务服务通常并不存在，自己去安装也很麻烦。所以更省事的做法是：清理脚本写在容器里，定时触发交给宿主机的定时器。

一、在容器中编写清除日志脚本

这一部分不论你是把定时器加在宿主机上还是容器中，都必须去做：先把清理脚本在容器里准备好。

网上随意一搜就可以看到如下的删除模板：

find 对应目录 -mtime +天数 -name "文件名" -exec rm -rf {} \;

这里要特别留意 -mtime +天数 的正负号：+5 表示「修改时间在 5 天以前」，-5 表示「最近 5 天以内」，两者含义正好相反。写错的话会把最新日志删掉，而老日志却越积越多。

因为本人的日志目录层级比较深，所以改良如下，脚本放在容器的 /opt/auto-del-log.sh：

#!/bin/sh
find /home/schedule_log/ -mtime +5 -type f -iname "*.log" -exec rm -rf {} \;

脚本里 -type f 只匹配普通文件，避免误伤同名目录；-iname 忽略文件名大小写；-mtime +5 只挑选 5 天以前修改过的日志。

一定记得加可执行权限：

chmod +x /opt/auto-del-log.sh

原文此处写的是 chmod +777。GNU chmod 确实能接受这种写法并得到 777 权限，但清理脚本只需要执行权限，向所有用户放开读写并没有必要，因此这里改为 chmod +x。

脚本写好后，重点是要先验证它有没有效果，不要直接挂定时任务。可以先用「只查不删」的方式确认匹配结果正是你要删的文件：

find /home/schedule_log/ -type f -iname "*.log"
# 或者
find /home/schedule_log/ -name "*.log"

无论用 -iname 还是 -name，只要能查出你想删除的文件，效果就达到了，这时再套用带 -exec rm -rf 的模板。

各参数含义如下：

-mtime：按修改时间筛选，标准写法为 -mtime +天数 或 -mtime -天数；
+30：查找 30 天以前修改过的文件，数字代表天数；
"*.log"：希望查找的数据类型，"*.jpg" 表示查找扩展名为 jpg 的所有文件，"*" 表示查找所有文件，可以灵活运用、举一反三；
-type f：只匹配普通文件，不匹配目录；
-exec：固定写法，后面跟要执行的命令；
rm -rf：强制删除文件，包括目录（-r 递归，-f 不再询问）；
{} \;：固定写法，{} 代表 find 找到的每个文件，\; 表示命令结束，分号需要转义。

二、宿主机加入定时器

先用 docker exec 命令校验之前写的脚本是否有效，在宿主机上执行：

docker exec -it tomcat8002 /opt/auto-del-log.sh
# tomcat8002：容器名称或者 ID
# /opt/auto-del-log.sh：脚本在容器中的位置

如果此命令有效，那么就可以编辑定时器了。本人采用的是 CentOS 7，具体可以参看网上介绍得挺全的一篇博客：centos7 linux定时任务详解

crontab -e
# 每天 04:02 执行一次清理
02 4 * * *  docker exec tomcat8002 /opt/auto-del-log.sh

注意写进 crontab 时要去掉 -it：-t 只用于交互式执行时分配终端，而 cron 运行环境没有 TTY，带上它会报 the input device is not a TTY，任务就静默失败了。

另外 cron 的 PATH 与登录 shell 不同，命令尽量写绝对路径；必要时可在 crontab 里显式设置 PATH，或把整条命令包进一个用绝对路径调用的脚本再交给 cron。

三、几个容易踩的坑

第一，删除文件不等于立刻释放磁盘空间。如果日志文件仍被容器内的进程打开着，rm 只是删掉了目录项，空间要等该进程关闭文件或重启后才会真正归还。对于长期运行、持续写日志的进程，清空文件内容往往比删除文件更稳妥，例如：

find /home/schedule_log/ -mtime +5 -type f -iname "*.log" -exec truncate -s 0 {} \;

第二，先确认日志目录的挂载方式。如果日志目录是通过 volume 挂载到宿主机的，也可以直接在宿主机上清理，省掉 docker exec 这一层，但要注意容器内路径与宿主机路径的对应关系。

第三，脚本务必先手动执行一遍再交给 cron。定时任务没有输出，排查时可查看 /var/log/cron，cron 的执行结果默认以邮件形式投递给 root，也可在 /var/spool/mail/root 中查看。
