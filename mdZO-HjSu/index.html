HashMap负载因子为什么是0.75，链表转红黑树阈值为什么是8

Posted on 2021-05-02，3 min read

HashMap 里有两个经常被追问的默认值：负载因子 0.75 和链表转红黑树的阈值 8。它们都不是随手写下的数字，而是 Java 开发人员在时间成本与空间成本之间反复权衡后得到的经验值。下面分别说明这两个数字的来历。

1.HashMap负载因子为什么是0.75

负载因子决定了哈希表装到多满时扩容，0.75 是它在时间成本与空间成本之间的折中值。

1.1时间成本

假设负载因子是 1，那么哈希表要装满之后才会扩容，空间利用率最高，但随之提高的是哈希碰撞的概率。
HashMap 解决哈希碰撞采用的是拉链法：落在同一个桶里的元素会挂成一条链表。碰撞越多，链表越长，而链表的查找需要从头逐个比较，平均时间复杂度是 O(n)。所以负载因子太高，查询的时间成本就会上升。

1.2空间成本

那么为了减少哈希冲突、提高查询效率，负载因子是不是越低越好呢？答案显然是否定的。
假设负载因子为 0.5，那么空间利用率只有 50%：容量为 64 时至少有 32 个桶长期空置，容量扩到 1024 时就有 512 个桶被浪费；而且扩容时还要重新计算哈希并搬移元素。扩容后的容量越大，空出来的绝对空间也越大。

所以 Java 开发人员经过权衡，认为负载因子不能太大也不能太小，最终折中选择为 0.75，也就是 HashMap 的默认值 DEFAULT_LOAD_FACTOR。

2.链表转红黑树阈值为什么是8

在负载因子为 0.75、并且 hashCode 分布均匀的前提下，同一个桶内的节点数服从参数约为 0.5 的泊松分布，期望出现次数为：P(k) = e^(-0.5) * 0.5^k / k!，其中 k 是桶内的节点数。这是概率论的范畴，不熟悉的同学只需要知道：负载因子为 0.75 时，我们可以算出桶内出现 k 个节点的概率。JDK 源码注释中给出了这些概率的取值：

Because TreeNodes are about twice the size of regular nodes, we
use them only when bins contain enough nodes to warrant use
(see TREEIFY_THRESHOLD). And when they become too small (due to
removal or resizing) they are converted back to plain bins.  In
usages with well-distributed user hashCodes, tree bins are
rarely used.  Ideally, under random hashCodes, the frequency of
nodes in bins follows a Poisson distribution
(http://en.wikipedia.org/wiki/Poisson_distribution) with a
parameter of about 0.5 on average for the default resizing
threshold of 0.75, although with a large variance because of
resizing granularity. Ignoring variance, the expected
occurrences of list size k are (exp(-0.5)*pow(0.5, k)/factorial(k)). 
The first values are:
0:    0.60653066
1:    0.30326533
2:    0.07581633
3:    0.01263606
4:    0.00157952
5:    0.00015795
6:    0.00001316
7:    0.00000094
8:    0.00000006
more: less than 1 in ten million

可以看到，碰撞 8 次（链表长度达到 8）的概率是 0.00000006，也就是千万分之一，几乎是一个不可能事件。如果真的发生，说明哈希函数分布很差或者数据被刻意构造，此时链表 O(n) 的查找代价已经不可接受；转成红黑树之后，查找代价降为 O(log n)。所以 Java 开发人员把链表转红黑树的阈值默认设为 8（TREEIFY_THRESHOLD）：既能兜住极端情况，又几乎不会触发树化这种相对耗时的操作。

还有两个相关常量值得一起记住：只有当 table 容量达到 MIN_TREEIFY_CAPACITY（64）时才会真正树化，否则优先扩容；而节点数减少到 UNTREEIFY_THRESHOLD（6）时又会退化回链表。回退阈值比树化阈值小，是为了避免节点数在 7 和 8 之间来回抖动时反复转换。
