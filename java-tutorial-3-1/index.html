3.1 HTML 基础

Posted on 2024-08-07，7 min read

浏览器里的每一个页面，最终都是一份 HTML 文档。它规定了“页面上有什么内容、这些内容是什么关系”，而 CSS 负责长什么样、JavaScript 负责怎么动。很多人写 Java Web 时只把 HTML 当成模板里的字符串拼接，结果结构一塌糊涂：样式调不动、表单提交拿不到值、爬虫和无障碍工具也读不懂。本章把 HTML 的地基一次性搭稳：文档结构怎么写、常用标签各自负责什么、表格与表单这两类最常打交道的元素怎么做对，以及为什么要用语义化标签。读完后应能独立写出一份结构清晰、能被浏览器和服务器正确解析的页面骨架。本章适合刚接触 Web 前端、准备写 JSP/Thymeleaf/Vue 模板的 Java 开发者。

一、文档结构：一份最小可用的 HTML 骨架

HTML（HyperText Markup Language，超文本标记语言）不是编程语言，它用一组标签给内容加注解。浏览器解析标签，构建出 DOM 树，再渲染成页面。一个规范的 HTML5 文档只需要下面这几行：

<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>商品列表</title>
</head>
<body>
  <h1>商品列表</h1>
  <p>共 12 件商品。</p>
</body>
</html>

这里有三个必须讲清楚的点。第一，<!DOCTYPE html> 不是标签，而是文档类型声明，它告诉浏览器“按标准模式渲染”。漏掉它，浏览器可能进入怪异模式（quirks mode），盒子宽度、行高等计算方式都会和预期不同，这是很多“样式莫名其妙”问题的根源。第二，<head> 中放的是给浏览器看的信息，如字符编码、标题、样式表、脚本；<body> 中才是给用户看的内容。<meta charset="UTF-8"> 必须尽量靠前，否则中文可能整页乱码。第三，标签大多成对出现，形如 <p>…</p>。也有少数空元素（void element）没有结束标签，如 <br>、<hr>、<img>、<input>、<meta>。HTML5 不要求写成 <br /> 这种自闭合形式，但写上也不算错，两者等价。

二、常用标签：文本、列表、链接与图片

标题用 <h1> 到 <h6>，它们表达的是层级而不是字号，不要为了“字大一点”把段落写成 <h4>——需要大字号请交给 CSS。一个页面通常只有一个 <h1>，标题层级尽量不跳级。段落用 <p>，需要换行用 <br>，需要一条分隔线用 <hr>。列表分两种：<ul> 是无序列表，<ol> 是有序列表，它们的子元素必须是 <li>。链接用 <a href="地址">，target="_blank" 表示在新标签页打开。此时建议补上 rel="noopener"，防止新页面通过 window.opener 反向操作原页面。图片用 <img src="路径" alt="说明">，alt 不是可选项：图片加载失败时它显示兜底文字，屏幕阅读器也依赖它。

<h2>帮助中心</h2>
<p>遇到问题可以按下面的顺序排查：</p>
<ol>
  <li>确认网络连接正常</li>
  <li>查看浏览器控制台报错</li>
  <li>联系客服</li>
</ol>
<ul>
  <li><a href="/docs" target="_blank" rel="noopener">使用文档</a></li>
  <li><a href="mailto:support@example.com">发送邮件</a></li>
</ul>
<img src="./images/logo.png" alt="站点 Logo" width="120">

路径是最容易出错的地方。相对路径的规则只有三条：同一级直接写文件名或 ./文件名；上一级写 ../文件名；下一级写 目录名/文件名。相对路径是相对于当前 HTML 文件的位置，而不是相对于代码里 <img> 所在的位置——把页面放到别的目录后图片集体失效，多半就是这个原因。页面锚点用 href="#id" 跳转到同页元素；暂时没有目标地址的链接可以用 # 占位。

三、表格：只用来装表格数据

表格由 <table> 包住，行是 <tr>，单元格是 <td>（数据格）或 <th>（表头格）。更规范的写法是用 <thead>、<tbody>、<tfoot> 把表头、表体、表尾分组，再用 <caption> 给整张表写标题。合并单元格用 colspan（跨列）和 rowspan（跨行）。rowspan="n" 表示这个格子向下占 n 行，被它占掉的位置在后续行里必须少写对应数量的 <td>，否则整张表会错位。

<table>
  <caption>季度销售额（万元）</caption>
  <thead>
    <tr><th>区域</th><th>一季度</th><th>二季度</th></tr>
  </thead>
  <tbody>
    <tr><td rowspan="2">华东</td><td>120</td><td>135</td></tr>
    <tr><td>141</td><td>150</td></tr>
    <tr><td colspan="3">合计：546</td></tr>
  </tbody>
</table>

很多老教程（包括常见的电商注册页案例）用 <table> 加 cellpadding、cellspacing、border、bgcolor 搭整站布局，这在今天已不推荐。这些都属于表现属性，HTML5 中已被废弃，应当改用 CSS 的 border-collapse、padding 控制；而页面布局本身则交给 flex 或 grid。结论很简单：表格只用来展示二维数据，不要用来排版。

四、表单：让页面把数据交给服务器

表单是前后端交互的入口，容器是 <form>，关键属性有三个：action 指定提交地址，method 取 get 或 post，enctype 决定编码方式。get 把参数拼在 URL 后面，长度有限、会留在浏览记录里，适合查询；post 把数据放在请求体里，适合新增、修改和任何敏感信息。只要表单里有文件上传，就必须写成 method="post" 且 enctype="multipart/form-data"，否则后端一个字节的文件都收不到。

表单控件绝大多数是 <input>，由 type 决定具体形态。text、password、radio、checkbox、file、hidden、submit、reset、button 是常用类型。HTML5 又新增了 email、number、date、color 等。多行文本用 <textarea>，下拉框用 <select> 配 <option>，说明文字用 <label>。几条硬规则：控件必须写 name，没有 name 的值不会被提交。一组单选框的 name 必须相同，才能互斥；readonly 的值会提交而 disabled 的值不会提交，服务端校验失败的字段想“只读但要传值”时别用错。

<form action="/user/register" method="post">
  <div>
    <label for="username">用户名</label>
    <input id="username" name="username" type="text"
           maxlength="12" required placeholder="4-12 位字符">
  </div>
  <div>
    <label for="pwd">密码</label>
    <input id="pwd" name="password" type="password" maxlength="20" required>
  </div>
  <div>
    性别：
    <label><input type="radio" name="gender" value="male" checked> 男</label>
    <label><input type="radio" name="gender" value="female"> 女</label>
  </div>
  <div>
    <label for="avatar">头像</label>
    <input id="avatar" name="avatar" type="file" accept="image/*">
  </div>
  <div>
    <label for="city">城市</label>
    <select id="city" name="city">
      <option value="bj">北京</option>
      <option value="sh" selected>上海</option>
    </select>
  </div>
  <button type="submit">注册</button>
</form>

<label for="id"> 与控件的 id 一一对应，点文字也能聚焦控件，对手机端和读屏软件都很重要。还有一个隐蔽的坑：<button> 在表单内的默认 type 就是 submit，如果它只是用来弹个提示，务必显式写 type="button"，否则会意外提交整个表单。

HTML5 表单校验：第一道关卡交给浏览器

老教程里的表单校验清一色是 JavaScript 手写：监听 submit、逐个取值、拼提示文字。HTML5 起浏览器内置了约束校验（constraint validation），多数规则用声明式属性就能表达：required 表示必填，type="email" 按邮箱格式检查，type="url" 检查网址，type="number" 配 min/max/step 限制数值范围，minlength/maxlength 限制长度，pattern 用正则约束格式。校验不通过时浏览器会阻止提交并给出原生提示，不需要额外代码——这是相对“全靠手写 JS 校验”的重要演进。

<form action="/user/register" method="post">
  <input name="email" type="email" required placeholder="you@example.com">
  <input name="phone" type="tel" pattern="1[3-9]\d{9}" title="请输入 11 位手机号">
  <input name="age" type="number" min="18" max="120" step="1">
  <input name="zip" pattern="\d{6}" required>
  <button type="submit">注册</button>
</form>

有三个细节容易踩坑：

  • 其一，pattern 里写的是 JavaScript 正则源码（不带两侧的斜杠），并且浏览器会自动整串匹配，相当于替你加了 ^(?:…)$，所以不要再自己写 ^ 和 $。如果正则本身有语法错误，这个属性会被整个忽略、校验直接放行，这是最隐蔽的一种失效。
  • 其二，title 会作为原生提示的补充说明，建议写清楚期望的格式。
  • 其三，客户端校验只负责体验，不负责安全：请求完全可以绕过页面直接构造，服务端必须把同一套规则再校验一遍。这也是“前端校验 + 后端校验”两道关的由来。

需要自定义逻辑时还有一层 API。在 <form> 上写 novalidate 可关闭原生校验、完全接管流程，其余接口各管一段：

  • form.checkValidity() 返回整体是否通过；form.reportValidity() 让浏览器显示提示。
  • input.setCustomValidity('提示文字') 可注入自定义错误，通过时要传空字符串清除，否则该控件会一直处于无效状态。
  • input.validity 上能读到具体是哪条规则不满足。

这些属性与 API 在现代浏览器中普遍可用，老项目里仍是手写 JavaScript，遇到时可以按需逐步替换。

const form = document.querySelector('form');
form.addEventListener('submit', (e) => {
  if (!form.checkValidity()) {
    e.preventDefault();        // 拦下这次提交
    form.reportValidity();     // 交给浏览器显示原生提示
  }
});

const pwd2 = document.querySelector('#pwd2');
pwd2.setCustomValidity(pwd2.value === pwd.value ? '' : '两次密码不一致');

五、语义化标签与常见坑

只用 <div> 加 class 也能拼出一切，但 HTML5 提供了一批语义化标签。常用的有 <header>、<nav>、<main>、<article> 与 <section>。<aside>、<footer>、<figure>、<time> 等标签也很常用。它们不会自动带来样式，却能让结构自解释：搜索引擎知道哪块是正文，读屏软件能跳到主导航，同事读代码时也不必靠 class 名猜测。<main> 每页只应出现一次，<article> 表示可独立成篇的内容（一篇文章、一条评论），<section> 表示带主题的分块。

最后集中清理几个常见的错误写法。其一，<h1>–<h6> 是成对标签，写成 <hn /> 这种“自闭合的标题”并不存在。其二，<font>、<center>、<big> 已被 HTML5 废弃，字号、颜色、字体一律交给 CSS。老代码里的 <font size="4" color="#3366cc"> 应改写成 class 加样式。其三，<frameset> 框架集也已废弃，页面分栏请用 <iframe> 或后端模板、前端路由。其四，<ol> 的 type 与 start 属性能用，但 reversed 是布尔属性，写 reversed 即可，不必写成 reversed="reversed"。其五，加粗和斜体要分清语义：<strong>、<em> 表示强调，<b>、<i> 只表示视觉加粗倾斜，正文里表示强调应优先用前者。此外，标签名不区分大小写，但统一小写是通行规范；属性值建议始终加引号。

小结：HTML 的骨架是 DOCTYPE + html + head + body，head 里管编码和标题，body 里用语义标签组织内容。链接、图片、列表负责表达内容关系，表格只装数据，表单负责把带 name 的控件值交给服务器。写页面时应养成两个习惯：结构用语义化标签，而不是满屏 <div>；样式和布局一律交给 CSS；表单则先用 required、pattern、type="email" 这类 HTML5 校验属性拦一道，服务端再校验一次。后面学习 CSS 布局、DOM 操作与服务端模板渲染时，会省下大量返工时间。
