Posted on 2021-05-21，16 min read

视图

为了提高复杂SQL语句的复用性和表操作的安全性，MySQL数据库管理系统提供了视图特性。所谓视图，本质上是一种虚拟表，在物理上是不存在的，其内容与真实的表相似，包含一系列带有名称的列和行数据。但是，视图并不在数据库中以存储的数据值形式存在。行和列数据来自定义视图的查询所引用基本表，并且在具体引用视图时动态生成。

视图使开发者只关心感兴趣的某些特定数据和所负责的特定任务，只能看到视图中所定义的数据，而不是视图所引用表中的数据，从而提高了数据库中数据的安全性。

特点

视图的特点如下:

  • 视图的列可以来自不同的表，是表的抽象和在逻辑意义上建立的新关系。
  • 视图是由基本表(实表)产生的表(虚表)。
  • 视图的建立和删除不影响基本表。
  • 对视图内容的更新(添加，删除和修改)直接影响基本表。
  • 当视图来自多个基本表时，不允许添加和删除数据。

视图的操作包括创建视图，查看视图，删除视图和修改视图。

使用场景

视图根本用途：简化sql查询，提高开发效率。如果说还有另外一个用途那就是兼容老的表结构。

下面是视图的常见使用场景：

  • 重用SQL语句；
  • 简化复杂的 SQL 操作：在编写查询后，可以方便地重用它，而不必知道它的基本查询细节；
  • 使用表的组成部分而不是整个表；
  • 保护数据。可以给用户授予表的特定部分的访问权限而不是整个表的访问权限；
  • 更改数据格式和表示。视图可返回与底层表的表示和格式不同的数据。

优点

  1. 查询简单化。视图能简化用户的操作
  2. 数据安全性。视图使用户能以多种角度看待同一数据，能够对机密数据提供安全保护
  3. 逻辑数据独立性。视图对重构数据库提供了一定程度的逻辑独立性

缺点

  1. 性能。数据库必须把视图的查询转化成对基本表的查询，如果这个视图是由一个复杂的多表查询所定义，那么，即使是视图的一个简单查询，数据库也把它变成一个复杂的结合体，需要花费一定的时间。
  2. 修改限制。当用户试图修改视图的某些行时，数据库必须把它转化为对基本表的某些行的修改。事实上，当从视图中插入或者删除时，情况也是这样。对于简单视图来说，这是很方便的，但是，对于比较复杂的视图，可能是不可修改的

下面几类视图通常是不可更新的，即不能通过它们执行 INSERT/UPDATE/DELETE：

  1. 有UNIQUE等集合操作符的视图。

  2. 有GROUP BY子句的视图。

  3. 含有诸如 AVG、SUM、MAX 等聚合函数的视图。

  4. 使用DISTINCT关键字的视图。

  5. 连接表的视图（其中有些例外）

创建与使用视图

-- 创建视图：只暴露需要的列，隐藏敏感字段
CREATE VIEW v_emp_dept AS
SELECT e.id, e.name, d.dept_name
FROM employee e JOIN dept d ON e.dept_id = d.id;

-- 查询视图，用法和查表一样
SELECT * FROM v_emp_dept WHERE dept_name = '研发部';

-- 查看视图定义
SHOW CREATE VIEW v_emp_dept;
-- 也可以查数据字典（MySQL 8.0 中视图定义统一由数据字典维护）
SELECT TABLE_NAME, VIEW_DEFINITION
FROM information_schema.VIEWS
WHERE TABLE_SCHEMA = DATABASE();

-- 修改与删除
CREATE OR REPLACE VIEW v_emp_dept AS SELECT id, name FROM employee;
ALTER VIEW v_emp_dept AS SELECT id, name, dept_id FROM employee;
DROP VIEW IF EXISTS v_emp_dept;

带 WITH CHECK OPTION 的视图会校验写入的数据是否仍满足视图的 WHERE 条件。视图本身不存储数据，它的定义会被合并进对基表的查询，所以复杂视图的查询开销并不比直接写 SQL 小。

游标

游标是系统为用户开设的一个数据缓冲区，存放SQL语句的执行结果，每个游标区都有一个名字。用户可以通过游标逐一获取记录并赋给主变量，交由主语言进一步处理。

在 MySQL 中，游标只能写在存储过程、函数或触发器里，而且是只读、不可滚动、asensitive 的：只能从前往后逐行读取，不能跳过或回退。使用步骤固定为：声明游标 → 声明结束条件 → 打开 → 循环 FETCH → 关闭。

DELIMITER $$
CREATE PROCEDURE p_list_emp()
BEGIN
    DECLARE done INT DEFAULT 0;
    DECLARE v_name VARCHAR(50);
    -- 1. 声明游标
    DECLARE cur CURSOR FOR SELECT name FROM employee;
    -- 2. 声明“没有更多行”的处理：置标记并继续执行
    DECLARE CONTINUE HANDLER FOR NOT FOUND SET done = 1;
    -- 3. 打开游标
    OPEN cur;
    read_loop: LOOP
        FETCH cur INTO v_name;              -- 4. 逐行读取
        IF done = 1 THEN LEAVE read_loop; END IF;
        SELECT v_name;                      -- 这里换成真正的业务处理
    END LOOP;
    CLOSE cur;                              -- 5. 关闭游标
END$$
DELIMITER ;

CALL p_list_emp();

注意：HANDLER 必须声明在游标之后；游标适合表达不好用集合运算描述的逻辑，能用一条 SQL 完成时不要用游标。

存储过程与函数

存储过程是一个预编译的SQL语句，优点是允许模块化的设计，就是说只需要创建一次，以后在该程序中就可以调用多次。如果某次操作需要执行多次SQL，使用存储过程比单纯SQL语句执行要快。

优点

  1. 存储过程是预编译过的，执行效率高。
  2. 存储过程的代码直接存放于数据库中，通过存储过程名直接调用，减少网络通讯。
  3. 安全性高，执行存储过程需要有一定权限的用户。
  4. 存储过程可以重复使用，减少数据库开发人员的工作量。

补充：MySQL 的存储过程由服务器解析并缓存执行计划，并不像 Oracle 那样生成本地编译代码，它带来的主要收益是减少网络往返、统一业务逻辑，而不是“执行一定更快”。

缺点

  1. 调试麻烦：缺少像应用代码那样成熟的单步调试和版本管理手段。
  2. 移植问题：数据库端代码与具体数据库绑定，换库通常要重写。
  3. 重新编译问题：带有引用关系的对象发生改变时，受影响的存储过程、函数需要重新编译（也可以设置为运行时刻自动编译）。
  4. 大量使用存储过程后，随着需求增加会导致数据结构变化，后期维护成本很高。

触发器

触发器是用户定义在关系表上的一类由事件驱动的特殊的存储过程。触发器是指一段代码，当触发某个事件时，自动执行这些代码。

使用场景

  • 可以通过数据库中的相关表实现级联更改。
  • 实时监控某张表中的某个字段的更改而需要做出相应的处理。
  • 例如可以生成某些业务的编号。
  • 注意不要滥用，否则会造成数据库及应用程序的维护困难：触发器逻辑对应用层不可见，出问题时更难排查。

MySQL中都有哪些触发器

按触发时机（BEFORE / AFTER）与事件（INSERT / UPDATE / DELETE）组合，MySQL 共有如下六种触发器：

  • Before Insert、After Insert
  • Before Update、After Update
  • Before Delete、After Delete
DELIMITER $$
-- BEFORE 触发器可以改写即将写入的行：NEW 表示新行，OLD 表示旧行
CREATE TRIGGER trg_emp_before_insert
BEFORE INSERT ON employee
FOR EACH ROW
BEGIN
    IF NEW.join_date IS NULL THEN
        SET NEW.join_date = CURDATE();
    END IF;
    SET NEW.name = TRIM(NEW.name);
END$$

-- AFTER 触发器常用于写日志、同步冗余字段
CREATE TRIGGER trg_emp_after_update
AFTER UPDATE ON employee
FOR EACH ROW
    INSERT INTO emp_log(emp_id, old_name, new_name, changed_at)
    VALUES (OLD.id, OLD.name, NEW.name, NOW());
$$
DELIMITER ;

SHOW TRIGGERS;
DROP TRIGGER IF EXISTS trg_emp_after_update;

版本与限制：MySQL 5.7.2 之前，同一张表的同一事件只能有一个触发器；5.7.2 起允许同一事件存在多个触发器，并用 FOLLOWS / PRECEDES 指定执行顺序。MySQL 不支持 Oracle 那样的 INSTEAD OF 触发器（不能建在视图上）；触发器里也不能修改触发它的那条语句正在使用的表，否则会报 “Can't update table ... already used”（错误码 1442）。

SQL语句

SQL语句分类

  1. 数据定义语言 DDL（Data Definition Language）：CREATE、DROP、ALTER、TRUNCATE、RENAME，操作对象是库、表、视图、索引等逻辑结构。DDL 会隐式提交当前事务。

  2. 数据查询语言 DQL（Data Query Language）：SELECT。各种简单查询、连接查询都属于 DQL。

  3. 数据操纵语言 DML（Data Manipulation Language）：INSERT、UPDATE、DELETE（REPLACE、LOAD DATA 也常被归入 DML），即对数据进行增删改。DQL 与 DML 共同构成了日常的增删改查。

  4. 数据控制语言 DCL（Data Control Language）：GRANT、REVOKE，负责权限控制。而 COMMIT、ROLLBACK、SAVEPOINT 属于事务控制语言 TCL（Transaction Control Language），不要与 DCL 混为一谈。

超键、候选键、主键、外键

  • 超键：在关系中能唯一标识元组的属性集称为关系模式的超键。一个属性可以是超键，多个属性的组合也可以是超键。超键包含候选键和主键。
  • 候选键：是最小超键，即没有任何冗余属性的超键。
  • 主键：从候选键中选定一个用于唯一标识元组。一个表只能有一个主键，主键可以由多列组成（复合主键）；主键列不允许为空——MySQL 中声明为 PRIMARY KEY 的列会被隐式加上 NOT NULL。
  • 外键：表中的一个或多个列，其取值必须匹配另一张表（或本表）的主键或唯一键，也可以为 NULL。InnoDB 支持外键约束，MyISAM 会解析外键定义但忽略它。

SQL 约束

  • NOT NULL：用于控制字段的内容一定不能为空（NULL）。
  • UNIQUE：字段内容不能重复，一个表允许有多个 UNIQUE 约束，且允许多个 NULL 值。
  • PRIMARY KEY：唯一且非空，一个表只允许有一个（可以由多列组合而成）。
  • FOREIGN KEY：维护表之间的引用完整性，外键列的值必须是其指向表的主键/唯一键中的值之一，或者为 NULL。
  • CHECK：控制字段的取值范围。注意 MySQL 8.0.16 之前只是解析并忽略 CHECK 约束，8.0.16 起才真正生效。
  • DEFAULT：插入时未提供该列时使用的默认值。

六种关联查询

  • 交叉连接（CROSS JOIN）
  • 内连接（INNER JOIN，可简写为 JOIN）
  • 左外连接（LEFT JOIN）
  • 右外连接（RIGHT JOIN）
  • 联合查询（UNION 与 UNION ALL）
  • 全外连接（FULL JOIN，MySQL 不支持，需要用 UNION 模拟）

交叉连接不带关联条件，结果是笛卡尔积，行数等于两张表行数之积，结果集很大，实际很少使用：SELECT * FROM A CROSS JOIN B 等价于 SELECT * FROM A, B。

内连接只保留关联条件成立的数据行：SELECT * FROM A, B WHERE A.id = B.id 与 SELECT * FROM A INNER JOIN B ON A.id = B.id 等价，INNER JOIN 可以缩写为 JOIN。

内连接分为三类

内连接分为三类

  • 等值连接：ON A.id=B.id
  • 不等值连接：ON A.id > B.id
  • 自连接：SELECT * FROM A T1 INNER JOIN A T2 ON T1.id=T2.pid

外连接（LEFT JOIN/RIGHT JOIN）

  • 左外连接：LEFT OUTER JOIN, 以左表为主，先查询出左表，按照ON后的关联条件匹配右表，没有匹配到的用NULL填充，可以简写成LEFT JOIN
  • 右外连接：RIGHT OUTER JOIN, 以右表为主，先查询出右表，按照ON后的关联条件匹配左表，没有匹配到的用NULL填充，可以简写成RIGHT JOIN

联合查询（UNION与UNION ALL）

SELECT * FROM A UNION SELECT * FROM B UNION ...
  • 就是把多个结果集集中在一起，UNION前的结果为基准，需要注意的是联合查询的列数要相等，相同的记录行会合并
  • 如果使用UNION ALL，不会合并重复的记录行
  • 效率 UNION ALL 高于 UNION

全连接（FULL JOIN）

  • MySQL不支持全连接

  • 可以使用LEFT JOIN 和UNION和RIGHT JOIN联合使用

    SELECT * FROM A LEFT JOIN B ON A.id = B.id
UNION
SELECT * FROM A RIGHT JOIN B ON A.id = B.id;

子查询

  1. 条件：一条SQL语句的查询结果做为另一条查询语句的条件或查询结果
  2. 嵌套：多条SQL语句嵌套使用，内部的SQL查询语句称为子查询。

子查询的三种情况

  1. 单行单列：结果集是一个值，父查询使用 =、<、> 等运算符。

    -- 查询工资最高的员工
SELECT * FROM employee WHERE salary = (SELECT MAX(salary) FROM employee);

  2. 多行单列：结果集类似一个数组，父查询使用 IN、ANY、ALL 等运算符。

    -- 查询“研发部”下的所有员工
SELECT * FROM employee
WHERE dept_id IN (SELECT id FROM dept WHERE dept_name = '研发部');

  3. 多行多列：结果集类似一张虚拟表，不能直接用于 WHERE 条件，通常放在 FROM 之后作为子表，或改写为连接。

    -- 子表写法：先筛出 2011 年以后入职的员工，再与部门表比对
SELECT d.*, e.*
FROM dept d, (SELECT * FROM employee WHERE join_date > '2011-01-01') e
WHERE e.dept_id = d.id;

-- 等价的连接写法（一般由优化器处理得更好）
SELECT d.*, e.*
FROM dept d INNER JOIN employee e ON d.id = e.dept_id
WHERE e.join_date > '2011-01-01';

mysql中 in 和 exists 区别

in 是先把子查询的结果集取出来再做匹配，exists 是拿外表的每一行去子查询里判断是否存在。谁更快取决于优化器能否把子查询改写成半连接（semi-join，MySQL 5.6 起支持的优化）以及两张表的大小关系，建议用 EXPLAIN 看实际执行计划：

  1. 如果两个表大小相当，用 in 和 exists 差别不大。
  2. 如果一个大表一个小表，子查询表大时用 exists，子查询表小时用 in（把小结果集放进内存匹配更划算）。
  3. not in 与 not exists：NOT IN 遇到子查询结果中含 NULL 时会返回空结果集，这是最常见的坑，此时应改用 NOT EXISTS 或在子查询中过滤掉 NULL；NOT EXISTS 通常也能更好地利用索引。

varchar与char的区别

char的特点

  • char表示定长字符串，长度是固定的；
  • 如果插入数据的长度小于char的固定长度时，则用空格填充；
  • 因为长度固定，所以存取速度要比varchar快很多，甚至能快50%，但正因为其长度固定，所以会占据多余的空间，是空间换时间的做法；
  • 对于char来说，最多能存放的字符个数为255，和编码无关

varchar的特点

  • varchar表示可变长字符串，长度是可变的；
  • 插入的数据是多长，就按照多长来存储；
  • varchar在存取方面与char相反，它存取慢，因为长度不固定，但正因如此，不占据多余的空间，是时间换空间的做法；
  • 对于varchar来说，最多能存放的字符个数为65532

总之，结合性能角度（char更快）和节省磁盘空间角度（varchar更小），具体情况还需具体来设计数据库才是妥当的做法。

varchar(50)中50的涵义

最多存放 50 个字符。varchar(50) 和 varchar(200) 存储 hello 占用的空间一样，但后者在排序、临时表等场景会按定义长度预留更多内存（order by col 采用 fixed_length 计算列长度，MEMORY 引擎也一样），所以长度够用即可。MySQL 4.1 之前 50 代表字节数，4.1 起代表字符数；在 utf8mb4 下 varchar(50) 最多占 50×4=200 字节（另加 1~2 字节长度前缀），建索引时要留意索引键长度限制。

int(20)中20的涵义

是指显示字符的长度：20 表示最大显示宽度为 20，但仍固定占 4 字节存储，取值范围不变；只影响带 ZEROFILL 定义的 int 前面补多少个 0，便于报表展示。注意显示宽度与 ZEROFILL 从 MySQL 8.0.17 起已被废弃，8.0.19 起 SHOW CREATE TABLE 不再输出 int(11) 这类写法，新项目直接写 INT 即可。

mysql为什么这么设计字段

对大多数应用没有意义，只是规定一些工具用来显示字符的个数；int(1)和int(20)存储和计算均一样；

mysql中int(10)和char(10)以及varchar(10)的区别

  • int(10) 的 10 表示显示宽度，不是存储大小；char(10)、varchar(10) 的 10 表示能存储多少个字符。
  • INT 固定占 4 字节（32 位），与括号中的数字无关，有符号范围约 -21 亿 ~ 21 亿，INT UNSIGNED 上限约 42 亿。
  • char(10)：定长字符串，不足 10 个字符时用空格补齐，占用空间固定，读取时尾部空格会被去掉。
  • varchar(10)：变长字符串，只存实际内容加 1~2 字节长度前缀，尾部的空格会按字符保留，这一点与 char 不同。

FLOAT和DOUBLE的区别

  • FLOAT 是单精度浮点数，占 4 字节，约 7 位有效十进制数字。
  • DOUBLE 是双精度浮点数，占 8 字节，约 15~16 位有效十进制数字。
  • 两者都是近似值类型，比较时容易出现精度误差；金额等需要精确计算的场景应使用 DECIMAL。
  • MySQL 8.0.17 起，非标准的 FLOAT(M,D)、DOUBLE(M,D) 写法以及 FLOAT/DOUBLE 的 UNSIGNED 属性已被废弃。

drop、delete与truncate的区别

三者都表示删除，但是差别很大：

Delete Truncate Drop
类型 属于 DML 属于 DDL 属于 DDL
回滚 可回滚（InnoDB） 隐式提交，不可回滚 隐式提交，不可回滚
删除内容 表结构还在，删除全部或一部分数据行（可带 WHERE） 表结构还在，清空表中所有数据 删除表本身，数据、索引、权限一并删除
AUTO_INCREMENT 不重置，继续从当前值递增 重置为 1 表已删除
触发器 会触发 DELETE 触发器 不触发触发器 不触发触发器
删除速度 慢，逐行删除并写 undo/redo 日志 快，按页释放 最快

因此，在不再需要一张表的时候，用 drop；在想删除部分数据行时候，用 delete；在保留表而删除所有数据的时候用 truncate。

UNION与UNION ALL的区别

  • UNION 会对合并后的结果去重（通常需要排序或临时表），UNION ALL 直接拼接，不做去重。
  • 因此效率上 UNION ALL 高于 UNION：可以确定没有重复行时优先使用 UNION ALL。
  • 两者都要求前后两个结果集的列数相同、类型兼容，结果集的列名以第一个 SELECT 为准。
  • UNION 去重时按整行比较，NULL 被视为相同，这一点与用 = 判断不同。

MySQL 5.7 与 8.0 的关键差异

对比项 MySQL 5.7 MySQL 8.0
默认字符集 latin1 utf8mb4
默认排序规则 latin1_swedish_ci utf8mb4_0900_ai_ci（基于 Unicode 9.0 / UCA 9.0.0）
utf8 的含义 utf8 即 utf8mb3，最多 3 字节，emoji 存不进去 utf8 仍是 utf8mb3 的别名，自 8.0.28 起被废弃，应显式使用 utf8mb4

-- 8.0 客户端报 "Authentication plugin 'caching_sha2_password' cannot be loaded" 时：
-- 方案一（推荐）：升级客户端/驱动；方案二：把账号改回 mysql_native_password
ALTER USER 'app'@'%' IDENTIFIED WITH mysql_native_password BY 'StrongPass!2024';
FLUSH PRIVILEGES;

-- 从 5.7 升级到 8.0 前，建议先统一字符集，避免升级后出现乱码
ALTER DATABASE mydb CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
ALTER TABLE employee CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
