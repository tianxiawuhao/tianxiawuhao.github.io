数据结构与算法

Posted on 2026-09-19，10 min read

算法与数据结构是面试的第一道门槛，也是写出高性能代码的底层能力。1.4 已经讲过数组、选择排序、冒泡排序与二分查找，本章接着把剩下的排序算法补齐，再往下钻一层：为什么 HashMap 会「树化」成红黑树，为什么数据库索引偏爱 B+ 树而不是红黑树。理解这两件事，面试里关于集合原理、索引优化、海量数据排序的追问就都能接住。全章代码都可直接编译运行。

八大排序：先看对照表，再看实现

排序算法不需要背代码，但必须能说清每个算法的思想、复杂度、空间开销和稳定性，并且能现场手写其中两三个。下面这张表是本章的总纲。

「稳定性」值得单独解释：排序前后值相等的两个元素相对顺序不变，就叫稳定。它在多关键字排序里很实用——先按金额排序、再按时间排序时，只有稳定排序才能保住前一次的次序。选择排序、希尔排序、快速排序、堆排序都不稳定，归并排序和计数排序稳定，冒泡与插入排序也稳定（前提是交换条件写成严格大于，而不是大于等于）。

插入排序与希尔排序

插入排序把数组分成「已排序区」和「未排序区」，每次取未排序区的第一个元素，在已排序区里从后往前找位置并依次后移。它在数组近乎有序时接近 O(n)，所以生产实现里常被用作小数组的收尾手段（JDK 的 TimSort 就是这么做的）。

public class InsertionSort {

    public static void sort(int[] arr) {
        for (int i = 1; i < arr.length; i++) {
            int current = arr[i];          // 待插入元素，先取出来避免被覆盖
            int j = i - 1;
            while (j >= 0 && arr[j] > current) {   // 比它大的元素依次后移
                arr[j + 1] = arr[j];
                j--;
            }
            arr[j + 1] = current;          // 空出来的位置放进去
        }
    }
}

希尔排序是插入排序的「增量版」：先用较大的步长把数组分成若干组做插入排序，让元素能够大步长地移动，再逐步缩小步长，最后步长为 1 时数组已接近有序，插入排序开销很小。它突破了插入排序 O(n²) 的限制，平均约 O(n^1.3)，代价是不稳定。

public class ShellSort {

    public static void sort(int[] arr) {
        for (int gap = arr.length / 2; gap > 0; gap /= 2) {   // 步长折半
            for (int i = gap; i < arr.length; i++) {
                int current = arr[i];
                int j = i - gap;
                while (j >= 0 && arr[j] > current) {          // 组内插入排序
                    arr[j + gap] = arr[j];
                    j -= gap;
                }
                arr[j + gap] = current;
            }
        }
    }
}

归并排序：唯一稳定的 O(n log n)

归并排序是典型的分治：把数组一分为二，分别排好序，再把两个有序子数组合并成一个。合并时用两个指针比较头部元素，相等时优先取左边那个，稳定性就是靠这一条保证的。它的复杂度在所有情况下都是 O(n log n)，但需要 O(n) 的额外空间。

public class MergeSort {

    public static void sort(int[] arr) {
        if (arr == null || arr.length < 2) {
            return;
        }
        int[] temp = new int[arr.length];   // 复用同一个辅助数组，避免递归里反复开辟
        mergeSort(arr, temp, 0, arr.length - 1);
    }

    private static void mergeSort(int[] arr, int[] temp, int left, int right) {
        if (left >= right) {
            return;
        }
        int mid = left + (right - left) / 2;      // 这样写可避免 left + right 溢出
        mergeSort(arr, temp, left, mid);
        mergeSort(arr, temp, mid + 1, right);
        merge(arr, temp, left, mid, right);
    }

    private static void merge(int[] arr, int[] temp, int left, int mid, int right) {
        int i = left;          // 左半区起点
        int j = mid + 1;       // 右半区起点
        int k = left;
        while (i <= mid && j <= right) {
            // 关键：相等时先取左半区，保证稳定
            if (arr[i] <= arr[j]) {
                temp[k++] = arr[i++];
            } else {
                temp[k++] = arr[j++];
            }
        }
        while (i <= mid) {
            temp[k++] = arr[i++];
        }
        while (j <= right) {
            temp[k++] = arr[j++];
        }
        for (int index = left; index <= right; index++) {   // 拷回原数组
            arr[index] = temp[index];
        }
    }
}

归并排序的实际价值主要在两点：一是外部排序——数据大到内存放不下时，先分块排序写回磁盘，再做多路归并；二是链表排序——链表没有随机访问，归并不需要，而快排需要。

快速排序：实际最快的比较排序

快排选一个基准值（pivot），把数组划分成「小于基准」和「大于基准」两部分，再对两部分递归。它的平均复杂度是 O(n log n) 且常数最小，所以是实践中最快的比较排序；但如果每次都选到最值当基准（例如对已排序数组取第一个元素），就会退化成 O(n²)。

public class QuickSort {

    public static void sort(int[] arr) {
        if (arr == null || arr.length < 2) {
            return;
        }
        quickSort(arr, 0, arr.length - 1);
    }

    private static void quickSort(int[] arr, int low, int high) {
        if (low >= high) {
            return;
        }
        int p = partition(arr, low, high);
        quickSort(arr, low, p - 1);
        quickSort(arr, p + 1, high);
    }

    /** 三数取中选基准，降低「已排序序列」导致退化的概率 */
    private static int medianOfThree(int[] arr, int low, int high) {
        int mid = low + (high - low) / 2;
        if (arr[low] > arr[mid]) {
            swap(arr, low, mid);
        }
        if (arr[low] > arr[high]) {
            swap(arr, low, high);
        }
        if (arr[mid] > arr[high]) {
            swap(arr, mid, high);
        }
        swap(arr, mid, high - 1);   // 把中位数换到 high-1，作为基准
        return arr[high - 1];
    }

    private static int partition(int[] arr, int low, int high) {
        int pivot = medianOfThree(arr, low, high);
        int i = low;
        int j = high - 1;
        while (true) {
            while (arr[++i] < pivot) {
                // 从左找第一个不小于基准的元素
            }
            while (j > low && arr[--j] > pivot) {
                // 从右找第一个不大于基准的元素
            }
            if (i >= j) {
                break;
            }
            swap(arr, i, j);
        }
        swap(arr, i, high - 1);     // 基准归位
        return i;
    }

    private static void swap(int[] arr, int i, int j) {
        int temp = arr[i];
        arr[i] = arr[j];
        arr[j] = temp;
    }
}

工程实现上还有两个常见优化：小区间改用插入排序（长度小于 8～16 时插入排序更快），以及三路划分（把数组分成小于、等于、大于基准三段，大量重复元素时不会退化）。JDK 对基本类型数组用的就是「双轴快排」DualPivotQuicksort。

堆排序：原地且最坏也是 O(n log n)

堆是一棵完全二叉树，用数组就能表示：下标 i 的左孩子是 2i+1、右孩子是 2i+2、父节点是 (i-1)/2。堆排序先建大顶堆，再反复把堆顶（最大值）换到末尾并缩小堆。

public class HeapSort {

    public static void sort(int[] arr) {
        int n = arr.length;
        // 1. 建堆：从最后一个非叶子节点开始向前下沉
        for (int i = n / 2 - 1; i >= 0; i--) {
            siftDown(arr, i, n);
        }
        // 2. 依次把堆顶最大值换到末尾，再对剩余部分重新下沉
        for (int end = n - 1; end > 0; end--) {
            swap(arr, 0, end);
            siftDown(arr, 0, end);
        }
    }

    private static void siftDown(int[] arr, int i, int size) {
        while (true) {
            int left = 2 * i + 1;
            int right = 2 * i + 2;
            int largest = i;
            if (left < size && arr[left] > arr[largest]) {
                largest = left;
            }
            if (right < size && arr[right] > arr[largest]) {
                largest = right;
            }
            if (largest == i) {
                return;
            }
            swap(arr, i, largest);
            i = largest;
        }
    }

    private static void swap(int[] arr, int i, int j) {
        int temp = arr[i];
        arr[i] = arr[j];
        arr[j] = temp;
    }
}

堆排序的价值不在「排序最快」，而在只需 O(1) 额外空间且最坏情况也是 O(n log n)。而堆这个结构本身用途更广：优先队列、TopK 问题（维护一个大小为 K 的小顶堆，遍历一遍即可拿到最大的 K 个）、任务调度、延迟队列，都是堆的应用。Java 里对应 PriorityQueue，默认是小顶堆。

计数排序：不走比较的 O(n + k)

计数排序不比较元素，而是直接统计每个值出现的次数，再按值从小到大输出。它适用于数据范围 k 不大的整数；k 远大于 n 时会白费大量空间。

public class CountingSort {

    /** 适用前提：arr 中的元素都是非负整数，且最大值不太大（k 与 n 同量级） */
    public static int[] sort(int[] arr) {
        if (arr == null || arr.length == 0) {
            return new int[0];
        }
        int max = arr[0];
        for (int value : arr) {
            max = Math.max(max, value);
        }
        int[] count = new int[max + 1];
        for (int value : arr) {
            count[value]++;                 // 统计每个值出现的次数
        }
        // 前缀和：count[i] 变成「值小于等于 i 的元素个数」，用于确定输出位置
        for (int i = 1; i <= max; i++) {
            count[i] += count[i - 1];
        }
        int[] result = new int[arr.length];
        // 从后往前遍历，配合前缀和写入，保证稳定性
        for (int i = arr.length - 1; i >= 0; i--) {
            result[--count[arr[i]]] = arr[i];
        }
        return result;
    }
}

它是基数排序的基础：基数排序按位（个位、十位、百位……）做多轮计数排序，适合对位数固定的非负整数排序，复杂度 O(d × (n + k))。桶排序则是把数据分到若干个桶里，桶内各自排序——三者都属于「非比较排序」，都依赖数据的分布特征。

快速选择与二分查找

「求第 K 大的元素」不需要整体排序：借用快排的划分思想，只递归包含目标的那一半，平均复杂度从 O(n log n) 降到 O(n)，这就是快速选择（Quick Select）。

public class QuickSelect {

    /** 返回数组中第 k 小（k 从 1 开始）的元素 */
    public static int select(int[] arr, int k) {
        int low = 0;
        int high = arr.length - 1;
        while (low <= high) {
            int pivotIndex = partition(arr, low, high);
            if (pivotIndex == k - 1) {
                return arr[pivotIndex];
            } else if (pivotIndex > k - 1) {
                high = pivotIndex - 1;      // 只递归左半边
            } else {
                low = pivotIndex + 1;       // 只递归右半边
            }
        }
        throw new IllegalArgumentException("k 超出范围");
    }

    /** Lomuto 划分：以最后一个元素为基准，比它小的挪到前面 */
    private static int partition(int[] arr, int low, int high) {
        int pivot = arr[high];
        int i = low;
        for (int j = low; j < high; j++) {
            if (arr[j] < pivot) {
                int temp = arr[i];
                arr[i] = arr[j];
                arr[j] = temp;
                i++;
            }
        }
        int temp = arr[i];
        arr[i] = arr[high];
        arr[high] = temp;
        return i;
    }
}

二分查找的前提是数组有序，注意 mid 要用 low + (high - low) / 2 计算，避免 low + high 溢出。除了查「某个值在不在」，二分还有两个高频变体：查第一个大于等于目标的位置（左边界）、查最后一个小于等于目标的位置（右边界）。

public class BinarySearch {

    /** 标准二分：找到返回下标，否则返回 -1 */
    public static int search(int[] arr, int target) {
        int low = 0;
        int high = arr.length - 1;
        while (low <= high) {
            int mid = low + (high - low) / 2;
            if (arr[mid] == target) {
                return mid;
            } else if (arr[mid] < target) {
                low = mid + 1;
            } else {
                high = mid - 1;
            }
        }
        return -1;
    }

    /** 左边界：第一个大于等于 target 的下标；不存在时返回 arr.length */
    public static int lowerBound(int[] arr, int target) {
        int low = 0;
        int high = arr.length;              // 注意是开区间
        while (low < high) {
            int mid = low + (high - low) / 2;
            if (arr[mid] >= target) {
                high = mid;                 // 可能是答案，继续往左找
            } else {
                low = mid + 1;
            }
        }
        return low;
    }
}

红黑树：HashMap 树化的那一层

1.9 提到 TreeMap 基于红黑树、HashMap 在链表过长时会树化，但没有解释红黑树是什么。红黑树是一种自平衡二叉查找树，每个节点额外存一个颜色位，用五条性质约束树的形状。

五条性质里最关键的是后两条：红节点的子节点必须是黑色（不能出现连续两个红节点）、任一节点到其所有叶子路径上的黑节点数目相同。两条合起来保证「最长路径不超过最短路径的两倍」，因此树高为 O(log n)，增删查都是 O(log n)。

插入节点为什么默认涂红？因为红色不改变黑高，不会破坏性质 5，只在出现「红红相连」时才需要修复。修复分两种情形：叔叔节点是红色时只需变色（父与叔变黑、祖父变红，再把祖父当新节点向上检查）；叔叔节点是黑色时需要旋转（LL/RR 型单旋、LR/RL 型双旋），旋转后把新的子树根涂黑、其子涂红。

面试常问「红黑树和 AVL 树怎么选」：AVL 树要求左右子树高度差不超过 1，平衡更严格、查询略快，但插入删除时旋转更频繁；红黑树放弃严格平衡，换来更少的旋转次数。增删频繁、查询也频繁的场景（如 TreeMap、HashMap 桶）选红黑树；查询远多于修改的场景可以选 AVL。

还要能说清 HashMap 树化的条件与意义：当某个桶的链表长度达到 8 且数组容量不小于 64 时，链表转成红黑树，把该桶的查找从 O(n) 降到 O(log n)；元素减少到 6 时会退回链表。阈值 8 不是随便定的——在哈希均匀分布下，一个桶里出现 8 个元素的概率约为千万分之六，正常情况根本不会触发，它是为「哈希被恶意构造」等极端情况准备的兜底。需要提醒的是，HashMap 靠 hashCode() 分布，树化后仍以哈希值为主要比较依据，只有在哈希冲突时才用 Comparable；如果 key 是不可比较的对象且哈希又大量冲突，树化后性能会打折扣。

B 树与 B+ 树：数据库索引为什么不用红黑树

既然红黑树查询是 O(log n)，为什么 MySQL 索引用的是 B+ 树？关键在于 log n 里的常数以及磁盘 IO 的次数。红黑树是二叉的，100 万条数据树高约 20 层，一次查询最多要读 20 个节点；而磁盘读写以「页」（InnoDB 默认 16KB）为单位，每个节点单独一次 IO 意味着 20 次随机读。B+ 树是多路平衡树，一个节点能存几百个 key，树高通常只有 3～4 层，一次查询最多 3～4 次 IO。

B 树与 B+ 树的核心差别有三条：

  • 数据存放位置：B 树的每个节点都存 key 和 data，查找可能在内部节点就命中；B+ 树的内部节点只存 key 做导航，所有 data 都在叶子节点，因此同样一页能容纳更多 key，树更矮。
  • 叶子节点是否相连：B+ 树的叶子节点用链表串起来，范围查询（BETWEEN、>、排序）只需定位到起点后顺序扫描；B 树则需要在树中反复回溯。
  • 查询开销是否稳定：B+ 树每次都要走到叶子，路径长度一致，开销可预测；B 树的查询路径长度不一。

MySQL InnoDB 的两类索引都建立在 B+ 树上。

  • 聚簇索引的叶子节点直接存放整行数据，所以按主键查询一次就能拿到数据。
  • 二级索引（普通索引）的叶子节点存的是主键值，因此「先查二级索引拿到主键，再回聚簇索引取整行」这个过程叫回表。

这也解释了两条优化经验：能用覆盖索引（查询列都在索引里）就避免回表；主键尽量用自增整数，避免页分裂与索引膨胀。

还有两个常被追问的点。

  • 为什么不是哈希索引：哈希索引等值查询是 O(1)，但不支持范围查询和排序，也无法利用最左前缀。
  • 为什么不是跳表：跳表实现简单、并发友好（Redis 的 zset 就用跳表），但它是链表结构，内存开销和局部性都不如 B+ 树，不适合磁盘页。

怎么选：一张决策表收尾

把上面的结论压缩成可直接套用的判断：

  • 小数组（长度小于 16）或近乎有序：插入排序。
  • 要求稳定且要 O(n log n)：归并排序（代价是 O(n) 额外空间）。
  • 通用、追求实际速度、内存够用：快速排序（配合三数取中与小区间插入排序）。
  • 空间受限或要求最坏也 O(n log n)：堆排序。
  • 整数且取值范围不大：计数排序 / 基数排序。
  • 只要第 K 大：快速选择，或维护大小为 K 的堆；TopK 用堆，全排序用快排。
  • 数据大到内存放不下：分块排序 + 多路归并（外部排序）。
  • 需要有序容器且频繁增删：红黑树（TreeMap / TreeSet）。
  • 要做磁盘索引、范围查询：B+ 树。

小结：本章是 1.4 的延续与加深。排序部分要能说清「稳定性、复杂度、空间」三件事，并手写插入、归并、快排、堆排中的两三个；树结构部分要能回答「红黑树的五条性质是什么、HashMap 为什么树化、数据库为什么用 B+ 树而不是红黑树」。把「磁盘按页读」和「树高决定 IO 次数」这两句话记住，索引类问题大多能推导出来。
