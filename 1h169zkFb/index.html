ClickHouse-3数据类型

Posted on 2021-11-14，5 min read

1. 整型

固定长度的整型，包括有符号整型（可取正负）和无符号整型（只能取非负值）。

类比 Java 类型：

CH 类型 取值范围 Java 类型
Int8 -128 ~ 127 Byte
Int16 -32768 ~ 32767 Short
Int32 -2147483648 ~ 2147483647 Int
Int64 -9223372036854775808 ~ 9223372036854775807 Long
UInt8 0 ~ 255 —
UInt16 0 ~ 65535 —
UInt32 0 ~ 4294967295 —
UInt64 0 ~ 18446744073709551615 —

类型名后缀的数字就代表位数：Int8 占 8 位，因此有符号整型的范围是 \(-2^{n-1} \sim 2^{n-1}-1\)，无符号整型的范围是 \(0 \sim 2^{n}-1\)；Java 中没有对应的无符号类型。

-- ClickHouse 会根据字面量大小自动推断类型
SELECT toTypeName(1), toTypeName(-1), toTypeName(300), toTypeName(3000000000);
-- UInt8         Int8          UInt16        UInt64

使用场景：个数、数量，也可以存储 id。

2. 浮点型

类比 Java 类型：

CH类型 Java类型
Float32 float
Float64 double

建议尽可能以整数形式存储数据。例如，将固定精度的数字转换为整数值，如时间用毫秒为单位表示，因为浮点型进行计算时可能引起四舍五入的误差。

使用场景：一般数据值比较小，不涉及大量的统计计算，精度要求不高的时候。比如保存商品的重量。

3. 布尔型

没有单独的类型来存储布尔值。可以使用 UInt8 类型，取值限制为 0 或 1。

4. Decimal 型

Decimal 是有符号的定点数，在加、减、乘法运算过程中可以保持精度；但除法会丢弃最低有效位，并且不四舍五入。

声明方式为 Decimal32(s) / Decimal64(s) / Decimal128(s)，其中 s 表示小数位数（scale），含义与底层位数如下：

类型 总位数 s 的取值 等价的 MySQL 类型
Decimal32(s) 32 位 0 ~ 9 Decimal(9-s, s)
Decimal64(s) 64 位 0 ~ 18 Decimal(18-s, s)
Decimal128(s) 128 位 0 ~ 38 Decimal(38-s, s)

使用场景：金额、汇率、利率等字段为了保证小数点精度，都用 Decimal 存储。

-- 5 位小数，整数部分最多 4 位，整体等价于 MySQL 的 DECIMAL(9, 5)
CREATE TABLE t_price
(
	price Decimal32(5)
)
ENGINE = TinyLog;

INSERT INTO t_price VALUES (12.34567);
-- 除法会截断而非四舍五入
SELECT toDecimal64(1, 4) / toDecimal64(3, 4);  -- 0.3333

5. 字符串

String — 对应 MySQL 的 Varchar
长度不受限，可以包含任意的字节集，也包括空字节。

FixedString(N)
固定长度的字符串，N 必须是严格的正整数。写入长度小于 N 的字符串时，ClickHouse 在末尾补空字节补齐到 N 字节；写入长度大于 N 的字符串时，服务端直接返回错误。
与 String 相比，FixedString 极少使用，因为用起来并不方便。

使用场景：名称、文字描述、字符型编码。定长类型可以保存长度固定的内容，比如编码、性别等；但考虑到数据内容可能变化、定长带来的收益又不明显，定长字符串的使用意义有限。

6. 枚举类型

包括 Enum8 和 Enum16 两种类型。Enum 保存的是『字符串 = 整数』的对应关系：

  • Enum8 用 'String' = Int8 描述，最多 256 个取值；
  • Enum16 用 'String' = Int16 描述，取值更多。

下面创建一个带枚举列 Enum8('hello' = 1, 'world' = 2) 的表：

CREATE TABLE t_enum
(
	x Enum8('hello' = 1, 'world' = 2)
)
ENGINE = TinyLog;

这个 x 列只能存储类型定义中列出的值：'hello' 或 'world'。

INSERT INTO t_enum VALUES ('hello'), ('world'), ('hello');

如果尝试保存任何其他值，ClickHouse 会抛出异常（不同版本报错文案略有差异）：

INSERT INTO t_enum VALUES ('a');
-- Unknown element 'a' for enum

如果需要看到对应行的数值，必须把 Enum 值转换成整数类型：

SELECT CAST(x AS Int8) FROM t_enum;

使用场景：对一些状态、类型的字段算是一种空间优化，也算是一种数据约束。但实际使用中，往往因为数据内容的变化而增加维护成本，甚至造成数据丢失，所以要谨慎使用。

7. 时间类型

目前 ClickHouse 常用的时间类型有 Date、Date32、DateTime 和 DateTime64：

类型 存储 精度与范围
Date 2 字节 精确到天，范围 1970-01-01 ~ 2149-06-06
Date32 4 字节 精确到天，范围 1900-01-01 ~ 2299-12-31
DateTime 4 字节 精确到秒，范围 1970-01-01 00:00:00 ~ 2106-02-07 06:28:15
DateTime64(precision, tz) 8 字节 precision 取 0 ~ 9 表示亚秒精度，如 3 为毫秒、6 为微秒

字面量写法示例：Date 接受 '2019-12-16'，DateTime 接受 '2019-12-16 20:50:10'，DateTime64 接受 '2019-12-16 20:50:10.66'。DateTime 和 DateTime64 还可以附加时区参数，例如 DateTime('Asia/Shanghai')。

8. 数组

Array(T)：由 T 类型元素组成的数组。
T 可以是任意类型，也包括数组类型本身；但不推荐使用多维数组，ClickHouse 对多维数组的支持有限，例如不能在 MergeTree 表中存储多维数组。

创建数组方式 1：使用 array 函数 array(T)

SELECT array(1, 2) AS x, toTypeName(x);
-- [1,2]   Array(UInt8)

创建数组方式 2：使用方括号 []

SELECT [1, 2] AS x, toTypeName(x);
-- [1,2]   Array(UInt8)

9. 其他

除上面这些，ClickHouse 还提供 Nullable(T)（允许 NULL）、LowCardinality(T)（字典编码优化）、UUID、IPv4 / IPv6、Tuple、Map、Nested、AggregateFunction 等类型；Integer、Float 则是 Int32、Float32 的别名。

完整的类型清单可以参考官方文档：ClickHouse 数据类型。
