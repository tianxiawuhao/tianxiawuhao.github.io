1.3 流程控制语句

Posted on 2024-06-20，6 min read

前面几章的程序都是一行一行往下执行的：声明变量、运算、打印，顺序固定。但真实需求很少如此规整——成绩要分等级、月份要判季节、1 到 100 要累加、找到目标要停手。这些都需要程序具备“做判断”与“重复做”的能力，也就是本章的主角：流程控制语句。本章面向刚写完 HelloWorld 的初学者，把顺序、选择、循环、跳转四条线索一次讲透。

一、顺序结构与 if 的三种格式

程序最简单也最常见的流程是顺序结构：代码按书写顺序自上而下依次执行。真正让程序“活”起来的，是在顺序结构里插入判断与循环。

if 解决“满足条件才做某件事”，有三种格式，分别对应一种情况、两种情况、多种情况。判断的载体是关系表达式，它的结果只能是 boolean 类型的 true 或 false——Java 里不能写 if (1)，必须写成 if (x != 0) 这类明确的布尔表达式。

  • 格式一 if (条件) { ... }：条件为真才执行语句体，为假直接跳过。
  • 格式二 if (条件) { ... } else { ... }：二选一，必执行其中一支。例如判断奇偶：a % 2 == 0 是偶数，否则是奇数。
  • 格式三 if (条件1) { ... } else if (条件2) { ... } else { ... }：自上而下逐个判断，命中一个就跳出整个 if 结构，后面的条件不再判断。

第三种格式最适合做分段判断。下面的例子把百分制成绩映射为等级，注意 else 分支负责兜底，同时把非法数据挡在最前面：

public class GradeDemo {
    public static void main(String[] args) {
        int score = 87;

        // 先排除非法数据，让后面的条件可以放心简化
        if (score < 0 || score > 100) {
            System.out.println("成绩数据有误");
        } else if (score >= 90) {
            System.out.println("优秀");
        } else if (score >= 80) {
            System.out.println("良好");
        } else if (score >= 70) {
            System.out.println("中等");
        } else if (score >= 60) {
            System.out.println("及格");
        } else {
            System.out.println("不及格");
        }
    }
}

这里把 score >= 90 后面的条件写成 score >= 80 就够了，不必再写 && score < 90：因为能走到这一行，说明前面已经排除了“大于等于 90”的情况。这种写法既短又不易出错，是 if-else if 链的常用技巧。

二、switch 与 case 穿透

当判断条件是“某个值与一串常量做等值比较”时（比如根据数字 1~7 输出星期），一长串 if-else if 会显得啰嗦，switch 更清晰。它的执行流程是：先算出括号里表达式的值，再用它和各个 case 后的常量依次比较，命中就往下执行，遇到 break 结束整个 switch；全部不匹配时执行 default，default 的位置可以写在任意处，但习惯放在最后。

关于表达式类型，有个常见的过时说法要纠正：老教程说“只支持 byte、short、int、char，JDK 7 以后才支持 String”。实际上枚举类型从 Java 5 起就可用，与 int 兼容的包装类 Integer 也能用（自动拆箱）；String 从 Java 7 起确实可用，但比较的是字符串内容而非引用，且表达式不能为 null，否则运行时会抛 NullPointerException。另外，case 后必须是编译期常量，不能写变量或范围。

switch 最容易踩的坑是遗漏 break 导致的穿透（fall through）：匹配成功后不会自动停止，而是继续执行后面所有分支的语句。穿透有时是故意利用的，比如按月份判断季节：12、1、2 三个月共用同一个语句体。把 case 12:、case 1:、case 2: 依次排好，只在最后一个 case 的语句体末尾写一个 break，命中其中任意一个月都会往下穿到“冬季”并停在那里。写 switch 时的自查习惯是：每一段语句体的末尾都问一句——这里需要一个 break 吗？如果是故意穿透，最好加注释说明，否则半年后连自己都会以为是漏写。补充一点：Java 14 起 switch 还支持箭头语法（如 case 1 -> "优秀";），天然不会穿透，可在熟练经典写法后再了解。

三、循环结构：for、while 与 do-while

循环解决“重复执行同一段代码”。Java 有三种循环语句，它们的执行流程完全一致：初始化 → 判断条件 → 为真则执行循环体 → 执行控制语句 → 回到判断；条件为假时结束。三者的差别只在写法与细节。

  • for (初始化语句; 判断条件语句; 控制条件语句) { 循环体 }：三段式一目了然，适合循环次数已知的场景，如遍历 1~100、遍历数组下标。
  • while (判断条件) { 循环体; 控制语句; }：初始化和控制语句写在循环外，适合循环次数事先不确定的场景。
  • do { 循环体; 控制语句; } while (判断条件);：先执行一次循环体再判断，因此循环体至少执行一次。注意 while (判断条件) 后面必须有分号，这是最容易漏的符号。

还有一个容易被忽略的差别：for 的初始化变量只在循环内可见，循环结束后无法访问；while 的循环变量声明在循环外，循环结束后仍可继续使用。如果这个变量后面还要用，就选 while，否则用 for 更紧凑。

四、break、continue 与递归入门

循环执行到一半想提前结束时，就需要跳转语句：

  • break：立刻结束整个循环，循环体剩下的语句不再执行，循环后面的代码继续。它同时用于 switch 中结束分支。
  • continue：只结束本次循环，跳过循环体剩余部分，接着执行控制语句并进入下一次判断。

以 for (int x = 1; x <= 10; x++) 为例，当 x % 3 == 0 时：写 break，输出 2 次（x 为 1、2）；写 continue，输出 7 次（3、6、9 被跳过）。下面这段代码利用 continue 只累加偶数，循环里 if 与跳转语句的配合一目了然：

public class SumDemo {
    public static void main(String[] args) {
        int sum = 0;

        for (int x = 1; x <= 100; x++) {
            // 奇数直接跳过本次循环
            if (x % 2 != 0) {
                continue;
            }
            sum += x;
        }

        System.out.println("1~100 的偶数和是：" + sum); // 2550
    }
}

在嵌套循环中，两者默认只作用于最内层循环；若想一次跳出外层，需要给循环加标签（outer:）再写 break outer;，但可读性会下降，初学阶段建议改用方法加 return。

还有一类特殊的“重复”：方法自己调用自己，称为递归。写递归必须同时给出两样东西——终止条件（base case）和向终止条件靠近的递归调用，缺一个就会无限递归并抛出 StackOverflowError。以阶乘为例，n! = n × (n-1)!，而 0! 与 1! 都等于 1：

public class FactorialDemo {
    public static void main(String[] args) {
        System.out.println(factorial(5));  // 120
        System.out.println(factorial(10)); // 3628800
    }

    public static long factorial(int n) {
        // 终止条件
        if (n <= 1) {
            return 1L;
        }
        // 递归调用，规模不断缩小
        return n * factorial(n - 1);
    }
}

注意返回值用 long 而不是 int——13! 已超出 int 的取值范围（约 21 亿），会静默溢出成负数；更大的阶乘应当使用 java.math.BigInteger。另外递归层数不能太深，每次调用都占用栈空间，几千层就可能栈溢出。

再看经典的斐波那契数列（1, 1, 2, 3, 5, 8, ……），朴素递归写出来很漂亮，性能却很差：

// 朴素递归：写法直观，但存在大量重复计算
public static long fib(int n) {
    if (n <= 2) {
        return 1L;
    }
    return fib(n - 1) + fib(n - 2);
}

计算 fib(40) 时，fib(2) 这样的最小子问题会被重复求值数千万次，耗时以秒计。写成循环、从小到大递推（保存前两项再滚动更新，O(n) 时间、O(1) 额外空间）才是稳妥的做法。这也说明递归虽优雅，却要为重复计算和栈深度付出代价。

五、常见坑与小结

把初学者最容易出错的地方集中列一遍，再回头做个总结：

  • if / else if 的条件顺序写反：把范围小的条件放在前面。若先写 score >= 60，后面的 score >= 90 永远轮不到。
  • 只判断一边的边界：分段判断要考虑安全数据、边界数据、错误数据，先挡掉非法输入再细分。
  • if / else if 链里变量可能未赋值：若所有分支都写 else if 而没有兜底的 else，编译器会认为变量在某种情况下没有被赋值，从而报“可能尚未初始化”。给变量一个初始值，或补上 else 分支即可。
  • switch 漏写 break：导致穿透，输出多出一串结果。
  • 循环里忘了改变量：while (x < 10) 的循环体中没有 x++，就是死循环；同时注意“差一错误”——x <= 100 与 x < 100 相差一次。
  • while、for 后的分号：for (...); 会让循环体变成空语句，循环空转一轮；do-while 则容易漏写结尾分号。
  • 递归没有终止条件，或递归规模没有缩小，都会导致栈溢出。
  • 整数溢出：int 参与累乘（阶乘、幂运算）前要评估范围，必要时换 long 或 BigInteger。
  • 复杂条件忘加括号：a && b || c 的优先级容易记混，加括号既清晰又安全。

小结：顺序结构是默认路径，if 负责分支选择，switch 负责多路等值匹配（小心穿透），for、while、do-while 负责重复执行，break 与 continue 负责提前结束循环或跳过一轮，递归则是用方法调用表达重复。循环的选择可记成一句话：次数确定用 for，次数不定用 while，必须先做一次用 do-while。真正掌握它们的标志不是背下语法，而是看到需求就能判断该用哪种结构、边界是否周全。建议把示例敲进 IDE 跑一遍，再故意改坏几个条件，观察输出如何变化。
