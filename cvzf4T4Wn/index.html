kafka常用命令

Posted on 2021-10-29，9 min read

管理

从 Kafka 2.2 开始，topic 管理类命令统一通过 --bootstrap-server 连接 broker；旧版的 --zookeeper 参数已经废弃，并在 Kafka 3.0 中被移除，新集群不要再用。下面的示例除对照说明外都使用 --bootstrap-server localhost:9092。

## 创建 topic：4 个分区、2 个副本（副本数不能超过 broker 数量）
bin/kafka-topics.sh --bootstrap-server localhost:9092 --create --topic test --partitions 4 --replication-factor 2

## 分区扩容：只能增加，不能减少（Kafka 不支持删除分区，只能删掉整个 topic 重建）
bin/kafka-topics.sh --bootstrap-server localhost:9092 --alter --topic test --partitions 8

## 删除 topic：需要 broker 配置 delete.topic.enable=true（默认即为 true）
bin/kafka-topics.sh --bootstrap-server localhost:9092 --delete --topic test

## 旧版写法（Kafka < 2.2，仅作对照，--zookeeper 已废弃）
bin/kafka-topics.sh --create --zookeeper localhost:2181 --replication-factor 2 --partitions 4 --topic test
bin/kafka-topics.sh --zookeeper localhost:2181 --alter --topic topic1 --partitions 2
bin/kafka-topics.sh --zookeeper localhost:2181 --delete --topic test

分区数决定 topic 的并行度上限：同一个消费组内，一个分区同一时刻只会分给一个消费者，因此消费者数量超过分区数时，多出来的消费者会一直空闲。副本数（replication-factor）决定冗余能力，取值必须小于等于 broker 数量；同一分区的多个副本分布在不同 broker 上，其中一个为 leader 对外提供读写，其余 follower 持续同步。

查询

## 查看所有 topic
bin/kafka-topics.sh --bootstrap-server localhost:9092 --list

## 查看指定 topic 的分区、副本与 ISR
bin/kafka-topics.sh --bootstrap-server localhost:9092 --describe --topic test
#   Partition  Count  Leader  Replicas  Isr
#   分区号      副本数  leader 所在 broker  副本所在 broker 列表  与 leader 保持同步的副本集合
#   Isr 少于 Replicas 说明有副本没跟上，该分区的可靠性在下降

## 不带 --topic 时，列出集群内所有 topic 的描述信息
bin/kafka-topics.sh --bootstrap-server localhost:9092 --describe

## 消费者组列表
bin/kafka-consumer-groups.sh --bootstrap-server localhost:9092 --list

## 消费组详情：CURRENT-OFFSET / LOG-END-OFFSET / LAG
bin/kafka-consumer-groups.sh --bootstrap-server localhost:9092 --describe --group my-group
#   还可加 --members 看成员分配、--state 只看状态、--all-groups 看所有消费组

## 旧版命令（offset 还存放在 ZooKeeper 的时代，仅作对照）
bin/kafka-consumer-groups.sh --zookeeper localhost:2181 --list
bin/kafka-run-class.sh kafka.tools.ConsumerOffsetChecker --zookeeper localhost:2181 --group test

消费组详情中最关键的一列是 LAG：LAG = LOG-END-OFFSET − CURRENT-OFFSET，也就是「这个分区还有多少条消息没被消费」。LAG = 0 表示已经追平；LAG 长期不降说明消费能力不足，可以在不超过分区数的前提下增加消费者，或优化消费逻辑；LAG 突然暴涨通常是上游流量激增或消费者掉线。详情里还会给出消费组状态（STATE），只有 Stable 时 LAG 才有稳定的参考价值，否则应先排查 rebalance。

发送和消费

## 生产者：从标准输入逐行发送（parse.key=true 时用 \t 分隔 key 与 value）
bin/kafka-console-producer.sh --bootstrap-server localhost:9092 --topic test

## 指定生产者配置文件；旧参数 --broker-list 仍可用，但建议统一改成 --bootstrap-server
bin/kafka-console-producer.sh --broker-list localhost:9092 --topic test --producer.config config/producer.properties

## 消费者：默认只消费新消息，--from-beginning 表示从头消费
bin/kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic test --from-beginning

## 指定消费组（会提交 offset，可在 kafka-consumer-groups.sh 中看到该组的 LAG）
bin/kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic test --group my-group --consumer.config config/consumer.properties

## 打印 key、分区、offset 等元信息，便于确认消息落在哪个分区
bin/kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic test --property print.key=true --property print.partition=true

## 指定分区与起始 offset，最多消费 10 条（offset 也可写 earliest / latest）
bin/kafka-console-consumer.sh --bootstrap-server localhost:9092 --topic test --partition 0 --offset 1234 --max-messages 10

## 消费者早期写法（--zookeeper / --new-consumer 均已废弃，仅作对照）
bin/kafka-console-consumer.sh --zookeeper localhost:2181 --topic test
bin/kafka-console-consumer.sh --new-consumer --bootstrap-server localhost:9092 --topic test

## kafka-verifiable-consumer.sh：消费并打印 offset 提交等事件，用于验证消费链路
## 注意：该工具的参数是 --broker-list，不是 --bootstrap-server
bin/kafka-verifiable-consumer.sh --broker-list localhost:9092 --topic test --group-id groupName

生产与消费工具都支持用 --property 定制输出格式；--bootstrap-server 只需填集群中任意一个（或多个）broker 地址，客户端会自动拉取完整元数据，不必列全所有 broker。

切换leader

## kafka版本 <= 2.4
bin/kafka-preferred-replica-election.sh --zookeeper zk_host:port/chroot

## kafka新版本
bin/kafka-preferred-replica-election.sh --bootstrap-server broker_host:port

kafka自带压测命令

bin/kafka-producer-perf-test.sh --topic test --num-records 100 --record-size 1 --throughput 100  --producer-props bootstrap.servers=localhost:9092

kafka持续发送消息

持续发送消息到指定的topic中，且每条发送的消息都会有响应信息：

kafka-verifiable-producer.sh --broker-list $(hostname -i):9092 --topic test --max-messages 100000

zookeeper-shell.sh

如果 kafka 集群的 zk 配置了 chroot 路径，那么需要加上 /path。

bin/zookeeper-shell.sh localhost:2181[/path]
ls /brokers/ids
get /brokers/ids/0

删除消费者组

查询消费者组列表：

kafka-consumer-groups.sh --bootstrap-server 172.31.1.245:9092 --list

查询消费者组明细：

kafka-consumer-groups.sh --bootstrap-server {Kafka instance connection address} --describe --group {consumer group name}

删除消费者组：

kafka-consumer-groups.sh --bootstrap-server {Kafka instance connection address} --delete --group {consumer group name}
