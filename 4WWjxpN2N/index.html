Groovy基础

基本规则

  • 没有分号
  • 方法括号可以省略
  • 方法可以不写return，返回最后一句代码
  • 代码块可以作为参数传递

Groovy 的定位是运行在 JVM 上的动态语言，编译后同样是字节码，可以与 Java 类互相调用。上面的四条规则中，“没有分号”和“省略括号”让 Gradle 构建脚本看起来像声明式 DSL，而“代码块作为参数传递”正是闭包的基础。

定义

def param = 'hello world'
def param1 = "hello world"
println "${param1} ,li"

${} 里面可以放变量，也可以是表达式，但只有双引号字符串（GString）才会插值；单引号字符串是普通的 java.lang.String，其中的 ${} 会原样输出。GString 在需要时可通过 toString() 或 as String 转换回普通字符串。

GString 与字符串插值

GString 与 Java 字符串的另一个差别是惰性求值：闭包占位符会在 GString 被转成字符串时才执行，而 ${} 中的表达式在构造时就求值。

def name = 'li'
def greeting = "hello ${name}"      // GString，转字符串后为 hello li
def plain = 'hello ${name}'         // String，原样输出 hello ${name}

def counter = 0
def lazy = "count=${-> ++counter}"   // 闭包占位符，惰性求值
println lazy.toString()             // count=1
println lazy.toString()             // count=2

assert greeting instanceof groovy.lang.GString
assert plain instanceof java.lang.String

声明变量

可以在构建脚本中声明两种变量：局部变量和额外属性。

局部变量

局部变量用def关键字声明。它们仅在声明它们的范围内可见。局部变量是基础Groovy语言的功能。

def dest = "dest"
task copy(type: Copy) {
    from "source"
    into dest
}

ext属性

Gradle的域模型中的所有增强对象都可以容纳额外的用户定义属性。

可以通过拥有对象的ext属性添加，读取和设置其他属性。可以使用一个ext块一次添加多个属性。

plugins {
    id 'java'
}
 
ext {
    springVersion = "3.1.0.RELEASE"
    emailNotification = "build@master.org"
}
 
sourceSets.all { ext.purpose = null }
 
sourceSets {
    main {
        purpose = "production"
    }
    test {
        purpose = "test"
    }
    plugin {
        purpose = "production"
    }
}
 
task printProperties {
    doLast {
        println springVersion
        println emailNotification
        sourceSets.matching { it.purpose == "production" }.each { println it.name }
    }
}

输出 gradle -q printProperties

> gradle -q printProperties
3.1.0.RELEASE
build@master.org
main
plugin

变量范围：本地和脚本范围

用类型修饰符（如 String）或 def 声明的变量在闭包中可见，但在方法中不可见；而直接赋值创建的脚本绑定（script binding）在方法中可以访问到。下面的例子分别验证这三种情况。

String localScope1 = 'localScope1'
def localScope2 = 'localScope2'
scriptScope = 'scriptScope'
 
println localScope1
println localScope2
println scriptScope
 
closure = {
    println localScope1
    println localScope2
    println scriptScope
}
 
def method() {
    try {
        localScope1
    } catch (MissingPropertyException e) {
        println 'localScope1NotAvailable'
    }
    try {
        localScope2
    } catch(MissingPropertyException e) {
        println 'localScope2NotAvailable'
    }
    println scriptScope
}
 
closure.call()
method()

输出：闭包可以读取全部三个变量；方法内只有脚本绑定 scriptScope 可见，读取 localScope1 与 localScope2 会抛出 MissingPropertyException。

> groovy scope.groovy
localScope1
localScope2
scriptScope
localScope1
localScope2
scriptScope
localScope1NotAvailable
localScope2NotAvailable
scriptScope

对象

使用对象

您可以按照以下易读的方式配置任意对象。

build.gradle

import java.text.FieldPosition
 
task configure {
    doLast {
        def pos = configure(new FieldPosition(10)) {
            beginIndex = 1
            endIndex = 5
        }
        println pos.beginIndex
        println pos.endIndex
    }
}
> gradle -q configure
1
5

使用外部脚本配置任意对象

您也可以使用外部脚本配置任意对象。

build.gradle

task configure {
    doLast {
        def pos = new java.text.FieldPosition(10)
        // Apply the script
        apply from: 'other.gradle', to: pos
        println pos.beginIndex
        println pos.endIndex
    }
}

other.gradle

// Set properties.
beginIndex = 1
endIndex = 5

输出 gradle -q configure

> gradle -q configure
1
5

闭包

闭包（闭合代码块，可以引用传入的变量）

task testClosure {
    doLast {
        func {
            println it
        }
        funa { a, b ->
            println a + b
        }
    }
}
 
def funa(closure) {
    closure(10, 3)
}
 
def func(closure) {
    closure(10)
}

闭包委托

每个闭包都有一个delegate对象，Groovy使用该对象来查找不是闭包的局部变量或参数的变量和方法引用。

委托策略决定变量和方法的解析顺序：OWNER_FIRST（默认，先找闭包的所有者，再找 delegate）、DELEGATE_FIRST（先找 delegate）、OWNER_ONLY、DELEGATE_ONLY 与 TO_SELF。Gradle 的配置块普遍使用 DELEGATE_FIRST，所以在闭包里写 code = "cix" 会直接设置到 delegate 对象上。

例.闭包委托

class Info {
    int id;
    String code;
 
    def log() {
        println("code:${code};id:${id}")
    }
}
 
def info(Closure<Info> closure) {
    Info p = new Info()
    closure.delegate = p
    // 委托模式优先
    closure.setResolveStrategy(Closure.DELEGATE_FIRST)
    closure(p)
}
 
task configClosure {
    doLast {
        info {
            code = "cix"
            id = 1
            log()
        }
    }
}

输出

> Task :configClosure
code:cix;id:1
 
BUILD SUCCESSFUL in 276ms

例：使用闭包委托设置依赖

dependencies {
    assert delegate == project.dependencies
    testImplementation('junit:junit:4.13')
    delegate.testImplementation('junit:junit:4.13')
}

Groovy 与 Java 的差异

Groovy 不是 Java 的替代品，而是补充：它编译成 JVM 字节码，可以直接调用 Java 类库，也可以在 Java 项目中调用 Groovy 类。下面是日常使用中最容易感知的差异，图中按类别做了对照。

  • 类型系统：def 声明的变量是动态类型，方法调用在运行时解析；Java 是静态类型，编译期检查。需要性能与静态检查时，可以用 @CompileStatic 或 @TypeChecked 让编译器按静态方式处理。
  • 字符串：Groovy 有 GString（"${name}" 插值、多行字符串、闭包占位符惰性求值），Java 用 String.format 或拼接。
  • 闭包：Groovy 的闭包是一等公民，有 owner、this、delegate 和委托策略；Java 只有 Lambda 与匿名内部类，没有 delegate 概念。
  • 安全操作符：Groovy 提供 ?. 安全导航、?.. 安全属性/方法访问、?: Elvis 运算符和 ?. 与 ?: 的组合；Java 需要显式判空或 Optional。
  • 集合：Groovy 为 List、Map、Range 内置 each、collect、find、findAll、inject、groupBy、sort 等扩展方法，并有负数下标与区间取值；Java 依赖 for 循环或 Stream API。
  • 对象配置：with 与 tap 可以在闭包内直接读写对象属性；Java 通常用构造器、setter 链或 Builder。
  • 语法糖：Groovy 可省略分号、括号与 return，支持命名参数自动收拢为 Map、属性访问器与运算符重载；Java 语法更严格。

安全导航与 Elvis

?. 在对象为 null 时不会抛 NullPointerException，而是直接返回 null；Elvis 运算符 ?: 在左侧表达式为假值（null、false、0、空字符串）时取右侧的值。

def user = [name: 'li', address: null]

println user.address?.city        // null，不会抛 NPE
println user.address?.city ?: '未填写'  // 未填写
println user?.name?.toUpperCase() // LI
def city = null
println city ?: 'unknown'         // unknown，等价于 city ? city : 'unknown'

// ?.. 用于直接访问属性或方法而跳过 getter 派发
def prop = user.@class            // 直接读取字段

集合扩展方法

def nums = [1, 2, 3, 4, 5]

println nums.collect { it * 2 }        // [2, 4, 6, 8, 10]
println nums.findAll { it % 2 == 0 }   // [2, 4]
println nums.find { it > 3 }           // 4
println nums.inject(0) { sum, it -> sum + it } // 15
println nums.sum()                     // 15
println nums.groupBy { it % 2 }        // [1:[1, 3, 5], 0:[2, 4]]
println nums.max()                     // 5
nums.eachWithIndex { n, i -> println "$i:$n" }

with 与 tap

with 返回闭包中最后一行表达式的值，适合对一个对象做多步读取或计算；tap 始终返回对象本身，适合链式配置。

def sb = new StringBuilder()
def len = sb.with {
    append('hello')
    append(' world')
    length()                 // with 的返回值
}
println "len=$len, text=$sb" // len=11, text=hello world

def config = new Expando()
config.tap {
    name = 'demo'
    timeout = 30
}.tap {
    retries = 3
}
println "$config.name/$config.timeout/$config.retries" // demo/30/3

@CompileStatic 与性能

动态派发带来灵活性，也带来运行时开销。在热点代码或希望获得编译期检查时，可以加上 @CompileStatic 注解，让编译器生成与 Java 等价的静态调用；@TypeChecked 只做类型检查而不改变调用方式。

import groovy.transform.CompileStatic
import groovy.transform.TypeChecked

@CompileStatic
class Calculator {
    int add(int a, int b) { a + b }   // 编译为静态调用，速度接近 Java
}

@TypeChecked
class Checked {
    String upper(String s) { s.toUpperCase() } // 类型不匹配会在编译期报错
}

需要注意：@CompileStatic 会关闭动态特性，依赖 delegate 的 Gradle 配置块、Expando 动态属性等写法不能直接套用。

与 Gradle 和 Spock 的关系

Gradle 的构建脚本 build.gradle 就是 Groovy 脚本，前面看到的 ext 属性、闭包委托、命名参数、with 与属性访问器，正是 Gradle DSL 的实现方式；而 Gradle 的 Kotlin DSL 则是另一套语法。Spock 是建立在 JUnit 之上的 Groovy 测试框架，用 given/when/then 标签组织用例，并支持数据驱动的 where 块，测试代码可以直接调用被测的 Java 类。

class MathSpec extends spock.lang.Specification {
    def "max should return the larger number"() {
        expect:
        Math.max(a, b) == expected

        where:
        a | b | expected
        1 | 3 | 3
        5 | 2 | 5
    }
}

集合

List

def list = [1,2,3,4]
println list[0] // 1
println list[-1] // 4 最后一个
println list[-2] // 3 倒数第二个
println list[0..2] // [1, 2, 3]，下标 0 到 2 的子列表
println list[0..-2] // [1, 2, 3]，负数下标可以与区间混用
 
list.each { //迭代
    println it
}

Map

def map = ['name':'li', 'age':18]
println map['name'] // li
println map.age // 18
 
map.each { key, value -> // 迭代 Map，闭包接收两个参数
    println "${key}:${value}"
}
map.each { entry -> // 只声明一个参数时拿到 Map.Entry
    println "${entry.key}:${entry.value}"
}

Map 的键默认是字符串，写 map[name] 会先求值变量 name 而抛出 MissingPropertyException，所以中括号里要写字符串字面量或已定义的变量。另外，Groovy 会把 apply plugin: 'java' 这类命名参数自动收拢成一个 Map 作为最后一个参数，这正是 Gradle DSL 能写成 plugin: 'java' 的原因。

JavaBean

class A {
    private int a          // Groovy 属性：自动生成 getter/setter，可通过 a 访问
    int b                  // 同上，公共属性
    final int c = 1        // 只有 getter，没有 setter，不能修改
}
def x = new A()
x.a = 10                   // 实际调用 setA(10)
println x.a                // 实际调用 getA()
println x.b

属性访问器是 Groovy 简化 JavaBean 的关键：字段声明本身就等价于私有字段加 getter/setter，点号访问会自动派发到对应方法；只有 getter 没有 setter 时赋值会抛出 ReadOnlyPropertyException。这一机制也是后面 with、tap 与闭包委托得以工作的基础。
