同步 异步 阻塞 非阻塞

Posted on 2021-09-27，6 min read

IO操作

一次 IO 操作通常被拆成两个阶段（数据一旦拿到手，就变成纯数据操作，不再是 IO）：

  1. 数据准备阶段：等待数据到达内核缓冲区，例如等待网卡收包、等待磁盘把数据读入页缓存。
  2. 数据复制阶段：内核把数据从内核空间复制到用户进程的缓冲区。

操作系统把内存划分为内核空间和用户空间：应用程序运行在用户空间，能直接操作的数据也在用户空间，所以内核必须把数据复制过去，应用才能使用。

这两个阶段正好对应两组最容易混淆的概念：

  • 阻塞 IO 与非阻塞 IO：区别在阶段 1。发起 IO 请求后如果一直等到数据就绪才返回，就是阻塞 IO；如果数据没就绪也立即返回一个状态值，就是非阻塞 IO。
  • 同步 IO 与异步 IO：区别在阶段 2。如果阶段 2 仍要用户线程自己参与（复制完才返回），就是同步 IO；如果由内核把数据复制好、再把结果通知（或回调）用户线程，才是异步 IO。

所以阻塞 IO、非阻塞 IO、IO 多路复用（select/poll/epoll）、信号驱动 IO 都属于同步 IO——它们的阶段 2 依然是阻塞的（虽然耗时很短）。只有内核真正完成“复制 + 通知”的模型（Linux native AIO、io_uring 等）才叫异步 IO。

同步和异步IO 阻塞和非阻塞IO

同步 IO 与异步 IO

  • 同步：用户线程发起 IO 请求后，需要等待或者轮询内核的 IO 操作完成，才能继续执行。
  • 异步：用户线程发起 IO 请求后仍可继续执行，内核完成 IO 后会通知用户线程，或者调用用户线程注册的回调函数。

阻塞 IO 与非阻塞 IO

  • 阻塞：IO 操作需要彻底完成后，调用才返回用户空间。
  • 非阻塞：IO 调用后立即返回一个状态值，不需要等 IO 操作彻底完成。

一句话区分：同步/异步说的是“结果怎么拿到”（自己等待或轮询，还是由对方通知）；阻塞/非阻塞说的是“调用是否立即返回、线程是否被挂起”。前者描述两个对象之间的协作方式，后者描述一个线程当下的状态，二者不在同一个维度上。

同步与异步（线程间调用）

同步与异步对应的是调用者与被调用者，也就是线程之间的关系：两个线程之间要么是同步的，要么是异步的。

  • 同步调用：调用者需要等待被调用者返回结果，才会进行下一步操作。
  • 异步调用：调用者不需要等待被调用者返回，就可以进行下一步操作；被调用者通常依靠事件、回调等机制把结果通知给调用者。

阻塞与非阻塞（线程内调用）

阻塞与非阻塞是对同一个线程来说的：在某个时刻，线程要么处于阻塞状态，要么处于非阻塞状态。它们关注的是程序在等待调用结果（消息、返回值）时的状态。

  • 阻塞调用：调用结果返回之前，当前线程会被挂起，只有得到结果之后调用才会返回。
  • 非阻塞调用：在不能立刻得到结果之前，该调用不会阻塞当前线程，而是立即返回（此时通常还没有结果，需要稍后重试或等待通知）。

同步与异步调用/线程/通信

从更一般的角度看，同步就是两种东西通过某种机制实现步调一致，异步则是两种东西不必步调一致。同一个词在不同语境下含义略有差别：

一、同步调用与异步调用

用在调用场景中，无非是对调用结果的不同处理：

  • 同步调用一旦返回就能知道结果；
  • 异步调用返回时不一定知道结果，还得通过其他机制获知，例如 状态、通知、回调函数。

二、同步线程与异步线程

  • 同步线程：两个线程步调要一致，其中一个线程可能要阻塞等待另外一个线程运行，需要相互协商——快的阻塞一下，等慢的步调一致。
  • 异步线程：步调不用一致，各自按各自的步调运行，不受另一个线程影响。

三、同步通信与异步通信

指的是发送方和接收方是否协调步调一致：

  • 同步通信：发送方和接收方通过一定机制实现收发步调协调。例如发送方发出数据后，等接收方发回响应以后才发下一个数据包。
  • 异步通信：发送方的发送不管接收方的接收状态。例如发送方发出数据后，不等接收方发回响应，接着发送下一个数据包。

最后强调两点：阻塞可以是实现同步的一种手段——两个东西需要同步时，一旦出现不同步，就阻塞快的一方，使双方重新同步；而同步是两个对象之间的关系，阻塞是一个对象的状态，两者不能混为一谈。

四种组合方式

把“发送方是否等待响应”与“接收方 IO 未就绪时是否等待”交叉组合，就得到下面四种方式：

  • 同步阻塞：发送方发送请求之后一直等待响应；接收方处理请求时进行的 IO 操作如果不能马上得到结果，就一直等到有结果才响应发送方，期间不能进行其他工作。这是最常用的方式。
  • 同步非阻塞：发送方发送请求之后一直等待响应；接收方进行的 IO 操作如果不能马上得到结果就立即返回，先去做其他事情，但由于还没有结果，仍不响应发送方。当 IO 完成后把状态和结果通知接收方，接收方再响应发送方，发送方才进入下一次请求过程。（实际不应用）
  • 异步阻塞：发送方向接收方请求后不等待响应，可以继续其他工作；接收方进行的 IO 操作如果不能马上得到结果就一直等，期间不能进行其他操作。（实际不应用）
  • 异步非阻塞：发送方向接收方请求后不等待响应，可以继续其他工作；接收方进行的 IO 操作如果不能马上得到结果也不等待，而是立即返回去做其他事情。当 IO 完成后把状态和结果通知接收方，接收方再响应发送方。（效率最高）

需要说明的是：这里的四种组合是按“发送方是否等待响应”与“接收方 IO 是否等待”抽象划分的，和前面 Linux 五种 IO 模型不是同一套分类；在 IO 模型语境下，只有由内核完成数据复制并通知的异步 IO（对应异步非阻塞）效率最高，其余组合实际很少使用。
