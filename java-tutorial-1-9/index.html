集合框架

Posted on 2026-09-19，6 min read

前面几章用数组存过一批数据，也手写过动态扩容的容器。数组能按下标快速取值，但长度一旦确定就改不了，想删除中间某个元素还得自己把后面的元素往前搬。集合框架解决的正是这类问题：它提供了一整套已经写好的容器，可以自动扩容、按需增删、按键查找、自动去重、自动排序。适合已经掌握类、接口、泛型和基本语法的读者。文中示例基于 JDK 8 及以上，示例均可直接编译运行。

一、集合框架的骨架：两条主线

Java 的集合类都放在 java.util 包中，整体由两条主线构成，理解这两条主线比背下每个类名重要得多。

第一条是 Collection，表示“一组单个元素的容器”，它下面分三支。List 有序、可重复、能按下标访问；Set 不重复、没有下标，只关心“在不在”；Queue 按排队规则取元素，用于先进先出等场景。第二条是 Map，表示“键到值的映射”，它以一对键值作为一个存储单位，所以不继承 Collection。判断该用哪一个，只需问自己三个问题：存的是单个元素还是一组对应关系？元素顺序重要吗？允许重复吗？

这些接口下各有一批常用实现类。ArrayList 用数组实现，查询快；LinkedList 用双向链表实现，头尾增删快；HashSet 用哈希去重，无序；TreeSet 用红黑树，自动排序；HashMap 用哈希表，是最常用的键值容器；TreeMap 是按键排序的映射。写代码时应尽量把变量声明为接口类型，例如 List<String> list = new ArrayList<>();，这样以后换成 LinkedList 时只改一行。

需要说明的是，早期的 Vector、Hashtable、Stack 等类属于遗留集合（legacy collections）。它们的方法是同步的，因此单线程下性能较差，新代码不应该再使用；需要线程安全，请用 ConcurrentHashMap 或 Collections 工具类包装。

二、List 与 Set：ArrayList、HashSet 的取舍

ArrayList 内部是一个 Object[] 数组，所以按下标取值是常数时间，非常快；但往中间插入或删除元素时，需要把后面的元素整体复制后移，代价与元素个数成正比。它有两个容易混淆的概念：容量（capacity）和元素个数（size）。容量是底层数组的长度，会随元素增多自动扩容，默认约为原容量的 1.5 倍，扩容时会复制整个数组；所以如果能预估元素数量，可以用 new ArrayList<>(1000) 一次性给足容量。

HashSet 常被讲得很神秘，其实它本身几乎没有实现：内部持有一个 HashMap，把要保存的元素当作 map 的 key，value 统一使用一个静态常量对象占位。

public class HashSet<E> extends AbstractSet<E>
        implements Set<E>, Cloneable, java.io.Serializable {

    // 所有元素都存放在这个 HashMap 的 key 上
    private transient HashMap<E, Object> map;

    // 占位用的虚拟 value，static final，全局只有一份
    private static final Object PRESENT = new Object();

    public HashSet() {
        map = new HashMap<>();          // 默认容量 16、加载因子 0.75
    }

    public boolean add(E e) {
        return map.put(e, PRESENT) == null;   // put 返回旧的 value
    }

    public boolean contains(Object o) {
        return map.containsKey(o);
    }

    public boolean remove(Object o) {
        return map.remove(o) == PRESENT;
    }

    public int size() {
        return map.size();               // 元素个数，不是底层数组容量
    }
}

为什么 add 写成 map.put(e, PRESENT) == null？因为 HashMap.put 返回的是该 key 原来的 value。如果这个元素之前没出现过，返回 null，说明是新元素，add 返回 true。如果已经存在，返回的是 PRESENT，于是 add 返回 false 且集合内容不变，这正好实现了 Set“不重复”的语义。由此还能推出一个实用结论：Set 靠 hashCode() 和 equals() 判断重复，所以 往 HashSet 里放自定义对象时，必须同时重写这两个方法；只重写其中一个，去重就会失效。另外，HashSet 允许放入 null，且元素的迭代顺序与插入顺序无关，还会随扩容而改变；需要保持插入顺序应改用 LinkedHashSet，需要排序则用 TreeSet。

三、Map：HashMap、TreeMap 与 Hashtable 的对比

HashMap 是最常用的映射实现，它用哈希值定位桶，平均情况下增删改查都是常数时间。它允许一个 null 键和多个 null 值，不保证顺序，且不是线程安全的。JDK 8 之后，当单个桶内的链表长度超过阈值（8）且表容量足够大时，链表会转换成红黑树，把极端情况下的查找从 O(n) 降为 O(log n)。

TreeMap 用红黑树（一种自平衡二叉查找树）实现，元素按键有序存放。因此除了常规的增删查改，它还提供了一批“导航方法”，用来做其它 Map 做不到的事：取最小或最大的键、找小于等于某个键的最大条目、按区间截取子映射。

import java.util.*;

public class MapDemo {
    public static void main(String[] args) {
        Map<String, Integer> scores = new HashMap<>();
        scores.put("语文", 90);
        scores.put("数学", 95);
        System.out.println(scores.get("语文"));        // 90
        System.out.println(scores.getOrDefault("英语", 0));  // 0，键不存在时的默认值

        // 遍历推荐用 entrySet，一次拿到 key 和 value
        for (Map.Entry<String, Integer> e : scores.entrySet()) {
            System.out.println(e.getKey() + "=" + e.getValue());
        }

        // TreeMap 按键排序，并提供导航方法
        TreeMap<Integer, String> rank = new TreeMap<>();
        rank.put(3, "第三名");
        rank.put(1, "第一名");
        rank.put(2, "第二名");
        System.out.println(rank);                 // {1=第一名, 2=第二名, 3=第三名}
        System.out.println(rank.firstKey());      // 1
        System.out.println(rank.floorKey(2));     // 2，小于等于 2 的最大键
        System.out.println(rank.headMap(2));      // {1=第一名}，不含 2

        // TreeSet 同理：自动排序、去重
        TreeSet<String> names = new TreeSet<>();
        names.add("Tom");
        names.add("Amy");
        names.add("Tom");
        System.out.println(names);                // [Amy, Tom]
    }
}

使用 TreeMap/TreeSet 有一个必须知道的前提：元素必须“可比较”，否则运行时抛 ClassCastException。排序规则有两种来源——元素自身实现 Comparable 接口（自然排序），或者在构造时传入 Comparator（定制排序），后者优先级更高。注意“有序”不等于“遍历也高效”：TreeMap 的单次操作是 O(log n)，比 HashMap 的常数时间慢，所以只在确实需要按键排序时才选择它。

关于 Hashtable，它是 JDK 1.0 就存在的遗留类，继承自 Dictionary，所有公开方法都加了 synchronized，因此是线程安全的，但并发性能远不如 ConcurrentHashMap。它与 HashMap 最关键的差别是：Hashtable 既不允许 null 键，也不允许 null 值，而 HashMap 两者都允许（null 键只允许一个）。一些旧笔记写成“Hashtable 的 key 不能为 null，value 可以为 null”，这是错的：Hashtable.put 会先校验 value，为 null 直接抛 NullPointerException。旧教材里常见的 Enumeration 遍历方式已被 Iterator 取代，新代码不应再用。

四、迭代器、泛型与三个常见坑

集合的遍历统一通过迭代器完成。Iterator 有三个方法：hasNext() 判断是否还有元素、next() 取出下一个元素、remove() 删除刚取出的元素。增强 for 循环（for-each）本质上就是迭代器的语法糖，编译后会展开成同样的代码，所以能用 for-each 就不要手写迭代器。

泛型 <E> 给集合加上了编译期类型检查。写成 List<String> list = new ArrayList<>(); 后，list.add(123) 会直接编译报错，而取元素时也不需要再强制类型转换。要记住泛型只存在于编译期。由于类型擦除，运行时 List<String> 和 List<Integer> 是同一个类，所以不能用 instanceof List<String> 判断，也不能 new 泛型数组。<? extends T> 表示“上界，只读”，<? super T> 表示“下界，可写”，这对通配符是集合工具方法里最常见的写法。

最后是三个高频错误。第一，遍历时用集合自己的方法增删元素：在 for-each 中调用 list.remove(o) 会触发 fail-fast 机制，抛出 ConcurrentModificationException。原因是迭代器内部记录了修改次数，集合被直接修改后，计数对不上。正确做法是显式使用迭代器的 remove()，或使用 removeIf()。第二，用 == 比较元素内容：Set 和 List 的 contains、remove 依赖 equals，自定义类不重写 equals 就会按地址比较，导致“明明有这个元素却找不到”。第三，把 size() 当成容量：size() 返回元素个数，反映不出底层数组已扩容到多大，也就不能用来判断是否需要预留空间。

五、小结

集合框架的两条主线是 Collection（List / Set / Queue）与 Map。选型可以按一句话决策：按下标随机访问用 ArrayList；频繁在头尾增删用 LinkedList；自动去重用 HashSet；自动排序用 TreeSet、TreeMap；按 key 快速查找用 HashMap。其中 HashSet 只是把元素放在 HashMap 的 key 上，value 统一用占位对象，因此它完全继承了 hashCode()/equals() 的规则。Hashtable 作为遗留类既慢又禁止 null，新代码不要使用。写代码时优先声明接口类型、优先使用泛型、遍历时不要直接修改集合，就能避开绝大多数集合相关的坑。下一章继续讨论集合之外的另一类基础工具：泛型的进阶用法与类型系统。
