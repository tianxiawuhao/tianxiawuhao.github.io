3.2 CSS 基础与布局

Posted on 2024-08-09，7 min read

上一篇把 HTML 当作“内容的骨架”来搭页面，但如果只写 HTML，浏览器渲染出来的就是一堆从上到下排列的黑字。要让页面有栏、有卡片、有间距、能在手机上正常显示，就必须用 CSS 控制“每个盒子长什么样、摆在哪里”。这一章围绕布局这条主线，把 CSS 的核心机制串起来：选择器怎么精确命中元素、盒模型怎么算出宽度、浮动为什么会塌陷、定位与层叠怎么用，以及今天真正该用的 Flex、Grid 与响应式写法。读完本章应当能做到：拿到一张设计稿，知道用哪种布局方案落地，不再被那些经典 bug 卡住。本章适合已经会写基本 HTML 标签、准备第一次手写页面样式的读者。

一、选择器：先学会“精准命中”

CSS 的全部工作可以概括为一句话：选中元素，然后给它套用声明。选择器决定“选中谁”，声明块决定“变成什么样”。最常用的选择器只有五类，记住它们就足以应付绝大多数页面。

/* 1. 元素选择器：命中所有该标签 */
p { line-height: 1.7; }

/* 2. 类选择器：一个类可以被多个元素复用，也可以在一个元素上叠加多个类 */
.card { border: 1px solid #c8d3e0; border-radius: 8px; }

/* 3. id 选择器：id 在同一页面内必须唯一，不要用来写样式 */
#site-header { height: 64px; }

/* 4. 后代选择器（空格）与子选择器（>） */
.nav a   { color: #2f6fd0; }   /* .nav 内部任意层级的 a */
.nav > a { padding: 0 12px; }    /* 只有 .nav 的直接子元素 a */

/* 5. 伪类：描述“状态”，而不是结构 */
a:hover   { text-decoration: underline; }  /* 鼠标悬停 */
li:nth-child(2n) { background: #f7f9fc; }   /* 第偶数个 li */
input:focus { outline: 2px solid #2f6fd0; } /* 获得焦点 */
input:disabled { opacity: .6; }             /* 被禁用 */

这里要纠正一个常见误解：div p 和 div > p 都是“后代/子”关系，但写法不能混。有些资料把 div p 叫“包含选择器”，把 div > p 叫“子选择器”，其实前者的规范叫法是后代选择器（descendant combinator），后者才是子选择器（child combinator）。另有一个容易写错的细节：.a.b 表示“同时拥有 a 和 b 两个类”，而 .a .b 表示“a 里面的 b”，中间只差一个空格，含义完全不同。

当多条规则同时命中一个元素时，浏览器按层叠（cascade）决定胜负，顺序是：先比来源与重要性（!important 的声明优先），再比特异性（specificity），最后比书写顺序（后写的赢）。特异性的常用记法是四级权重 (a, b, c, d)：

\[ \text{specificity} = (a,\ b,\ c,\ d) \]

其中 a 为行内 style 属性，b 为 id 选择器个数，c 为类、属性选择器与伪类个数，d 为元素与伪元素个数，比较时按位逐级比大小。!important 并不参与这套计算，它直接提升声明的优先级，所以要尽量少用。

p            { color: black; }  /* (0,0,0,1) */
.card p      { color: green; }  /* (0,0,1,1) 胜出 */
#main p      { color: red;   }  /* (0,1,0,1) 再胜出 */

/* 典型翻车：.card p 的权重高于 .title，虽然 .title 写得更靠后 */
.card p  { color: green; }
.title   { color: blue; }

二、盒模型：一切宽度计算的起点

在 CSS 眼里，每个元素都是一个矩形盒子，由内到外分四层：内容区 content、内边距 padding、边框 border、外边距 margin。理解这四层的关键在于分清谁“占位”、谁“可见”：padding 和 border 会撑大元素占用的空间，背景色也会铺到 border 内侧；margin 则是纯透明的间隔，背景不会画上去。

默认情况下，width 设定的只是内容区宽度，元素实际占据的宽度要再加上左右 padding 和左右 border：

\[ W_{\text{占位}} = \text{width} + 2 \times \text{padding} + 2 \times \text{border} \quad(\text{box-sizing: content-box}) \]
\[ W_{\text{占位}} = \text{width} \quad(\text{box-sizing: border-box}) \]

这就是为什么两个各写 width: 50% 又带 padding 的盒子会换行——它们加起来超过了 100%。现代项目的标准做法是在样式表开头统一改成 border-box：

/* 推荐的项目级基线设置 */
*, *::before, *::after {
  box-sizing: border-box;   /* 注意：box-sizing 本身不可继承，必须显式设置每个盒子 */
}
body {
  margin: 0;                /* 浏览器默认给 body 8px 外边距 */
  font: 16px/1.7 system-ui, "Segoe UI", "Microsoft YaHei", sans-serif;
}
img { max-width: 100%; height: auto; display: block; }

还有两个高频踩坑点。

第一是外边距合并（margin collapsing）：相邻的块级元素上下 margin 不会相加，而是取较大值。父子元素之间如果没有 border 或 padding 隔开，子元素的 margin-top 还会“跑”到父元素外面，表现为父元素整体下移。它不是 bug，而是规范规定的行为，所以垂直方向布局更推荐用 Flex 的 gap，或者只让元素保留单侧外边距。

第二是内联元素不吃 width / height。对 <span>、<a> 这类默认 display: inline 的元素设置宽高没有效果，上下 margin 也不生效；需要靠 display: inline-block 才能既保持同行排列、又能设置尺寸。而 display: none 是连盒子都不生成、彻底不占位，别看错成 visibility: hidden——后者只是把元素画成透明，位置仍然留着。

三、从浮动到弹性：布局方式怎么选

早期页面用 float 做多栏布局。浮动的规则是：元素脱离标准文档流，向左右贴靠父容器边缘，后面的文本会绕着它排。紧跟其后的块级元素会填进它腾出的位置，并可能与它重叠；浮动元素则压在重叠区域之上。

.thumb { float: left; width: 200px; margin-right: 16px; }

浮动最经典的坑是父容器高度塌陷：父元素的高度由普通流内容撑开，而浮动子元素已经脱离普通流，于是父元素高度算成 0，背景和边框“缩”成一条线，后面的内容也会顶上来。历史上有三种修法，但优先级完全不同：

/* ① 追加空元素清除浮动：能用，但污染 HTML 结构，不推荐 */
.clearfix { clear: both; }

/* ② 给父元素触发 BFC：overflow: hidden 会裁剪溢出内容，慎用 */
.parent { overflow: hidden; }

/* ③ 现代写法：只清除浮动、不影响溢出裁剪 */
.parent { display: flow-root; }

如今浮动只保留一个正当用途——让文字环绕图片。真正的多栏排版应该交给 Flex 和 Grid。

/* flex：一维排列，主轴上的对齐与空间分配一步到位 */
.toolbar {
  display: flex;
  align-items: center;      /* 交叉轴居中 */
  justify-content: space-between;
  gap: 12px;                /* 用 gap 代替子元素的 margin */
}
.toolbar .search { flex: 1; }        /* 占满剩余空间 */
.toolbar .actions { flex: 0 0 auto; } /* 不伸不缩，按内容宽度 */

/* grid：二维网格，适合整页骨架与卡片墙 */
.cards {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(240px, 1fr));
  gap: 16px;
}

选择标准可以简化成一句话：一维（一行或一列）用 Flex，二维（行列都要对齐）用 Grid，文字环绕用 float。grid-template-columns: repeat(auto-fill, minmax(240px, 1fr)) 这一行还能让卡片按容器宽度自动决定列数，很多时候连媒体查询都省了。

四、定位与层叠：让元素离开原来的位置

position 决定元素“参照谁、是否还占位”。四个常用取值的行为差别很大，必须先记住一条：absolute 的参照物是“包含块”，也就是离它最近、且 position 不是 static 的祖先元素。如果整条祖先链上都没有这样的元素，才会退回到初始包含块（可以粗略理解为视口）。

.banner { position: relative; }          /* 只做参照物，不改变自身位置 */
.banner .badge {
  position: absolute;                    /* 脱离文档流，不再占位 */
  top: 8px;
  right: 8px;                            /* 相对 .banner 的 padding 盒定位 */
}

.site-header { position: fixed; top: 0; left: 0; right: 0; }  /* 相对视口，滚动时不动 */
.toc-title   { position: sticky; top: 0; }                    /* 滚到 top:0 之前就像 relative */

使用定位时最容易混淆的有三点。其一，absolute 的元素会完全脱离文档流，父元素不会再为它留高度，所以常配合 relative 父容器使用。其二，z-index 只对定位元素生效（position: static 的元素设了没用），并且它只在同一个层叠上下文里比较。父元素一旦创建了层叠上下文（例如带 transform、opacity 小于 1、position: fixed），子元素的 z-index 就再也压不过该父元素的兄弟节点。其三，sticky 需要同时给出 top/bottom 之类的阈值才会生效，而祖先元素上的 overflow: hidden 会让它失效。

五、响应式：一套代码适配多种屏幕

响应式的第一步不是写媒体查询，而是在 HTML 里声明视口，否则手机浏览器会假装自己是 980px 宽的桌面浏览器，把整页缩小显示：

<meta name="viewport" content="width=device-width, initial-scale=1">

然后按移动优先的顺序写样式：默认样式面向小屏，再用 min-width 逐级增强。这样做的原因是小屏样式更简单，能避免在窄屏上覆盖一大堆桌面规则；同时媒体查询必须按宽度从窄到宽书写，后写的规则才能在更宽的屏幕上继续生效。

/* 移动端默认：单列 */
.layout { display: grid; grid-template-columns: 1fr; gap: 16px; }

/* 平板及以上：两列 */
@media (min-width: 768px) {
  .layout { grid-template-columns: 200px 1fr; }
}

/* 桌面：三列 */
@media (min-width: 1200px) {
  .layout { grid-template-columns: 200px 1fr 240px; }
}

响应式的本质是内容优先级的重排，而不是把桌面版等比缩小：侧边栏在小屏应当被折叠或移到内容之后，图片要限制最大宽度，表格在窄屏下要考虑横向滚动。断点也不必照抄别人，跟着自己内容的换行临界点走即可。验收时别只看浏览器宽度——把字号调到 200%、把窗口缩到 320px 看看有没有横向滚动条，往往比看设计稿更能发现问题。

六、小结

这一章的主线是“盒子怎么摆”。选择器负责精准命中，特异性 (a, b, c, d) 与书写顺序决定谁说了算；盒模型的四层结构决定了宽度怎么算，项目里统一用 border-box 能省掉大量对齐烦恼。浮动只用来做文字环绕，多栏布局交给 Flex（一维）与 Grid（二维）；absolute 定位要牢记包含块，z-index 只在层叠上下文内比较。响应式则靠 viewport 声明加移动优先的 min-width 媒体查询。下一篇将带着这套样式能力进入 JavaScript，让页面从“静态好看”变成“能响应用户操作”。
