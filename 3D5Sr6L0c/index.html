docker安装ELK

Posted on 2021-05-27，11 min read

一、ELK 组件与版本选择

ELK 是 Elasticsearch（存储与检索）、Logstash（采集与转换）、Kibana（可视化）三个组件的合称，实际生产中通常再加一个 Filebeat（轻量采集端）组成 EFK/ELK 链路。本文按「Elasticsearch → Kibana → Logstash → Filebeat」的顺序用 Docker 逐个部署。

三件事必须在动手前确认，否则后面必然踩坑：

  1. 版本必须统一：Elasticsearch、Kibana、Logstash、Filebeat 四者版本号应完全一致（本文用 7.12.0），跨版本混用会在握手阶段直接报错。
  2. 内核参数 vm.max_map_count：Elasticsearch 使用 mmap 读取索引文件，Linux 默认值 65530 太小，启动时会直接退出并提示 max virtual memory areas vm.max_map_count [65530] is too low。必须先把宿主机参数调到 262144 以上。
  3. 容器网络与卷权限：--link 是 Docker 的早期特性，已不推荐；正确做法是先建一个自定义 bridge 网络，容器之间用容器名互访。Elasticsearch 官方镜像以 uid/gid 1000 的 elasticsearch 用户运行，挂载目录属主不对会报 AccessDeniedException。
# 1. 调整内核参数，写入后立即生效
sudo sysctl -w vm.max_map_count=262144
# 永久生效
echo "vm.max_map_count=262144" | sudo tee -a /etc/sysctl.conf

# 2. 创建自定义网络，后续所有容器都接入该网络
docker network create elk

# 3. 准备数据与日志目录，并交给 elasticsearch 容器用户（uid 1000）
sudo mkdir -p /data/elk/es-data /data/elk/es-logs
sudo chown -R 1000:1000 /data/elk

如果宿主机内存较小，还应在启动 Elasticsearch 时通过 ES_JAVA_OPTS 限制堆内存（见下一节）。

二、Docker 部署 Elasticsearch

搜索 Elasticsearch 镜像

docker search elasticsearch

拉取镜像

拉取镜像时建议显式指定版本；不指定则默认 latest，在 8.x 之后 latest 会拉到 8.x 镜像，行为与 7.x 差异很大（见第八节版本差异对比）。

docker pull elasticsearch:7.12.0

查看镜像

docker images

docker 启动 Elasticsearch

下面的命令在原文基础上补了三处关键参数：-v 数据卷（否则容器删除后索引全丢）、ES_JAVA_OPTS 堆内存上限，以及显式的集群名。容器接入第一步创建的 elk 网络。

# --name : 为 elasticsearch 容器起个别名
# -e : 指定为单节点集群模式
# -i：表示运行容器
# -t：表示容器启动后会进入其命令行。加入这两个参数后，容器创建就能登录进去。即分配一个伪终端。
# -v：表示目录映射关系（前者是宿主机目录，后者是映射到宿主机上的目录），可以使用多个－v做多个目录或文件映射。注意：最好做目录映射，在宿主机上做修改，然后共享到容器上。
# -d：在run后面加上-d参数,则会创建一个守护式容器在后台运行（这样创建容器后不会自动登录容器，如果只加-i -t两个参数，创建后就会自动进去容器）。
# -p：表示端口映射，前者是宿主机端口，后者是容器内的映射端口。可以使用多个-p做多个端口映射
docker run -d --name elasticsearch --net elk \
  -p 9200:9200 -p 9300:9300 \
  -e "discovery.type=single-node" \
  -e "cluster.name=docker-cluster" \
  -e "ES_JAVA_OPTS=-Xms512m -Xmx512m" \
  -v /data/elk/es-data:/usr/share/elasticsearch/data \
  -v /data/elk/es-logs:/usr/share/elasticsearch/logs \
  elasticsearch:7.12.0

# 验证：等待 30 秒左右待其完成启动
curl http://localhost:9200
# 返回 JSON 中出现 "number" : "7.12.0"、"cluster_name" : "docker-cluster" 即成功

Elasticsearch 索引策略与模板配置

下文命令中的 ${host} 是 shell 变量，需先导出，例如 export host=http://localhost:9200；所有请求都是 JSON 体，-H 'Content-Type: application/json' 不能省。

创建elasticsearch滚动策略

# 定义审计日志管理策略
curl -X PUT "${host}/_ilm/policy/audit_policy" -H 'Content-Type: application/json' -d'
{
  "policy": {                       
    "phases": {
      "hot": {                      
        "actions": {
          "rollover": {             
            "max_size": "30GB",
            "max_age": "180d"
          }
        }
      },
      "delete": {
        "min_age": "180d",           
        "actions": {
          "delete": {}              
        }
      }
    }
  }
}

热数据最大 30G、最多 180 天；数据保留超过 180 天后删除。

三、Docker 安装 Kibana

拉取镜像

拉取镜像的时候，需要注意的是, kibana 的版本最好与 elasticsearch 保持一致, 避免发生不必要的错误

docker pull kibana:7.12.0

查看镜像

docker images

docker 启动 kibana

# -e I18N_LOCALE：Kibana 7.x 的中文界面开关（Kibana 8.x 起改用 i18n.locale 配置）
# ELASTICSEARCH_HOSTS：Kibana 连接 ES 的地址，容器间用容器名 + 9200 端口
docker run -d --name kibana --net elk \
  -e "ELASTICSEARCH_HOSTS=http://elasticsearch:9200" \
  -e "I18N_LOCALE=zh-CN" \
  -p 5601:5601 \
  kibana:7.12.0
# 如果不习惯汉化，去掉 I18N_LOCALE 环境变量即可：
docker run -d --name kibana --net elk -e "ELASTICSEARCH_HOSTS=http://elasticsearch:9200" -p 5601:5601 kibana:7.12.0

启动后访问 http://<宿主机IP>:5601，能打开 Kibana 首页即说明与 ES 连接正常；若页面提示 Unable to connect to Elasticsearch，先在容器内用 curl http://elasticsearch:9200 排查网络与地址。Kibana 启动较慢，首次访问可能需要等 1—2 分钟。

四、Docker 安装 Logstash

拉取镜像

拉取镜像的时候，需要注意的是, Logstash 的版本最好与 elasticsearch 保持一致, 避免发生不必要的错误

docker pull logstash:7.12.0

查看镜像

docker images

文件映射

在本机建立配置文件和目录，用来存放所有需要映射进容器的配置。

# 宿主机目录结构
/usr/local/logstash/config/logstash.yml   # 主配置
/usr/local/logstash/conf.d/               # 存放各个 pipeline 配置
/usr/local/logstash/data/                 # 持久化 sincedb、last_run 元数据

logstash.yml（主配置文件，内容如下）：

path.config: /usr/share/logstash/conf.d/*.conf
path.logs: /var/log/logstash
# 关掉自带的 X-Pack 监控上报，单机部署没必要，也可避免无谓的 ES 连接报错
xpack.monitoring.enabled: false

conf.d/configuration.conf（pipeline 配置文件，每个文件是一套独立的 input/filter/output，内容如下）：

Filebeat和elasticsearch的交互

input {
  beats {
    port => 5044
    # Filebeat 默认发送的是逐行 JSON，用 json_lines 才能按行解析
    codec => json_lines
  }
}

output {
  elasticsearch {
    hosts => ["http://elasticsearch:9200"]
    index => "export_log_index"
  }
  stdout { codec => rubydebug }
}

mysql和elasticsearch的交互

input {
  jdbc {
    jdbc_driver_class => "com.mysql.cj.jdbc.Driver"
    jdbc_driver_library => "/usr/share/logstash/logstash-core/lib/jars/mysql-connector-java-8.0.28.jar"
    jdbc_connection_string => "jdbc:mysql://localhost:3306/db_example"
    jdbc_user => root
    jdbc_password => ymruan123
    #启用追踪，如果为true，则需要指定tracking_column
    use_column_value => true
    #指定追踪的字段，
    tracking_column => "last_updated"
    #追踪字段的类型，目前只有数字(numeric)和时间类型(timestamp)，默认是数字类型
    tracking_column_type => "numeric"
    #记录最后一次运行的结果
    record_last_run => true
    #上面运行结果的保存位置
    last_run_metadata_path => "jdbc-position.txt"

    index => "export_log_index"

  stdout{
    codec => rubydebug
  }
}

docker 启动 Logstash

用同一条自定义网络 elk 代替 --link。启动后用 docker logs 关注日志里的 Pipeline started，确认 pipeline 配置语法无误。

docker run -d --name logstash --net elk \
  -p 5044:5044 -p 4560:4560 -p 9600:9600 \
  -v /usr/local/logstash/config/logstash.yml:/usr/share/logstash/config/logstash.yml \
  -v /usr/local/logstash/conf.d/:/usr/share/logstash/conf.d/ \
  -v /usr/local/logstash/data/:/usr/share/logstash/data/ \
  logstash:7.12.0

# 查看启动日志，确认没有 ConfigurationError 且出现 Pipeline started
docker logs -f logstash

注意版本：原文这里写的是 logstash:7.4.1，与 ES/Kibana 的 7.12.0 不一致，已统一为 7.12.0。另外 Logstash 必须同时映射 9600 端口——这是它自己的监控 API，GET /_node/stats 可查看事件吞吐与管道状态。

五、Docker 安装 Filebeat

拉取镜像

拉取镜像的时候，需要注意的是, Filebeat 的版本最好与 elasticsearch 保持一致, 避免发生不必要的错误

# 官方镜像仓库域名形式（推荐），等效于 7.12 时期的 store/elastic/filebeat:7.12.0
docker pull docker.elastic.co/beats/filebeat:7.12.0

查看镜像

docker images

文件映射

下载默认官方配置文件

wget https://raw.githubusercontent.com/elastic/beats/7.12/deploy/docker/filebeat.docker.yml

注意：文件放在宿主机的 /data/elk/filebeat 目录下

打开配置文件
vim filebeat.docker.yml，内容如下：

# 日志输入配置
filebeat.inputs:
- type: log
  enabled: true
  paths:
  # 需要收集的日志所在的位置，可使用通配符进行配置
  #- /data/elk/*.log
  - /logs/*/*.log

# 日志输出配置（采用 logstash 收集日志，5044 为 logstash 端口）
# 同一 docker 网络内可直接用容器名，不必写死宿主机 IP
output.logstash:
  hosts: ['logstash:5044']

若 Filebeat 与 Logstash 不在同一台机器或同一网络，则把 logstash:5044 换成 Logstash 所在宿主机 IP（例如 192.168.12.183:5044），并确保该端口已放通防火墙。

docker 运行 Filebeat

docker run -d --name filebeat --user=root --net elk \
  --volume="/usr/local/filebeat/log/nginx/:/var/log/nginx/" \
  --volume="/data/elk/filebeat/filebeat.docker.yml:/usr/share/filebeat/filebeat.yml" \
  --volume="/var/lib/docker/containers:/var/lib/docker/containers:ro" \
  --volume="/var/run/docker.sock:/var/run/docker.sock:ro" \
  docker.elastic.co/beats/filebeat:7.12.0

这里挂载 /var/lib/docker/containers 与 docker.sock 是为了采集宿主机上其他容器的标准输出日志（Filebeat 的 add_docker_metadata / autodiscover 需要它们），只读挂载即可；--user=root 是为了让容器内进程有权读取这些 root 属主的路径。原文这里用的网络名是 somenetwork，而前面创建的是 elk，已统一，否则 Filebeat 无法解析 logstash 这个容器名。

六、中文分词插件 analysis-ik

前面创建索引模板时用到了 ik_max_word 分析器。这是第三方插件，Elasticsearch 官方镜像不自带；如果不安装就直接按该模板创建索引，会报 analyzer [ik_max_word] not found（模板本身能创建成功，但用它建索引时会失败）。

# 方式一：进容器安装（插件版本必须与 ES 版本严格一致）
docker exec -it elasticsearch bash
bin/elasticsearch-plugin install https://github.com/medcl/elasticsearch-analysis-ik/releases/download/v7.12.0/elasticsearch-analysis-ik-7.12.0.zip
exit
docker restart elasticsearch

# 方式二：构建自带插件的镜像（生产更推荐，容器重建后插件不会丢）
cat > Dockerfile <<'EOF'
FROM elasticsearch:7.12.0
RUN bin/elasticsearch-plugin install --batch \
    https://github.com/medcl/elasticsearch-analysis-ik/releases/download/v7.12.0/elasticsearch-analysis-ik-7.12.0.zip
EOF
docker build -t elasticsearch-ik:7.12.0 .

若把 /usr/share/elasticsearch/plugins 映射到宿主机目录，则插件必须提前解压到该目录，否则容器重建后插件丢失、索引无法写入。安装完成后验证：

curl -X POST "http://localhost:9200/_analyze" -H 'Content-Type: application/json' -d'
{"analyzer": "ik_max_word", "text": "中华人民共和国国歌"}
'
# 返回的 tokens 中若能切出「中华人民共和国」「国歌」等词，说明插件生效

七、用 docker-compose 统一编排

逐个 docker run 适合理解各组件参数，但环境难以复现。下面这份 compose 文件等价覆盖了前五节的全部内容，可直接 docker compose up -d 启动（Compose V2 命令为 docker compose，老版本是 docker-compose）。

version: "3.8"
services:
  elasticsearch:
    image: elasticsearch:7.12.0
    container_name: elasticsearch
    environment:
      - discovery.type=single-node
      - cluster.name=docker-cluster
      - ES_JAVA_OPTS=-Xms512m -Xmx512m
    ulimits:
      memlock: { soft: -1, hard: -1 }
      nofile: { soft: 65536, hard: 65536 }
    volumes:
      - ./es-data:/usr/share/elasticsearch/data
      - ./es-logs:/usr/share/elasticsearch/logs
    ports:
      - "9200:9200"
      - "9300:9300"
    networks: [elk]
    healthcheck:
      test: ["CMD-SHELL", "curl -fs http://localhost:9200/_cluster/health || exit 1"]
      interval: 10s
      timeout: 5s
      retries: 12

  kibana:
    image: kibana:7.12.0
    container_name: kibana
    environment:
      - ELASTICSEARCH_HOSTS=http://elasticsearch:9200
      - I18N_LOCALE=zh-CN
    ports:
      - "5601:5601"
    depends_on:
      elasticsearch: { condition: service_healthy }
    networks: [elk]

  logstash:
    image: logstash:7.12.0
    container_name: logstash
    volumes:
      - ./logstash/config/logstash.yml:/usr/share/logstash/config/logstash.yml
      - ./logstash/conf.d:/usr/share/logstash/conf.d
      - ./logstash/data:/usr/share/logstash/data
    ports:
      - "5044:5044"
      - "4560:4560"
      - "9600:9600"
    depends_on:
      elasticsearch: { condition: service_healthy }
    networks: [elk]

  filebeat:
    image: docker.elastic.co/beats/filebeat:7.12.0
    container_name: filebeat
    user: root
    volumes:
      - ./filebeat/filebeat.docker.yml:/usr/share/filebeat/filebeat.yml
      - /var/lib/docker/containers:/var/lib/docker/containers:ro
      - /var/run/docker.sock:/var/run/docker.sock:ro
      - ./nginx-logs:/logs:ro
    depends_on: [logstash]
    networks: [elk]

networks:
  elk:
    driver: bridge

使用前注意三点：宿主机目录 ./es-data、./es-logs 需先 mkdir 并 chown 1000:1000（否则 ES 直接启动失败）；vm.max_map_count=262144 仍需在宿主机设置；depends_on 只保证启动顺序，condition: service_healthy 才保证依赖服务真正就绪（7.12 的 ES 镜像不含 curl 时，健康检查可改用 bash -c 'echo > /dev/tcp/localhost/9200'）。

八、7.x 与 8.x 的关键差异

本文示例基于 7.12.0。若要改用 8.x，下面几处差异会让原文命令直接报错，务必先调整。

# 8.x 默认开启安全认证：ES 首次启动会自动生成 elastic 用户密码，并启用 HTTPS
# 快速验证环境可以显式关闭安全（仅限内网测试，勿用于生产）
docker run -d --name elasticsearch --net elk \
  -p 9200:9200 \
  -e "discovery.type=single-node" \
  -e "xpack.security.enabled=false" \
  -e "ES_JAVA_OPTS=-Xms512m -Xmx512m" \
  -v /data/elk/es-data:/usr/share/elasticsearch/data \
  docker.elastic.co/elasticsearch/elasticsearch:8.13.4

# 若保留默认安全：用以下命令重置/查看密码，请求需携带 -u 与 -k（自签证书）
docker exec -it elasticsearch bin/elasticsearch-reset-password -u elastic
curl -k -u elastic:<密码> https://localhost:9200
  • 安全认证：7.x 默认关闭（需手动配置 xpack.security 才启用）；8.x 默认开启，HTTP 端口启用 TLS，写入/查询必须带认证。
  • Kibana 连接加密开关：8.x 连接启用 HTTPS 的 ES 时要额外配置 ELASTICSEARCH_HOSTS=https://elasticsearch:9200、ELASTICSEARCH_USERNAME、ELASTICSEARCH_PASSWORD，以及证书信任（或 ELASTICSEARCH_SSL_VERIFICATIONMODE=none，仅用于测试）。
  • Logstash 输出：8.x 连接启用安全的 ES 需加 user/password（或 api_key）与 ssl => true、cacert。
  • 索引模板 API：_template（legacy template）自 7.8 起被可组合模板 _index_template 取代、8.x 中移除，需改写为带 template 与 composed_of 结构的可组合模板。
  • Filebeat 输入类型：8.x 推荐 filestream 输入（log 类型仍可用但已不推荐）。
  • 镜像仓库：统一使用 docker.elastic.co/... 官方仓库，旧别名 store/elastic/* 已不再维护。
  • 默认 JVM 堆：8.x 镜像默认按容器内存自动推断堆大小，小内存机器反而更容易被 OOM Kill，仍建议显式设置 ES_JAVA_OPTS。

九、部署验证与常见报错

四步验证，全部通过即链路可用：

  1. curl http://localhost:9200/_cluster/health?pretty → "status" : "green"（单节点无副本时可能为 yellow，属正常）。
  2. Kibana 打开 http://<宿主机IP>:5601，Stack Management → 索引管理能看到 export_log_index-000001。
  3. curl http://localhost:9600/_node/stats/pipelines?pretty → 查看 events.in / events.out 是否增长。
  4. docker logs filebeat 无 Failed to connect，Kibana 中能搜到业务日志。

常见报错与处理：

  • max virtual memory areas vm.max_map_count [65530] is too low：宿主机未设置内核参数，执行第一节的 sysctl -w vm.max_map_count=262144。
  • AccessDeniedException: /usr/share/elasticsearch/data/...：挂载目录属主不是 uid 1000，执行 sudo chown -R 1000:1000 /data/elk。
  • analyzer [ik_max_word] not found：未安装 analysis-ik 插件，见第六节。
  • Logstash 报连接 ES 超时：配置里写了 localhost:9200，容器内应改为 http://elasticsearch:9200。
  • Logstash 只收到一条合并的日志或字段错乱：codec 用了 json，需改为 json_lines。
  • Kibana 反复重启：与 ES 版本不一致，或 ELASTICSEARCH_HOSTS 写成了 localhost。
  • 启动后 docker ps 看不到容器：缺少 -d，或容器启动即退出，用 docker logs <容器名> 查看退出原因。
