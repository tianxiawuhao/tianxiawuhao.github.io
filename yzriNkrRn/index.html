Linux文件操作高频使用命令

Posted on 2021-04-25，14 min read

新建操作：

mkdir abc #新建一个文件夹
touch abc.sh #新建一个文件

查看操作

查看目录：

ll              # 显示目录文件详细信息（ls -l 的别名）
du -h 文件/目录  # 查看文件或目录占用的大小
df -h           # 查看各文件系统的空间使用率
df -i           # 查看 inode 使用率（inode 用满时，即使还有空间也建不了新文件）
pwd             # 显示当前路径

查看文件内容：

cat|head|tail命令

# 查看 abc.txt 的内容
cat abc.txt
# 查看前 5 行（默认显示 10 行）
head -5 abc.txt
# 从第 3 行开始显示到文件末尾
tail -n +3 abc.txt
# 查看最后 20 行
tail -20 abc.txt
# 循环读取文件末尾新增的内容，常用于实时观察日志（Ctrl+C 退出）
tail -f filename
# 日志被切割/重建后，-F 会按文件名重新跟踪，长期观察日志更推荐 -F
tail -F filename

more命令：

more 命令一次显示一屏信息，信息未显示完时屏幕底部会出现“--More--(xx%)”。此时按 Space 显示下一屏，按回车显示下一行，按 B 显示上一屏，按 Q 退出。more 只能向后翻页，因此实际使用中 less 更常用。

less命令：

和more命令类似，但是比more命令更强大。在很多时候，必须使用less,比如管道。例如：

ll /etc | less

stat 命令：

查看文件的详细信息，比如创建修改时间，大小等

[root@localhost zx]# stat index.html
  文件："index.html"
  大小：29006     	块：64         IO 块：4096   普通文件
设备：fd00h/64768d	Inode：17589607    硬链接：1
权限：(0644/-rw-r--r--)  Uid：(    0/    root)   Gid：(    0/    root)
环境：unconfined_u:object_r:home_root_t:s0
最近访问：2021-04-25 21:47:41.824053666 +0800
最近更改：2021-04-25 21:44:33.588587500 +0800
最近改动：2021-04-25 21:44:33.588587500 +0800
创建时间：-

stat 输出里的三个时间是：最近访问（Access，atime，文件被读取）、最近更改（Modify，mtime，文件内容被修改）、最近改动（Change，ctime，权限、属主等元数据变化）。创建时间取决于文件系统与内核是否记录 birth time，不支持时显示为 -，也可以用 stat -c '%w %n' 文件 单独查看。

du 命令：

选项：-h 以合适的单位显示（会根据文件的大小自动选择kb或M等单位）

[root@localhost zx]# du -h index.html
32K	index.html

du 统计的是文件内容实际占用，df 统计的是文件系统整体占用，两者口径不同。空间“看起来没满却写不进去”通常有两种原因：inode 被用完（df -i 查看），或者有进程仍持有已删除的文件（用 lsof +L1 定位）。

复制操作

同一机器的复制：

cp:复制文件或目录

语法：

cp [options] source dest

    -a：此选项通常在复制目录时使用，它保留链接、文件属性，并复制目录下的所有内容。等价于 -dR --preserve=all（常简写理解为 -dpR）。
    -d：复制时保留链接。这里所说的链接相当于Windows系统中的快捷方式。
    -f：覆盖已经存在的目标文件而不给出提示。
    -i：与-f选项相反，在覆盖目标文件之前给出提示，要求用户确认是否覆盖，回答"y"时目标文件将被覆盖。
    -p：除复制文件的内容外，还把修改时间和访问权限也复制到新文件中。
    -r：若给出的源文件是一个目录文件，此时将复制该目录下所有的子目录和文件。
    -l：不复制文件，只是生成链接文件。

举例：

#将../html/index.html 复制到当前目录
cp ../html/index.html .
#将../html/ 目录下的文件及子目录复制到当前的tt目录下，如果tt不存在，会自动创建
cp -r ../html/  tt/
#将文件file复制到目录/usr/men/tmp下，并改名为file1
cp file /usr/men/tmp/file1

#如果dir2目录已存在，则需要使用
cp -r dir1/. dir2
#如果这时使用cp -r dir1 dir2,则也会将dir1目录复制到dir2中，明显不符合要求。
ps:dir1、dir2改成对应的目录路径即可

远程复制

# 把当前目录的 test.txt 复制到远程 192.168.111.12 的 /zx 目录下
scp test.txt root@192.168.111.12:/zx

# 复制到远程用户的家目录，并改名为 textA.txt
scp test.txt root@192.168.111.12:testA.txt

# 省略用户名时，使用的是本地当前登录的用户名，而不是稍后再提示输入
scp test.txt 192.168.111.12:/zx

# 从远程复制到本地，-r 递归整个目录，-P（大写）指定非默认的 SSH 端口
scp -r -P 2222 remote_user@remote_ip:remote_folder ./local_path

提示：scp 每次都是全量传输，也无法跳过目标端已存在的相同文件；需要增量同步时请使用后面的 rsync。

移动操作:

在同一文件系统内，mv 只是修改目录项（相当于重命名），不会真正复制数据；只有跨文件系统移动时才会复制后删除。这一点与 cp 有本质区别。

# 移动 /zx/soft 目录中的所有文件到当前目录
mv /zx/soft/* .
# 把当前目录的 a.txt 移动到 ./test/ 下（目标目录必须已存在）
mv a.txt ./test/
# 移动整个目录到 /tmp/ 下，要求 /tmp 已存在
mv /zx/soft/ /tmp/soft
# 目标已存在时默认直接覆盖：-i 覆盖前确认，-n 不覆盖
mv -i a.txt ./test/a.txt

重命名操作

重命名用的还是移动命令，比如：

# 将目录(文件) A 重命名为 B
mv A B
# 将 /a 移动到 /b 下并重命名为 c，要保证 b 目录存在
mv /a /b/c
# 将当前 test1 目录移动到当前的 test 目录并命名为 b
mv ./test1 ./test/b

# 批量改名：先用 echo 演练，确认无误后把 echo 换成 mv
for f in *.txt; do echo mv "$f" "${f%.txt}.md"; done

解压压缩操作

tar

# 主操作（五选一）
-c 建立归档      -x 解开归档      -t 列出归档内容
-r 向归档末尾追加文件            -u 只更新归档中较新的文件

# 压缩方式（可选，与主操作连写）
-z  gzip（.tar.gz / .tgz）   -j  bzip2（.tar.bz2）   -J  xz（.tar.xz）
-Z  compress（.tar.Z，已过时，建议改用 gzip 或 xz）
-v  显示处理过程             -O  把文件解到标准输出

# -f 必须提供，且 -f 后面要紧跟档案名，所以习惯把它写在最后
tar -czf all.tar.gz *.jpg

举例说明

tar -cf all.tar *.jpg        # 把所有 .jpg 打成 all.tar（-c 新建，-f 指定包名）
tar -tf all.tar              # 只列出包内文件，不解压
tar -xf all.tar              # 解出包内所有文件到当前目录

tar -czvf jpg.tar.gz *.jpg   # 打包并用 gzip 压缩，同时显示过程
tar -xzf nginx-1.14.0.tar.gz # 解压 .tar.gz 到当前目录
tar -zxf nginx-1.14.0.tar.gz -C /usr/local/nginx  # 解压到指定目录（目录需已存在）
tar -xJf node-v16.0.0-linux-x64.tar.xz            # 一步解开 .tar.xz
tar -czf backup.tar.gz --exclude='*.log' /data    # 打包时排除文件

注意：解压工具可能没有预装，例如 unzip 可用 yum install unzip（CentOS）或 apt-get install unzip（Ubuntu）安装。

总结

1、*.tar            tar -xvf 解压
2、*.gz             gzip -d 或 gunzip 解压
3、*.tar.gz/*.tgz   tar -xzf 解压
4、*.bz2            bzip2 -d 或 bunzip2 解压
5、*.tar.bz2        tar -xjf 解压
6、*.Z              uncompress 解压
7、*.tar.Z          tar -xZf 解压
8、*.xz/*.tar.xz    tar -xJf 一步解压（也可先 xz -d 再去掉外层 tar）
9、*.rar            unrar e 解压
10、*.zip           unzip 解压

# zip 常用选项
unzip -n test.zip            # 不覆盖已存在的文件
unzip -n -d /temp test.zip   # 解压到指定目录且不覆盖
unzip -l test.zip            # 只列出包内文件，不解压
unzip -v test.zip            # 列表并显示压缩率
unzip -t test.zip            # 检查压缩包是否损坏
unzip -o test.zip -d /tmp/   # 覆盖已有文件，不再询问

# 示例：解压到 mydatabak 目录
unzip mydata.zip -d mydatabak

# .tar.xz 是两层压缩：外层 xz、内层 tar，可以分两步，也可以一步完成
xz -d node-v6.10.1-linux-x64.tar.xz    # 得到 .tar
tar -xvf node-v6.10.1-linux-x64.tar    # 再解 tar
tar -xJf node-v6.10.1-linux-x64.tar.xz # 等价的一步写法

ln、file和touch命令

ln命令

用于创建链接文件，包括硬链接(Hard Link)和符号链接（Symbolic Link) 。我们常用的是符号链接，也称软链接。软链接就类似 Windows 里的快捷方式。

示例：

# 在当前目录创建软链接，指向 /etc/fstab（省略链接名时用目标文件的基名 fstab）
ln -s /etc/fstab

# 指定链接名：在当前目录创建指向 /boot/grub 的软链接 gb
ln -s /boot/grub gb

# 创建硬链接：两个文件名指向同一个 inode，不能跨文件系统，也不能指向目录
ln /etc/fstab ./fstab.hard

# 查看链接指向：软链接的权限位显示为 lrwxrwxrwx
ls -l fstab gb

注意：删除软链接的正确方式是 rm -rf ./gb（或 rm gb）。如果写成 rm -rf ./gb/，末尾的斜杠会让 rm 顺着链接进入目标目录，把 /boot/grub 里的内容一起删掉。针对系统文件的软链接，删除时一定要确认清楚。

file命令

用于识别文件的类型

Linux中文件后缀只是方便使用者识别，没有实质的约束作用。file命令可以查看文件的实质类型：

file [-bcLz] 文件|目录

选项说明：

    文件|目录：需要识别的文件或目录
    -b: 显示识别结果时，不显示文件名
    -c: 显示执行过程
    -L: 直接显示符号链接文件指向的文件类型
    -z: 尝试去解读压缩文件的内容

示例：

可以看出，index.mp4本质是一个HTML而非一个mp4文件

[root@VM_0_13_centos soft]# file index.mp4
index.mp4: HTML document, UTF-8 Unicode text, with very long lines

touch命令：

用于改变文件或目录的访问时间和修改时间。

touch [-am] [-t<日期时间>] [目录|文件]

如果指定目录文件不存在，则会直接创建一个空文件，所以touch也常用来创建一个空白文件

#创建一个新文件aa.txt
touch aa.txt

选项说明：

    -a: 只修改访问时间
    -m : 只修改 修改时间
    -t : 使用指定日期时间，而非系统时间 。例如要修改为2019年10月20日16：38分13秒。参数就是：‘20191020163813’

示例：

修改之前可以先查看文件的时间戳: 用stat 命令查看

查找操作命令：

对于要用到的文件，目录等，经常有忘记的时候，所以查找命令就显得极为必要：

find:

查找文件或目录 (常用)

语法如下：

find [目录…] [-amin <分钟>] [-atime <24小时数>] [-cmin <分钟>] [-ctime<24小时数>][-empty][-exec<执行命令>][-fls<列表文件>][-follow]
    [-fstype <系统文件类型>] [-gid <组编号>] [-group <组名称>] [-nogroup] [-mmin <分钟>]  [-mtime
    <24小时数>] [-name <查找内容>] [-nogroup] [-nouser] [-perm <权限数值>] [-size <文件大小>] [-uid
    <用户编号>] [-user <用户名称>] [-nouser]

几个常用选项说明：

    -size <文件大小>：查找符合指定大小的文件。文件大小单位可以是“c”表示Byte；“k”表示KB。如配置为“100k”，find命令会查找文件大小正好100KB的文件；配置为“+100k”，find命令会查找文件大小大于100KB的文件；配置为“-100k”，find命令会查找文件大小小于100KB的文件。
    -user<用户名称>：查找所有者是指定用户的文件或目录，也能以用户编号指定
    -name <查找内容>：按名称匹配，支持通配符 “*”（任意多个字符）和 “?”（任意一个字符）。模式要用引号包起来（如 'nginx*'），否则会被 shell 先展开
    -mtime <24小时数>：查找在指定时间**曾更改过内容**的文件或目录，单位以24小时计算。如配置为2，find命令会查找刚好在48小时之前更改过内容的文件；配置为+2，find命令会查找超过在48小时之前更改过内容的文件；配置为-2，find命令会查找在48小时之内更改过内容的文件。
    -mmin <分钟>：查找在指定时间曾被**更改过内容**的文件或目录，单位以分钟计算。
    -cmin <分钟>：查找在指定时间曾被**更改过权限**属性的文件或目录，单位以分钟计算。-ctime对应小时。
    -amin <分钟>：查找的是指定时间**访问过**的文件或目录。-atime 对应小时。
-perm <权限数值>：按权限匹配。GNU find 中 -perm 0700 表示权限正好是 0700；-perm -0700 表示至少包含 0700 的全部权限位（即权限是 0700 的超集）；-perm /0700 表示包含其中任意一个权限位即可（旧写法 +0700 已废弃）。

选项大概有以下几类：

1.按时间范围查找

2.按文件大小查找

3.按文件名称查找

4.按其他：比如权限、用户组、类型等

示例：

# 从根目录开始查找名称以 nginx 开头的文件（模式加引号，避免被 shell 先展开）
find / -name 'nginx*'

# 只在 /etc 下、最多 2 层目录内查找 .conf 文件
find /etc -maxdepth 2 -type f -name '*.conf'

# 查找大于 100MB 的文件
find / -type f -size +100M

# 查找 /home/zx 下 10 分钟内被修改过的文件和目录
find /home/zx/ -mmin -10

# 对结果执行命令：-exec ... \; 逐个执行，-exec ... + 批量传参（更快）
find /tmp -name '*.tmp' -exec ls -l {} \;
find /tmp -name '*.tmp' -exec rm -f {} +
# 文件名可能含空格时，用 -print0 配合 xargs -0（见“通配符、引号与管道”）
find /tmp -name '*.tmp' -print0 | xargs -0 rm -f

locate：

查找文件或目录(不常用)

locate 查找内容

例如：locate nginx 会将所有包含nginx的目录和文件都列出来。可以用* 或？等匹配符。

locate的查找速度非常快，因为该命令查找的是数据库，所以有些刚修改的文件和目录，可能无法找到。可以采用：updatedb 命令更新数据库。

which:

查找文件(不常用)

which [文件]

which命令只会在PATH环境变量定义的路径及命令别名中查找，所以范围有限。

whereis :

查找文件(不常用)



whereis [-bu] [-B<目录>] [-M<目录>] [-S<目录>] [文件]

常用选项：

    文件：要查找的命令

    -b: 只查找二进制文件

    -u: 查找不包含指定类型的文件

    -B<目录>： 只在指定目录下查找二进制文件

    -M<目录>：只在指定目录查找帮助文件

    -S<目录>：只在指定目录查找源码目录

whereis 默认只在系统预定义的标准目录（如 /usr/bin、/usr/sbin、/usr/share/man 等）中查找，不会搜索当前目录，所以刚写好的脚本用 whereis 是找不到的

[root@VM_0_13_centos soft]# whereis nginx
nginx: /usr/local/nginx /usr/local/nginx/sbin/nginx /usr/local/nginx/sbin/nginx.bak

通配符、引号与管道

shell 的处理顺序是：先做引号与转义处理，再做变量替换和命令替换，然后展开通配符，最后才把结果交给命令。因此命令看到的往往不是我们敲进去的字符串，而是展开后的文件名列表，这也是很多“命令本身没问题、结果却不对”的根源。

# 单引号：内部全部是字面量，通配符和 $变量 都不展开
echo '$HOME *'
# 双引号：阻止通配符展开，但 $变量、$(命令) 仍会替换
echo "$HOME *"
# 不加引号：shell 先展开通配符，命令收到的是展开后的文件名
echo *

# find 的 -name 模式一定要加引号，否则会被 shell 在当前目录先行展开
find / -name 'nginx*'          # 正确：模式原样交给 find
find / -name nginx*            # 错误：shell 先展开，找不到匹配时行为随 shell 配置而变

# 文件名含空格或换行时，用 -print0 与 xargs -0 配对，避免被空白拆断
find . -type f -name '*.log' -print0 | xargs -0 rm -f
# xargs -I 指定占位符，-P 指定并发数（并发写同一文件时要自行保证互斥）
find . -name '*.jpg' -print0 | xargs -0 -I{} -P4 cp {} /backup/

# 退出码：0 表示成功、非 0 表示失败；管道默认只反映最后一个命令的退出码
grep -q 'error' app.log && echo found || echo 'not found'
set -o pipefail                # 让管道返回第一个非零退出码，配合 set -e 才能失败即停
grep -q 'error' app.log | tee /dev/null; echo "${PIPESTATUS[0]}"

文本处理命令：grep、sed、awk、sort、uniq

grep

按行匹配并输出。常用选项：-i 忽略大小写、-n 显示行号、-r 递归目录、-v 反向匹配、-w 整词匹配、-c 只输出匹配行数、-E 使用扩展正则。

grep -in 'error' app.log                          # 忽略大小写并显示行号
grep -rn --include='*.conf' 'listen' /etc/nginx    # 只递归搜索 .conf 文件
grep -E '^(GET|POST) ' access.log | wc -l          # 扩展正则 + 统计行数
grep -v '^#' nginx.conf                            # 去掉注释行
grep -c 'error' app.log                            # 只输出匹配的行数

sed

sed 默认按行处理并把结果输出到标准输出，只有加 -i 才会写回原文件（建议用 -i.bak 先留备份）。

sed -n '10,20p' app.log              # 只打印第 10~20 行
sed -i.bak 's/old/new/g' config.ini  # 全局替换，同时保留 config.ini.bak
sed '/^$/d' app.log                  # 删除空行（只输出到屏幕，不改文件）
sed -n '/ERROR/,/END/p' app.log      # 打印 ERROR 到 END 之间的内容

awk

awk 适合按列处理文本：$0 是整行，$1 是第一列，NF 是当前行的列数，NR 是行号，-F 指定字段分隔符，逻辑写在 '条件{动作}' 里。

awk '{print $1}' access.log                      # 打印第一列
awk -F: '$3 >= 1000 {print $1}' /etc/passwd      # 打印 UID 大于等于 1000 的用户名
awk '{sum += $1} END {print sum}' num.txt        # 求第一列之和
awk 'NR==1 {next} {print $2}' data.txt           # 跳过表头再处理

sort 与 uniq

uniq 只能去掉相邻的重复行，所以通常先 sort 再 uniq。

sort -k2 -n score.txt                            # 按第 2 列数值升序排列
sort -u names.txt                                # 排序并去重
sort access.log | uniq -c | sort -nr | head -10  # 出现次数最多的前 10 行
uniq -d names.txt                                # 只输出重复出现的行（需已排序）

权限管理：chmod 与 chown

权限分三组：属主(user)、属组(group)、其他人(other)，每组三种权限 r(4)、w(2)、x(1)，所以 644 表示 rw-r--r--。

chmod 644 index.html             # 属主可读写，其他人只读
chmod u+x deploy.sh              # 给属主增加执行权限
chmod -R 755 /var/www/html       # 递归修改（会改掉所有子文件，慎用）
chown www:www app.log            # 修改属主和属组（需要 root）
chown -R www:www /var/www/html   # 递归修改属主和属组
stat -c '%a %U:%G %n' index.html # 直接查看权限与属主

注意：chmod -R 777 会让任何人都能改写这些文件，是常见的安全隐患。通常目录用 755（需要执行位才能进入），普通文件用 644 即可。

磁盘与进程排查：df、du、lsof

df -h                            # 各文件系统已用空间（人类可读）
df -i                            # inode 使用率
du -sh /var/log                  # 统计目录总大小（-s 汇总，-h 人类可读）
du -h --max-depth=1 /var | sort -h   # 逐层看清谁占用最大
lsof +L1                         # 已删除但仍被进程占用的文件（空间不释放的常见原因）
lsof -p 1234                     # 查看某个进程打开的文件
lsof -i :8080                    # 查看谁占用了 8080 端口

远程同步：rsync

# 结尾的 / 很关键：表示同步目录“内容”，不加则会把目录本身放进目标目录
rsync -avz /data/logs/ root@192.168.1.10:/backup/logs/

# --delete 让目标与源完全一致（会删除目标端多余的文件，务必先 --dry-run）
rsync -avz --delete --dry-run /data/ /backup/data/

# 排除文件、限速、断点续传
rsync -avz --exclude='*.tmp' --bwlimit=2000 --partial /data/ /backup/data/

tar 适合打包归档，rsync 适合反复增量同步，scp 每次都是全量复制且不能跳过相同文件。

危险命令与安全习惯

# 1. rm -rf 与通配符：变量为空时会退化成 rm -rf /，必须先判断变量
rm -rf "$dir"/                    # 引号包裹变量
rm -rf "${dir:?dir is empty}"/    # 更安全：变量为空直接报错退出
[ -n "$dir" ] || exit 1; rm -rf "$dir"/*

# 2. 通配符不匹配时可能把模式原样交给命令，删除前先打印确认
find /tmp -maxdepth 1 -name '*.tmp' -print    # 先看结果
find /tmp -maxdepth 1 -name '*.tmp' -delete   # 确认无误再删

# 3. > 会截断覆盖文件，>> 才是追加；覆盖前先备份
cp app.log app.log.bak && grep -v 'debug' app.log.bak > app.log
# set -o noclobber 可以禁止 > 覆盖已存在的文件

# 4. dd 直接写块设备，of= 写错会毁掉整块磁盘，务必先核对设备名
lsblk                                                  # 先确认设备
dd if=image.iso of=/dev/sdb bs=4M status=progress conv=fsync

# 5. mv/cp 覆盖不可逆，chmod -R 777、chown -R 影响面很大
mv -i a.txt b.txt        # 覆盖前确认
alias rm='rm -i'         # 交互式删除，降低误删风险
