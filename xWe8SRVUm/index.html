GraalVM + Native-Image + Spring Boot 3（实战）

GraalVM Native Image 可以把 Spring Boot 3 应用提前编译（AOT）成不依赖 JVM 的原生可执行文件，换来毫秒级启动与更低的内存占用。本文以 Windows 为例，从一个最小的 Web 项目出发，走完「打包 → AOT 处理 → native 编译 → 双击运行验证」的完整流程，并记录 Windows 下最容易卡住的 MSVC 环境变量配置。

一、准备 Spring Boot 项目

1、新建项目，JDK 选择 GraalVM JDK 17。Spring Boot 3 要求 JDK 17 及以上，而 native-image 命令由 GraalVM 发行版提供，所以这里直接把 JAVA_HOME 指向 GraalVM 自带的 JDK：

Spring Boot 版本选择 3.1.1，以一个 Web 项目为例：

自动生成核心的 pom.xml 文件：

<!-- 核心依赖示例 -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>

<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-test</artifactId>
    <scope>test</scope>
</dependency>

2、编写一个简单的 Controller：

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class GraalController {

    @GetMapping("/")
    public String demo(){
        return "Hello Springboot3 AOT";
    }
}

3、常规运行并访问该 demo 接口。先在 JVM 模式下确认业务代码本身没问题，这样后面原生编译失败时，就能判断问题出在 native-image 的编译环境上，而不是代码：

项目运行无问题，可用于测试。

二、核心编译命令

Spring Boot 3 已经内置了原生编译的 Maven 支持，按顺序执行下面三条命令即可（在 IDEA 的 Maven 面板里执行对应插件目标，效果相同）：

# 1、先对原项目进行一次 package 打包
mvn clean package -DskipTests

# 2、运行 AOT 提前处理命令，生成 GraalVM 需要的元数据
mvn spring-boot:process-aot

# 3、运行 native 编译，产物是原生可执行文件
mvn -Pnative native:compile

注意 native:compile 是 native-maven-plugin 较新版本中的目标名（更早的版本写作 native:build，在新版本中已标记为过时）。如果执行时报「找不到该目标」，把 native:compile 换成插件版本对应的写法即可。另外，使用 -Pnative 时插件生命周期内通常已自动完成 AOT 处理，第 2 步主要用于单独检查 AOT 生成结果。

1、如果在 Windows 环境下直接运行编译命令，会报如下的错误：

Execution of C:\installation\graalvm-jdk17\graalvm-community-openjdk-17.0.8\bin\native-image.cmd @target\tmp\native-image-16043596690894935382.args returned non-zero result

原因是 native-image 在 Windows 上要调用 MSVC 的 C/C++ 编译器（cl.exe）和链接器，必须让 native-image 找到 MSVC 与 Windows SDK 的头文件、库文件目录。这个错误解决起来比较麻烦，需要修改 3 个环境变量：Path、INCLUDE、LIB。

首先需要知道自己机器上 Visual Studio 与 Windows Kits 的安装位置，我的如下（版本号会因安装版本而不同）：

  • Visual Studio 安装目录：C:\Program Files\Microsoft Visual Studio\2022\Community
  • 其中 MSVC 的 include 目录位置：C:\Program Files\Microsoft Visual Studio\2022\Community\VC\Tools\MSVC\14.35.32215\include
  • 其中 MSVC 的 lib 目录位置：C:\Program Files\Microsoft Visual Studio\2022\Community\VC\Tools\MSVC\14.35.32215\lib\x64
  • Windows 工具包的 include 目录位置：C:\Program Files (x86)\Windows Kits\10\Include\10.0.22000.0
  • Windows 工具包的 lib 目录位置：C:\Program Files (x86)\Windows Kits\10\Lib\10.0.22000.0

三、配置三个环境变量

配置第 1 个环境变量，在 Path 中添加 cl.exe 所在目录：

C:\Program Files\Microsoft Visual Studio\2022\Community\VC\Tools\MSVC\14.35.32215\bin\Hostx64\x64

配置第 2 个环境变量，新增 INCLUDE 环境变量（MSVC 与 Windows SDK 的头文件目录）：

C:\Program Files\Microsoft Visual Studio\2022\Community\VC\Tools\MSVC\14.35.32215\include;
C:\Program Files (x86)\Windows Kits\10\Include\10.0.22000.0\shared;
C:\Program Files (x86)\Windows Kits\10\Include\10.0.22000.0\ucrt;
C:\Program Files (x86)\Windows Kits\10\Include\10.0.22000.0\um;
C:\Program Files (x86)\Windows Kits\10\Include\10.0.22000.0\winrt;

配置第 3 个环境变量，新增 LIB 环境变量（与上面头文件对应的库目录）：

C:\Program Files\Microsoft Visual Studio\2022\Community\VC\Tools\MSVC\14.35.32215\lib\x64;
C:\Program Files (x86)\Windows Kits\10\Lib\10.0.22000.0\um\x64;
C:\Program Files (x86)\Windows Kits\10\Lib\10.0.22000.0\ucrt\x64;

改完环境变量要重启命令行窗口或 IDEA，否则新进程读到的仍是旧值。更省事的替代做法是直接使用 Visual Studio 提供的「x64 Native Tools Command Prompt for VS 2022」，该窗口已经预设好这些变量，在其中执行 native 编译即可。

最后补充一点取舍：原生可执行文件的优势集中在启动速度与内存占用上，但它并非在所有场景都更快——静态编译的峰值吞吐通常不如经过 JIT 长期优化的 JVM，反射、动态代理、动态类加载等运行期动态特性也受到限制，构建时间更长。因此它更适合 Serverless、命令行工具、需要快速伸缩的短生命周期容器等场景，而不是无差别地替换 JVM 部署。
