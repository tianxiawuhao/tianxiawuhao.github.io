大模型框架体系

Posted on 2025-01-10，5 min read

零、三层框架的分工与依赖

大模型工程里最容易被混淆的一件事，是把不同层次的工具当成同一类东西来比较。常见说法如「PyTorch 和 Hugging Face 哪个好」「用了 LangChain 是不是就不需要 transformers 了」，都属于层次错位：它们解决的是完全不同的问题，彼此是依赖关系而不是替代关系。

把常用工具按职责归成三层，关系立刻清晰：

  • 底层：深度学习框架（PyTorch / TensorFlow / JAX）。提供张量计算、自动求导、优化器、分布式与 GPU 加速。它只认张量和计算图，不认识「模型」「数据集」这些概念。
  • 中层：模型与数据平台（Hugging Face 生态：transformers、datasets、Trainer、peft）。提供开箱即用的预训练模型结构、权重、数据集与训练/微调编排，建立在底层框架之上。
  • 上层：应用编排框架（LangChain / LlamaIndex）。把模型、检索、工具、记忆串成业务链路（RAG、Agent、工作流），自身不含模型权重，也不做训练。

由此可以得到两条判断准则。其一，依赖方向永远向下：transformers 依赖 PyTorch 提供计算，peft 依赖 transformers 的模型结构，LangChain 依赖模型加载/推理接口；反过来都不成立。其二，可替换性只存在于同层之内：TensorFlow 可以换掉 PyTorch，ModelScope 可以换掉 Hugging Face Hub，LlamaIndex 可以换掉 LangChain，但拿 LangChain 去替代 transformers 是无效替换——它们根本不在同一层。

还有一个高频误解：Trainer、peft 不是「模型库」，而是训练侧的编排与参数高效微调工具，它们同样站在 PyTorch 之上；而 LangChain 也不是「模型库」，它是应用侧的编排框架。把 Trainer 与 LangChain 放在一起比较，等于把「怎么把模型训出来」和「怎么把模型用起来」混为一谈。

下面按「模型加载 → 微调 → 算法搭建 → 训练 → 功能搭建」的真实工作流，逐环节看每一层各自做什么。

大模型加载

  • Hugging Face：

    提供 transformers 库，通过 AutoModel 和 AutoTokenizer快速加载预训练模型（如 GPT、BERT），支持多框架（PyTorch/TensorFlow）。

    依赖：直接对接模型仓库（Model Hub），依赖 PyTorch 或 TensorFlow 作为底层计算框架。

  • LangChain：通过集成 Hugging Face 接口，简化模型加载与调用，支持多模型统一管理（如调用本地或远程 LLM）。

微调（Fine-tuning）

  • Hugging Face：

    提供 Trainer 与 TrainingArguments，封装训练循环、优化器、混合精度、梯度累积与评估逻辑；底层由 accelerate 调度单卡/多卡，因此 Trainer 是「训练编排」而不是「深度学习框架」。peft 库则在其上提供 LoRA/QLoRA 等参数高效微调。

  • PyTorch：提供底层训练支持（如自动求导、损失函数、优化器），Hugging Face 的微调工具基于 PyTorch 实现。

  • LangChain：通常不直接参与微调，但可通过调用 Hugging Face 的微调后模型，快速集成到应用中。

算法搭建

  • PyTorch：核心深度学习框架，提供张量操作、动态计算图（autograd）和神经网络模块（torch.nn），支持从零构建自定义模型。

  • Hugging Face：基于 PyTorch 实现预训练模型架构（如 BERT、GPT），提供开箱即用的模型配置和权重。

  • LangChain：专注应用层逻辑，通过组合现有模型（如 Hugging Face 的模型）实现复杂功能（如链式调用、记忆机制）。

训练

  • PyTorch：负责训练核心流程（前向传播、损失计算、反向传播），支持分布式训练和 GPU 加速。

  • Hugging Face：通过 datasets库加载和预处理数据，结合 transformers实现端到端训练。

  • LangChain：不直接参与训练，但可利用训练好的模型进行推理或构建应用。

功能搭建（应用开发）

  • LangChain：核心优势在于整合模型、数据源和工具（如数据库、API），支持构建端到端应用（如聊天机器人、Agent）。

    依赖：需结合 Hugging Face（模型）、PyTorch（计算）等框架实现功能。

  • Hugging Face：提供 pipelines快速实现特定任务（如文本生成、分类），可作为 LangChain 的组件。

  • PyTorch：提供底层算力支持，确保模型推理和训练的高效性。

框架关系总结

框架 核心角色 依赖关系
PyTorch 底层计算引擎，支持模型构建与训练 独立框架，被 Hugging Face 和 LangChain 间接依赖。
Hugging Face 模型与数据中台，提供预训练模型和工具链 依赖 PyTorch/TensorFlow 实现模型；被 LangChain 调用其模型能力。
LangChain 应用层框架，整合模型与工具构建复杂逻辑 依赖模型服务与推理接口（可直接调用 Hugging Face 模型或 vLLM 等推理引擎），不直接依赖 PyTorch API。

典型流程示例

  1. 模型加载：通过 Hugging Face 的 AutoModel 加载预训练 LLM。

  2. 微调：使用 Hugging Face 的 Trainer和 PyTorch 优化器进行领域适配。

  3. 应用开发：通过 LangChain 将模型与外部数据源（如数据库）连接，构建聊天机器人。

PyTorch 的同类框架

  • 定位：深度学习基础框架，提供张量计算、自动微分和动态计算图，支持模型从训练到推理的全流程。
  • 同类框架：
    • TensorFlow：曾以静态计算图为主，2.x 起默认动态图（Eager），生产部署生态成熟，与 PyTorch 共享 Hugging Face 的模型生态。
    • JAX：谷歌推出，纯函数式、以 jit/vmap 等变换为核心，在 TPU 与大规模并行上表现突出，生态（如 Flax、Equinox）相对年轻。
    • MXNet：Apache 基金会项目，曾用于 AWS 的深度学习服务，2023 年进入维护终止（已退役），新项目不建议选用。

Hugging Face 的同类框架

  • 定位：模型即服务（MaaS）平台，提供预训练模型、数据集和工具链，简化大模型应用开发。
  • 同类框架：
    • ModelScope（魔搭）：阿里达摩院推出的模型开放平台，提供大量预训练模型（如 Qwen），定位与 Hugging Face 类似。
    • TensorFlow Hub：谷歌的模型仓库，与 Hugging Face Hub 定位类似，但生态较小。
    • PaddleNLP：百度飞桨生态的 NLP 工具库，集成文心（ERNIE）等模型，提供开箱即用的 API。

LangChain 的同类框架

  • 定位：大模型应用开发框架，通过链式组件、工具集成和记忆机制构建复杂应用（如 Agent）。
  • 同类框架：
    • LlamaIndex：专注检索增强生成（RAG），提供数据索引、查询优化和缓存功能，适合文档问答场景。
    • TensorFlow Extended（TFX）：谷歌的端到端机器学习生产流水线工具（训练、验证、部署、监控），属 MLOps 工具，与 LangChain 并非同类，列在这是为了说明「不要混为一谈」。
    • AutoML 工具（如 AutoKeras、Optuna）：负责模型与超参搜索，与 LangChain 是互补而非同类。

框架关系与选择建议

场景 建议选型（举例）
模型训练与实验 底层框架：PyTorch、TensorFlow、JAX；预训练模型与数据集平台：Hugging Face Hub、ModelScope、PaddleNLP
生产级部署与推理 MLOps 流水线：TFX 或云平台（如 SageMaker、阿里云 PAI）；大模型推理可用 vLLM、TensorRT-LLM 等推理引擎
快速应用开发 应用编排：LangChain、LlamaIndex；检索组件：向量库 + Embedding 模型；开箱即用组件：Hugging Face pipelines

关键依赖关系

  • PyTorch 是 Hugging Face 和 LangChain 的底层计算引擎。
  • Hugging Face 作为模型中台，向 LangChain 提供预训练模型和工具链。
  • LangChain 依赖模型能力（Hugging Face 模型或 vLLM 等推理服务）和检索/工具组件实现复杂应用逻辑；它不直接依赖 PyTorch API，而是通过模型加载与推理接口间接使用下层框架。

把三条依赖连起来就是一条单向链路：PyTorch → transformers → peft → 应用编排。任何一环都可以在同层内被替换，但不会出现「上层替代下层」的情况——这也是判断某个新框架属于哪一层最省事的办法：看它依赖谁、向谁提供能力。
