JWT介绍

在介绍 JWT 之前，先看一下传统的令牌校验方法，流程如下图：

传统授权流程如上图：客户端先到授权服务器申请令牌；拿到令牌后，携带令牌访问资源服务器；资源服务器再访问授权服务器校验令牌的合法性。

授权服务器返回校验结果，校验通过时还会返回用户信息；资源服务器收到通过的校验结果后，才把资源返回给客户端。

问题：用户每次请求资源服务，资源服务都要携带令牌去认证服务校验合法性，并据此获取用户信息，性能低下。

解决：使用 JWT 的思路是，用户认证通过后会得到一个 JWT 令牌，令牌本身已经包含了用户相关的信息。客户端只需携带 JWT 访问资源服务，资源服务按事先约定的算法自行完成校验，无需每次都请求认证服务完成授权。

什么是JWT？

JSON Web Token（JWT）是一个开放的行业标准（RFC 7519），它定义了一种紧凑的、URL 安全的方式，用于在通信双方之间传递以 JSON 对象表示的声明（claims）；这些信息经过数字签名，可以被验证和信任。JWT 可以使用 HMAC 算法（双方共享的对称密钥）签名，也可以使用 RSA 的公钥/私钥对签名，从而防止内容被篡改。

官网：https://jwt.io/

标准：https://tools.ietf.org/html/rfc7519

优点：

  1. JWT 基于 JSON，非常方便解析。

  2. 可以在令牌中自定义丰富的内容，易扩展。

  3. 通过非对称加密算法及数字签名技术，JWT防止篡改，安全性高。

  4. 资源服务使用JWT可不依赖认证服务即可完成授权。

缺点：

  1. JWT令牌较长，占存储空间比较大。

令牌结构

先弄清 JWT 的令牌结构，才能为后面自定义 JWT 令牌打好基础。

JWT 令牌由三部分组成，各部分之间用点（.）分隔，形如：xxxxx.yyyyy.zzzzz

Header（头部）

头部描述令牌的类型（即 JWT）以及所使用的签名算法（如 HMAC SHA256 或 RSA）。一个例子如下：

{
    "alg": "HS256",
    "typ": "JWT"
}

把上面的内容做 Base64Url 编码，得到的字符串就是 JWT 令牌的第一部分。

Payload（负载）

第二部分是负载，内容同样是一个 JSON 对象，用于存放有效信息。它可以存放 JWT 提供的现成字段，比如 iss（签发者）、sub（面向的用户）、aud（接收方）、exp（过期时间戳）、nbf（生效时间）、iat（签发时间）等，也可以自定义字段。

此部分不建议存放敏感信息，因为它只是编码而不是加密，可以被解码还原出原始内容。

{
    "sub": "1234567890",
    "name": "456",
    "admin": true
}

最后把负载做 Base64Url 编码，得到的字符串就是 JWT 令牌的第二部分。

Signature（签名）

第三部分是签名，用于防止 JWT 内容被篡改。它的计算方式是：把 Base64Url 编码后的前两部分用点（.）连接成一个字符串，再用 Header 中声明的签名算法配合密钥进行签名。

HMACSHA256(base64UrlEncode(header) + "." + base64UrlEncode(payload), secret)

base64UrlEncode(header)：JWT 令牌的第一部分。

base64UrlEncode(payload)：JWT 令牌的第二部分。

secret：签名所使用的密钥。使用 HMAC 算法时是双方共享的对称密钥；使用 RSA 等非对称算法时，签名用私钥，验签用公钥。

另外，Base64Url 与普通 Base64 的区别是：把 + 换成 -、/ 换成 _，并去掉末尾的 = 补位，这样才能安全地放在 URL 中传输。

JWT入门

Spring Security 提供对JWT的支持，本节我们使用Spring Security 提供的JwtHelper来创建JWT令牌，校验JWT令牌等操作。

生成私钥和公钥

本节使用非对称加密算法（RSA）生成 JWT 令牌所需的密钥对。

  1. 生成密钥证书

    下面的命令生成密钥证书，采用 RSA 算法，每个证书包含公钥和私钥：

    keytool -genkeypair -alias xckey -keyalg RSA -keypass xuecheng -keystore xc.keystore -storepass xuechengkeystore

    Keytool 是 JDK 提供的证书管理工具

    -alias：密钥对的别名

    -keyalg：密钥算法，如 RSA

    -keypass：私钥的访问密码

    -keystore：密钥库文件名，xc.keystore 保存了生成的证书

    -storepass：密钥库的访问密码

    注意：JDK 9 及以后版本 keytool 默认生成 PKCS12 格式的密钥库，此时私钥密码必须与密钥库密码相同。若沿用上面的命令报错，把 -keypass 也设置为 xuechengkeystore 即可。

    查询证书信息

    keytool -list -keystore xc.keystore

    删除别名

    keytool -delete -alias xckey -keystore xc.keystore

  2. 导出公钥

    openssl是一个加解密工具包，这里使用openssl来导出公钥信息。安装 openssl：http://slproweb.com/products/Win32OpenSSL.html

    配置openssl的path环境变量，本文配置在D:\OpenSSL-Win64\bin cmd进入xc.keystore文件所在目录执行如下命令：

    keytool -list -rfc --keystore xc.keystore | openssl x509 -inform pem -pubkey

生成jwt令牌

在认证工程创建测试类，测试jwt令牌的生成与验证。

@Test
public void testCreateJwt(){
//证书文件
String key_location = "xc.keystore";
//密钥库密码
String keystore_password = "xuechengkeystore";
//访问证书路径
ClassPathResource resource = new ClassPathResource(key_location);
//密钥工厂
KeyStoreKeyFactory keyStoreKeyFactory = new KeyStoreKeyFactory(resource,
keystore_password.toCharArray());
//密钥的密码，此密码和别名要匹配

String keypassword = "xuecheng";
//密钥别名
String alias = "xckey";
//密钥对（密钥和公钥）
KeyPair keyPair = keyStoreKeyFactory.getKeyPair(alias,keypassword.toCharArray());
//私钥
RSAPrivateKey aPrivate = (RSAPrivateKey) keyPair.getPrivate();
//定义payload信息
Map<String, Object> tokenMap = new HashMap<>();
tokenMap.put("id", "123");
tokenMap.put("name", "mrt");
tokenMap.put("roles", "r01,r02");
tokenMap.put("ext", "1");
//生成jwt令牌
Jwt jwt = JwtHelper.encode(JSON.toJSONString(tokenMap), new RsaSigner(aPrivate));
//取出jwt令牌
String token = jwt.getEncoded();
System.out.println("token="+token);
} //资源服务使用公钥验证jwt的合法性，并对jwt解码
