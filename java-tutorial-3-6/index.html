3.6 jQuery 与 UI 框架

Posted on 2024-08-19，7 min read

jQuery 是老一代前端工程师的必修课，也是今天读懂大量遗留项目、后台管理页面和 Bootstrap 3 站点的钥匙。本章解决三个问题：怎样用选择器精准而简短地选中元素，怎样用链式调用把“选、改、取”串成一条流水线，怎样用 Ajax 和现成的 UI 框架把页面拼出来。内容适合已经会写原生 JavaScript、做过 DOM 操作、准备接手 Web 项目的 Java 后端读者。

先给结论：jQuery 是维护老系统的技能，不是新项目的起点。新项目请优先使用原生 DOM（querySelector、fetch、addEventListener）或 Vue 3、React 等框架；jQuery 的主线版本为 3.x，1.x / 2.x 只应出现在必须兼容 IE8 的遗留工程里。今天它主要出现在老后台管理页面、Bootstrap 3/4 站点与大量历史代码中，本章完整讲清它的写法，是为了让你能读懂并安全改造这些代码。

一、jQuery 到底解决了什么问题

原生 DOM 的痛点是“啰嗦”加“兼容”：按 id 取一个元素要写 document.getElementById，遍历一批节点要自己写循环，改样式要记住 style 与 classList 的差别，绑定事件还要考虑 IE 的 attachEvent。jQuery 用两招把这些问题一起抹平。一是 $() 工厂函数接收 CSS 选择器字符串，返回一个类数组的 jQuery 对象。二是这些对象自带一整套跨浏览器的 DOM、样式、事件和 Ajax 方法。

要牢记的第一条规则是：jQuery 对象不是 DOM 对象。事件回调里的 this 是原生 DOM 对象，必须写成 $(this) 才能调用 jQuery 方法；反过来，$("#box").get(0) 或 $("#box")[0] 又能取回原生 DOM，交给依赖 DOM 的第三方库使用。新手最常见的报错“undefined is not a function”，大多就是把 this 当成 jQuery 对象直接调用了 .css()。

$(function () { ... }) 是 $(document).ready() 的简写，它保证 DOM 解析完成后再执行绑定，比把 <script> 放在任何位置都更稳妥。引入方式上，jQuery 1.x 兼容 IE6–8，2.x 起放弃老 IE，3.x 是当前主线并移除了 $.browser、$(window).load() 等老 API；老项目里常见的 1.11.3 正是为兼容 IE8 而保留的版本。文件既可用 CDN 引入，也可下载到 webapp/js/ 下由页面引用，后者在离线环境更可靠。

二、选择器：一句话选中目标元素

jQuery 的选择器沿用 CSS 规范，按用途可分为基本、层级和过滤三类。基本选择器包括 #id、.class、element、* 以及并集写法 selector1, selector2，其中 * 会匹配全部元素，性能很差，实际项目中几乎不该出现。

层级选择器描述元素之间的位置关系：ancestor descendant（中间是空格，匹配所有后代）、parent > child（只匹配直接子元素）、prev + next（紧跟其后的下一个兄弟）、prev ~ siblings（后面的所有兄弟）。示例中 $(".itcast a") 会把嵌套在 p 里的链接也染红，而 $(".itcast>a") 只处理直接子链接，差别就在这个符号上。

过滤选择器是在已有结果集里“再筛一刀”。:first、:last、:eq(index)、:gt(index)、:lt(index)、:even、:odd 按索引筛（索引从 0 开始）；:not(selector)、:has(selector)、:contains(text)、:empty（既无子元素也无文本）、:parent（有子元素或文本）按内容与结构筛；:visible、:hidden、:animated 按可见性与状态筛；[attr=value]、[attr^=value]、[attr$=value]、[attr*=value] 按属性筛；表单场景还有 :input、:text、:checked、:selected、:disabled 等。

两个容易踩的坑：:even、:odd 数的是结果集内的索引而不是视觉行号，所以 $("tr:even") 命中的是第 1、3、5 行（索引 0、2、4）；:first 只取整个结果集的第一个元素，而 CSS 的 :first-child 是“每个父元素下的第一个子元素”，两者语义完全不同。此外 *、:contains() 这类选择器无法交给浏览器原生的 querySelectorAll 处理，数据量大时明显变慢，能用 id、class 就不要用它们。

三、链式调用：一次选中，连续加工

jQuery 的大多数方法都返回 jQuery 对象本身，于是可以像流水线一样一路点下去。下面这段代码演示了选择器与链式调用的配合：给表格隔行着色、给列表项加标记，并用 .end() 回到上一层集合。

$(function () {
  // 基本 + 层级 + 位置过滤：表格正文里索引为偶数的行加底色
  $("table.items > tbody > tr:gt(0):even").css("background", "#f7f7f7");

  // 链式调用：选中的集合被依次加工
  $("#list li")
    .filter(":contains('Java')")   // 只留含 Java 文本的项
    .addClass("hot")
    .find("a")                     // 破坏性操作：集合变为 li 内部的 a
    .attr("target", "_blank")
    .end()                         // 退回到上一级集合（#list li.hot）
    .append("<span class=\"badge\">热门</span>");

  // 遍历取值：map 返回 jQuery 对象，get 才是真正的数组
  const texts = $(".item").map(function () {
    return $(this).text().trim();  // this 是 DOM 对象，必须用 $() 包装
  }).get();
  console.log(texts, $("div").index($("#foo")));
});

写链式调用要先看清每一步的返回类型：.text()、.val()、.attr("href") 这类取值调用返回字符串，链就此断开；而 .css("color", "red")、.addClass()、.append() 返回的仍是 jQuery 对象，可以继续接。find()、filter()、children()、parent() 会改变当前集合，属于破坏性操作，用 .end() 可以回退一层。一条链写七八个方法虽然显得利落，出错时却很难定位，实践中的做法是每三四个方法换行并写清注释。

事件绑定同样支持链式与委托，这一块也是旧代码里废弃写法最集中的地方：.click(fn)、.bind("click", fn)、.delegate()（以及更早的 .live()）在 jQuery 3.0 起都已废弃，统一改用 .on()。$("button").on("click", fn) 等价于旧的 $("button").bind("click", fn)；委托写法 .on(events, selector, handler) 则取代了 .delegate(selector, events, handler)。如果按钮是 Ajax 动态渲染出来的，就应该用这种委托形式把监听绑在静态父元素上：$("#list").on("click", ".del", fn)，这样新增的行自动生效，不必反复重新绑定。

四、DOM 增删改查：创建、插入、删除、复制与遍历

选择器和链式调用解决的是“怎么拿到元素”，这一节解决“拿到之后怎么改结构”。这是 jQuery 最常用的另一半 API，也是维护老页面时改动量最大的部分。先记住一条贯穿全节的规则：jQuery 的插入方法移动的是已经存在于页面上的节点，而不是复制一个副本。例如 $("#box").append($("#src")) 执行后，#src 会从原来的位置消失，被搬到 #box 内部的末尾；如果确实需要保留原节点，必须先 clone()。

4.1 创建与插入：谁被移动

创建元素用 $() 包一段 HTML 字符串，它会当场构造出新的 DOM 节点（尚未进入文档，因此页面上看不到）。字符串形式时注意补全闭标签，$("<div>") 与 $("<div></div>") 等价；也可以传属性对象，如 $("<a>", { href: "/list", text: "列表" })。

$(function () {
  // 1. 创建：只构造节点，此时还在文档之外，页面上看不到
  const $row = $("<div class=\"row\">新行</div>");
  const $link = $("<a>", { href: "/list", text: "列表" });  // 属性对象写法

  // 2. 插入到内部：append 放末尾，prepend 放开头
  $("#box").append($row);          // 把 $row 追加进 #box 内部的末尾
  $("#box").prepend("<span>置顶</span>");
  $row.appendTo("#box");           // 与 append 同义，只是主语和宾语颠倒
  $("<span>置顶</span>").prependTo("#box");

  // 3. 插入到外部：after / before 是“兄弟关系”，不是父子关系
  $("#box").after($link);          // $link 成为 #box 后面紧邻的兄弟
  $("#box").before("<hr>");     // 成为 #box 前面紧邻的兄弟
  $link.insertAfter("#box");       // 与 after 同义
  $("<hr>").insertBefore("#box"); // 与 before 同义

  // 4. 移动的证明：$("#src") 会从原位置消失，只剩一份
  $("#target").append($("#src"));
  console.log($("#src").length, $("#target #src").length); // 1 1，不是 2 1

  // 5. 想保留原节点必须先克隆
  $("#target").append($("#src").clone());
});

四组方法的区别只有两个维度：位置（内部还是外部）和主语（谁写在前面）。append/prepend 插入到目标元素内部的末尾/开头，after/before 插入到目标元素外部的后面/前面；appendTo/prependTo/insertAfter/insertBefore 是前四者的镜像写法，返回的是被插入的那个节点而不是目标节点，链式调用时务必分清，否则后续方法会作用到错误的集合上。若传入的是一段 HTML 字符串，jQuery 会先创建再插入，因此不涉及“移动”。

性能提示：在循环里逐个 append 会触发多次重排。数据量大时应先把整段 HTML 拼成一个字符串或 DocumentFragment，一次性插入；也可以先 detach() 容器，改完再插回。

4.2 删除与分离：remove、detach 与 empty

三个删除类方法的差别集中在是否保留事件与数据、是否保留自己这两点上。旧代码里最典型的内存泄漏，就是在 detach 与 remove 之间选错，或在移除后仍持有引用。

$(function () {
  $("#list li").on("click", function () { $(this).toggleClass("done"); });

  // remove：把自己和后代从文档中摘掉，并清除其上的事件与数据
  const $gone = $("#list li:first").remove();
  $gone.appendTo("#list");     // 插得回去，但 click 事件已经没了

  // detach：同样摘掉，但完整保留事件与 jQuery 数据，可原样插回
  const $keep = $("#list li:first").detach();
  $keep.appendTo("#list");     // 插回后 click 事件依然生效

  // empty：只清空内部，自己留在页面上（子元素的事件与数据一并清除）
  $("#box").empty();           // #box 还在，内容全没了

  // 彻底清场并释放引用，避免持有已移除节点造成泄漏
  $("#old").find("*").addBack().off();  // 先解绑（3.x 起 off 代替 unbind）
  $("#old").empty().remove();
});
  • remove()：把自己和所有后代从文档中摘掉，同时清除绑定的事件与 jQuery 数据。适合确实不再使用、要彻底回收的元素；返回值仍是该集合，理论上可再插入，但事件不会跟着回来。
  • detach()：同样从文档中摘掉，但保留事件与数据。适合“临时移出、改完再放回”的场景，例如表格重排、把节点挪到另一个容器，插回后原有监听依然有效。
  • empty()：只删除子节点，自己留在原处；子节点上的事件与数据会被一并清除，常用于局部刷新前清空容器，如 $("#list").empty() 之后重新渲染数据。
  • unwrap()：删除父元素而保留自己（下一小节与替换一并讲）。

选择准则可以简化成一句话：还要用、还想保留监听就用 detach()；确定不要了就 remove()；只是清空内容就用 empty()。用 remove() 移出的节点若被 JavaScript 变量长期引用，它占用的内存不会释放，这一点与原生 removeChild 一致。

4.3 复制与替换：clone、replaceWith、wrap

clone() 的默认行为是浅复制：只复制元素与后代的结构、属性和文本，不复制绑定的事件与附加数据。传入 true 才会连事件与数据一起深拷贝，这就是 clone(true) 的含义。

$(function () {
  $("#add").on("click", function () {
    // clone() 不带参数：副本没有事件，点击副本不会触发
    const $plain = $("#tpl li:first").clone();
    $("#list").append($plain);

    // clone(true)：连事件与数据一起复制，副本点击照常生效
    const $deep = $("#tpl li:first").clone(true);
    $("#list").append($deep);
  });

  // 替换：replaceWith 用新内容换掉自己，返回被换掉的旧元素
  const $old = $("#title").replaceWith("<h2>新标题</h2>");
  // replaceAll 是镜像写法：返回被换掉的旧集合，主语是“新的内容”
  $("<h2>同样的新标题</h2>").replaceAll("#title");

  // 包装：wrap 给每个匹配元素各套一层父元素，自己保留
  $("#list li").wrap("<div class=\"cell\"></div>");
  // wrapAll 只套一层，把所有匹配元素装进同一个父元素
  $("#list li").wrapAll("<ul class=\"outer\"></ul>");
  // wrapInner 包的是内部内容，元素本身留在外层
  $("#box").wrapInner("<div class=\"inner\"></div>");
  // unwrap 是 wrap 的逆操作：删掉父元素，自己上移一级
  $("#list li").unwrap();
  // replaceWith(函数) 可以按当前元素逐个生成新内容
  $("#list li").replaceWith(function (i) { return "<li>第 " + (i + 1) + " 项</li>"; });
});

两点容易忽略的细节：clone(true) 复制的是直接绑在该元素上的事件；用委托方式绑在祖先上的监听（如 $("#list").on("click", "li", fn)）本来就不属于 li，因此新副本只要插进同一个 #list 就自动生效，无需克隆事件。另外，replaceWith 返回的是已被移除的旧元素，对它再调用 .end() 或插入方法时，操作对象是被换掉的旧节点，这一点与直觉相反。

4.4 遍历与筛选：集合的下标与父子的序号

遍历方法可以归为两类：一类沿 DOM 树横向或纵向走（children、parent、siblings、closest、find），一类在当前集合里按下标或条件再筛（filter、eq、slice、first、last）。

$(function () {
  const $items = $("#list li");

  $items.find("a");                 // 后代中的 a（含深层）
  $items.children("a");             // 只找直接子元素中的 a
  $items.first();                   // 集合第 1 个（下标 0）
  $items.last();                    // 集合最后 1 个
  $items.eq(2);                     // 集合中下标为 2 的那个（第 3 个）
  $items.slice(1, 3);               // 集合下标 [1, 3) 的切片，即第 2、3 个
  $items.filter(".hot");            // 保留自身满足条件的（不查后代）
  $items.not(".hot");               // 去掉自身满足条件的
  $items.has("a");                  // 保留“后代里含 a”的那些项
  $items.parent();                  // 各自的直接父元素
  $items.parents("ul");             // 各自的所有祖先中匹配 ul 的
  $items.closest("ul");             // 从自身开始向上找第一个 ul（含自身）
  $items.siblings("li");            // 各自的兄弟元素
  $items.next();                    // 各自后面紧邻的兄弟
  $items.prevAll();                 // 各自前面所有兄弟
  $items.addBack();                 // 把上一轮集合合并回来
  $items.each(function (i) {        // 遍历：this 是 DOM 对象，i 是下标
    $(this).attr("data-index", i);
  });
  $items.map(function () { return $(this).text(); }).get(); // 收集文本为数组

  // 两个 index：不传参数返回“在兄弟中的位置”，传选择器返回“在集合中的位置”
  console.log($items.index($items.eq(2)));  // 2
  console.log($items.eq(2).index());        // 2（同为第 3 个兄弟）
});

下面这组对比是本节最容易出错的地方。两者都带“第几个”的含义，但计数起点和计数范围完全不同：

  • :eq(n) 是 jQuery 集合的下标，从 0 开始，只对当前 jQuery 对象有效：$("li:eq(0)") 取整个页面结果集里的第一个 li。
  • :nth-child(n) 是 CSS 的伪类，从 1 开始，且逐个父元素分别计算：$("li:nth-child(1)") 会取每个父元素下的第一个 li，有 3 个列表就有 3 个匹配。
  • 因此 $("li:eq(1)") 是“全集第 2 个”，而 $("li:nth-child(2)") 是“每个父元素下排第 2 个的 li”，两者通常并不相同，也不存在固定的换算关系。
  • 计数基准也不同：:nth-child 数的是父元素下所有子元素的序号（中间夹着别的标签也会占号），jQuery 另有 :nth-of-type 表示“同类型元素中的第几个”；也可以用 nth-child(2n) / nth-child(odd) 按奇偶批量匹配。
$(function () {
  // :eq 从 0 起，按集合下标；:nth-child 从 1 起，按各自父元素下的子元素序号
  $("li:eq(1)").css("color", "red");            // 全部 li 里的第 2 个
  $("li:nth-child(2)").css("color", "blue");    // 每个父元素下排第 2 个的 li
  $("li:nth-child(2n)").addClass("even");       // 每个父元素下的偶数位
  $("li:nth-of-type(2)").addClass("second-of-type"); // 同类型元素里的第 2 个

  // 类比：:eq 相当于结果数组下标 0 起，:nth-child 相当于 CSS 的第 1 个
  $("#list li").eq(0).addClass("first-by-index");      // 只命中 1 个
  $("#list li:nth-child(1)").addClass("first-by-child"); // 每个父元素各命中 1 个

  $(".card")
    .find(".title")            // 破坏性操作：集合变为各卡片内的标题
    .addClass("big")
    .end()                     // 回退一层，集合重新变回 .card
    .addClass("checked")
    .end()                     // 继续回退（已到栈底，仍是 .card）
    .css("margin", "8px");
});

end() 的行为取决于 jQuery 对象的“回退栈”：find、filter、children、parent、eq、slice 等破坏性方法会在改变集合前压栈，end() 弹出上一层；能连续回退几层，取决于之前链了几次破坏性操作。而 addClass、css、attr 这类不改变集合的方法不压栈，end() 会直接跳回更早的集合——链式调用出现“结果作用到意外的元素上”时，八成是这里数错了层数。

4.5 jQuery 的现状与原生 DOM 等价写法

先给结论：新项目已经不该再把 jQuery 作为首选。它诞生于 IE6–8 时代，当时的主要价值是抹平浏览器差异；这些差异今天已经消失。原生 API 也早已补齐：querySelector/querySelectorAll 支持完整 CSS 选择器（含 :nth-child），classList 与 dataset 让样式与数据属性读写更直接，addEventListener 支持事件委托（event.target.closest()），fetch 取代了 Ajax 封装。jQuery 目前的维护线是 3.x（另有 4.0 处于 beta 阶段、API 有破坏性调整，1.x / 2.x 已停止维护）。如今它主要出现在老后台管理页面、Bootstrap 3/4 站点、以及大量历史业务代码中。所以本章的定位是“读得懂、改得动存量项目”，而不是“新项目从 jQuery 起步”：接手老代码时按原有写法保持一致，新写模块则优先原生 DOM 或 Vue 3 / React。

下面的对照表把这一节的方法一一映射到原生写法，迁移或局部替换时可直接查用（el 表示原生 DOM 元素，$el 表示 jQuery 对象）：

  • 选择：$("#id") ↔ document.querySelector("#id")；$(".item") ↔ document.querySelectorAll(".item")（返回静态 NodeList，不能直接点 jQuery 方法）
  • 创建：$("<div>") ↔ document.createElement("div")
  • 插入：$el.append(x) ↔ el.appendChild(x)；prepend ↔ el.prepend(x)；before/after ↔ el.before(x)/el.after(x)（原生同样“移动已有节点”，需要保留时先克隆）
  • 删除：$el.remove() ↔ el.remove()（DOM4 起支持，旧浏览器用 el.parentNode.removeChild(el)）；empty() ↔ el.replaceChildren() 或 el.textContent = ""
  • 分离：detach() 没有一对一的原生方法——用 el.remove() 摘下来并自己保存引用，原生监听本来就不随节点删除而消失，removeEventListener 才会解绑
  • 复制：$el.clone() ↔ el.cloneNode(false)（仅自身）、$el.clone(true) ↔ el.cloneNode(true)（含后代）；但原生克隆不复制 addEventListener 注册的监听，需要重新绑定
  • 替换：replaceWith ↔ el.replaceWith(newEl)；wrap ↔ 先 createElement 再 parent.insertBefore(wrapper, el) 后 wrapper.appendChild(el)；unwrap ↔ 用 replaceWith(...el.childNodes) 把自己替换掉
  • 遍历：children() ↔ el.children；parent() ↔ el.parentElement；siblings() 无直接对应，可用 [...el.parentElement.children].filter(n => n !== el)；closest() ↔ el.closest(sel)；eq(n)/slice() ↔ 展开 NodeList 后的 list[n]/list.slice(a, b)
  • 样式与属性：addClass ↔ el.classList.add()；attr ↔ el.getAttribute/setAttribute 或 el.dataset
// 原生等价写法：把“新增一行并绑定删除按钮”做完，全程不需要 jQuery
document.addEventListener("click", function (event) {
  const btn = event.target.closest(".del");     // 事件委托，等价于 $("#list").on("click", ".del", fn)
  if (!btn) { return; }
  const row = btn.closest("li");
  row.remove();                                 // 等价于 $(row).remove()
});

function addRow(text) {
  const li = document.createElement("li");      // 等价于 $("<li>")
  li.className = "item";
  li.textContent = text;
  const btn = document.createElement("button");
  btn.className = "del";
  btn.textContent = "删除";
  li.appendChild(btn);                          // 等价于 li.append(btn)
  document.querySelector("#list").prepend(li);  // 等价于 $("#list").prepend(li)
}

// 循环里逐个插入同样会多次重排，先用 Fragment 攒好再插一次
const frag = document.createDocumentFragment();
for (let i = 0; i !== 20; i++) {
  const li = document.createElement("li");
  li.textContent = "第 " + (i + 1) + " 项";
  frag.appendChild(li);
}
document.querySelector("#list").appendChild(frag);

最后提醒一句：迁移时不要把 jQuery 与原生写法在同一段逻辑里来回混用，尤其是事件——同一元素上既用 .on() 又用 addEventListener 并不冲突，但 .off() 解不掉 addEventListener 注册的监听，反之亦然。要么整块用 jQuery，要么整块用原生。

五、Ajax：不刷新页面拿数据

jQuery 的 Ajax 是对原生 XMLHttpRequest 的封装，顺带解决了 JSONP 跨域和浏览器差异。jQuery 3.0 起，$.ajax() 配置对象里的 success:、error:、complete: 回调已被废弃（挂在 jqXHR 上的 .success() / .error() / .complete() 方法在 3.0 中直接被移除），应改用 Promise 风格的 done、fail、always。新旧写法的对应关系如下——老代码照原样保留可读，但新写或改造时请用右边那一版。

// 旧写法：jQuery 1.x 时代的 success/error 回调，3.0 起废弃
$.ajax({
  url: "/api/user",
  success: function (res) { render(res); },
  error: function (xhr) { console.error("HTTP " + xhr.status); }
});

// 现行写法：三个回调挂到返回的 jqXHR（Promise 兼容对象）上
$.ajax({ url: "/api/user" })
  .done(function (res) { render(res); })              // 对应 success
  .fail(function (xhr) { console.error("HTTP " + xhr.status); }) // 对应 error
  .always(function () { $("#loading").hide(); });      // 对应 complete
$(function () {
  $("#submit").on("click", function () {
    $.ajax({
      type: "POST",
      url: "/api/users",
      contentType: "application/json;charset=UTF-8",
      data: JSON.stringify({ name: "tom", age: 20 }),
      dataType: "json"
    })
      .done(function (res) {
        if (res.code === 0) {
          render(res.data);        // 成功分支
        } else {
          alert(res.msg);
        }
      })
      .fail(function (xhr, status) {
        // 超时、断网、4xx、5xx 都会走到这里
        console.error("请求失败：" + status + "，HTTP " + xhr.status);
      })
      .always(function () {
        $("#loading").hide();      // 无论成败都要复位界面
      });
  });
});

日常开发中更常用的是快捷方法：$.get(url, data, callback, dataType)、$.post()、$.getJSON(url, callback)，以及把整个表单序列化成查询串的 $("#form").serialize()。如果页面上已经有 form 且需要异步提交，可以引入 jquery.form.js 插件，用 $("#form").ajaxForm(options) 在页面加载时绑定一次，或用 $("#form").ajaxSubmit(options) 在事件中临时提交，二者的参数与 $.ajax 一致，只多了 beforeSubmit 回调。

必须提醒的是：只写成功分支是线上“点了没反应”的头号原因。超时、断网、后端返回 4xx/5xx 都会落到 fail，这里至少要给出提示并复位 loading 状态。

发送数据时还要留意编码：$.ajax 默认以 application/x-www-form-urlencoded 提交，中文可能乱码，建议显式声明 contentType: "application/json;charset=UTF-8" 并配合 JSON.stringify；若后端只接受表单格式，则用 $.param() 或 $("#form").serialize() 序列化后再发送。

六、UI 框架：Bootstrap 与 Element UI

Bootstrap 是一个“半成品”前端框架：它预定义好一整套 CSS 类和对应行为，你只要提供固定的 HTML 结构、加上固定的 class，就能得到栅格、按钮、表单、导航、模态框等成品效果。所谓响应式，就是同一份页面在手机、平板、桌面自动重排，Bootstrap 靠栅格系统与 CSS3 媒体查询实现。

<div class="container">
  <div class="row">
    <div class="col-md-8">主内容（中等屏幕占 8/12）</div>
    <div class="col-md-4">侧边栏</div>
  </div>
</div>

<!-- Bootstrap 3 的经典面板写法 -->
<div class="panel panel-default">
  <div class="panel-heading">标题</div>
  <div class="panel-body">内容</div>
</div>

<!-- Bootstrap 4/5 中 panel 已被 card 取代 -->
<div class="card">
  <div class="card-body">内容</div>
</div>

版本差异必须分清，关键区别如下：

  • Bootstrap 3 的 JS 组件（模态框、下拉菜单、折叠面板等）依赖 jQuery，所以引入 bootstrap.js 前必须先引入 jQuery；栅格用 col-xs-* / col-sm-* / col-md-* / col-lg-*，面板是 .panel；
  • Bootstrap 4 仍依赖 jQuery，栅格改为不带前缀的 col-*（超小屏）加断点后缀，.panel / .well 被 .card 取代，脚本引入也从 jquery + bootstrap 两件套变成 bootstrap.bundle.min.js（内含 Popper）；
  • Bootstrap 5 已经移除 jQuery 依赖，改用原生 JavaScript；同时把 col-xs-* 改成 col-*、.panel 改成 .card、.well 改成 .card 或 .alert；
  • Bootstrap 5 还改了一批工具类与 data 属性：ml-* / mr-* → ms-* / me-*，text-left / text-right → text-start / text-end，data-toggle / data-target → data-bs-toggle / data-bs-target。

照抄旧教程的 class 名和数据属性，是样式与交互双双失效最常见的原因。维护老站点就用它原本的版本，别半途混版；新项目直接上 Bootstrap 5，或干脆改用 Vue 3 组件库。

Element UI 是饿了么团队为 Vue 2 打造的组件库，思路与 Bootstrap 相似，但组件粒度更重：表格、分页、表单校验、弹窗、日期选择器都可以拿来即用。在 vue-cli 创建的项目里安装后，用 Vue.use(ElementUI) 全局注册即可，也可以按需引入以减小打包体积。Element Plus 是它面向 Vue 3 的对应版本（包名 element-plus），组件名与大部分 props 保持一致，是今天的现行写法。

<!-- 旧写法：Element UI（Vue 2），slot-scope 已不推荐 -->
<template>
  <el-table :data="rows" stripe>
    <el-table-column prop="id" label="编号" width="80"></el-table-column>
    <el-table-column prop="name" label="姓名"></el-table-column>
    <el-table-column label="操作">
      <template slot-scope="scope">
        <el-button size="mini" @click="edit(scope.row)">编辑</el-button>
      </template>
    </el-table-column>
  </el-table>
</template>

<script>
import Vue from "vue";
import ElementUI from "element-ui";
import "element-ui/lib/theme-chalk/index.css";

Vue.use(ElementUI);   // Vue 2：全局注册后，所有 el- 开头的组件均可直接使用
</script>
<!-- 现行写法：Element Plus（Vue 3），按需引入 + 新插槽语法 -->
<template>
  <el-table :data="rows" stripe>
    <el-table-column prop="id" label="编号" width="80" />
    <el-table-column prop="name" label="姓名" />
    <el-table-column label="操作">
      <template #default="scope">
        <el-button size="small" @click="edit(scope.row)">编辑</el-button>
      </template>
    </el-table-column>
  </el-table>
</template>

<script setup>
import { ElTable, ElTableColumn, ElButton } from "element-plus";
import "element-plus/dist/index.css";   // 全量样式；也可用 unplugin-vue-components 做按需自动引入
</script>

官网地址已从 element-cn.eleme.io 迁移到 element.eleme.cn，旧地址会跳转或失效；Element Plus 的文档则在 element-plus.org。从 Element UI 迁移到 Element Plus 的主要改动是：注册由 Vue.use(ElementUI) 变为 app.use(ElementPlus)（按需引入时在单文件组件里 import）；作用域插槽 slot-scope="scope" → #default="scope"；按钮尺寸 size="mini" → size="small"；图标由 class（el-icon-edit）改为组件（需安装 @element-plus/icons-vue）；样式路径 element-ui/lib/theme-chalk/index.css → element-plus/dist/index.css。两者 API 大体相近但不能混用，混装会出现同名组件冲突。

选型建议很直接，按存量项目分别处理：

  • jQuery 与 Bootstrap 3/4 的老项目：继续沿用栅格、panel 与原有 data 属性，只做必要修复；
  • Vue 2 后台系统：继续用 Element UI；
  • 新写的 Vue 3 项目：用 Vite + Element Plus。

小结：把本章的四步串起来，就是一套完整的旧时代前端工作流——用 $() 加选择器定位元素，用链式调用连续加工，用 Ajax 从后端取数据，用 UI 框架拼出界面。掌握它们，就能读懂并维护绝大多数 jQuery + Bootstrap 时代的页面。当项目迁移到 Vue 或 React 时，直接操作 DOM 的选择器思维会退场。但“组件复用”和“数据变化驱动视图”，正是这些框架的升级方向。
