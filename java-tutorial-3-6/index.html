jQuery 与 UI 框架

Posted on 2026-09-19，7 min read

jQuery 是老一代前端工程师的必修课，也是今天读懂大量遗留项目、后台管理页面和 Bootstrap 3 站点的钥匙。本章解决三个问题：怎样用选择器精准而简短地选中元素，怎样用链式调用把“选、改、取”串成一条流水线，怎样用 Ajax 和现成的 UI 框架把页面拼出来。内容适合已经会写原生 JavaScript、做过 DOM 操作、准备接手 Web 项目的 Java 后端读者。

一、jQuery 到底解决了什么问题

原生 DOM 的痛点是“啰嗦”加“兼容”：按 id 取一个元素要写 document.getElementById，遍历一批节点要自己写循环，改样式要记住 style 与 classList 的差别，绑定事件还要考虑 IE 的 attachEvent。jQuery 用两招把这些问题一起抹平。一是 $() 工厂函数接收 CSS 选择器字符串，返回一个类数组的 jQuery 对象。二是这些对象自带一整套跨浏览器的 DOM、样式、事件和 Ajax 方法。

要牢记的第一条规则是：jQuery 对象不是 DOM 对象。事件回调里的 this 是原生 DOM 对象，必须写成 $(this) 才能调用 jQuery 方法；反过来，$("#box").get(0) 或 $("#box")[0] 又能取回原生 DOM，交给依赖 DOM 的第三方库使用。新手最常见的报错“undefined is not a function”，大多就是把 this 当成 jQuery 对象直接调用了 .css()。

$(function () { ... }) 是 $(document).ready() 的简写，它保证 DOM 解析完成后再执行绑定，比把 <script> 放在任何位置都更稳妥。引入方式上，jQuery 1.x 兼容 IE6–8，2.x 起放弃老 IE，3.x 是当前主线并移除了 $.browser、$(window).load() 等老 API；老项目里常见的 1.11.3 正是为兼容 IE8 而保留的版本。文件既可用 CDN 引入，也可下载到 webapp/js/ 下由页面引用，后者在离线环境更可靠。

二、选择器：一句话选中目标元素

jQuery 的选择器沿用 CSS 规范，按用途可分为基本、层级和过滤三类。基本选择器包括 #id、.class、element、* 以及并集写法 selector1, selector2，其中 * 会匹配全部元素，性能很差，实际项目中几乎不该出现。

层级选择器描述元素之间的位置关系：ancestor descendant（中间是空格，匹配所有后代）、parent > child（只匹配直接子元素）、prev + next（紧跟其后的下一个兄弟）、prev ~ siblings（后面的所有兄弟）。示例中 $(".itcast a") 会把嵌套在 p 里的链接也染红，而 $(".itcast>a") 只处理直接子链接，差别就在这个符号上。

过滤选择器是在已有结果集里“再筛一刀”。:first、:last、:eq(index)、:gt(index)、:lt(index)、:even、:odd 按索引筛（索引从 0 开始）；:not(selector)、:has(selector)、:contains(text)、:empty（既无子元素也无文本）、:parent（有子元素或文本）按内容与结构筛；:visible、:hidden、:animated 按可见性与状态筛；[attr=value]、[attr^=value]、[attr$=value]、[attr*=value] 按属性筛；表单场景还有 :input、:text、:checked、:selected、:disabled 等。

两个容易踩的坑：:even、:odd 数的是结果集内的索引而不是视觉行号，所以 $("tr:even") 命中的是第 1、3、5 行（索引 0、2、4）；:first 只取整个结果集的第一个元素，而 CSS 的 :first-child 是“每个父元素下的第一个子元素”，两者语义完全不同。此外 *、:contains() 这类选择器无法交给浏览器原生的 querySelectorAll 处理，数据量大时明显变慢，能用 id、class 就不要用它们。

三、链式调用：一次选中，连续加工

jQuery 的大多数方法都返回 jQuery 对象本身，于是可以像流水线一样一路点下去。下面这段代码演示了选择器与链式调用的配合：给表格隔行着色、给列表项加标记，并用 .end() 回到上一层集合。

$(function () {
  // 基本 + 层级 + 位置过滤：表格正文里索引为偶数的行加底色
  $("table.items > tbody > tr:gt(0):even").css("background", "#f7f7f7");

  // 链式调用：选中的集合被依次加工
  $("#list li")
    .filter(":contains('Java')")   // 只留含 Java 文本的项
    .addClass("hot")
    .find("a")                     // 破坏性操作：集合变为 li 内部的 a
    .attr("target", "_blank")
    .end()                         // 退回到上一级集合（#list li.hot）
    .append("<span class=\"badge\">热门</span>");

  // 遍历取值：map 返回 jQuery 对象，get 才是真正的数组
  const texts = $(".item").map(function () {
    return $(this).text().trim();  // this 是 DOM 对象，必须用 $() 包装
  }).get();
  console.log(texts, $("div").index($("#foo")));
});

写链式调用要先看清每一步的返回类型：.text()、.val()、.attr("href") 这类取值调用返回字符串，链就此断开；而 .css("color", "red")、.addClass()、.append() 返回的仍是 jQuery 对象，可以继续接。find()、filter()、children()、parent() 会改变当前集合，属于破坏性操作，用 .end() 可以回退一层。一条链写七八个方法虽然显得利落，出错时却很难定位，实践中的做法是每三四个方法换行并写清注释。

事件绑定同样支持链式与委托。老写法 $("button").click(fn) 在 jQuery 3.0 中已被 $("button").on("click", fn) 取代；如果按钮是 Ajax 动态渲染出来的，应把监听绑在静态父元素上做事件委托：$("#list").on("click", ".del", fn)，这样新增的行自动生效，不必反复重新绑定。

四、Ajax：不刷新页面拿数据

jQuery 的 Ajax 是对原生 XMLHttpRequest 的封装，顺带解决了 JSONP 跨域和浏览器差异。jQuery 3.0 之后，success、error、complete 三个回调已被标记为废弃，推荐使用 Promise 风格的 done、fail、always。

$(function () {
  $("#submit").on("click", function () {
    $.ajax({
      type: "POST",
      url: "/api/users",
      contentType: "application/json;charset=UTF-8",
      data: JSON.stringify({ name: "tom", age: 20 }),
      dataType: "json"
    })
      .done(function (res) {
        if (res.code === 0) {
          render(res.data);        // 成功分支
        } else {
          alert(res.msg);
        }
      })
      .fail(function (xhr, status) {
        // 超时、断网、4xx、5xx 都会走到这里
        console.error("请求失败：" + status + "，HTTP " + xhr.status);
      })
      .always(function () {
        $("#loading").hide();      // 无论成败都要复位界面
      });
  });
});

日常开发中更常用的是快捷方法：$.get(url, data, callback, dataType)、$.post()、$.getJSON(url, callback)，以及把整个表单序列化成查询串的 $("#form").serialize()。如果页面上已经有 form 且需要异步提交，可以引入 jquery.form.js 插件，用 $("#form").ajaxForm(options) 在页面加载时绑定一次，或用 $("#form").ajaxSubmit(options) 在事件中临时提交，二者的参数与 $.ajax 一致，只多了 beforeSubmit 回调。

必须提醒的是：只写成功分支是线上“点了没反应”的头号原因。超时、断网、后端返回 4xx/5xx 都会落到 fail，这里至少要给出提示并复位 loading 状态。

发送数据时还要留意编码：$.ajax 默认以 application/x-www-form-urlencoded 提交，中文可能乱码，建议显式声明 contentType: "application/json;charset=UTF-8" 并配合 JSON.stringify；若后端只接受表单格式，则用 $.param() 或 $("#form").serialize() 序列化后再发送。

五、UI 框架：Bootstrap 与 Element UI

Bootstrap 是一个“半成品”前端框架：它预定义好一整套 CSS 类和对应行为，你只要提供固定的 HTML 结构、加上固定的 class，就能得到栅格、按钮、表单、导航、模态框等成品效果。所谓响应式，就是同一份页面在手机、平板、桌面自动重排，Bootstrap 靠栅格系统与 CSS3 媒体查询实现。

<div class="container">
  <div class="row">
    <div class="col-md-8">主内容（中等屏幕占 8/12）</div>
    <div class="col-md-4">侧边栏</div>
  </div>
</div>

<!-- Bootstrap 3 的经典面板写法 -->
<div class="panel panel-default">
  <div class="panel-heading">标题</div>
  <div class="panel-body">内容</div>
</div>

<!-- Bootstrap 4/5 中 panel 已被 card 取代 -->
<div class="card">
  <div class="card-body">内容</div>
</div>

版本差异必须分清，关键区别如下：

  • Bootstrap 3 的 JS 组件（模态框、下拉菜单、折叠面板等）依赖 jQuery，所以引入 bootstrap.js 前必须先引入 jQuery；
  • Bootstrap 5 已经移除 jQuery 依赖，改用原生 JavaScript；
  • Bootstrap 5 同时把 col-xs-* 改成 col-*、.panel 改成 .card、.well 改成 .card 或 .alert。

照抄旧教程的 class 名，是样式失效最常见的原因。

Element UI 是饿了么团队为 Vue 2 打造的组件库，思路与 Bootstrap 相似，但组件粒度更重：表格、分页、表单校验、弹窗、日期选择器都可以拿来即用。在 vue-cli 创建的项目里安装后，用 Vue.use(ElementUI) 全局注册即可，也可以按需引入以减小打包体积。

<template>
  <el-table :data="rows" stripe>
    <el-table-column prop="id" label="编号" width="80"></el-table-column>
    <el-table-column prop="name" label="姓名"></el-table-column>
    <el-table-column label="操作">
      <template slot-scope="scope">
        <el-button size="mini" @click="edit(scope.row)">编辑</el-button>
      </template>
    </el-table-column>
  </el-table>
</template>

<script>
import Vue from "vue";
import ElementUI from "element-ui";
import "element-ui/lib/theme-chalk/index.css";

Vue.use(ElementUI);   // 全局注册后，所有 el- 开头的组件均可直接使用
</script>

官网地址已从 element-cn.eleme.io 迁移到 element.eleme.cn，旧地址会跳转或失效。Vue 3 项目应改用 Element Plus（包名 element-plus），两者 API 大体相近，但不能混用。选型建议很直接：jQuery 与 Bootstrap 3 的老项目继续沿用栅格和 panel，Vue 2 后台系统优先 Element UI，Vue 3 用 Element Plus。

小结：把本章的四步串起来，就是一套完整的旧时代前端工作流——用 $() 加选择器定位元素，用链式调用连续加工，用 Ajax 从后端取数据，用 UI 框架拼出界面。掌握它们，就能读懂并维护绝大多数 jQuery + Bootstrap 时代的页面。当项目迁移到 Vue 或 React 时，直接操作 DOM 的选择器思维会退场。但“组件复用”和“数据变化驱动视图”，正是这些框架的升级方向。
