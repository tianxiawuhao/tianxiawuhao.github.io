7.2 文本处理三剑客

Posted on 2024-12-02，5 min read

服务上线之后，日志、配置、进程列表、访问记录全都是文本。排查问题时，你面对的往往是几百 MB 的日志文件和一个 SSH 终端，没有 IDE，也没有可视化工具，只有一条命令行。这时候决定效率的就是 grep、sed、awk 这三个命令：它们几乎在所有 Linux 发行版和容器镜像里都默认存在，不需要安装任何东西。本章面向已经掌握基本 Linux 操作、但排查问题时还只会 tail -f 的 Java 后端开发者。读完本章，你应该能在几秒内从日志里定位异常，在成百上千个配置文件里完成批量替换，并对访问日志做出一份能看的统计。

一、先分清三者的分工

把文本处理想成一条流水线：三个命令各负责一个环节，这也是它们总被写成管道的原因。

  • grep 管“挑行”：按整行内容筛选，命中就输出，不命中就丢弃，它不修改内容。
  • sed 管“改行”：按行做替换、删除、插入，常用于配置文件的批量修改。
  • awk 管“拆列”：默认按空白把一行切成字段，再按字段做条件判断、计算与格式化输出。

记住这个分工会少走很多弯路：只想找东西用 grep，想改文件用 sed，想按某一列过滤或统计就用 awk。三者都默认逐行读取数据，都能接管道、读文件，因此可以像积木一样拼起来。

还有一点要提前记住：grep 的退出码是有约定的——匹配到返回 0，没匹配到返回 1，文件不存在或参数错误返回 2。脚本和 CI 流水线正是靠这三个值判断“检查是否通过”，后文会再展开。

二、正则：三个命令共用的语法底座

正则表达式是这三个命令的共同语言。先把最常用的一小部分记牢就够用：

  • ^ 行首，$ 行尾。例如 '^ERROR' 匹配以 ERROR 开头的行。
  • . 任意一个字符（不含换行），.* 任意长度内容。
  • [] 字符集合，如 '[Ee]rror'；[^] 表示取反，如 '[^0-9]' 匹配任意非数字字符。
  • * 修饰它前面那一个字符重复零次或多次，所以 'ab*' 表示 a 后面跟任意个 b。
  • +、?、{m,n} 属于扩展正则。基础正则下要写成 \+、\?、\{2,5\}，或者加 -E 让 grep 按扩展正则解析。
  • 常用字符类可以直接写成 POSIX 字符类，如 [[:digit:]]（数字）、[[:space:]]（空白）、[[:alpha:]]（字母）。

这里有一个容易被忽略的细节：默认正则只要“行里某处出现”就算匹配，不是整行匹配。想精确匹配整行要加 -x，想只匹配完整单词要加 -w。漏掉这一点，就会出现“明明只想匹配 user，结果 user_service 也被匹配出来”的情况。

三、grep：把要看的那几行挑出来

最常用的选项就那么几个，组合起来已能覆盖排查场景的大部分需求。-i 忽略大小写，-n 显示行号，-v 反向选择（输出不匹配的行），-c 只输出匹配的行数。需要递归目录用 -r；-A/-B/-C 额外显示匹配行后/前/前后几行，--include 限定文件类型。

# 1. 在日志里找异常，并带上前后 3 行上下文
grep -n -C 3 'NullPointerException' /var/log/app/app.log

# 2. 忽略大小写，统计几分钟内 ERROR 出现的行数
grep -c -i 'error' /var/log/app/app.log

# 3. 去掉噪音：先排除 debug 行，再找超时
grep -v 'DEBUG' app.log | grep -i 'timeout'

# 4. 递归搜索配置，只扫 properties 和 yml
grep -rn --include='*.properties' --include='*.yml' 'jdbc:mysql' /opt/app/conf

# 5. 只看异常本身，不要那条 grep 自己
ps -ef | grep '[t]omcat'

最后一条用了正则的小技巧。[t]omcat 匹配的字符串是 tomcat，而 grep 进程自己的命令行里写的是 [t]omcat，因此不会匹配自己，不必再额外 grep -v grep。同理，grep -f patterns.txt data.txt 表示“从 patterns.txt 里逐行读正则，去 data.txt 里筛”，适合维护一份固定的关键字清单。

还有一个绕不开的边界：grep -P。它让 grep 改用 PCRE 引擎，于是 \d、\b、(?<=...) 这类写法才可用。但 -P 不是所有 grep 都有：它是 GNU grep 在编译时链接了 PCRE 才提供的功能。Rocky Linux 9 自带的 GNU grep 3.6、Ubuntu 22.04 自带的 3.7 都支持。而 macOS 自带的 BSD grep、Alpine 默认的 BusyBox grep 都不支持，前者会报 grep: invalid option -- P，后者往往把 -P 当成普通参数或退化为字面量匹配，脚本会静默给出错误结果。跨平台脚本更稳的做法是避开 -P：用 -E（POSIX 扩展正则）替代，把 \d 写成 [0-9]、把 \b 写成 [[:<:]] 与 [[:>:]]；确实需要 PCRE 时，在脚本入口先探测一次 grep -P '' /dev/null 2>/dev/null 的退出码再决定走哪个分支。同类的兼容性问题还有 GNU grep 3.8 起收紧了未定义转义（如 \!、\-）的处理并给出警告，老脚本升级发行版后会开始刷警告甚至改变匹配结果

在脚本中使用时，利用退出码做判断比解析输出更可靠：

if grep -q 'Started Application' /var/log/app/app.log; then
  echo "应用已启动"
else
  echo "未检测到启动日志，退出码 $?"
  exit 1
fi

-q 让 grep 安静下来、不打印任何内容，只保留退出码，这正是自动化检查最常用的写法。反过来，如果脚本开头有 set -e，那么一条“没匹配到”的 grep 会返回 1 并直接终止脚本。这时需要写成 grep ... || true，显式表达“没找到也可以接受”。

四、sed：不动手打开文件就完成批量替换

sed 的基本模型是 sed '地址+动作' 文件，最常用的动作只有四五个：s 替换、d 删除、p 打印、i/a 在行前/行后插入。s 的完整形式是 s/正则/替换/标志，其中 g 表示一行内全部替换（不加则只替换每行第一处）。

# 1. 先预览：把旧域名换成新域名，只在屏幕上输出，不改文件
sed 's/old.example.com/new.example.com/g' nginx.conf

# 2. 确认无误后原地修改，并留一份 .bak 备份
sed -i.bak 's/old.example.com/new.example.com/g' nginx.conf

# 3. 删除空行、删除以 # 开头的注释行
sed -e '/^[[:space:]]*$/d' -e '/^[[:space:]]*#/d' nginx.conf

# 4. 只打印第 10 到 20 行（-n 抑制默认输出，p 才是打印）
sed -n '10,20p' app.log

# 5. 在匹配行后面追加一行
sed -i '/server_name/a\    access_log /var/log/nginx/access.log;' site.conf

使用 sed 有三条经验值得记住。第一，先用不带 -i 的方式预览输出，确认无误再原地修改，因为 -i 会直接覆盖文件，写错正则几乎没有后悔的机会。第二，替换内容里出现 / 时不必一路转义，可以换个分隔符，例如 sed 's#/opt/old#/opt/new#g'，可读性会好很多。第三，Linux 上用的是 GNU sed，-i 后面的备份后缀可以紧跟其后（如 -i.bak）。而 macOS/BSD 的 -i 必须带一个参数，写成 sed -i '' 's/a/b/'。如果脚本要在两种系统上跑，最好显式写出备份后缀来规避差异。这里把发行版基线也补一句：CentOS 7 已于 2024 年 6 月 30 日 EOL，新环境应换成 Rocky Linux 9／AlmaLinux 9，或 Ubuntu 22.04 及之后的 LTS。它们自带 GNU sed 4.8，属于「GNU 语义、后缀可选」那一类；真正要防的仍是 macOS/BSD 与 Alpine（BusyBox sed，连 -i 的语义都与 GNU 不同，且不支持 a\ 这类 GNU 扩展写法）。另外 -i 是原子替换的实现（GNU sed 写临时文件再改名），但不保证保留原文件的硬链接、属主与扩展属性，改系统配置文件时若在意权限，改完要顺手 ls -l 复核一次。

五、awk：按字段筛选、计算与统计

awk 的名字来自三位创造者 Alfred Aho、Peter Weinberger 和 Brian Kernighan 的姓氏首字母。它每次读一行，把行切成若干字段：$1 是第一列、$2 是第二列，$0 代表整行。两个内置变量必须记住：NF 是当前行的字段总数，NR 是当前处理到第几行。默认分隔符是空白，用 FS 可以修改（在 BEGIN 里设置）。

完整语法是 awk '条件 {动作}' 文件，条件省略就对每一行执行动作。几个能立刻用上的例子：

# 1. 从 /etc/passwd 取出 UID 小于 10 的账号（字段分隔符为冒号）
awk -F: '$3 < 10 {print $1 "\t" $3}' /etc/passwd

# 2. 只看某条日志里的第 7 列，并打印行号
awk '{print NR "\t" $7}' app.log

# 3. 统计访问日志里每个 IP 的请求次数，按次数倒序取前 10
awk '{print $1}' /var/log/nginx/access.log | sort | uniq -c | sort -rn | head -10

# 4. 求和：统计状态码为 500 的响应总耗时（第 10 列为耗时，单位毫秒）
awk '$9 == 500 {sum += $10; n++} END {print "total(ms):", sum, "count:", n}' access.log

# 5. 输出时指定分隔符，做成表格
awk 'BEGIN {OFS=","} {print $1, $7, $9}' access.log

三个要点能让 awk 从“能看懂”变成“敢用”。一是 END 块在所有行处理完后执行一次，是写求和、计数、平均值的地方；对应的 BEGIN 在处理第一行之前执行，适合初始化 FS、OFS 或打印表头。二是比较时要注意类型：$3 < 10 是数值比较，而 $1 == "GET" 是字符串比较，字符串一定要加引号。三是 NF 常被用来做“防越界”，比如 awk 'NF >= 10 {print $9}' 可以跳过格式不完整的行，避免把残缺日志当成正常数据统计。

第四点是要知道自己用的是哪个 awk。GNU/Linux 上 awk 只是一个指向具体实现的软链：Rocky Linux 9 默认是 gawk（GNU awk，5.1 起），而 Ubuntu 22.04／Debian 默认是 mawk，两者并不等价。mawk 更快、更省内存，但缺少 gawk 的一批扩展——gensub()、asort()/asorti()、length(array)、PROCINFO、--csv 等；反过来 gawk 5.1+ 的 awk --csv 可以直接解析带引号的 CSV，比手写 -F, 可靠得多。同一条命令在本地（Ubuntu 开发机）与线上（Rocky 服务器）跑出不同结果，往往就是 mawk 与 gawk 的差别。脚本里若用了扩展特性，就显式写成 gawk 并在部署文档里写清依赖，或者用 awk -W version 在启动时打印实现与版本，别让环境替你选。

六、常见坑：组合使用时的四个陷阱

  • Windows 换行导致匹配不上：文件里每行结尾是 \r\n，'error$' 就永远匹配不到。可以先用 cat -A app.log | head 观察行尾是否有 ^M，再用 sed -i 's/\r$//' app.log 把 \r 去掉。
  • 忘记引号，正则被 shell 抢先展开：模式里含 *、?、$ 时一律用单引号包住，例如 grep 'ERROR.*timeout'。用双引号会被 shell 先做变量替换和路径展开，结果往往不是你想要的。
  • grep 卡住不返回：对正在被写入的文件递归搜索大目录，或把 tail -f 的输出通过管道交给 grep 时，命令会一直等待新内容。排查前先确认目标范围，必要时用 timeout 10 grep ... 给自己加一道保险。
  • 直接改生产配置文件：sed -i 之前先备份，或者先输出到新文件再比对。例如 sed 's/a/b/g' old.conf > new.conf && diff old.conf new.conf。批量改完记得让服务重新加载配置，不要想当然地认为进程已经生效。

七、小结

这一章的核心只有一句话：grep 挑行、sed 改行、awk 拆列。围绕这个分工，记住三组关键参数就足够应付日常排查。grep 方面是 -i -n -v -c -r -A/-B/-C 与退出码 0/1/2。sed 方面是 s/正则/替换/g、d、-n 'x,yp'，以及改文件前先预览的习惯。awk 方面是 $1/$0、NF、NR、-F 和 BEGIN/END。真正拉开差距的不是记住更多参数，而是把三者串成管道。先用 grep 缩小范围，再用 awk 抽列和统计，最后用 sort | uniq -c | sort -rn 排序取前几名，一条命令就能回答“哪个接口最慢、哪个 IP 打得最多”这类问题。建议在自己的测试环境里找一份真实日志，把本章示例逐个跑一遍，再改写成适合自己项目的版本。
