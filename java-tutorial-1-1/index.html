Java 语言概述与开发环境

Posted on 2026-09-19，5 min read

Java 的第一课往往不是语法，而是环境：很多人还没写出第一行代码，就先被 JDK、JRE、JVM 三个缩写和 Path、classpath 两个环境变量拦住。本章要解决的就是这个问题——把 Java 程序"从源代码到运行结果"这条链路讲清楚，让你在自己的电脑上搭好环境，并成功跑出第一个 HelloWorld。适合零基础、或者装过 JDK 但说不清三个名词区别的读者。读完之后，你应该能解释"为什么 Java 能跨平台"，也能独立排查最常见的环境与编译报错。

为什么 Java 需要一套运行环境

Java 诞生于 1995 年，由 Sun 公司的詹姆斯·高斯林（James Gosling）团队设计（早期叫 Oak，后改名 Java）。它最出名的两个特点是开源和跨平台。跨平台的含义是：同一份源代码，编译一次之后可以在 Windows、Linux、macOS 上运行，也就是常说的"一次编写，到处运行"（Write Once, Run Anywhere）。

计算机只能执行本机的机器指令，不同操作系统的可执行文件格式互不通用。Java 的做法是引入一层中间层：源代码不直接编译成机器码，而是编译成与平台无关的字节码（.class 文件）；再由各操作系统上各自的虚拟机把字节码翻译成本机能识别的指令。所以跨平台并不是"Java 代码到处都能直接跑"，而是"每个平台都装了一个能读懂同一份字节码的虚拟机"。写 Java 的人只需要面对字节码这一个标准，剩下的差异由虚拟机承担。

Java 按用途分成三个平台方向：JavaSE（标准版，桌面与基础类库，是学习主线）、JavaEE（企业版，Web 与服务器开发，现多称 Jakarta EE）、JavaME（微型版，早期功能机与 Android 前身）。本教程始终以 JavaSE 为基础。

JDK、JRE、JVM 分别是什么

这三个词是包含关系，不是并列关系，记住一张图就够了：

  • JVM（Java Virtual Machine，Java 虚拟机）：负责执行字节码。不同操作系统有各自的 JVM 实现，它是"跨平台"这件事的承担者。
  • JRE（Java Runtime Environment，Java 运行环境）：运行一个已经编译好的 Java 程序所需要的一切，即 JVM + 核心类库（String、System 这类基础类）。
  • JDK（Java Development Kit，Java 开发工具包）：给开发者用的完整套装，即 JRE + 开发工具，例如编译器 javac、打包工具 jar。

由此可以推论出两条实用结论。第一，装 JDK 就够了：JDK 里已经带了 JRE，不需要再单独装一遍。第二，如果某台机器只负责运行别人做好的程序（比如服务器上跑打包好的 jar），理论上只装 JRE 就行——但实际部署中通常还是装 JDK，因为排查问题时常常要用到 jps、jstack 等工具。

提示：从 JDK 9 开始，官方不再单独提供 JRE 安装包，JDK 本身就包含了运行环境；如果只是为了"能运行"，下载最新的 JDK LTS 版本即可。安装路径请避开中文和空格，例如 D:\develop\Java\jdk-21，否则后续工具链容易出问题。

配置 Path 与 classpath

Path：让 javac 和 java 在任意目录可用

安装完成后，javac.exe 和 java.exe 位于 JDK 安装目录下的 bin 目录里。如果只把程序写在 bin 目录下，当然能运行，但这显然不是办法。操作系统的 Path 环境变量记录了一批"可执行文件搜索目录"：当你在命令行输入 javac 时，系统会按 Path 里的目录顺序去找这个程序。把 JDK 的 bin 目录加进 Path，javac 和 java 就能在任何目录下直接使用。

推荐的做法是分两步配置，而不是把长路径硬写进 Path：

  1. 新建系统变量 JAVA_HOME，值为 JDK 的安装根目录（注意：是 JDK 根目录，不是 bin 目录）。
  2. 编辑系统变量 Path，在最前面追加 %JAVA_HOME%\bin（Windows）或 $JAVA_HOME/bin（Linux / macOS）。

这样做的好处是：将来升级 JDK，只需要改 JAVA_HOME 一处，Path 不用动。

# Windows：验证配置是否生效（重新打开一个命令行窗口再执行）
java -version
javac -version
echo %JAVA_HOME%

# Linux / macOS
java -version
javac -version
echo $JAVA_HOME

两个命令都能打印出版本号，说明 Path 配置成功。若提示"不是内部或外部命令"，请检查三件事：是否重新打开了命令行窗口（环境变量修改只对新窗口生效）、%JAVA_HOME%\bin 是否写成了 %JAVA_HOME%\bin; 且没有破坏原有的其他路径、JAVA_HOME 的值是否指向了真实存在的目录。

classpath：让 JVM 找得到 .class 文件

classpath 是 JVM 查找类文件的路径集合。执行 java 类名 时，JVM 会按 classpath 的顺序去搜索对应的 .class。

需要注意：现代 JDK 默认不需要手动配置 classpath。如果命令行没有用 -classpath（或 -cp）指定，也没有设置 CLASSPATH 环境变量，JVM 会把当前目录（.）作为默认值——这正好覆盖了新手"在 .class 所在目录下运行"的场景。反而要小心的是：一旦手动设置了 CLASSPATH 却没有包含 .，程序就会莫名其妙提示找不到类。这也是很多老教程里"配置 classpath"这一步现在可以跳过的原因。

# 显式指定 classpath：在任意目录下运行 D:\code 里的类
java -cp D:\code HelloWorld

# Linux / macOS 用冒号分隔多个目录
java -cp /home/me/code:. HelloWorld

另外要区分"编译期的文件路径"和"运行期的类路径"：javac 处理的是你给出的源文件路径，java 处理的是从 classpath 中查找到的类。两者用错了，就会分别报"找不到文件"和"找不到或无法加载主类"。

第一个程序：HelloWorld

Java 程序的最小单位是类，所有代码都写在类里面；程序执行的入口是一个固定签名的 main 方法。把下面这段代码保存为 HelloWorld.java：

public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("HelloWorld");
    }
}

逐行理解：public class HelloWorld 定义了一个公开的类，类名与文件名必须一致；public static void main(String[] args) 是 JVM 寻找的入口方法，签名固定，String[] args 用来接收命令行参数；System.out.println(...) 表示向标准输出打印一行内容，双引号里的文字可以随意修改。Java 严格区分大小写，System、String、main 都不能改写。

接着在命令行中进入该文件所在目录，依次执行编译和运行：

javac HelloWorld.java   # 编译：生成字节码 HelloWorld.class
java HelloWorld         # 运行：注意不加 .class 扩展名
# 输出：HelloWorld

这两条命令的规则要分清：javac 后面跟文件名，必须带 .java；java 后面跟类名，不能带 .class。从 JDK 11 开始，还可以用 java HelloWorld.java 一步完成"编译 + 运行"单文件源码，适合做小练习，但真实项目仍然走"先编译、再运行"的标准流程。

常见报错与排查

  • 找不到文件 / 类 HelloWorld 是公共的，应在名为 HelloWorld.java 的文件中声明：文件名与 public 类名不一致，或文件的扩展名被系统隐藏了（真实文件名可能是 HelloWorld.java.txt）。请在资源管理器中打开"显示文件扩展名"后核对。
  • 非法字符: '\uff1b' 之类的提示：代码里混入了中文标点（分号、括号、引号）。Java 要求除字符串内容与注释外全部使用英文半角符号。
  • 找不到或无法加载主类：java 命令后多写了 .class，或者当前目录不在 classpath 中，或者类名大小写写错。
  • 在类 HelloWorld 中找不到主方法：main 方法签名写错，如 main 拼成 mian、漏掉 static、把 String[] args 写成 string[] args。
  • 缺少分号、括号不配对：Java 语句以分号结尾，{}、() 必须成对。IDE 的括号高亮能帮你快速定位，写代码时建议先成对写出括号再填内容。

小结

本章的主线是一条链路：Java 源代码经 javac 编译成与平台无关的字节码，再由各平台上的 JVM 执行，跨平台能力由此而来。围绕这条链路，三个名词是包含关系——JDK = JRE + 开发工具，JRE = JVM + 核心类库；两个环境变量各管一段——Path 让编译与运行命令随处可用，classpath 让 JVM 找得到类文件（现代 JDK 下默认使用当前目录，通常无需手工配置）。最后，javac 文件名.java、java 类名 这一对命令和 HelloWorld 的四行代码，是后续所有 Java 程序的原型。下一章将在此基础上进入注释、关键字、常量与变量，把"代码里能写什么"讲清楚。
