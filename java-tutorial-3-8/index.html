Vue 进阶

Posted on 2026-09-19，5 min read

上一章我们把数据绑定和指令用在单个页面里。组件一拆开，新问题就来了：父子之间怎么传数据、重复的结构怎么复用、多个页面怎么切换、共享状态和后端请求怎么统一管理。本章用 Vue 2.7 讲清这四件事，并标出 Vue 3 的差异，适合已经掌握指令、计算属性和生命周期的读者。

一、组件通信：props 向下，事件向上

组件化的第一原则是单向数据流：数据用 props 从父流向子，子组件不直接修改它，这样每次变化都能追溯到唯一来源。props 推荐写成对象形式，声明类型、必填和默认值，开发环境下类型不符会给出警告。

子组件通知父组件靠自定义事件 this.$emit('like', id)，父组件用 @like 监听。只想同步一个值时，Vue 2 的 .sync 修饰符是语法糖：:title.sync="t" 等价于 :title="t" @update:title="t = $event"（Vue 3 改为 v-model:title）。层级很深时逐层传 props 会变成「钻透」，可以用 provide / inject 从祖先注入，但普通对象注入后不是响应式的。$refs、$parent、事件总线虽然能用，调用关系却隐蔽，只适合临时场景。

下面这个子组件同时用到了 props、事件和插槽：

<!-- PostCard.vue：子组件 -->
<template>
  <h3>{{ title }}</h3>
  <slot name="meta">暂无摘要</slot>
  <slot :post="post"></slot>  <!-- 作用域插槽 -->
</template>
<script>
export default {
  props: { title: String, post: Object },
  methods: { like() { this.$emit('like', this.post.id) } }
}
</script>

父组件负责传值、监听事件，并填充插槽内容；注意事件名要写成 kebab-case：

<post-card :title="post.title" :post="post" @like="onLike">
  <template #meta>{{ post.summary }}</template>
  <template #default="{ post }">{{ post.author }}</template>
</post-card>

二、插槽：把结构和渲染权交给调用方

组件之间除了传数据还要传结构。写死内容的组件无法复用，插槽就是留给父组件的占位出口：<slot> 是默认插槽，标签内的内容作为兜底；带 name 的是具名插槽；在 <slot> 上绑定数据、由父组件决定怎么渲染的是作用域插槽。

Vue 2.6 起，具名插槽和作用域插槽统一用 v-slot（简写 #）书写，旧的 slot="name" 与 slot-scope 已废弃并在 Vue 3 中移除。v-slot 只能写在 <template> 或组件标签上，这是最常见的报错原因；列表、表格、布局组件几乎都靠作用域插槽实现「数据在我这、样式你决定」。

三、路由：从整页刷新到页面级组件切换

用 <a href> 跳转会整页刷新，状态和请求全部重来。vue-router 把 URL 映射到组件：每条路由声明 path、name、component，页面用 <router-view> 作为渲染出口，用 <router-link> 生成链接。path: '/post/:id' 这样的动态段通过 this.$route.params.id 读取；query 会留在地址栏，而未在 path 中声明的 params 刷新后就丢了，这是新手最常踩的坑。

页面多了要做路由级懒加载：component: () => import('@/views/PostDetail.vue') 让 webpack 把每个页面拆成独立 chunk。权限校验放在全局前置守卫 router.beforeEach 里，next(false) 中断导航、next('/login') 重定向。注意版本对应：Vue 2 配 vue-router 3 并调用 Vue.use(VueRouter)，Vue 3 则用 vue-router 4 的 createRouter，404 通配也从 '*' 改成了 '/:pathMatch(.*)*'。

import Vue from 'vue'; import VueRouter from 'vue-router'
Vue.use(VueRouter)
const router = new VueRouter({
  mode: 'history',
  routes: [
    { path: '/post/:id', component: () => import('@/views/PostDetail.vue') },
    { path: '*', component: () => import('@/views/NotFound.vue') } // v4 用 /:pathMatch(.*)*
  ]
})
router.beforeEach((to, from, next) =>
  store.state.token || to.path === '/login' ? next() : next('/login'))
export default router

四、请求层与状态管理

在组件里直接写 axios.get 会让域名散落各处、token 要手动附加、错误处理重复三遍。工程化的做法是用 axios.create({ baseURL, timeout }) 建一个实例，在请求拦截器里统一加 token，在响应拦截器里剥离数据层并处理 401；baseURL 从环境变量读取，切换环境只改配置。axios 基于 Promise 封装 XMLHttpRequest，支持并发请求、自动转换 JSON 和取消请求。

真正跨组件的共享状态（登录用户、购物车、主题）要抽到 store。Vuex 的模型是 state 存数据、getters 派生、mutations 同步修改、actions 处理异步再提交 mutation，模块加 namespaced: true 后互不干扰。就像官方文档提醒的，应用不大时引入 Vuex 只会增加样板代码——Vue 2.6+ 新增的 Vue.observable 就能搭一个极简共享 store；Vue 3 中则推荐用 Pinia 取代 Vuex（无 mutation、对 TypeScript 更友好），Vue 2.7 的项目同样可以使用。

import axios from 'axios'
const service = axios.create({ baseURL: process.env.VUE_APP_BASE_URL, timeout: 10000 })
service.interceptors.request.use(cfg => {
  if (store.state.token) cfg.headers.Authorization = 'Bearer ' + store.state.token
  return cfg
})
service.interceptors.response.use(res => res.data, err => {
  if (err.response && err.response.status === 401) router.push('/login')
  return Promise.reject(err)
})
export default service

顺带改正两处旧笔记里的错误。其一，fetch 的响应体必须写成 await response.json()（json() 返回 Promise），而且 fetch 只在网络错误时 reject，遇到 400/500 仍算成功，需要自己判断 response.ok，默认也不带 cookie，要显式写 credentials: 'include'；「fetch 不支持取消和超时」的说法也已过时，现在可以用 AbortController 配合 signal。其二，fetch 属于 WHATWG Fetch 标准而非 ES6 规范的一部分，axios 也不能「自动防 CSRF」——它只是支持按配置携带 XSRF-TOKEN（xsrfCookieName / xsrfHeaderName），仍需服务端校验。

五、工程化与常见坑

项目走到这一步就需要构建工具：vue-cli（底层是 webpack）把 .vue 单文件组件和 ES6+ 语法编译成浏览器可运行的文件，Element UI 这类组件库要按需引入（配 babel-plugin-component），否则首屏体积明显变大。生产构建用 vue.config.js 设置 publicPath，用 .env.production 中的 VUE_APP_* 变量区分接口地址。

几个高频坑：重复写两个 class 属性（如 class="playing" :class="{playing: isPlaying}"）时浏览器只认第一个，动态类会失效，应写成 :class="['playing', { playing: isPlaying }]"；v-show 与行内 style="display: none" 同时使用会互相打架。v-for 必须绑定稳定的 :key，不要用数组下标。另外，源笔记里那种公开测试接口（如 autumnfish.cn）随时可能下线，练手可以，真实项目必须换成自己的后端。

小结：props 与事件划清组件边界，插槽把结构复用出去，路由让 URL 驱动页面，store 与 axios 封装收拢共享状态和网络请求，这四块正是组件化之后的主干。掌握以后再学 Vue 3 的 setup、defineProps / defineEmits 与 Pinia，只是换写法，思路完全一致。下一步建议动手把一个多页面小项目从零配置到能打包上线。
