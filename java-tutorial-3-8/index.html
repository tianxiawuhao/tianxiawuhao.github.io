3.8 Vue 进阶

Posted on 2026-09-19，5 min read

上一章把数据绑定和指令用在单个页面里。组件一拆开，新问题就来了：父子之间怎么传数据、重复的结构怎么复用、多个页面怎么切换、共享状态和后端请求怎么统一管理。本章以 Vue 3（配合 Vite 工程）讲清这四件事，并标出与 Vue 2 的差异，适合已经掌握指令、计算属性和生命周期的读者。

一、组件通信：props 向下，事件向上

组件化的第一原则是单向数据流：数据用 props 从父流向子，子组件不直接修改它，这样每次变化都能追溯到唯一来源。props 推荐写成对象形式，声明类型、必填和默认值，开发环境下类型不符会给出警告；Vue 3 在 <script setup> 里用编译宏 defineProps 声明，运行时校验的行为与选项式写法一致。

子组件通知父组件靠自定义事件：<script setup> 中先用 defineEmits(['like']) 声明，再调用 emit('like', id)，父组件用 @like 监听。只想同步一个值时，Vue 3 用 v-model:title，它展开为 :title 加 @update:title。层级很深时逐层传 props 会变成“钻透”，可以用 provide / inject 从祖先注入；Vue 3 中注入的值可以是 ref 或 reactive，因此天然保持响应式，不希望后代改写时用 readonly() 包一层。$refs、$parent 虽然能用，调用关系却隐蔽，只适合临时场景。

下面这个子组件同时用到了 props、事件和插槽：

<!-- PostCard.vue：子组件 -->
<template>
  <h3>{{ title }}</h3>
  <slot name="meta">暂无摘要</slot>
  <slot :post="post"></slot>  <!-- 作用域插槽 -->
</template>
<script setup>
const props = defineProps({
  title: String,
  post: { type: Object, required: true }
});
const emit = defineEmits(['like']);
function like() {
  emit('like', props.post.id);
}
</script>

父组件负责传值、监听事件，并填充插槽内容；注意事件名要写成 kebab-case：

<post-card :title="post.title" :post="post" @like="onLike">
  <template #meta>{{ post.summary }}</template>
  <template #default="{ post }">{{ post.author }}</template>
</post-card>

版本提示：Vue 2 里同一个子组件写成 export default { props: { title: String, post: Object }, methods: { like() { this.$emit('like', this.post.id) } } }，父组件用 :title.sync="t" 同步单个值——.sync 在 Vue 3 中已移除，改用 v-model:title；组件默认的 v-model 也不再绑定 value 与 input，而是 modelValue 与 update:modelValue。另外 Vue 3 移除了实例方法 $on / $off / $once 以及 $children，Vue 2 时代流行的“事件总线”写法不再可用，跨层级通信请用 provide / inject、Pinia，或第三方库 mitt。provide 注入的普通对象在 Vue 2 中不是响应式的，这一点也是迁移时的常见差异。

二、插槽：把结构和渲染权交给调用方

组件之间除了传数据还要传结构。写死内容的组件无法复用，插槽就是留给父组件的占位出口：<slot> 是默认插槽，标签内的内容作为兜底；带 name 的是具名插槽。在 <slot> 上绑定数据、由父组件决定怎么渲染的，是作用域插槽。

Vue 2.6 起，具名插槽和作用域插槽统一用 v-slot（简写 #）书写，Vue 3 沿用这套语法，旧的 slot="name" 与 slot-scope 已废弃并在 Vue 3 中移除。v-slot 只能写在 <template> 或组件标签上，这是最常见的报错原因；列表、表格、布局组件几乎都靠作用域插槽实现“数据由子组件提供、样式由父组件决定”。Vue 3 还支持动态插槽名 #[slotName]，用变量决定往哪个具名插槽里填内容。

三、路由：从整页刷新到页面级组件切换

用 <a href> 跳转会整页刷新，状态和请求全部重来。vue-router 把 URL 映射到组件：每条路由声明 path、name、component，页面用 <router-view> 作为渲染出口，用 <router-link> 生成链接。path: '/post/:id' 这样的动态段，选项式写法里通过 this.$route.params.id 读取，组合式写法里用 useRoute().params.id。query 会留在地址栏，而未在 path 中声明的 params 刷新后就丢了，这是新手最常踩的坑。

页面多了要做路由级懒加载：component: () => import('@/views/PostDetail.vue') 让 Vite 把每个页面拆成独立 chunk（@ 指向 src，官方脚手架已在 vite.config.js 里配好这个别名）。权限校验放在全局前置守卫 router.beforeEach 里：vue-router 4 的守卫可以直接返回值表达结果，return false 中断导航、return '/login' 重定向；第三个参数 next 的老写法仍然兼容，但不再推荐，容易漏写导致导航挂起。注意版本对应：Vue 3 配 vue-router 4，用 createRouter + createWebHistory；Vue 2 配 vue-router 3，用 new VueRouter 并调用 Vue.use(VueRouter)。404 通配也从 '*' 改成了 '/:pathMatch(.*)*'。

import { createRouter, createWebHistory } from 'vue-router'

const router = createRouter({
  // Vue 3 用 createWebHistory 取代 Vue 2 的 mode: 'history'
  history: createWebHistory(import.meta.env.BASE_URL),
  routes: [
    { path: '/post/:id', component: () => import('@/views/PostDetail.vue') },
    // 未匹配的路径统一进 404
    { path: '/:pathMatch(.*)*', component: () => import('@/views/NotFound.vue') }
  ]
})

router.beforeEach((to) => {
  if (!store.state.token && to.path !== '/login') return '/login'
})

export default router

版本提示：下面是 Vue 2 + vue-router 3 的等价写法，迁移时按上面的形式改写即可。

import Vue from 'vue'; import VueRouter from 'vue-router'
Vue.use(VueRouter)
const router = new VueRouter({
  mode: 'history',   // vue-router 4 改为 createWebHistory()
  routes: [
    { path: '/post/:id', component: () => import('@/views/PostDetail.vue') },
    { path: '*', component: () => import('@/views/NotFound.vue') } // v4 用 /:pathMatch(.*)*
  ]
})
router.beforeEach((to, from, next) =>
  store.state.token || to.path === '/login' ? next() : next('/login'))
export default router

四、请求层与状态管理

在组件里直接写 axios.get 会让域名散落各处、token 要手动附加、错误处理重复三遍。工程化的做法是用 axios.create({ baseURL, timeout }) 建一个实例，在请求拦截器里统一加 token，在响应拦截器里剥离数据层并处理 401。baseURL 从环境变量读取：Vite 项目里只有以 VITE_ 开头的变量会注入到客户端，读取方式是 import.meta.env.VITE_API_BASE_URL，切换环境只改对应的 .env 文件。axios 基于 Promise 封装 XMLHttpRequest，支持并发请求、自动转换 JSON，也能用 AbortController 的 signal 取消请求或设置超时。

真正跨组件的共享状态（登录用户、购物车、主题）要抽到 store。Vue 3 官方推荐 Pinia：state 存数据、getters 派生、actions 负责同步或异步修改，没有 mutations 这一层，对 TypeScript 与组合式 API 都更友好，Pinia 同样可以用于 Vue 2.7 的项目。下面是一个典型的用户 store 与 axios 封装：

import { defineStore } from 'pinia'
import request from '@/utils/request'

export const useUserStore = defineStore('user', {
  state: () => ({ token: '', name: '' }),
  getters: {
    isLogin: (state) => !!state.token
  },
  actions: {
    async login(form) {
      const data = await request.post('/login', form)
      this.token = data.token
      this.name = data.name
    },
    logout() {
      this.token = ''
    }
  }
})
import axios from 'axios'

const service = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL,
  timeout: 10000
})

service.interceptors.request.use((cfg) => {
  if (store.state.token) cfg.headers.Authorization = 'Bearer ' + store.state.token
  return cfg
})
service.interceptors.response.use(
  (res) => res.data,
  (err) => {
    if (err.response && err.response.status === 401) router.push('/login')
    return Promise.reject(err)
  }
)

export default service

版本提示：Vue 2 时代的官方状态库是 Vuex。它的模型包含四个部分：state 存数据、getters 派生、mutations 同步修改、actions 处理异步再提交 mutation。模块加上 namespaced: true 后互不干扰。官方文档也提醒过，应用不大时引入 Vuex 只会增加样板代码，Vue 2.6+ 用 Vue.observable 就能搭一个极简共享 store。新项目不必再选 Vuex，直接上 Pinia。环境变量同理：Vue CLI（webpack）把 .env 里的 VUE_APP_* 暴露为 process.env.VUE_APP_BASE_URL，Vite 换成 VITE_* 与 import.meta.env。另外 Vuex 4 仍可与 Vue 3 搭配使用，只是官方默认推荐 Pinia。

这里顺便纠正两处常见的错误说法。其一，fetch 的响应体必须写成 await response.json()，因为 json() 返回 Promise。fetch 只在网络错误时 reject，遇到 400/500 仍算成功，需要自己判断 response.ok；它默认也不带 cookie，要显式写 credentials: 'include'。“fetch 不支持取消和超时”的说法也已过时，现在可以用 AbortController 配合 signal。其二，fetch 属于 WHATWG Fetch 标准而非 ES6 规范的一部分；axios 也不能“自动防 CSRF”，它只是支持按配置携带 XSRF-TOKEN（xsrfCookieName / xsrfHeaderName），仍需服务端校验。

五、工程化与常见坑

项目走到这一步就需要构建工具。Vue 3 的标准组合是 Vite：npm create vue@latest 生成官方脚手架（可选 TypeScript、Router、Pinia）。开发时基于原生 ESM 按需编译，热更新几乎是即时的。生产构建同样由 Vite 打包，Node 18 及以上即可满足要求。.vue 单文件组件和 ES2020+ 语法都在这一步编译成浏览器可运行的文件。Element Plus 这类 Vue 3 组件库要按需引入，用 unplugin-vue-components / unplugin-auto-import 这两个 Vite 插件自动导入，否则首屏体积明显变大。生产构建的部署路径由 vite.config.js 里的 base 决定，接口地址用 .env.production 中的 VITE_* 变量区分。

几个高频坑：重复写两个 class 属性（如 class="playing" :class="{playing: isPlaying}"）时，浏览器只认第一个，动态类会失效，应写成 :class="['playing', { playing: isPlaying }]"。v-show 与行内 style="display: none" 同时使用会互相打架；v-for 必须绑定稳定的 :key，不要用数组下标；v-if 与 v-for 不要写在同一个元素上（Vue 3 中 v-if 优先级更高，详见上一章）。另外，公开测试接口（如 autumnfish.cn）随时可能下线，练手可以，真实项目必须换成自己的后端。

版本提示：Vue 2 时代的官方脚手架是 Vue CLI，底层是 webpack，配置文件为 vue.config.js，部署路径用 publicPath 设置；配套组件库是 Element UI，按需引入靠 babel-plugin-component。这套工具链仍能运行，但 Vue CLI 已进入维护模式，官方推荐新项目用 Vite 起步；Element UI 对应 Vue 3 的版本是 Element Plus。选项式 API 在 Vue 3 中依然完整可用，上面用到的 <script setup> 只是更主流的写法，两者可以混用。

小结：props 与事件划清组件边界，插槽把结构复用出去，路由让 URL 驱动页面，Pinia 与 axios 封装收拢共享状态和网络请求，这四块正是组件化之后的主干。配套的 <script setup>、defineProps / defineEmits 只是把选项式写法换成组合式写法，思路完全一致。下一步建议动手把一个多页面小项目从零配置到能打包上线。
