方法与面向对象基础

Posted on 2026-09-19，9 min read

上一章我们把数据装进了数组，可代码的复用还停留在"复制粘贴"阶段。方法解决"同一段逻辑写很多遍"的问题，类和对象解决"一堆零散数据该不该绑在一起"的问题——这两件事合起来，才是 Java 面向对象的地基。本章从方法的定义与调用讲起，说清方法重载的判定规则、参数传递到底是值还是引用，再落到类与对象、private 封装、构造方法与 this，最后讲清 static 什么时候该用、什么时候是坑。适合已经会写 for、if 与数组的初学者。

方法：给一段逻辑起名字

方法就是完成特定功能的代码块。假设一个游戏程序里"发射炮弹"需要 100 行代码，每次发射都重写一遍，程序会又臃肿又难改；把这 100 行提取出来放进一对 {} 里并起个名字，之后按名字调用即可。这正是方法存在的理由。

修饰符 返回值类型 方法名(参数类型 参数名1, 参数类型 参数名2) {
    方法体;
    return 返回值;
}

写一个方法之前，先做"两个明确"：返回值类型（结果是什么类型，没有结果就写 void）、参数列表（需要几个参数、分别是什么类型）。这两点定下来，方法体只是把逻辑填进去。下面求两个整数的和：

public class MethodDemo {
    // 两个明确：返回值类型 int，参数列表 (int a, int b)
    public static int sum(int a, int b) {
        return a + b;
    }

    public static void main(String[] args) {
        // 赋值调用：推荐方式，结果还能继续参与运算
        int s = sum(10, 20);
        s += 100;
        System.out.println("s:" + s);      // s:130

        // 输出调用：能用，但结果拿不到手上
        System.out.println(sum(1, 2));     // 3

        // 单独调用：有返回值却不接收，等于白算
        sum(1, 2);
    }
}

有返回值的方法每次调用都会在栈上开辟一个栈帧，参数在栈帧里各有一份；执行到 return 时方法立刻结束、栈帧弹出，返回值交回调用处，程序接着执行下一行。方法里第一个 return 之后的语句永远不会执行——这是编译器就会报"unreachable statement"的错误。

void 表示"没有返回值"，这类方法只能单独调用，写成 int x = printHello(); 编译不通过。方法体里可以写 return; 提前结束，但后面不能跟值。要让方法影响外部世界，void 方法通常靠打印结果、修改传入对象的属性来产生效果。

注意：方法不能嵌套定义，必须在类体中、其他方法之外；调用自己的这种"递归"可以，但要有终止条件，否则会抛 StackOverflowError。

方法重载：同名不同参

方法重载（overload）指在同一个类中允许存在多个同名方法，只要参数列表不同即可。判断标准只有两条：参数个数不同，或参数类型不同。返回值类型、参数名、修饰符都不参与判断。

public class OverloadDemo {
    public static int sum(int a, int b) {
        return a + b;
    }

    // 参数个数不同
    public static int sum(int a, int b, int c) {
        return a + b + c;
    }

    public static double sum(double a, double b) {
        return a + b;
    }

    // 合法重载：返回值类型不同，但参数列表也不同
    public static String sum(String a, String b) {
        return a + b;
    }

    public static void main(String[] args) {
        System.out.println(sum(1, 2));            // 3，调 int 版本
        System.out.println(sum(1, 2, 3));         // 6
        System.out.println(sum(1.5, 2.5));        // 4.0，调 double 版本
        System.out.println(sum("a", "b"));        // ab
    }
}

虚拟机在调用时靠参数列表来区分同名方法，这个过程叫"重载决议"。它发生在编译期：编译器先按参数个数筛选，再按类型匹配；没有完全匹配时会尝试自动类型提升（int → long → double）。如果两个版本只能靠返回值区分，编译器会直接判定重复定义：

// 编译错误：方法签名只看名字 + 参数列表，返回值不算
public static int get() { return 1; }
public static double get() { return 1.0; }   // 报错：已在类中定义 get()

所以"重载可以改变返回值类型"这句话的准确说法是：重载与返回值类型无关，你可以让重载方法的返回值不同，但前提是参数列表本身已经不同。

参数传递：Java 只有值传递

这是初学者最容易被绕晕的一点，先给结论：Java 中参数传递一律是值传递，实参的值被复制一份给形参。区别只在于"被复制的东西"是什么。

基本类型的实参，复制的是数值本身。方法里怎么改形参，都不影响外面的变量：

public class ArgsDemo {
    public static void main(String[] args) {
        int a = 10;
        int b = 20;
        change(a, b);
        System.out.println("a:" + a + ", b:" + b);   // a:10, b:20
    }

    public static void change(int a, int b) {   // 形参：接收实际数据的变量
        System.out.println("a:" + a + ", b:" + b);   // a:10, b:20
        a = b;                                       // a = 20
        b = a + b;                                   // b = 40
        System.out.println("a:" + a + ", b:" + b);   // a:20, b:40
    }
}

引用类型的实参，复制的是对象的地址。副本和实参指向堆上同一个对象，所以通过形参修改对象内容，实参能看到变化；但如果让形参重新指向一个新对象，实参的指向不受影响：

public class ArgsDemo2 {
    public static void main(String[] args) {
        int[] arr = {1, 2, 3, 4, 5};
        change(arr);
        for (int x : arr) {
            System.out.print(x + " ");     // 1 4 3 8 5
        }
        System.out.println();

        reset(arr);
        System.out.println(arr[0]);        // 仍是 1，指向没被改
    }

    // 改内容：生效，因为访问的是同一个堆对象
    public static void change(int[] a) {
        for (int i = 0; i < a.length; i++) {
            if (a[i] % 2 == 0) {
                a[i] *= 2;
            }
        }
    }

    // 改指向：换成新数组，只改了副本，实参看不到
    public static void reset(int[] a) {
        a = new int[a.length];
    }
}
常见坑：很多资料说"引用类型是引用传递"，这不准确。判断方法很简单——只要方法里出现 形参 = new ...，外面一定看不到效果，因为被改的只是副本里的地址。

类与对象：封装、构造方法、this

类是对一类事物的描述（属性 + 行为），对象是它的具体个体。Student s = new Student(); 背后发生了几件事：JVM 遇到 new 先在堆中开辟空间，为成员变量分配空间并赋默认值；然后调用构造方法进栈执行；构造方法里先隐式完成"调用父类构造 → 成员变量显式初始化 → 执行构造代码块"三步，再执行自己写的代码；构造方法出栈后，对象才算创建完成，堆中的地址赋给变量 s。

public class Student {
    // 1. 封装：字段一律 private，外界不能直接改
    private String name;
    private int age;

    // 2. 无参构造：一旦手写了带参构造，系统就不再送你无参构造，建议永远手写一个
    public Student() {
    }

    // 3. 带参构造：this 解决"局部变量隐藏成员变量"的问题
    public Student(String name, int age) {
        this.name = name;
        this.age = age;
    }

    // 4. 对外只开放必要的访问方式
    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }

    public int getAge() {
        return age;
    }

    public void setAge(int age) {
        if (age < 0) {
            throw new IllegalArgumentException("年龄不能为负");
        }
        this.age = age;
    }

    public String describe() {
        return name + " 今年 " + age + " 岁";
    }
}

封装就是"隐藏实现细节，只提供公共的访问方式"。字段用 private 修饰后，只有本类内部能访问，外部必须走公有的 getXxx()/setXxx()。好处有三点：可以在 setAge 里加校验，把非法数据挡在门外；内部结构以后改动（比如把 age 换成出生日期），只要方法签名不变，调用方无需修改；代码的复用性和安全性都更高。

this 代表当前对象的引用——哪个对象调用方法，方法里的 this 就指向那个对象。它最常用来区分同名的成员变量和局部变量（this.age = age）；在构造方法里也可以写 this(...) 调用本类的其他构造方法，但必须是构造方法中的第一条语句。

public class StudentDemo {
    public static void main(String[] args) {
        // 方式一：无参构造 + setter
        Student s1 = new Student();
        s1.setName("林青霞");
        s1.setAge(27);
        System.out.println(s1.describe());     // 林青霞 今年 27 岁

        // 方式二：带参构造一步到位
        Student s2 = new Student("刘意", 30);
        System.out.println(s2.describe());     // 刘意 今年 30 岁

        // 匿名对象：只调用一次，不需要变量名，也可以直接当实参传
        System.out.println(new Student("匿名", 20).describe());
        printStudent(new Student("传参", 21));
    }

    public static void printStudent(Student s) {
        System.out.println(s.describe());
    }
}

关于构造方法，还有三个必须记住的规则。第一，方法名与类名相同，且没有返回值类型，连 void 都不能写；写了 void Student() 就变成普通方法，不再具备初始化能力。第二，如果没写任何构造方法，系统提供一个默认无参构造；一旦写了带参构造，默认的就不再提供，此时想用无参构造必须自己补上。第三，构造方法可以重载，但不能被继承，子类通过 super(...) 调用父类构造。

static：属于类，不属于对象

被 static 修饰的成员属于类，而不是某个对象。它随类的加载而加载，优先于对象存在，并且被该类的所有对象共享——这也是判断"该不该加 static"的依据：如果一个数据是全体对象共用的（比如创建过的学生总数），就用静态变量；如果每个对象各有一份（比如姓名、年龄），就用实例变量。

public class Counter {
    private static int count = 0;   // 静态变量：所有对象共享一份
    private String tag;             // 实例变量：每个对象一份

    public Counter(String tag) {
        this.tag = tag;
        count++;                    // 静态变量可以直接访问
    }

    public static int getCount() {  // 静态方法：没有 this
        return count;
    }

    public String getTag() {
        return tag;
    }

    public static void main(String[] args) {
        new Counter("a");
        new Counter("b");
        System.out.println(Counter.getCount());   // 2，推荐用类名调用
        System.out.println(new Counter("c").getTag());
        System.out.println(Counter.getCount());   // 3
    }
}
对比项静态变量（类变量）实例变量（成员变量）
所属类对象
内存位置方法区的静态区堆中的对象里
生命周期随类的加载而存在，随类的消失而消失随对象的创建而存在，随对象的消失而消失
调用方式类名调用，也可用对象名（不推荐）只能通过对象名调用
共享性被所有对象共享每个对象各一份

静态成员有两条硬性限制。第一，静态方法中没有 this，因此不能直接访问实例变量和实例方法——它们必须先有对象才能存在；第二，静态只能直接访问静态，而实例方法可以随意访问静态成员。反过来，非静态成员访问静态成员是允许的。

顺带回答一个常见疑问：main 方法为什么是静态的？因为它要作为程序入口，由 JVM 直接调用，此时还不能保证有任何对象存在，所以只能用 public static void main(String[] args)。String[] args 用于接收命令行参数，比如 java MainDemo hello world 时 args[0] 就是 "hello"。

常见坑与小结

把这一章最容易出错的地方集中列一下：

  • 重载看参数列表，重写看继承关系。同一个类里方法名相同、参数列表不同是重载；子类里出现与父类"方法签名完全相同"的方法是重写。二者只差一个字，含义完全不同。重载与返回值类型无关，重写要求返回值兼容（协变返回类型）。
  • 别用返回值区分重载。只改返回值类型而参数列表相同，编译直接报错。
  • 引用类型参数不是引用传递。方法内 形参 = new ... 对外界无效。
  • 构造方法没有返回值类型。写了 void 就不再是构造方法；手写了带参构造，记得补一个无参构造。
  • 静态方法里不能用 this，也不能直接访问实例成员。编译器会在 static 上下文里直接拒绝。

本章的主线其实只有一句话：方法负责复用逻辑，类负责把数据和行为绑在一起，而 private、构造方法、this、static 都是为这两件事服务的工具。弄懂"栈帧里有什么"和"堆里有什么"，参数传递与 static 的疑惑基本都会自动消失。下一章我们会在这个基础上继续往前走，看类与类之间如何通过继承复用代码。
