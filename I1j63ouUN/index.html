Spring Boot 自带 Buff 工具类

Posted on 2022-01-23，11 min read

Spring 框架自带了一大批工具类，绝大多数放在 org.springframework.util 与 org.springframework.beans 包下，跟着 Spring Boot 一起进入依赖，不需要再引第三方库。它们的特点是「空值安全」：方法大多接受 null 并返回一个可预期的结果，而不是直接抛 NullPointerException。下面按用途逐类整理，并在最后补充原文漏掉的 BeanUtils、ClassUtils、AnnotationUtils、StopWatch 以及使用中的易错点。文中 API 以 Spring Framework 5.3 / Spring Boot 2.x 为基准，若使用 Spring Boot 3（Spring Framework 6），请注意下文标注的废弃项。

断言

  1. 断言是一个逻辑判断，用于检查不应该发生的情况
  2. JDK 1.4 引入了 assert 关键字，需要通过 JVM 参数 -enableassertions（简写 -ea）开启，默认不生效，因此生产代码里很少用它做参数校验
  3. Spring 提供了 org.springframework.util.Assert 工具类，它是普通方法调用，永远生效，通常用于数据合法性检查
// 要求参数 object 必须为非空（Not Null），否则抛出异常，不予放行
// 参数 message 用于定制异常信息，只在失败时才参与拼接，不影响性能
public static void notNull(Object object, String message)
// 要求参数必须为空（Null），否则抛出异常，不予放行

public static void isNull(Object object, String message)

public static void isTrue(boolean expression, String message)
// 要求参数（List/Set）必须非空（Not Empty），否则抛出异常，不予放行

// 要求参数（Map）必须非空，否则抛出异常，不予放行

// 要求参数（Object[]）必须非空，否则抛出异常，不予放行

public static void hasLength(String text, String message)

public static void hasText(String text, String message)

import org.springframework.util.Assert;

public class UserService {

    public void register(String username, String password, Integer age) {
        // 失败时抛出 IllegalArgumentException: 用户名不能为空
        Assert.hasText(username, "用户名不能为空");
        Assert.hasText(password, "密码不能为空");
        // 失败时抛出 IllegalArgumentException: 年龄不能为负数
        Assert.isTrue(age != null && age >= 0, "年龄不能为负数");
        // 类型断言：失败时抛出 IllegalArgumentException
        Assert.isInstanceOf(CharSequence.class, username, "用户名必须是字符串");
    }

    public void checkState(boolean initialized) {
        // state() 失败时抛出的是 IllegalStateException，语义是「对象状态不对」
        Assert.state(initialized, "服务尚未初始化");
    }
}
  1. 易错点：Assert 抛出的是 IllegalArgumentException，不是 JDK 的 AssertionError，也不是 Spring 自定义异常。Assert.state() 是唯一的例外，它抛 IllegalStateException。因此如果全局异常处理器按 IllegalArgumentException 映射成 400，state() 的失败会被漏掉，需要单独处理。
  2. 易错点：不要用 Assert.notNull 代替业务校验。它只做非空判断，无法表达「长度在 1~20 之间」这类规则；后者更适合 Bean Validation（@NotBlank、@Size）配合 @Valid。建议只在「调用方违反契约」这类不该发生的情况使用 Assert。
  3. 注意 hasLength(String) 与 hasText(String) 的区别：" "（三个空格）对 hasLength 是通过，对 hasText 是不通过。
  4. 失败信息参数在 Spring 5.x 只有 String 重载；Spring 6 增加了 Supplier<String> 重载，可以延迟拼接消息（如 Assert.notNull(obj, () -> "user " + id + " not found")）。

import org.springframework.util.StringUtils;

public class TextChecker {

    public static void main(String[] args) {
        String blank = "   ";

        // 易错点：isEmpty 只看长度，全空白符的字符串「不是空」
        System.out.println(StringUtils.isEmpty(null));    // true
        System.out.println(StringUtils.isEmpty(""));      // true
        System.out.println(StringUtils.isEmpty(blank));   // false

        // 易错点：hasLength 与 hasText 的边界不同
        System.out.println(StringUtils.hasLength(blank)); // true
        System.out.println(StringUtils.hasText(blank));   // false

        // 最常见的误用：把 isEmpty 当成「不为空」来用
        // if (!StringUtils.isEmpty(name)) { ... } 语义正确但已过时
        // 推荐写法（Spring 5.3 起）：
        if (StringUtils.hasText(blank)) {
            System.out.println("有内容");
        } else {
            System.out.println("没有实际内容");
        }
    }
}

import java.util.ArrayList;
import java.util.Arrays;
import java.util.HashMap;
import java.util.List;
import java.util.Map;
import org.springframework.util.CollectionUtils;

public class CollectionDemo {

    public static void main(String[] args) {
        // 易错点：null 和空集合都会返回 true，两者不做区分
        System.out.println(CollectionUtils.isEmpty(null));            // true
        System.out.println(CollectionUtils.isEmpty(new ArrayList<>())); // true

        List<String> list = new ArrayList<>(Arrays.asList("a", "b", "c"));
        System.out.println(CollectionUtils.isEmpty(list));             // false
        System.out.println(CollectionUtils.lastElement(list));         // c
        System.out.println(CollectionUtils.hasUniqueObject(list));     // true

        // 易错点：Map 是单独的重载，不要传成 Collection
        Map<String, String> map = new HashMap<>();
        System.out.println(CollectionUtils.isEmpty(map));              // true
        System.out.println(CollectionUtils.containsAny(list, Arrays.asList("z", "b"))); // true
    }
}
  1. 易错点：isEmpty 把 null 与「空集合」视为同一种情况。如果调用方需要区分「没有传」和「传了空集合」，必须自己额外判断 collection == null。
  2. 易错点：lastElement(Set<T>) 依赖迭代顺序。HashSet 的迭代顺序本身不保证，「最后一个元素」没有业务含义，只适合调试输出；需要顺序时请用 List 或 LinkedHashSet。
  3. containsInstance 与 contains 都基于 equals，且都不接受 null 元素集合的语义保证，判断前请先判空。

import java.io.File;
import java.io.IOException;
import org.springframework.util.FileCopyUtils;

public class FileCopyDemo {

    public static void main(String[] args) throws IOException {
        File src = new File("/tmp/src.txt");
        File dest = new File("/tmp/dest.txt");

        // 文件到文件，返回实际拷贝的字节数
        int bytes = FileCopyUtils.copy(src, dest);
        System.out.println("copied bytes = " + bytes);
    }
}
  1. 易错点：copy(File, File) 不是「合并」，而是覆盖写。目标文件已存在时内容会被整体替换，需要追加请自行用 FileOutputStream(file, true)。

import java.io.BufferedReader;
import java.io.File;
import java.io.InputStreamReader;
import java.nio.charset.StandardCharsets;
import org.springframework.core.io.ClassPathResource;
import org.springframework.util.ResourceUtils;

public class ResourceReadDemo {

    public static void main(String[] args) throws Exception {
        // 推荐写法：用 Resource 抽象，打成 jar 包后依然能读到
        ClassPathResource resource = new ClassPathResource("application.yml");
        try (BufferedReader reader = new BufferedReader(
                new InputStreamReader(resource.getInputStream(), StandardCharsets.UTF_8))) {
            String line;
            while ((line = reader.readLine()) != null) {
                System.out.println(line);
            }
        }

        // 仅适用于「确定的物理文件」，例如本地调试、外置配置目录
        File file = ResourceUtils.getFile("classpath:application.yml");
        System.out.println(file.getAbsolutePath());
    }
}
  1. 易错点：ResourceUtils.getFile("classpath:xxx") 在 jar / war 包内会抛 FileNotFoundException。因为打包后资源位于 jar 内，没有对应的文件系统路径。生产代码请统一使用 ClassPathResource#getInputStream() 或 ResourceLoader 注入 Resource。
  2. getInputStream() 每次调用都会重新打开资源，可以反复读取；而 InputStreamResource 包装的流只能读一次，重复调用会抛 IllegalStateException。

import java.io.ByteArrayInputStream;
import java.io.ByteArrayOutputStream;
import java.io.InputStream;
import java.nio.charset.StandardCharsets;
import org.springframework.util.StreamUtils;

public class StreamDemo {

    public static void main(String[] args) throws Exception {
        InputStream in = new ByteArrayInputStream("hello spring".getBytes(StandardCharsets.UTF_8));
        ByteArrayOutputStream out = new ByteArrayOutputStream();

        // StreamUtils 不负责关闭流，需要自己管理生命周期
        int count = StreamUtils.copy(in, out);
        System.out.println("bytes = " + count);
        System.out.println(out.toString(StandardCharsets.UTF_8.name())); // hello spring
    }
}
  1. 易错点：FileCopyUtils 会关闭传入的流，StreamUtils 不会。两个类名字很像，但资源生命周期约定相反。把容器托管的流交给 FileCopyUtils，或者把需要复用的流交给 StreamUtils 后忘记关闭，都是常见故障来源。
  2. drain(InputStream) 的用途是「把请求体读干净再返回错误响应」，否则 HTTP 连接可能无法复用。

import java.lang.reflect.Field;
import org.springframework.util.ReflectionUtils;

public class ReflectionDemo {

    public static void main(String[] args) {
        Target target = new Target();
        // 相当于 target.setSecret("value")，绕过了 private 修饰
        ReflectionUtils.doWithFields(Target.class, field -> {
            if ("secret".equals(field.getName())) {
                ReflectionUtils.makeAccessible(field);
                ReflectionUtils.setField(field, target, "value");
            }
        });

        Field field = ReflectionUtils.findField(Target.class, "secret");
        System.out.println(ReflectionUtils.getField(field, target)); // value
    }

    static class Target {
        private String secret;
    }
}
  1. 易错点：ReflectionUtils.findField 返回 null 表示没找到，它不会抛异常。很多示例直接拿返回值调用 getField，字段重命名后就变成 NullPointerException，需要显式判空。
  2. 通过反射读写 private 字段在 JDK 9+ 模块化环境下可能被拒绝（InaccessibleObjectException），Spring 自身的 BeanUtils 也因此改用属性描述符而非直接反射字段。

AopContext

  1. 获取当前对象的代理对象

import org.springframework.aop.framework.AopContext;

public class OrderService {

    public void createOrder() {
        // 同一个 Bean 内部直接调用 this.pay() 不会经过代理，事务/缓存注解会失效
        // 通过 currentProxy() 拿到代理对象再调用，才能让 AOP 生效
        ((OrderService) AopContext.currentProxy()).pay();
    }

    public void pay() {
        // 真实的支付逻辑，带事务注解
    }
}
  1. 易错点：AopContext.currentProxy() 默认不可用。必须配置 @EnableAspectJAutoProxy(exposeProxy = true)，否则抛 IllegalStateException。而且它依赖 ThreadLocal 存代理对象，异步线程中调用会失效。

import org.springframework.beans.BeanUtils;

public class BeanCopyDemo {

    public static void main(String[] args) {
        Address address = new Address("杭州");
        User source = new User();
        source.setName("张三");
        source.setAddress(address);

        User target = new User();
        // 参数顺序：源在前，目标在后
        BeanUtils.copyProperties(source, target);
        System.out.println(target.getName());                    // 张三

        // 陷阱：嵌套对象只复制了引用，两者指向同一个 Address 实例
        target.getAddress().setCity("上海");
        System.out.println(source.getAddress().getCity());        // 上海，源对象被「隔空篡改」
        System.out.println(source.getAddress() == target.getAddress()); // true
    }

    static class User {
        private String name;
        private Address address;

        public String getName() { return name; }
        public void setName(String name) { this.name = name; }
        public Address getAddress() { return address; }
        public void setAddress(Address address) { this.address = address; }
    }

    static class Address {
        private String city;

        public Address(String city) { this.city = city; }
        public String getCity() { return city; }
        public void setCity(String city) { this.city = city; }
    }
}
  1. 易错点：参数顺序。BeanUtils.copyProperties 在 Spring 里是 (源, 目标)，在 Apache Commons BeanUtils 里是 (目标, 源)，两者顺序完全相反。写反后通常不会报错，只是目标对象什么都没拷到；如果两个类结构相似且都实现了同名属性，甚至会「反向覆盖」，把目标已有的值冲掉。建议统一使用 Spring 版本，并在单元测试里断言关键字段。
  2. 易错点：浅拷贝。copyProperties 对每个属性调用 getter/setter，值类型（String、int、包装类、时间等）是值拷贝，引用类型（集合、数组、自定义对象）只复制引用。需要深度拷贝时，要么手写递归赋值，要么用序列化（如 Jackson 的 objectMapper.convertValue）走一遍 JSON。示意图如下。
import org.springframework.beans.BeanUtils;

public class ShallowCopyTest {

    public static void main(String[] args) {
        // 易错点：属性名相同但类型不同时，Spring 会直接抛异常并中断拷贝
        // 典型场景：源里是 String createTime，目标里是 Date createTime
        // 抛出的异常是 FatalBeanException，cause 为 TypeMismatchException
        SourceBean source = new SourceBean();
        source.setPrice("12.5");     // String
        TargetBean target = new TargetBean(); // price 为 BigDecimal
        try {
            BeanUtils.copyProperties(source, target);
        } catch (org.springframework.beans.FatalBeanException e) {
            System.out.println("拷贝失败：" + e.getMessage());
        }

        // 易错点：源属性为 null 时同样会写目标，可能把已有值覆盖成 null
        // 需要保留目标原值时，用忽略列表或先判断再赋值
        BeanUtils.copyProperties(source, target, "price");
    }

    static class SourceBean {
        private String price;
        public String getPrice() { return price; }
        public void setPrice(String price) { this.price = price; }
    }

    static class TargetBean {
        private java.math.BigDecimal price;
        public java.math.BigDecimal getPrice() { return price; }
        public void setPrice(java.math.BigDecimal price) { this.price = price; }
    }
}

  1. 注意：Spring 的 copyProperties 会跳过 class 属性，也会跳过只读（没有 setter）的属性，不会报错。反过来，如果源对象的某个 getter 抛异常，拷贝会以 FatalBeanException 中止。

import java.lang.annotation.ElementType;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;
import java.lang.annotation.Target;
import org.springframework.core.annotation.AnnotationUtils;

public class AnnotationDemo {

    @Target(ElementType.TYPE)
    @Retention(RetentionPolicy.RUNTIME)
    @interface Component {
        String value() default "";
    }

    @Component("orderService")
    static class OrderService {
    }

    public static void main(String[] args) {
        // 易错点：JDK 的 getAnnotation 只能拿到「直接标注」在当前元素上的注解
        // AnnotationUtils.findAnnotation 会沿着父类、接口和元注解继续查找
        Component component = AnnotationUtils.findAnnotation(OrderService.class, Component.class);
        System.out.println(AnnotationUtils.getValue(component)); // orderService
    }
}
  1. 易错点：JDK 反射的 clazz.getAnnotation() 不处理元注解与继承，而 Spring 的 findAnnotation 会。编写自定义组合注解（如 @MyTransactional 上标了 @Transactional）时，必须用 findAnnotation 才能读到。
  2. 已合并的注解（如 Spring 的 @Transactional、@RequestMapping）属性可能来自别名，直接读 annotation.value() 可能拿到默认值，稳妥做法是 AnnotationUtils.getAnnotationAttributes(annotation)。

import org.springframework.util.StopWatch;

public class StopWatchDemo {

    public static void main(String[] args) throws InterruptedException {
        StopWatch stopWatch = new StopWatch("order-flow");

        stopWatch.start("load-user");
        Thread.sleep(50);
        stopWatch.stop();

        stopWatch.start("query-stock");
        Thread.sleep(30);
        stopWatch.stop();

        // shortSummary 只输出每个任务的耗时，prettyPrint 会输出表格
        System.out.println(stopWatch.prettyPrint());
        System.out.println("总耗时(ms) = " + stopWatch.getTotalTimeMillis());
        System.out.println("任务数 = " + stopWatch.getTaskCount());
    }
}
  1. 易错点：StopWatch 不是线程安全的，也不能嵌套使用。它基于 System.nanoTime()，只适合单线程内的分段耗时统计。跨线程统计请用 Micrometer 的 Timer。
  2. start() 会在后台自动 stop() 上一个任务，忘记调用 stop() 不会报错，但最后一个任务的时间统计会不准。

易错点总结与选择建议

场景                                  推荐工具类
-----------------------------------------------------------------------------------
参数为空 / 条件不成立，快速失败          Assert（抛 IllegalArgumentException）
对象判空（含集合、数组、字符串）          ObjectUtils.isEmpty
字符串判空且排除全空白                   StringUtils.hasText
集合判空                                 CollectionUtils.isEmpty
类名、接口、基础类型转换                 ClassUtils
属性拷贝                                 BeanUtils.copyProperties（浅拷贝，注意参数顺序）
读取组合注解 / 继承注解                  AnnotationUtils.findAnnotation
分段耗时统计                             StopWatch（单线程）
文件与流读写                             StreamUtils（不关流） / FileCopyUtils（会关流）
类路径资源读取                           ClassPathResource，避免 ResourceUtils.getFile
  1. 判空优先级：StringUtils.isEmpty 在 Spring 5.3 已废弃，新代码统一用 ObjectUtils.isEmpty（对象、集合、数组、字符串通吃）或 StringUtils.hasText（需要排除空白符时）。
  2. 边界差异：hasLength 认「有长度」，hasText 认「有实际内容」，全空白字符串是二者唯一的分歧点，也是线上最常见的误判。
  3. 异常类型差异：Assert 系列抛 IllegalArgumentException，Assert.state 抛 IllegalStateException，BeanUtils.copyProperties 抛 FatalBeanException，ResourceUtils.getFile 在 jar 内抛 FileNotFoundException。全局异常处理要覆盖到这几类，否则会漏成 500。
  4. 参数顺序差异：Spring 的 BeanUtils.copyProperties(源, 目标) 与 Apache Commons 的 copyProperties(目标, 源) 相反，是复制类 bug 的高发区。
  5. 拷贝深度差异：BeanUtils.copyProperties 是浅拷贝，嵌套对象、集合仍是共享引用；需要隔离时必须显式深拷贝。
  6. 资源生命周期差异：FileCopyUtils 关闭传入流，StreamUtils 不关闭，Resource#getInputStream() 可重复打开。
  7. Spring 6 废弃项：ResourceUtils.getFile、ResourceUtils.isUrl、ReflectionUtils.makeAccessible、ReflectionUtils.shallowCopyFieldState、StringUtils 的若干 trim 方法均已标记废弃，升级 Spring Boot 3 前建议先替换。
