多线程与并发基础

Posted on 2026-09-19，5 min read

学到这里，你已经能写单线程的 Java 程序了。但真实的服务端程序几乎都是并发的：三个售票窗口同时卖同一批票，一个线程在等网络返回时另一个线程还在算数据。并发带来吞吐量的同时，也带来了本章要解决的核心问题——多个线程同时读写同一份数据时，结果为什么会错，以及怎么修。本章适合刚学完 Java 基础语法与集合、准备进入并发世界的读者。读完你应该能说清线程的创建方式与生命周期，会用 synchronized 保护共享数据，理解 volatile 的能与不能，并知道为什么生产环境更愿意用线程池而不是手动 new Thread()。

一、线程、进程与 Runnable：并发从哪来

进程是操作系统分配资源（内存、文件句柄）的独立单位，线程是 CPU 调度的最小单位。一个进程至少包含一个线程，线程之间共享进程的堆内存——这既是并发高效的原因，也是所有线程安全问题的根源。

创建线程有两种方式：继承 Thread 并重写 run()，或者实现 Runnable 接口、把任务对象交给 Thread 执行。推荐后者：任务与线程解耦，一个任务能被多个线程复用，而且 Java 是单继承，实现接口不占继承名额。

start() 与 run() 的区别必须记牢：start() 会让 JVM 真正创建一个新线程，再由新线程回调 run()；直接调用 run() 只是一次普通方法调用，代码仍跑在原线程（通常是 main）里，等于没有并发。

二、线程生命周期：六个状态，别再用 stop()

源笔记说“线程总共有 5 大状态”，那是把“就绪”和“运行”拆开算的老说法。以 Thread.State 为准，官方只有六种：NEW（已创建未启动）、RUNNABLE（可运行，“排队等 CPU”和“正在运行”都算它）、BLOCKED（等锁）、WAITING（无限期等待唤醒）、TIMED_WAITING（限时等待）、TERMINATED（已结束）。

几个常用方法要分清。sleep(ms) 让当前线程休眠，不释放已持有的锁；wait() 会释放锁并进入等待，它和 notify() 一样属于 Object 而非 Thread，必须在同步块内调用，并且应放在 while 循环里判断条件，以抵御虚假唤醒。join() 让当前线程等待目标线程结束。interrupt() 是协作式中断：它只设置中断标志，sleep/wait/join 收到后抛出 InterruptedException，捕获后不要默默吞掉，应恢复中断标志或结束任务。

至于源笔记推荐的 stop()：它早已废弃，因为它会强行终止线程并释放锁，被保护的数据可能停在“改了一半”的中间状态。正确做法是用 volatile 标志位或 interrupt() 让线程自己退出。

三、synchronized：把临界区串成串行

先看问题的根源。tickets-- 看着是一步，实际是“读值、减一、写回”三步，两个线程完全可能读到同一个值，同一张票就被卖了两次。解决办法是让操作共享数据的代码在任何时刻只被一个线程执行，这就是同步。

class TicketWindow implements Runnable {
    private int tickets = 100;
    private final Object lock = new Object();   // 锁必须在 run() 之外创建

    @Override
    public void run() {
        while (true) {
            synchronized (lock) {               // 锁类型任意，但所有线程必须共用同一个
                if (tickets <= 0) break;
                System.out.println(Thread.currentThread().getName()
                        + " 正在发售第 " + tickets-- + " 张票");
            }
        }
    }
}

三条结论：同步代码块的锁可以是任意对象，但多个线程共享的锁必须唯一，所以锁对象不能写进 run()，否则每个线程各拿一把锁，同步形同虚设；synchronized 修饰实例方法时锁是 this，修饰静态方法时锁是 类名.class，两者互不相干；同步块只包操作共享数据的代码，范围越小越好。

源笔记用“锁对象标志位由 1 变 0”解释原理，那只是便于理解的比喻。JVM 真实实现是对象头 Mark Word 配合 monitor，字节码层面表现为 monitorenter / monitorexit，可重入性由锁计数器保证，异常路径上 JVM 会自动释放锁。另外，“JDK 1.2 之前的集合都线程安全、之后都不安全”也不准确：Vector、Hashtable 确实同步，而 1.2 引入的 ArrayList、HashMap 不是；必须用旧集合时可用 Collections.synchronizedList() 包装，但遍历时仍需自行加锁。

四、volatile：给可见性，不给原子性

Java 内存模型关注三件事：原子性（操作不可分割）、可见性（一个线程的修改何时对别的线程可见）、有序性（指令会不会被重排序）。volatile 保证可见性与有序性：写 volatile 变量会立即刷新到主内存，读取时绕过本地缓存取最新值，同时插入内存屏障禁止相关指令重排。

public class NoVisibility {
    private static volatile boolean ready;   // 去掉 volatile，读线程可能永远看不到 true
    private static int number;

    public static void main(String[] args) {
        new Thread(() -> {
            while (!ready) Thread.yield();
            System.out.println(number);      // 有 volatile 一定能读到 42，而不是 0
        }).start();
        number = 42;
        ready = true;
    }
}

但 volatile 不保证原子性：count++ 依然是“读-改-写”，加 volatile 也会丢更新，必须用 synchronized 包住或改用 AtomicInteger.incrementAndGet()。所以它适合“一个线程写、多个线程读”的状态标志量，经典用法是双重检查锁定的单例。源笔记里“赋值后多执行一条 load addl $0x0,(%esp)”是特定平台与编译器的实现细节，不同 CPU 和 JDK 版本并不相同，理解内存屏障的语义就够了（此细节存疑）。

五、从锁到线程池：工具怎么选

synchronized 上手最简单，异常时 JVM 自动释放锁，JDK 6 之后还有偏向锁、轻量级锁、锁消除、锁粗化等优化。ReentrantLock 的价值在于 synchronized 做不到的三件事：tryLock() 尝试获取、带超时的 tryLock(time, unit)、可被中断的 lockInterruptibly()，构造时还能选择公平锁（默认非公平）。日常优先用 synchronized，确实需要超时或中断语义时再换 Lock，并且 unlock() 必须写在 finally 里。

线程的创建与切换成本很高，给每个任务都 new Thread() 在压力下会把机器拖垮，因此生产代码用线程池：

ExecutorService pool = Executors.newFixedThreadPool(4);
for (int i = 1; i <= 8; i++) {
    final int id = i;
    pool.execute(() -> System.out.println(
            Thread.currentThread().getName() + " 执行任务 " + id));
}
pool.shutdown();   // 不再接收新任务，已提交的任务继续执行完

入门先记住两点：execute() 提交无返回值任务，submit() 返回 Future 可取结果；shutdown() 之后不再接新任务，但会把手上的活干完。还要留意 Executors 的工厂方法多用无界队列或超大线程数，队列积压就可能 OOM，真实项目更推荐直接 new ThreadPoolExecutor(...)，把核心线程数、最大线程数、队列容量、拒绝策略显式写清楚。最后一个提醒：如果每个线程需要的是“自己的副本”而非共享数据，可用 ThreadLocal 隔离状态（Java 8 起推荐 ThreadLocal.withInitial(...)），用完记得 remove()，否则在线程池里会因线程复用而串数据。

小结：并发问题的本质是“共享可变状态 + 无同步的读改写”。本章你掌握了线程的两种创建方式与 start()/run() 的区别，理清了 Thread.State 的六种状态及 sleep、wait、join、interrupt 的语义，学会用同步代码块、同步方法、静态同步方法保护临界区，也明白了 volatile 只管可见性与有序性、不管原子性。把规则背下来意义不大，把上面的卖票程序跑一遍——先去掉 synchronized 看错误结果，再加回来——比读十篇文章都有效。
