9.10 复习速查手册

Posted on 2026-09-19，7 min read

走到「面试与知识补充」阶段的最后一章，本章要做一件和前面所有章节都不同的事：不再引入新知识，而是把最容易记混、最容易在面试里答错、最容易在代码里踩坑的点压缩成一份速查手册。这一章适合已经跟着系列走过基础、集合、并发、JVM、数据库与框架的读者，用来做面试前的最后一轮快速回顾，也适合把这一章当作索引，发现哪一块记不清就回到对应章节补课。下面按「基本类型与包装类 → String → equals 与 hashCode → 集合选型 → 复习路线」的顺序串讲，每一节都给出高频问法、标准答法和常见陷阱。

一、基本类型与包装类：缓存池和 == 的陷阱

八种基本类型里，只有 boolean 的大小没有明确规定。JVM 规范只说它有 true、false 两个值，一般用 1 bit 表达，具体实现相关。其余七种是 byte/8、short/16、int/32、float/32、long/64、double/64、char/16。面试常问的第一个陷阱是：基本类型没有「引用」语义，比较永远比值；包装类型是对象，用 == 比较的是引用地址，比大小必须用 equals()。

第二个陷阱是缓存池。自动装箱并不是每次 new 一个对象，而是调用 Integer.valueOf(int)。它先看值是否落在缓存范围内：在范围内直接复用缓存数组里的对象，否则才 new。基本类型对应的缓存池是：boolean 的 true/false、全部 byte 值、short/int 的 -128~127、char 的 \u0000~\u007F。Integer 的上界可以通过 -XX:AutoBoxCacheMax=<size> 调整（源码读取的是系统属性 java.lang.Integer.IntegerCache.high，最终取 max(127, 设定值)，所以只能变大不能变小）。

Integer a = 127, b = 127;
Integer c = 128, d = 128;
Integer e = new Integer(127);   // Java 9 起已废弃，仅为演示

System.out.println(a == b);       // true  自动装箱走 valueOf()，命中缓存
System.out.println(c == d);       // false 超出 -128~127，两个不同对象
System.out.println(e == a);       // false new 一定新建对象，不走缓存
System.out.println(e.equals(a));  // true  equals 比的是值

顺带纠正一个流传很广的说法：boolean 在局部变量和操作数栈里确实按 int 处理，但 JVM 是支持 boolean[] 的，它用 byte 数组实现；「JVM 不支持 boolean 数组」是错的。实战建议也很简单：包装类型比较一律用 equals()，或者先拆箱成基本类型再比；能不用 new Integer(...) 就不用。

二、String：不可变性、字符串常量池与拼接

高频问法：「String 为什么设计成不可变？」标准答法是四点：可以安全缓存 hashCode，因此适合做 HashMap 的 key；字符串常量池需要不可变才能安全共享引用；作为参数传递时不可变保证安全，比如网络连接参数；天然线程安全。实现层面要注意版本差异：Java 8 中 String 内部是 private final char[]，Java 9 起改为 private final byte[] value 加一个 coder 标识编码（LATIN1 或 UTF16），这是为了节省内存——纯拉丁字符只占一半空间。

字符串常量池保存编译期确定的字面量，运行时也可以用 intern() 手动加入：如果池中已有 equals() 相等的字符串就返回池中引用，否则放入池中再返回。Java 7 之前常量池在永久代，Java 7 起被移到堆中，所以在大量字符串场景下不再那么容易触发永久代的 OutOfMemoryError。另一个经典问题是「new String("abc") 创建几个对象」：准确答案是——如果池中还没有 "abc"，先创建一个池中对象，再在堆中创建一个新对象，共两个；如果池中已经有了，只在堆中创建一个。

String s1 = "hello";
String s2 = "hel" + "lo";                    // 编译期常量折叠，仍指向常量池
String s3 = "hel" + new String("lo");        // 运行期拼接，堆中新对象
String s4 = "hel" + s3.length();             // 含变量，同样是运行期拼接

System.out.println(s1 == s2);                // true
System.out.println(s1 == s3);                // false
System.out.println(s1 == s3.intern());       // true 手动入池后拿到同一引用

StringBuilder sb = new StringBuilder();
for (int i = 0; i < 10; i++) {
    sb.append(i).append(',');
}
System.out.println(sb);                      // 循环拼接请显式用 StringBuilder

陷阱在于：循环里用 + 拼字符串，Java 8 会反复创建 StringBuilder 再 toString()，复杂度是平方级的；Java 9 起改成 invokedynamic 加 makeConcatWithConstants，每次拼接仍会产生新对象，只是开销更小。要多次拼接就用 StringBuilder（单线程）或 StringBuffer（方法加 synchronized，线程安全但更慢）。

三、equals 与 hashCode：必须同时重写

面试标准答案是一条契约：equals() 必须满足自反、对称、传递、一致性，且 x.equals(null) 必须返回 false。只要重写了 equals()，就必须重写 hashCode()，因为 HashMap、HashSet 先用 hashCode() 定位桶，再用 equals() 在桶内比较。只重写 equals() 的后果是：两个「相等」的对象算出不同的哈希值，落进不同的桶，于是 map.get(key) 返回 null、set.contains(obj) 返回 false——代码看起来完全合理，却查不到数据，这是最常见的隐蔽 bug。

import java.util.Objects;

public final class Point {
    private final int x;
    private final int y;

    public Point(int x, int y) {
        this.x = x;
        this.y = y;
    }

    @Override
    public boolean equals(Object o) {
        if (this == o) {
            return true;                       // 同一引用直接为真
        }
        if (!(o instanceof Point)) {
            return false;                      // 包含 o == null 的情况
        }
        Point other = (Point) o;
        return x == other.x && y == other.y;
    }

    @Override
    public int hashCode() {
        return Objects.hash(x, y);
    }
}

两个补充要点：一是用 Objects.equals() 和 Objects.hash() 可以少写判空和手写哈希公式；二是不要把「会变化的字段」放进 hashCode()，否则对象作为 HashMap 的 key 之后字段一变，桶位置就找不回来了。此外 hashCode() 只要求「equals 相等则哈希相等」，反向不成立——哈希冲突是正常的，不需要也不应该追求唯一。

四、集合选型与遍历：一页速查

List。ArrayList 底层是可变数组，按下标查询是 O(1)，中间增删要位移元素所以慢；LinkedList 是双向链表，增删只要改指针所以快，按下标查询要从头遍历所以慢，它同时实现了 Deque，可以当栈（push/pop/peek）或队列（offer/poll/peek）用。两者都不是线程安全的；Vector 是 JDK 1.0 就存在的遗留类，方法用 synchronized 修饰因而线程安全但性能差，新代码不应再用，需要并发容器时选 CopyOnWriteArrayList 或用 Collections.synchronizedList() 包装。

Set。HashSet 底层是哈希表，存取无序且不允许重复，靠 hashCode() 与 equals() 共同保证唯一。TreeSet 底层是红黑树，天然有序，排序规则来自元素实现的 Comparable（自然排序）或构造时传入的 Comparator；LinkedHashSet 在哈希表之外再维护一条双向链表，因此保持插入顺序。

Map。HashMap 是数组加链表，Java 8 起在链表长度达到 8 且容量不小于 64 时把该桶转成红黑树，把最坏查找从 O(n) 降到 O(log n)。容量保持 2 的幂、默认负载因子 0.75，扩容时容量翻倍并重算桶位置。遍历时 entrySet() 比先 keySet() 再 get(key) 更快，因为后者多了一次查找。另外 HashMap 允许一个 null key 和多个 null value，而 ConcurrentHashMap 都不允许，这是两者最容易被追问的差别。

Map<String, Integer> counts = new HashMap<>();
counts.put("java", 1);
counts.merge("java", 1, Integer::sum);          // 计数推荐写法

for (Map.Entry<String, Integer> entry : counts.entrySet()) {
    System.out.println(entry.getKey() + "=" + entry.getValue());
}

List<String> list = new ArrayList<>(List.of("a", "b", "a"));
list.removeIf("a"::equals);                     // 遍历中删除的正确姿势
list.replaceAll(String::toUpperCase);

遍历中删除元素是高频错误：用 for-each 循环配合 list.remove(obj) 会抛 ConcurrentModificationException，正确做法是用 Iterator.remove() 或直接 removeIf()。同理，Arrays.asList() 返回的是固定长度的视图，add/remove 会抛 UnsupportedOperationException，需要可变的列表就包一层 new ArrayList<>(...)。

五、复习路线回顾：把系列串成一条线

这一阶段的复习不该是零散背题，而应沿着一条主线回看。第一步回到基础：基本类型与包装类、String、equals/hashCode、异常体系，这些是后面所有内容的公共语言。第二步是集合与泛型：先弄清「数组、链表、哈希表、红黑树」四种底层结构，那么 ArrayList、LinkedList、HashMap、TreeMap 的取舍就不用死记。第三步是并发：从线程状态、synchronized 与 Lock、volatile 与 happens-before、线程池参数与拒绝策略一路推到 ConcurrentHashMap 和 AQS。第四步是 JVM：内存区域、对象创建与逃逸分析、垃圾回收算法与收集器、类加载与双亲委派，最后落到调优工具与常见参数。第五步是数据库、网络与框架：索引与执行计划、事务隔离级别、TCP 三次握手四次挥手、Spring 的 IoC/AOP 与自动配置。最后回到本章这样的速查清单做查漏补缺。

建议的复习方法是：把每个知识点压缩成「一句话结论 + 一个最小示例 + 一个易错点」三件套；把刷题时做错的题按知识点归类而不是按题号记录；面试前只翻错题清单和本手册，不再通读全书。判断一个知识点是否真的掌握，标准是能否不看资料手写出可运行的最小示例。

小结：这一章把高频考点压缩成了一份可以反复回看的速查表——包装类比较与缓存池边界、String 的不可变与常量池、equals 与 hashCode 的成对重写、集合的底层结构与遍历安全、以及贯穿整个系列的复习路线。它不替代深入阅读，而是帮你定位薄弱点：任何一条读完觉得模糊的内容，都值得回到对应章节重新走一遍「为什么需要 → 怎么做 → 示例 → 常见坑」的完整链路。至此，本系列正文告一段落，愿你在面试和真实项目里都能把知识用对、用好。
