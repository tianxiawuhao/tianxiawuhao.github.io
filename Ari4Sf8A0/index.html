Spring Boot、MyBatis、Druid 单数据源整合

本文用一个 Spring Boot 2.4.5 的示例工程，按由浅入深的顺序给出三种整合形态：单数据源、多数据源（@Primary 固定路由）、主从动态路由。三者共用同一套 Druid 连接池参数，差别只在数据源与 SqlSessionFactory 的组织方式。阅读时建议把配置项和运行现象对照起来看，文末「监控台与连接池」「常见坑」两节集中解释了控制台 404、SQL 监控不生效、密码加密等高频问题。

MyBatis 配置

  • mapper-locations：XML 映射文件的位置。多模块工程建议写成 classpath*:mapper/**/*.xml，classpath*: 会扫描所有 jar 与输出目录，只写 classpath: 容易在打成 jar 后找不到映射文件。
  • type-aliases-package：实体类包路径，配置后 XML 中的 parameterType 与 resultType 可以直接写类名。别名不区分大小写，但同一别名对应两个类时会直接抛异常，包路径不要跨模块重叠。
  • map-underscore-to-camel-case：下划线列名自动映射到驼峰属性，city_name 对应 cityName；但这只在没有手写 resultMap 时生效，一旦使用 resultMap，映射完全由 resultMap 决定。
  • @MapperScan：卸载启动类上批量注册 Mapper 接口，等价于给每个接口加 @Mapper。多数据源场景必须通过 sqlSessionFactoryRef 指定由哪个 SqlSessionFactory 创建代理，否则所有 Mapper 都会落到主数据源上。
  • Mapper XML 的 namespace 必须与接口全限定名一致（如 com.example.datasources.dao.CityMapper），方法名与 id 一一对应，否则启动时报 Invalid bound statement (not found)。

监控台与连接池

监控台能显示多少人、连接池该配多大，取决于下面两类参数。连接池参数决定「有多少连接、活多久」；StatFilter 与 StatViewServlet 决定「能看到哪些数字」。

  • 容量类：initialSize 是启动时建立的物理连接数，minIdle 是保底空闲连接，maxActive 是并发上限，maxWait 是借不到连接时的最长等待时间（毫秒）。maxActive 不是越大越好——它必须小于数据库的 max_connections，否则只会把压力推给 MySQL。
  • 检测类：validationQuery 是探活 SQL（MySQL 用 SELECT 1），testWhileIdle 建议开启，它只在空闲超过 timeBetweenEvictionRunsMillis 时才真正执行探活；testOnBorrow 与 testOnReturn 保持 false，否则每次借还都要多一次往返。
  • 回收类：minEvictableIdleTimeMillis 定义一个连接最少能空闲多久，removeAbandoned 与 removeAbandonedTimeout 只在怀疑调用方忘记关闭连接时用作兜底——真正该做的是排查代码里漏掉的 close()。
  • PSCache：poolPreparedStatements 在 MySQL 上通常保持 false，Oracle 才建议打开并配合 maxPoolPreparedStatementPerConnectionSize；分库分表场景同样建议关闭。
  • 监控指标：池状态关注空闲连接数与活跃连接数，SQL 页面关注执行次数、错误次数与慢 SQL，执行时间则用于判断该调 SQL 还是调池子大小。活跃连接长期贴着 maxActive，说明池子偏小；空闲连接长期为 0 且等待时间上升，也是同样的信号。

PrimaryDataBaseConfig

主数据源类同时承担三件事：把 primary.datasource.druid.* 绑定到字段、创建 DruidDataSource、以及创建配套的事务管理器与 SqlSessionFactory。@Primary 让未显式指定名称的注入点默认拿到主数据源；如果启动报 required a single bean, but 2 were found，通常就是漏了这个注解。

/**
 * @Description: 主数据源配置类
 */
@Data
@Configuration
// 前缀为primary.datasource.druid的配置信息
@ConfigurationProperties(prefix = "primary.datasource.druid")
@MapperScan(basePackages = PrimaryDataBaseConfig.PACKAGE, sqlSessionFactoryRef = "primarySqlSessionFactory")
public class PrimaryDataBaseConfig {
 
    /**
     * dao层的包路径
     */
    static final String PACKAGE = "com.example.datasources.dao.primary";
 
    /**
     * mapper文件的相对路径
     */
    private static final String MAPPER_LOCATION = "classpath:mapper/primary/*.xml";
 
    private String filters;
    private String url;
    private String username;
    private String password;
    private String driverClassName;
    private int initialSize;
    private int minIdle;
    private int maxActive;
    private long maxWait;
    private long timeBetweenEvictionRunsMillis;
    private long minEvictableIdleTimeMillis;
    private String validationQuery;
    private boolean testWhileIdle;
    private boolean testOnBorrow;
    private boolean testOnReturn;
    private boolean poolPreparedStatements;
    private int maxPoolPreparedStatementPerConnectionSize;
 
    // 主数据源使用@Primary注解进行标识
    @Primary
    @Bean(name = "primaryDataSource")
    public DataSource primaryDataSource() throws SQLException {
        DruidDataSource druid = new DruidDataSource();
        // 监控统计拦截的filters
        druid.setFilters(filters);
 
        // 配置基本属性
        druid.setDriverClassName(driverClassName);
        druid.setUsername(username);
        druid.setPassword(password);
        druid.setUrl(url);
 
        //初始化时建立物理连接的个数
        druid.setInitialSize(initialSize);
        //最大连接池数量
        druid.setMaxActive(maxActive);
        //最小连接池数量
        druid.setMinIdle(minIdle);
        //获取连接时最大等待时间，单位毫秒。
        druid.setMaxWait(maxWait);
        //间隔多久进行一次检测，检测需要关闭的空闲连接
        druid.setTimeBetweenEvictionRunsMillis(timeBetweenEvictionRunsMillis);
        //一个连接在池中最小生存的时间
        druid.setMinEvictableIdleTimeMillis(minEvictableIdleTimeMillis);
        //用来检测连接是否有效的sql
        druid.setValidationQuery(validationQuery);
        //建议配置为true，不影响性能，并且保证安全性。
        druid.setTestWhileIdle(testWhileIdle);
        //申请连接时执行validationQuery检测连接是否有效
        druid.setTestOnBorrow(testOnBorrow);
        druid.setTestOnReturn(testOnReturn);
        //是否缓存preparedStatement，也就是PSCache，oracle设为true，mysql设为false。分库分表较多推荐设置为false
        druid.setPoolPreparedStatements(poolPreparedStatements);
        // 打开PSCache时，指定每个连接上PSCache的大小
        druid.setMaxPoolPreparedStatementPerConnectionSize(maxPoolPreparedStatementPerConnectionSize);
 
        return druid;
    }
 
    // 创建该数据源的事务管理
    @Primary
    @Bean(name = "primaryTransactionManager")
    public DataSourceTransactionManager primaryTransactionManager() throws SQLException {
        return new DataSourceTransactionManager(primaryDataSource());
    }
 
    // 创建Mybatis的连接会话工厂实例
    @Primary
    @Bean(name = "primarySqlSessionFactory")
    public SqlSessionFactory primarySqlSessionFactory(@Qualifier("primaryDataSource") DataSource primaryDataSource) throws Exception {
        final SqlSessionFactoryBean sessionFactory = new SqlSessionFactoryBean();
        sessionFactory.setDataSource(primaryDataSource);  // 设置数据源bean
        sessionFactory.setMapperLocations(new PathMatchingResourcePatternResolver()
                .getResources(PrimaryDataBaseConfig.MAPPER_LOCATION));  // 设置mapper文件路径
 
        return sessionFactory.getObject();
    }
}

BackDataBaseConfig

从数据源类不再标注 @Primary，其余结构与主数据源一致。两个数据源分别对应各自的 DataSourceTransactionManager，因此跨库写入不能依赖单个 @Transactional 保证一致性。

        druid.setValidationQuery(validationQuery);
        //建议配置为true，不影响性能，并且保证安全性。
        druid.setTestWhileIdle(testWhileIdle);
        //申请连接时执行validationQuery检测连接是否有效
        druid.setTestOnBorrow(testOnBorrow);
        druid.setTestOnReturn(testOnReturn);
        //是否缓存preparedStatement，也就是PSCache，oracle设为true，mysql设为false。分库分表较多推荐设置为false
        druid.setPoolPreparedStatements(poolPreparedStatements);
        // 打开PSCache时，指定每个连接上PSCache的大小
        druid.setMaxPoolPreparedStatementPerConnectionSize(maxPoolPreparedStatementPerConnectionSize);
 
        return druid;
    }
 
    @Bean(name = "backTransactionManager")
    public DataSourceTransactionManager backTransactionManager() throws SQLException {
        return new DataSourceTransactionManager(backDataSource());
    }
 
    @Bean(name = "backSqlSessionFactory")
    public SqlSessionFactory backSqlSessionFactory(@Qualifier("backDataSource") DataSource backDataSource) throws Exception {
        final SqlSessionFactoryBean sessionFactory = new SqlSessionFactoryBean();
        sessionFactory.setDataSource(backDataSource);
        sessionFactory.setMapperLocations(new PathMatchingResourcePatternResolver()
                .getResources(BackDataBaseConfig.MAPPER_LOCATION));
 
        return sessionFactory.getObject();
    }
}

/**
 * aop从dao层判断使用哪个数据库
 * @MasterDataSource标识使用主数据库
 * 不标识使用从数据库
 */
@Aspect
@Component
public class DatabaseAOP {
    @Pointcut(value = "execution(* com.example.datasources.dao..*.*(..))")
    public void pointCut() {
 
    }
 
    @Before("pointCut()")
    public void before(JoinPoint joinPoint) {
        MethodSignature methodSignature = (MethodSignature) joinPoint.getSignature();
        Method method = methodSignature.getMethod();
        boolean isExist = method.isAnnotationPresent(MasterDataSource.class);
        if (!isExist) {
            DbUtil.setDb(DbUtil.slave);
            return;
        }
        DbUtil.setDb(DbUtil.master);
    }
}

/**

public class DbUtil {
    public static String master="master";
    public static String slave="slave";
 
    // ThreadLocal 必须带泛型参数，否则取出的是 Object，需要强转且容易出错
    private static final ThreadLocal<String> threadLocal=new ThreadLocal<>();
 
 
    public static void setDb(String db){
        threadLocal.set(db);
    }
 
    public static String getDb(){
        return threadLocal.get();
    }
 
}

DynamicDataSource

/**
 * spring的jdbc提供了动态数据源的入口
 * 继承AbstractRoutingDataSource覆盖determineCurrentLookupKey()方法 返回当前使用数据库
 */
@Slf4j
public class DynamicDataSource extends AbstractRoutingDataSource {

    // 返回值作为 lookupKey 去 targetDataSources 中查找数据源；
    // 返回 null 时使用 defaultTargetDataSource（这里配的是 master）
    @Override
    protected Object determineCurrentLookupKey() {
        log.info("当前使用数据库：{}", DbUtil.getDb());
        return DbUtil.getDb();
    }
}

常见坑

  • 监控台 404：多数是 Servlet 没注册上——@Configuration 类不在组件扫描路径内，包路径不在启动类同级或子级即可导致；另外 Spring Boot 内嵌容器下访问的是 /druid/login.html 或 /druid/index.html，URL 写错也会 404。
  • SQL 监控不生效：filters 没配 stat 时连接池不采集任何 SQL；StatFilter 未启用时监控台里只会看到连接数，SQL 列表为空。想看到合并后的统计还需 connectionProperties: druid.stat.mergeSql=true;druid.stat.slowSqlMillis=500，慢 SQL 才有阈值。
  • filter 名拼写：WebStatFilter 的初始化参数键是 exclusions，本文早期代码写成 excliusions，拼错后静态资源不会被排除，监控数据会混入大量 JS、CSS 请求。
  • 过滤器日志依赖：filters: stat,wall,log4j2 中的 log4j2 需要 classpath 上有对应实现，缺失时启动阶段就会报错；不打印 SQL 日志时只保留 stat,wall 即可。
  • 密码加密：把 password 配成 config.decrypt=true 或密文后，必须同时在 filters 中加入 config，Druid 才会用 ConfigFilter 解密；只替换密文而忘了加 config，连接池会直接认证失败。生产环境更稳妥的做法是走配置中心或环境变量注入。
  • @ConfigurationProperties 前缀对不上：主从章节里 YAML 用的是 primary.datasource.druid，而 @ConfigurationProperties 绑定的是 master.datasource.druid，属性绑定不上时会静默退化成 Druid 默认参数，表现为「配置明明改了却不生效」。排查时可在启动日志中确认连接池参数。
  • 多数据源事务：每个数据源各自一个 DataSourceTransactionManager，跨库操作不受同一个 @Transactional 保护；需要强一致时应改用分布式事务或业务补偿。
  • 动态路由的时机：AbstractRoutingDataSource 在获取连接时决定数据源，因此 AOP 或注解必须在事务开启、连接获取之前完成设置；同时 ThreadLocal 建议在请求结束时清理，避免线程池复用导致数据源串用。
  • 版本过时项：Spring Boot 2.4.5、Druid 1.1.10、MyBatis-Plus 3.2.0 与 MySQL Connector 5.1.45 均已停更，新项目建议 Spring Boot 3.x（或 2.7.x）+ Druid 1.2.x + MyBatis-Plus 3.5.x + Connector 8.x，并同步把驱动类改为 com.mysql.cj.jdbc.Driver。
