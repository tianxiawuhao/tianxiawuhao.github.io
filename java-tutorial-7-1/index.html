7.1 Linux 基础与文件操作

Posted on 2026-09-19，6 min read

写完 Java 代码，最终总要部署到一台 Linux 服务器上，这时你会发现：程序不过是一堆文件——一个 jar、一份 application.yml、一个不断变大的日志目录、一个启动脚本。很多人第一次 SSH 登上生产机时最容易慌的三件事：看不懂 ls -l 那串 drwxr-xr-x、不知道该把东西放在哪个目录、明明文件是自己的却删不掉。本章围绕「目录结构 + 文件操作 + 权限 + 用户与组 + 软链接」这条主线，把服务器上最常打交道的文件系统基础一次讲透。适合已经会写 Java、但没系统用过 Linux 的开发者，命令都可以在测试机上直接敲。

一、先建立地图：Linux 的目录结构

与 Windows 的「C 盘、D 盘」不同，Linux 只有一棵以 / 为根的目录树，磁盘分区和外接存储都通过「挂载」挂到树的某个节点上。主流发行版遵循 FHS（Filesystem Hierarchy Standard）约定，所以记住下面几个位置，换发行版也不会迷路：

  • /etc：配置文件，如 /etc/passwd、/etc/group、网卡配置 /etc/sysconfig/network-scripts/ifcfg-eth0（目录名是复数的 network-scripts，很多讲义会写错成 network-script）；
  • /usr：系统级程序与库，/usr/local 常用来放自己安装的软件，如 JDK、Tomcat；
  • /var：运行中不断变化的数据，/var/log 是日志目录，排障第一站；
  • /opt：可选的第三方大型软件，很多团队把应用装在这里，如 /opt/myapp；
  • /tmp：临时目录，重启可能被清理，不要放持久数据；
  • /root 是 root 用户的家目录，/home/用户名 是普通用户的家目录。

注意 /（根目录）与 /root（root 的家目录）是两个完全不同的地方，这是新手最常见的混淆点。定位自己在哪用 pwd，切换目录用 cd：cd ~ 回家目录、cd / 去根目录、cd - 回上一次的目录、cd .. 上一级。

另外，Linux 不靠扩展名判断文件类型，后缀主要给人看，只有少数约定依赖它（如 Shell 脚本的 .sh、包管理器的 .rpm）。真实类型看 ls -l 输出的第一个字符：- 普通文件、d 目录、l 软链接、b 块设备、c 字符设备、s 套接字、p 命名管道；拿不准时用 file 文件名 让内核告诉你。

二、文件与目录的常用操作

日常操作可以归纳成「定位 → 查看 → 增删改查」。创建目录用 mkdir -p，它能一次建出多层父目录；空目录删除用 rmdir，目录里一旦有内容它就会拒绝执行，这正是它比 rm -r 安全的地方。查看文件内容按「文件多大」选工具：cat 适合几行的小文件，more / less 适合大文件分页（less 支持上下翻页与 /关键词 搜索，按 q 退出），head -n 50 看开头，tail -n 100 看结尾，而 tail -f app.log 会持续输出新增行——这是盯滚动日志最常用的命令。

mkdir -p /opt/myapp/{conf,logs}   # -p：父目录不存在时一并创建
touch app.log                     # 创建空文件或更新时间戳
ls -lh                            # 人类可读大小；ll 通常是 ls -l 的别名

cp -r conf conf.bak               # -r 递归复制目录，缺了它复制目录会报错
mv app.log /tmp/                  # 移动；目标在同目录时就是重命名
rm -rf /opt/myapp-bak             # 危险操作：先 pwd + ls 确认路径再回车

tail -n 100 -f /var/log/myapp/app.log    # 跟踪最后 100 行，Ctrl+C 退出
find /opt -name '*.jar' -mtime -7        # 近 7 天内修改过的 jar 包
grep -rn 'OutOfMemoryError' /var/log/myapp
ps -ef | grep java                       # | 是管道：把前一个命令的输出交给后一个处理

两个小坑提前记住：ping 127.0.0.1 > ip.log & 里的 > 是覆盖写入（追加要用 >>），行尾的 & 表示后台运行，否则命令会一直占住终端；> 覆盖很容易把已有日志写没，重定向到重要文件前先确认。还有，cp 和 rm 默认都不带确认，且 rm 没有回收站。

三、看懂权限：九个字符与 chmod

执行 ls -l 看到的每一行，开头那串字符就是权限。把它切成四段读：

$ ls -l
-rw-r--r-- 1 root root 302108 Nov 13 06:03 log2012.log
drwxr-xr-x 2 root root   4096 Nov 13 05:50 test4
lrwxrwxrwx 1 root root     11 Nov 22 06:58 linklog.log -> log2012.log

第一列第 1 个字符是类型；紧接的 9 个字符每 3 个一组，依次是属主（u）、属组（g）、其他用户（o）的权限，每组内部顺序固定为 r（读）、w（写）、x（执行），无权限用 - 占位。所以 -rw-r--r-- 表示：普通文件，属主可读写，同组和其他用户只能读。数字设定法按 4（r）+2（w）+1（x）累加：rwx=7、rw-=6、r-x=5、r--=4。于是 755 是最常见的可执行脚本权限，644 是普通文件，600 用于私钥这类只许自己看的文件。

对目录而言，r 是「能列出目录内文件名」，x 是「能进入目录、能访问目录内已知路径的文件」，w 是「能在目录内创建、删除、重命名条目」。因此目录至少要 r-x 才用得顺手：只有 r 时能看名字却进不去，只有 x 时进得去却列不出名字。很多人以为「文件写权限」决定能不能删文件，其实删除和重命名看的是所在目录的 w 权限；只有目录设了粘滞位（t，如 /tmp）时，才额外要求你是文件属主或 root。

chmod 755 app.sh              # 属主 rwx，属组 r-x，其他人 r-x
chmod a+x app.sh              # 字母法：u/g/o/a 指定对象，+ 增加权限
chmod ug+w,o-x app.sh         # 属主与属组加写权限，去掉其他人的执行权限
chmod u=x app.sh              # = 会先清空该组原有权限，结果 ---xrw-r--
chmod -R u+rwX /var/log/myapp # 递归；大写 X 只给目录和本来就有 x 的文件加执行位

chown -R appuser:appgroup /opt/myapp   # 同时改属主与属组；只改组用 chgrp

两个易错点值得单独点出。第一，字母法里 + 增加、- 删除、= 是「先清空该组权限再赋值」，所以 chmod u=x 的结果是属主只剩执行位，而不是「拥有读权限」，有资料在这句说明上写反了。第二，数字权限别相加出错：r-x 是 4+1=5，不是 7。此外，递归时用大写 X 比小写 x 安全，它只给目录和本来就有执行位的文件加 x，不会把一批普通文件误变成可执行文件。

四、用户、用户组与软链接

Linux 是多用户系统，每个文件都记录自己的属主与属组，权限判定顺序是：先看你是不是文件属主（u），再看你的主属组或附加组是否匹配（g），最后落到其他用户（o）。创建和管理的基本命令如下，其中 su - 的 - 表示同时切换环境变量，userdel -r 会连带删除家目录（确认要删再用）。

groupadd appgroup               # 建组
useradd -g appgroup appuser     # 建用户并指定主属组
passwd appuser                  # 设置密码，太简单的密码会被拒绝
id appuser                      # 查看 uid/gid 及所属组
su - appuser                    # 切换用户
userdel -r appuser              # 删除用户并连带家目录

cat /etc/passwd                 # 用户信息（密码位置是占位符 x）
cat /etc/group                  # 组信息；真实密码哈希在 /etc/shadow

ln -s /opt/myapp/releases/20240601 /opt/myapp/current   # 软链接：当前版本开关
ls -l /opt/myapp/current        # lrwxrwxrwx ... current -> releases/20240601
ln -sfn /opt/myapp/releases/20240520 /opt/myapp/current # 回滚；-n 避免链进目录内部

软链接是「指向另一个路径的快捷方式」，用 ln -s 创建；ln 不加 -s 建的是硬链接。两者区别要清楚：软链接是独立文件，可跨文件系统、可指向目录，源文件删掉后它变成「断链」；硬链接只是同一 inode 的另一个名字，不能跨文件系统、通常不能指向目录，删掉任何一个名字文件仍在。发布系统最爱的用法就是把带版本号的目录链成固定的 current 路径，回滚只需重建链接，瞬间完成。

回到开头那个困惑：文件 /opt/myapp/data/aaa 属于 appuser，但目录 data 属于 root、权限是 755，那么即使你是 aaa 的属主也无法删除或重命名它——因为操作的是目录条目，而你没有该目录的 w 权限。同理，「读得到文件却进不去目录」通常就是目录缺 x 权限。排查时沿路径一级级 ls -ld 检查，比盲目 chmod 777 高效得多。顺便说，CentOS 7 以后网卡命名变成 ifcfg-ens33 这类形式，重启网络用 systemctl restart network（CentOS 8 / Ubuntu 请用 nmcli 或 netplan）。

五、新手最容易踩的五个坑

  • 上来就 chmod -R 777。它确实能让报错消失，但等于对所有用户开放读写执行，是典型的提权隐患。正确顺序是：先 ls -l 看属主属组，分辨是「人不对」还是「权限位不对」，人不对用 chown，位不对再按最小必要改 chmod。
  • 在错误目录执行 rm -rf。删除前先 pwd 确认位置，再用 ls 看一眼匹配结果；生产环境宁可先 mv 到 /tmp 观察一天。
  • 权限看着对但脚本跑不起来。脚本需要执行位 x，且要用 ./run.sh 而不是 run.sh（当前目录默认不在 PATH 里）。若报 bad interpreter，多半是 Windows 的 CRLF 换行导致的，用 dos2unix 转换即可。
  • 把日志写进 /home 或根分区。日志暴涨会把分区写满，服务连日志都写不出来；日志放 /var/log 或独立数据盘，并配 logrotate 做切割。
  • 直接改 /etc 下的配置。改前先 cp nginx.conf nginx.conf.bak，再用 nginx -t 这类命令校验语法，确认无误再重启服务。

小结：Linux 只有一棵根目录树，/etc、/usr、/var、/opt 是最常打交道的四个位置；ls -l 第一列按「类型 + u/g/o 各三位」解读，数字权限由 4/2/1 相加而来；改权限用 chmod、改归属用 chown/chgrp，递归时优先用大写 X 并远离 777；文件操作牢记 rm 不可恢复、实时看日志用 tail -f；软链接适合做版本切换与发布回滚。最后记住这条判定原则：能不能删文件看目录的 w，能不能进目录看目录的 x；遇到 Permission denied 先按路径逐级核查，再决定是改归属还是改权限位。下一章我们把这套基础用到实处：把 Spring Boot 应用部署到 Linux，并交给 systemd 管理。
