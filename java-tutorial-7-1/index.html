Linux 基础与文件操作

Posted on 2026-09-19，5 min read

写完 Java 代码，最终总要部署到一台 Linux 服务器上。很多人第一次 SSH 登上生产机时最容易慌的三件事：看不懂 ls -l 那串 drwxr-xr-x、不知道该往哪个目录放东西、明明文件是自己的却删不掉。本章就围绕「目录结构 + 权限 + 常用文件操作 + 软链接 + 用户与组」这条主线，把服务器上最常打交道的文件系统基础讲透。适合已经会写 Java、但没系统用过 Linux 的开发者阅读；所有命令都可以在一台测试机上直接敲。

一、先认识 Linux 的目录结构

与 Windows 的「C 盘、D 盘」不同，Linux 只有一棵以 / 为根的目录树，所有磁盘分区、U 盘、网络存储都是通过「挂载」挂到树的某个节点上的。作为开发者，只需要先记住这几个位置：

  • /etc：配置文件，如 /etc/passwd、/etc/group、网卡配置 /etc/sysconfig/network-scripts/ifcfg-eth0；
  • /usr：系统级程序与库，/usr/local 常用来放自己编译安装的软件（如 JDK、Tomcat）；
  • /var：会不断增长的数据，/var/log 是日志目录，排障第一站；
  • /opt：可选的大型第三方软件，很多团队习惯把应用装在这里；
  • /tmp：临时文件，可能被系统定期清理，别放重要数据；
  • /root：root 用户的家目录；/home/用户名 是普通用户的家目录。

注意 /（根目录）和 /root（root 的家目录）是两个完全不同的地方，这是新手最常见的混淆点。定位自己在哪里用 pwd，切换目录用 cd：cd ~ 回家目录、cd / 去根目录、cd - 回上一次待过的目录、cd .. 上一级。

Linux 不靠扩展名判断文件类型，后缀只为人眼服务。「一切皆文件」是它的设计哲学：普通文件、目录、设备、套接字在文件系统里都是文件，类型由 ls -l 输出的第一个字符区分：- 普通文件、d 目录、l 符号链接、b 块设备、c 字符设备、s 套接字。

二、看懂文件权限：drwxr-xr-x 到底是什么

执行 ls -l 会看到类似下面的一行，它是理解 Linux 权限的入口：

$ ls -l
-rw-r--r-- 1 root root 302108 Nov 13 06:03 log2012.log
drwxr-xr-x 2 root root   4096 Nov 13 05:50 test4
lrwxrwxrwx 1 root root     11 Nov 22 06:58 linklog.log -> log2012.log

把第一列切成四段来读：- 是文件类型；紧接着的 9 个字符，每 3 个一组，依次是 属主（u）、属组（g）、其他用户（o） 的权限；每组内部的顺序固定是 r（读）、w（写）、x（执行），没有该权限就用 - 占位。所以 -rw-r--r-- 的意思是：普通文件，属主可读写，同组用户和其他用户只能读。

对目录而言，r 是「能列出目录内文件名」，x 是「能进入目录、能访问目录内已知路径的文件」，w 是「能在目录内创建、删除、重命名条目」。很多人以为「文件写权限」决定能不能删文件，其实删除和重命名看的是所在目录的 w 权限；只有当目录设置了粘滞位（t，如 /tmp）时，才额外要求你是文件属主或 root。

权限的数字表示法按 4（r）+2（w）+1（x） 累加，比如 rw-=6、r-x=5、rwx=7。因此 chmod 755 app.sh 就是「属主 rwx，同组和其他人 r-x」，这也正是可执行脚本最常见的权限。

三、修改权限与归属：chmod、chown、chgrp

chmod 支持数字设定法和字母设定法两种写法。字母法中 u/g/o/a 指定作用对象，+ - = 表示增加、删除、直接赋值：

# 数字法：属主 rwx，属组 r-x，其他人 r-x
chmod 755 app.sh

# 字母法：给属主和属组加写权限，去掉其他人的执行权限
chmod ug+w,o-x app.sh

# 用 = 直接覆盖：只给属主留执行权限，其余权限全部清掉
chmod u=x app.sh        # 结果是 ---x------

# 递归处理目录及其下所有内容，常用于放开日志目录
chmod -R u+rwX /var/log/myapp

# 同时改属主和属组（属主:属组），只改属组可用 chgrp
chown -R appuser:appgroup /opt/myapp

两点实用细节：一是 -R 递归时用大写 X 比小写 x 更安全，它只给目录和本来就有执行位的文件加 x，不会把一批普通文件误变成可执行文件；二是生产环境不要习惯性 chmod 777，它等于对所有用户开放读写执行，是典型的提权隐患，正确做法是让服务以专用用户运行，只给它恰好够用的权限。

四、文件日常操作与软链接

增删查改的骨架命令不多，关键是记牢 rm 的破坏性——Linux 没有回收站：

# 创建与查看
mkdir -p /opt/myapp/{conf,logs}     # -p：父目录不存在时一并创建
touch app.log                       # 创建空文件或更新时间戳
ls -lh                              # 人类可读的大小；ll 只是 ls -l 的别名

# 复制、移动、删除
cp -r conf conf.bak                 # -r 递归复制目录
mv app.log /tmp/                    # 移动（同分区内改名是纯元数据操作，很快）
rm -f app.log                       # -f 不提示；-r 删目录；rm -rf 慎用

# 查看内容与实时日志
cat /etc/hosts
tail -n 100 -f /var/log/myapp/app.log   # 跟踪最后 100 行并持续输出，Ctrl+C 退出

# 查找文件
find /opt -name '*.jar' -mtime -7   # 近 7 天内修改过的 jar 包

软链接（symbolic link）是「指向另一个路径的快捷方式」，用 ln -s 创建，用 ln 不加 -s 创建的是硬链接。发布系统里最常见的用法是把带版本号的目录链接成一个固定的当前版本路径，回滚时只需重建链接，一次切换、瞬间完成：

ln -s /opt/myapp/releases/20240601 /opt/myapp/current
ls -l /opt/myapp/current        # lrwxrwxrwx ... current -> /opt/myapp/releases/20240601

# 回滚：注意 -n 表示把符号链接本身当作普通文件替换，避免被链接进目录里
ln -sfn /opt/myapp/releases/20240520 /opt/myapp/current

软链接与硬链接的区别要清楚：软链接是独立文件，可以跨文件系统、可以指向目录，源文件删掉后它变成「断链」；硬链接只是同一 inode 的另一个名字，不能跨文件系统、通常不能指向目录，删掉其中任何一个名字文件仍存在。

五、用户与组：为什么「我的文件我删不掉」

Linux 是多用户系统，权限判定的顺序是：先看你是不是文件属主（u），再看你的主属组或附加组是否匹配（g），最后才落到其他用户（o）。创建和管理用户的命令如下：

groupadd appgroup                 # 建组
useradd -g appgroup appuser       # 建用户并指定主属组
passwd appuser                    # 设置密码（密码过简单会被拒绝）

id appuser                        # 查看 uid/gid 及所属组
su - appuser                      # 切换用户（- 表示同时切换环境变量）
userdel -r appuser                # 删除用户并连带删除其家目录
groupdel appgroup

cat /etc/passwd                   # 用户信息（密码占位符 x，真实密码在 /etc/shadow）
cat /etc/group                    # 组信息

现在可以回答开头那个困惑了：文件 /opt/myapp/data/aaa 属于 appuser，但目录 data 属于 root 且权限是 755，那么即使你是 aaa 的属主，也无法删除或重命名它——因为操作的是目录条目，而你没有该目录的 w 权限。同理，「读得到文件却进不去目录」，通常就是目录缺少 x 权限。排查时沿着路径从上到下一级级 ls -ld 检查，比盲目 chmod 777 高效得多。

需要提权执行单条命令时用 sudo 而不是长期使用 root；注意 su appuser 只是切换身份但保留当前环境变量，su - appuser 才会加载目标用户的完整登录环境，环境变量相关的诡异问题常常出在这。

小结

本章从目录结构讲到权限与用户：Linux 只有一棵根目录树，/etc、/usr、/var、/opt 是你最常打交道的四个位置；ls -l 的第一列按「类型 + u/g/o 各三位」解读，数字权限由 4/2/1 相加而来；修改权限用 chmod、修改归属用 chown/chgrp，递归时优先用 X 且远离 777；文件操作牢记 rm 不可恢复，实时看日志用 tail -f；软链接适合做版本切换和发布回滚。最后记住一条判定原则：能不能删文件看目录的 w，能不能进目录看目录的 x，遇到权限报错先按路径逐级核查，再决定是否授权。下一章我们会把这些文件操作能力用到 Nginx 与 Docker 的配置管理上。
