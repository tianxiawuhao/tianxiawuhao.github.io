java中静态代码块，非静态代码块，构造函数之间的执行顺序

Posted on 2021-05-01，3 min read

静态代码块、非静态代码块、构造函数三者的执行时机经常被混淆。本文用一个「父类 + 子类」的可运行示例把顺序打印出来，再逐一解释每一步为什么发生、类加载在什么时候触发。

代码示例

它们之间的执行顺序为：静态代码块 → 非静态代码块 → 构造方法。
静态代码块只在第一次加载类的时候执行一次，之后不再执行；而非静态代码块和构造函数都是在每 new 一次就执行一次，只不过非静态代码块在构造函数之前执行而已。
如果存在子类，则加载顺序为先父类后子类。
看如下的代码：

package com.ykp.test;
 
class ClassA {
    public ClassA() {
        System.out.println("父类构造函数");
    }
 
    {
        System.out.println("父类非静态代码块1");
    }
    {
        System.out.println("父类非静态代码块2");
    }
    static {
        System.out.println("父类静态代码块 1");
    }
    static {
        System.out.println("父类静态代码块 2");
    }
}
 
public class ClassB extends ClassA {
    public ClassB() {
        System.out.println("子类构造函数");
    }
 
    {
        System.out.println("子类非静态代码块2");
    }
    {
        System.out.println("子类非静态代码块1");
    }
    static {
        System.out.println("子类静态代码块 2");
    }
    static {
        System.out.println("子类静态代码块 1");
    }
 
    public static void main(String[] args) {
        System.out.println("....主方法开始....");
        new ClassB();
        System.out.println("************");
        new ClassB();
        System.out.println("....主方法结束....");
    }
}

执行结果（JDK 8 及以上均可复现）：

父类静态代码块 1
父类静态代码块 2
子类静态代码块 2
子类静态代码块 1
....主方法开始....
父类非静态代码块1
父类非静态代码块2
父类构造函数
子类非静态代码块2
子类非静态代码块1
子类构造函数
************
父类非静态代码块1
父类非静态代码块2
父类构造函数
子类非静态代码块2
子类非静态代码块1
子类构造函数
....主方法结束....

从结果可以看出：加载类时先加载父类再加载子类，类加载阶段就会执行静态代码块，而且只执行一次；如果存在多个静态代码块，则按照代码的先后顺序执行。
对于非静态代码块，它并不是「在 new 的时候被加载」，而是每创建一个实例都会执行一次，只是执行时机排在构造函数体之前。如果存在多个非静态代码块，执行顺序同样按代码的先后。

执行时机与完整顺序

把上面的输出按阶段拆开，可以归纳成两个阶段：

阶段一：类加载（初始化）阶段，只发生一次。JVM 在首次「主动使用」一个类时完成加载、链接与初始化，静态代码块和静态字段赋值就在初始化阶段执行，并且只执行一次，顺序按源码先后。本例程序入口是 ClassB.main，加载 ClassB 之前必须先初始化它的父类 ClassA，所以父类静态块在前。
完整的类加载链条是：父类静态字段赋值/静态代码块（按源码顺序）→ 子类静态字段赋值/静态代码块（按源码顺序）→ 才轮到 main 方法执行。

阶段二：实例化阶段，每次 new 都完整重复。new 会经历「分配内存 → 执行父类实例初始化 → 执行子类实例初始化」。其中每个类的实例初始化都由三部分按固定顺序组成：

  1. 实例字段的显式赋值与所有非静态代码块，按源码出现顺序合并执行；
  2. 构造函数体。编译后，非静态代码块的内容会被插入到每个构造函数中 super(...) 调用之后、构造体语句之前，这就是「非静态代码块总在构造函数之前」的根本原因；
  3. 子类构造函数体内的第一条语句默认是 super()，因此父类的实例初始化必然整体早于子类。

于是继承场景的完整顺序是：

父类静态代码块（按源码顺序）
子类静态代码块（按源码顺序）
—— 以上只在类加载时执行一次 ——
每次 new 子类：
  父类非静态代码块 / 实例字段赋值（按源码顺序）
  父类构造函数体
  子类非静态代码块 / 实例字段赋值（按源码顺序）
  子类构造函数体

这也解释了为什么「先父后子」：子类构造必须先完成父类的实例初始化，父类对象部分才处于可用状态。

常见陷阱与注意点

  1. 非静态代码块被复制到每个构造函数中。一个类若有多个构造函数，非静态代码块在每个构造函数里都会执行一次；因此重载构造函数时应把公共逻辑抽到非静态代码块或私有方法里，避免重复代码。
  2. 父类没有无参构造时会编译失败或顺序变化。子类构造函数默认调用 super()，如果父类只定义了带参构造，子类必须显式写 super(参数)，否则编译不通过。此时父类构造函数仍先于子类执行，只是参数由子类传入。
  3. 静态代码块中不要访问静态字段之后声明的部分。静态初始化按源码顺序执行，写在静态字段声明之前的静态块读到的是该字段的默认值（如 0、null）。
  4. 实例初始化可用 double-brace 写法，但有代价。new HashMap<String, String>() {{ put("a", "1"); }} 正是「匿名内部类 + 非静态代码块」，会额外生成一个类，可读性与性能都不好，不建议在业务代码中使用。
  5. 类加载时机。静态代码块在以下情况触发：new 实例、访问或赋值静态字段（非编译期常量）、调用静态方法、反射 Class.forName(类名)（默认 initialize=true）、以及初始化子类时顺带初始化其父类。而仅仅声明一个引用、访问 static final 编译期常量（如 String/基本类型字面量）、Class.forName(类名, false, loader) 与 ClassLoader.loadClass() 都不会触发静态代码块。接口的静态字段赋值只在真正访问该字段时才执行，不会像父类那样「连坐」。
  6. 静态代码块抛异常会导致类初始化失败。抛出 ExceptionInInitializerError 后，该类在同一个类加载器中会一直处于失败状态，后续使用直接报 NoClassDefFoundError，排查时要特别留意。
  7. 单例与类加载。静态代码块只执行一次且由 JVM 保证线程安全，这也正是静态内部类、枚举实现单例能兼顾懒加载与线程安全的原因。
