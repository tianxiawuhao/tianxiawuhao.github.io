easeCode

Posted on 2022-11-06，20 min read

easeCode 是一套面向 Spring Boot 工程的代码生成平台：读取数据库表结构，把表名、列名、类型、注释等元数据交给模板引擎，一次性产出 Controller、Service、Mapper、Entity 及配套的查询对象与 XML 映射。生成件并不直接落进工程目录，而是先在服务端内存里渲染，供开发者在线预览，确认后再打包下载，由使用者自行放入工程。本文按「元数据 → 模板 → 产物」的顺序，把整条链路里的模板配置与运行时支撑代码完整记录一遍，重点是可复用的工程约定：类名怎么来、字段怎么映射、分页与条件查询怎么写、异常与响应体怎么统一。

需要先明确一点：模板文件（.vm）用的是 Apache Velocity 语法，#foreach、#if、#set 与 $!{...} 都出自 Velocity；Freemarker 是另一种可选的模板引擎，语法写成 <#list> 那一套，两套模板不能混用，同一个模板目录里只应存在一种后缀。下面的模板与工具类方法（$tool、$callback）都取自 MyBatis-Plus 代码生成器的 Velocity 模板上下文，理解这一点，后文的变量名就不会显得突兀。

一、元数据与模板变量

整条链路的输入不是「表名」，而是一个已经解析好的元数据对象 TableInfo。生成器先连库读取 information_schema，把每张表组装成 TableInfo，再交给模板渲染；模板里出现的所有变量最终都落在它身上：

  • tableInfo.name：表名转成的驼峰类名，如 sys_user → SysUser，用于拼类名、变量名；
  • tableInfo.comment：表注释，写进类注释与 Swagger 描述；
  • tableInfo.obj.name：数据库里的原始表名，只在直接拼 SQL 时使用，不能拿驼峰名代替；
  • tableInfo.pkColumn：主键列集合，取第 0 个作为唯一主键，pk.name 是属性名，pk.shortType 是简类名；
  • tableInfo.fullColumn：全部列；tableInfo.otherColumn：排除主键后的列，批量插入与更新时用它，避免误改主键；
  • tableInfo.savePath 与 tableInfo.savePackageName：输出根目录与基础包名，决定文件落在哪、package 语句写什么。

列级别上，column.name 是驼峰属性名，column.obj.name 是原始列名，column.type 是全限定类型名，column.shortType 是简类名，column.ext.jdbcType 供 XML 映射使用。这四个名字分工明确，混用是最常见的出错点：判断类型要用 shortType 或用 $tool.getClsNameByFullName($column.type) 转一道，写 SQL 一律用 obj.name。

三、Mapper 层：接口与 XML 映射

Mapper 层由两个模板承担：一个生成 Java 接口，一个生成 XML 映射文件。接口继承 MyBatis-Plus 的 BaseMapper，只拿到单条 SQL 的通用能力；XML 里则手写了三处 MyBatis-Plus 覆盖不到的场景——批量插入、批量更新（依赖 allowMultiQueries=true）以及一个显式列清单的查询。<resultMap> 用 #foreach 遍历全列生成 property/column/jdbcType 映射，这正是 column.ext.jdbcType 唯一的用武之地。

四、实体与传输对象

三个实体模板共用同一套骨架：$!{define.vm} 引入宏定义，$!{autoImport.vm} 引入默认导入，#tableComment(...) 生成类注释，最后 #foreach($column in $tableInfo.fullColumn) 逐列展开属性。区别只在回调与包后缀：实体落在 /entity，TO 落在 /entity/to 并继承 SearchPage 承载分页参数，VO 落在 /entity/vo。这三个 #save 与 #setPackageSuffix 的取值必须与 Service、Controller 模板里的 import 语句一致，否则生成出来的工程编译不过——这是改动模板时最先要核对的地方。

entity.java.vm

实体模板里有两处需要特别说明。@Table(name = "$!{tool.hump2Underline($tableInfo.name)}") 把类名还原成下划线表名，路径正确；但紧随其后的 schema = "$!{tableInfo.comment}" 把表注释当成了 schema 名，而 JPA 的 schema 属性期望的是数据库 schema（如 public），不是中文描述，实际依赖 ddl-auto: update 时可能生成出带中文 schema 的语句。此处判定为模板笔误，未改动代码，仅记录在日志里。另一处是列宽：@Column 里的 columnDefinition 把 String 一律写成 varchar(255)，Double 写成 double(5, 3)，并没有读取元数据里的真实长度与精度，因此实体注解只适合做 DDL 参考，不能当成表结构的来源。

五、统一响应体与错误码

Controller 里每个方法都返回 APIResponse，这是接口层的统一出口：code 表示业务结果，data 承载数据，msg 支持带占位符的国际化式消息——getMsg() 在 args 非空时用 StrUtil.format(msg, args) 现场格式化，因此错误码里的文案可以写成模板，调用处只传参数。不过要注意，APIResponse 引用的是 io.swagger.annotations（Swagger 2 的包名），而 Controller 模板用的是 io.swagger.v3.oas.annotations（OpenAPI 3），两套注解包不能同时生效，迁移时应把这里的 @ApiModel/@ApiModelProperty 一并换成 v3 注解。

import cn.hutool.core.util.StrUtil;

@Data

public class APIResponse<E> implements Serializable {

    @ApiModelProperty(value = "响应码 200:成功，其他:失败", required = true)
    private Integer code;

    private String msg;

    @ApiModelProperty(value = "响应数据")
    private E data;

    @JsonIgnore
    private Object[] args;

     * 获取响应消息
     * @return 响应消息
     */
    public String getMsg() {
        return (null != args && null != msg) ? StrUtil.format(msg, args) : msg;
    }

    public APIResponse() {
        this.code = ResponseCode.SUCCESS.getCode();
    }

    private APIResponse(ResponseCode code) {

    }

    public static APIResponse ok() {
        return new APIResponse(ResponseCode.SUCCESS);
    }

    public static <E> APIResponse<E> ok(E data) {
        APIResponse<E> res = new APIResponse(ResponseCode.SUCCESS);
        res.setData(data);
        return res;
    }

    public static <E> APIResponse<E> ok(E data, String msg) {
        APIResponse res = ok(data);
        res.setMsg(msg);
        return res;
    }

    private static APIResponse fail() {
        return new APIResponse(ResponseCode.FAIL);
    }

     * 失败响应
     * @param responseCode 异常码

六、分页对象

分页参数与分页结果分别由 SearchPage 和 PageInfo 承担。前者是入参基类，只有 page 与 size 两个字段，默认 size = 10；后者把 MyBatis-Plus 的 Page 转成前端友好的结构，保留 total、list、pageNum、pageSize，并额外算出 startRow、endRow。要注意 endRow 的算法是 total / pageSize，得到的是总页数而不是结束行号，命名与语义并不吻合；前端若按字面意思当成「结束行」使用会算错。这个命名问题属于既有接口约定，改动会影响调用方，因此保留原样，仅在此说明。

import com.baomidou.mybatisplus.extension.plugins.pagination.Page;
import lombok.Data;

import java.util.List;

@Data
public class PageInfo<T>{
    protected long total;
    protected List<? extends T> list;
    public static final int DEFAULT_NAVIGATE_PAGES = 8;
    private long pageNum;
    private long pageSize;
    private long startRow;
    private long endRow;

    public PageInfo(Page<T> page) {
        this.list = page.getRecords();
        this.total = page.getTotal();
        this.pageNum = page.getCurrent();
        this.pageSize = page.getSize();
        this.startRow = 0L;
        this.endRow = page.getTotal() > 0 ? (page.getTotal()/page.getSize()) : 0L;
    }

    public String toString() {
        String sb = "PageInfo{" + "pageNum=" + this.pageNum +
                ", pageSize=" + this.pageSize +
                ", startRow=" + this.startRow +
                ", endRow=" + this.endRow +
                ", total=" + this.total +
                ", list=" + this.list +
                '}';
        return sb;
    }
}

七、运行时配置

生成件要跑起来，还需要应用侧的 JPA 配置配合。开发阶段通常打开 SQL 打印并把 ddl-auto 设为 update，让实体注解能反推表结构；由于上文提到的 @Table 注解里 schema 取值来自表注释，这项配置在真实环境务必确认生成的 DDL 是否符合预期，正式环境建议改为 validate 或 none，由 DBA 维护的表结构说了算。

spring:
  jpa:
    hibernate:
      ddl-auto: update
    show-sql: true
    properties:
      hibernate:
        hbm2ddl:
          auto: update
