JavaScript 基础

Posted on 2026-09-19，9 min read

写 JavaWeb 项目时，服务端的 Servlet、JSP 只管把数据送到浏览器，页面上的表单校验、按钮响应、无刷新请求，最后都要落到 JavaScript 上。很多后端出身的开发者把 JS 当成“能跑就行的脚本语言”，于是反复踩同一批坑：var 提升导致循环里的回调拿到同一个值、this 在回调里莫名变成 undefined、判断数组类型却得到 'object'。这些坑的根源不是语法难，而是 JS 的类型系统、作用域规则和对象模型与 Java 差别很大。本章不追求覆盖全部 API，而是按“类型与变量 → 函数、作用域与闭包 → 对象与原型 → 数组与高阶函数 → 模块化与异步 → 旧写法到现代写法的演进”的顺序，把最容易出错的基础讲透。阅读前只需要会写最基本的 <script>，示例可直接粘贴到浏览器控制台或用 Node.js 运行。

一、类型与变量：松散类型不等于没有类型

JavaScript 是动态类型、松散类型的语言：变量本身不绑定类型，类型属于“值”，同一个变量可以先存数字再存字符串。这一点和 Java 的“变量声明即定类型”正相反，但并不意味着 JS 没有类型。原始类型一共七种：undefined、null、boolean、number、string、symbol（ES6）、bigint（ES2020）；除此之外的一切都是对象。注意 number 同时表示整数和浮点数，没有 int/long 之分。它遵循 IEEE 754 双精度，整数一旦超出安全范围（Number.MAX_SAFE_INTEGER）精度就会丢失，这类场景要用 bigint。

判断类型有两个必须记住的结论。第一，用 typeof 时 typeof null === 'object'，这是语言诞生第一版就留下的历史 bug，因为改动会让大量旧代码崩溃，所以永远不会修；判断 null 要写 value === null。第二，typeof 对数组和普通对象都返回 'object'，想准确区分要用 Object.prototype.toString.call(x) 得到形如 '[object Array]' 的字符串，日常判数组则直接用 Array.isArray(x)。另外，判 NaN 请用 Number.isNaN()，全局的 isNaN() 会先做隐式类型转换，isNaN('abc') 也返回 true，容易误判。

变量声明有 var、let、const 三种。早期资料常写“所有数据类型都用 var 定义”，那是 ES5 时代的做法；现代项目里应当默认 const，只有确实需要重新赋值时才用 let。原因是 var 只有函数作用域、没有块级作用域，声明还会被提升到作用域顶部，且初始值为 undefined：先使用后声明不报错，却只能拿到空值。let/const 是块级作用域，在声明前访问会直接抛 ReferenceError（这段区间叫暂时性死区，TDZ）。const 只约束“绑定不可重新赋值”，对象内部属性照样能改，想彻底冻结要用 Object.freeze()（且只冻结第一层）。最后，比较一律用 ===：== 会做隐式转换，'1' == 1、null == undefined 都为 true，这类规则记不全就干脆别用。

const name = 'Tom';        // 字符串
let age = 18;              // 数字：后面可能变化，所以用 let
const user = { name, age }; // 属性简写

typeof name;               // 'string'
typeof null;               // 'object'  ← 历史遗留问题，判断请用 === null
typeof (() => {});         // 'function'

Object.prototype.toString.call([]);  // '[object Array]'
Array.isArray([]);                   // true（日常推荐）

console.log(age === '18');  // false：=== 不做隐式转换
console.log(age == '18');   // true：== 把字符串转成了数字，别用
console.log(Number.isNaN(NaN)); // true

// console.log(score);      // ReferenceError：let 存在暂时性死区
let score = 90;
user.age = 20;              // 合法：const 只锁定绑定，不冻结对象

二、函数、作用域与闭包

函数在 JS 里是一等公民：可以赋给变量、作为参数传入、作为返回值传出，这正是后面高阶函数和回调式 API 的基础。定义方式有两种，行为并不相同。function f() {} 是函数声明，整个声明会被提升，在定义之前调用也没问题；const f = function () {} 与箭头函数属于表达式，只有变量的提升，没有函数体的提升，赋值之前调用会抛 TypeError: f is not a function。调用时 JS 也不校验参数个数和类型：多传的参数被忽略（可用 arguments 或剩余参数 ...args 取到），少传的参数值是 undefined，因此形参默认值要用 ES6 的 function f(a = 1) {}，不要靠手动判断。

this 是 JS 最反直觉的部分，记住一条：普通函数的 this 由“调用方式”决定，而非定义位置。obj.fn() 中 this 指向 obj；把方法单独取出写成 const g = obj.fn; g()，this 就变成 undefined（严格模式）或全局对象；用 new 调用则指向新创建的对象。箭头函数没有自己的 this 和 arguments，它捕获定义时外层作用域的 this（词法绑定），所以特别适合写回调和 setTimeout，但也因此不能用 call/apply 改变指向，不能当构造函数。

闭包是“函数 + 它定义时所处的作用域”的组合：内层函数引用了外层的变量，即使外层函数已经执行完毕，这些变量依然留在内存中可被访问。它带来两个能力——把变量变成外部拿不到的私有状态，以及把状态在多次调用之间保存下来（记忆化、防抖节流都依赖它）。代价是对应的变量不会被回收，若闭包长期持有大对象或 DOM 节点，就可能造成内存泄漏，必要时在不再使用后手动把引用置为 null。经典陷阱是循环里的 var：var 没有块级作用域，三个回调捕获的是同一个 i，输出全是 3；换成 let 后每轮迭代都有独立的绑定，输出 0、1、2。

function createCounter() {
  let count = 0;                 // 被闭包记住的私有变量
  return () => ++count;          // 返回的函数仍然能访问 count
}
const next = createCounter();
next();  // 1
next();  // 2
// count;  // ReferenceError：外部无法直接访问

// 经典陷阱：var 没有块级作用域
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);   // 3 3 3
}
for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log(j), 0);   // 0 1 2
}

// 防抖：事件停止触发 delay 毫秒后才真正执行一次
function debounce(fn, delay) {
  let timer = null;
  return function (...args) {
    clearTimeout(timer);                 // 每次触发都重置计时
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}
// window.onresize = debounce(() => console.log('resize end'), 300);

执行上下文：变量对象、活动对象与声明提升

前面说的“作用域”需要一个更底层的解释：执行上下文（Execution Context）是代码被求值时所在环境的抽象描述，可以理解成一张“记录表”，上面登记着变量、函数、this 和对外层环境的引用。每次调用一个函数，引擎就为这次调用创建一个新的函数执行上下文并压入执行上下文栈；此外还有全局执行上下文（整个程序只有一个）以及用 eval() 产生的执行上下文（现代代码里应当避免）。因此，函数每被调用一次就有全新的一份上下文，而作用域在定义时就固定了——这正是 this 与作用域容易混淆的根源。

函数上下文在创建阶段会依次做三件事：先建立变量对象（Variable Object，VO），再建立作用域链，最后确定 this。进入函数代码执行后，变量对象就被激活成活动对象（Activation Object，AO），二者的内容其实是同一份记录，只是“激活”意味着属性可以被访问了。变量对象的填充顺序如下：

  1. 先登记形参与实参的映射，缺省的实参值为 undefined；
  2. 再登记函数体内的函数声明，键是函数名，值是函数对象；
  3. 最后登记变量声明，键是变量名，值为 undefined，如果这个名字已经存在则不覆盖。

声明提升（Hoisting）就是这套创建流程的副产品：声明在“创建阶段”就写进了记录表，而赋值发生在“执行阶段”，所以在代码里看起来声明被提到了最前面。函数声明与 var 的提升并不等价，有三点要害：其一，函数声明提升的是整个函数定义，所以定义之前就能调用；var 只提升声明、值为 undefined，提前访问得到的是 undefined 而不是报错。其二，函数声明优先于变量声明，同一名字下变量不会覆盖已登记的函数。其三，赋值语句本身从不参与提升。看下面这段经典代码，顺序刻意写成“调用、声明、赋值”：

// 函数声明：整个函数体被提升，定义之前就能调用
greet();                                     // 'Hi'
function greet() { return 'Hi'; }

// var：只提升声明，值为 undefined，提前读取不报错
console.log(typeof count);                   // 'undefined'
var count = 1;
console.log(count);                          // 1

// 函数声明优先于变量声明：同名登记时变量不覆盖已登记的函数
console.log(typeof pick);                    // 'function'
var pick;
function pick() { return 'function'; }

// 提升只搬声明、不搬赋值：表达式形式的“函数”也是变量
console.log(typeof task);                    // 'undefined'，而不是 'function'
var task = function () { return 'later'; };
console.log(task());                         // 'later'

// 循环体内用 var 声明函数表达式，只有变量提升，函数体没有
for (var i = 0; i < 3; i++) {
  setTimeout(function () { console.log('var 版', i); }, 0);   // 3 3 3
}

let 与 const 的声明同样会“提前登记”，但它们的处理方式与 var 不同：从进入块级作用域到初始化完成之前，这个绑定存在却不可访问，这段区间叫暂时性死区（Temporal Dead Zone，TDZ），访问会抛 ReferenceError。换句话说，var 的提前访问得到 undefined，let/const 的提前访问直接报错——报错比静默的 undefined 更安全，这也是新代码一律优先 const、其次 let 的原因之一。class 声明同理，处在 TDZ 中，必须先定义后使用。另一个容易忽略的点是：在 var 声明的函数体内写 let 有语法限制（同一作用域内重复声明会直接抛 SyntaxError），而 var 允许重复声明。

// TDZ：绑定已登记，但初始化之前访问即报错
try {
  console.log(typeof value);   // ReferenceError，而不是 'undefined'
} catch (err) {
  console.log(err.name);       // 'ReferenceError'
}
let value = 1;

// 每轮迭代都是一块新的块级作用域，闭包各记一份
const fns = [];
for (let k = 0; k < 3; k++) {
  fns.push(() => k);           // 闭包捕获的是当轮那个 k
}
console.log(fns.map((f) => f()));   // [0, 1, 2]

最后把作用域链与闭包的关系串起来：作用域链是上下文创建时写下的静态查找路径，函数嵌套定义得越深，链就越长；闭包则是这条链在函数返回后依然可达所产生的效果——内层函数持有对外层活动对象的引用，于是外层函数的变量不会被回收。所以“闭包”不是语言额外提供的机制，而是“词法作用域 + 一等函数”的必然结果。用 var 还是 let 决定的是“有几个绑定”，用函数表达式还是函数声明决定的是“提升到什么程度”，两件事都发生在上下文创建阶段，只是影响的侧面不同。

this 的四种绑定规则与优先级

第二节给出了结论，这里补上可操作的判定顺序。this 与作用域链无关，它只由调用位置（call site）决定，判断时按下面的优先级由高到低依次匹配，命中一条即可停止：

  1. new 绑定（最高）：用 new fn() 调用时，this 是新建的实例对象。构造函数的显式返回值若是对象，则替换掉这个实例，否则忽略。
  2. 显式绑定：fn.call(obj, ...args) 与 fn.apply(obj, argsArray) 立即执行并把 this 指定为 obj；fn.bind(obj, ...args) 不执行，返回一个 this 被永久固定的新函数，可用于偏函数。
  3. 隐式绑定：obj.fn() 的形式，this 指向调用点前面的那个对象；多层调用只看最后一级，即 a.b.fn() 里 this 是 b。
  4. 默认绑定（最低）：光杆调用 fn()。非严格模式下 this 是全局对象（浏览器里是 window），严格模式和 ES Module 顶层是 undefined。

需要留意的边界有两个：call/apply/bind 传入 null 或 undefined 会被忽略，退回默认绑定（严格模式下则保持 null/undefined）；bind 的 this 是永久的，之后再 call 也改不掉，但 new 的优先级更高，用 new 调用一个 bind 过的函数时，this 仍然是新实例。箭头函数是另一套规则：它没有自己的 this、arguments 和 prototype，函数体里的 this 直接取自定义时外层作用域（词法继承），call/apply/bind 无法改变，也不能用 new 调用（会抛 TypeError: fn is not a constructor）。所以箭头函数适合写“不需要自己的 this”的回调，而不适合当对象方法或构造函数。

'use strict';

const counter = { count: 0, add(n) { this.count += n; return this.count; } };

// 1 默认绑定：光杆调用，严格模式下 this 是 undefined
function whoAmI() { return this; }
whoAmI();                                   // undefined

// 2 隐式绑定：this 是调用点前面的对象，只看最后一级
counter.add(1);                             // 1
const holder = { counter };
holder.counter.add(1);                      // 2，this 仍是 counter

// 3 显式绑定：call/apply 立即执行，bind 返回固定 this 的新函数
counter.add.call({ count: 10 }, 1);         // 11
counter.add.apply({ count: 20 }, [2]);      // 22
const addToCounter = counter.add.bind(counter);
addToCounter(3);                            // 3，this 被永久固定为 counter

// 4 new 绑定优先级最高：bind 也拦不住 new
function Point(x, y) { this.x = x; this.y = y; }
const BoundPoint = Point.bind({ x: -1, y: -1 });
const p = new BoundPoint(1, 2);
p.x;                                        // 1，this 是新实例而非 bind 的目标

// 箭头函数：词法继承外层 this，且不能 new
const obj = {
  value: 42,
  get() {
    const arrow = () => this.value;         // this 是 get 调用时的 this
    return arrow();
  },
};
obj.get();                                  // 42
obj.get.call({ value: 7 });                 // 7，箭头函数跟着外层走
// new (() => {})();                        // TypeError: not a constructor

理解了规则，就能定位最常见的“this 丢失”：本质都是调用方式从 obj.fn() 退化成了 fn()，于是从隐式绑定跌到默认绑定。三个高频场景：其一，把方法赋给变量或当参数传给回调，const g = obj.fn; g() 与 setTimeout(obj.fn, 0)、arr.map(obj.fn) 都属于此类；其二，解构赋值把方法从对象上摘下来，const { fn } = obj; fn() 同样丢失；其三，把方法传给第三方库或挂在 addEventListener 上，函数虽然会执行，但调用点是浏览器决定的，this 变成触发事件的 DOM 元素。this 一旦丢失就取不到实例字段，读写会得到 undefined，在严格模式下还可能直接抛错，因此不要指望“运行时再看”。

const user = {
  name: 'Tom',
  greet() { return `Hi, ${this.name}`; },
};

// 场景一：方法被单独取出，this 变成 undefined（严格模式）
const detached = user.greet;
// detached();                              // TypeError: 读不到 name

// 场景二：解构赋值也会摘掉 this
const { greet } = user;
// greet();                                 // 同样丢失

// 三种修法：bind、包装函数、改写成箭头函数属性
const bound = user.greet.bind(user);
const wrapped = () => user.greet();
const safeUser = { name: 'Tom', greet: () => `Hi, ${safeUser.name}` };
console.log(bound(), wrapped(), safeUser.greet());

// 定时器与数组回调：需要 this 时用包装函数或 bind，不要直接传方法
setTimeout(wrapped, 0);
[1, 2].map(user.greet.bind(user));

三、对象、原型与 class

JS 的对象本质是“键值对集合”，键只能是字符串或 symbol，读取时 obj.a 与 obj['a'] 等价（键名含特殊字符或来自变量时必须用后者）。对象字面量 {} 比 new Object() 更简洁常用，同理数组应写 [1, 2] 而不是 new Array(1, 2)——后者的参数语义还很坑：new Array(3) 得到的是长度为 3 的空数组，而不是 [3]。

属性查找靠原型链：每个对象都有一个内部引用 [[Prototype]]（通过 Object.getPrototypeOf() 读取），访问属性时先查自身，找不到就沿着原型链往上找，直到值为 null 为止。要区分两个容易混淆的东西：函数的 prototype 属性是给 new 出来的实例当原型用的，而对象的原型要用 [[Prototype]]/__proto__ 访问，二者不是一回事。常见说法是“JS 是基于对象的语言”，更准确的表述是：JS 是基于原型的面向对象语言，没有 Java 那样的类继承。ES6 的 class 只是原型继承的语法糖，底层依旧是构造函数加原型对象。instanceof 判断的也不是“由谁创建”，而是“构造函数的 prototype 是否出现在对象的原型链上”，所以判断数组更可靠的是 Array.isArray()。

用 class 书写时有三点与 Java 不同：类声明不会被提升（存在 TDZ），必须先定义后使用；类体内的代码默认运行在严格模式下；子类必须在构造函数里先调用 super() 才能使用 this。ES2022 起支持 #字段 私有成员，这才是语言层面的真私有——此前只能靠闭包或 WeakMap 模拟，而用“构造函数里保存私有变量”的写法会让每个实例都重新创建一份特权方法，内存开销更大。

function Person(name) {
  this.name = name;
}
Person.prototype.say = function () {
  return 'I am ' + this.name;
};

const p = new Person('Tom');
p.say();                                        // 'I am Tom'
Object.getPrototypeOf(p) === Person.prototype;  // true
p instanceof Person;                            // true

class Student extends Person {          // class 只是原型继承的语法糖
  #score = 0;                           // 私有字段，外部无法访问
  constructor(name, score) {
    super(name);                        // 必须先调用 super 才能用 this
    this.#score = score;
  }
  say() {                               // 重写父类方法
    return super.say() + ', score ' + this.#score;
  }
  static of(name, score) {               // 静态方法属于类本身
    return new Student(name, score);
  }
}
Student.of('Jerry', 90).say();           // 'I am Jerry, score 90'

四、数组与高阶函数

数组是项目里用得最多的结构，真正要熟练的是 map、filter、reduce、some、every、find、flat 这几个高阶方法。它们的回调统一接收 (当前元素, 索引, 原数组) 三个参数，且都不修改原数组，返回新值（会改原数组的是 sort、splice、reverse，用之前要留意）。几个边界值必须记牢：some 对空数组恒返回 false，every 对空数组恒返回 true（逻辑上的“空真”）。reduce 不传初始值时以第一个元素为初始值，对空数组会直接抛 TypeError，所以求和、计数这类场景务必显式传初始值。flat 默认只降一层，传 Infinity 才能彻底拍平——注意正确拼写是 Infinity，不要写成 Inifity。

另一个常见疑问是 map(callback, thisArg) 的第二个参数：它用来指定回调里的 this，但如果回调写成箭头函数，箭头函数按词法绑定 this，这个参数就完全失效了。这也是“回调优先用箭头函数，但需要自定义 this 时改用普通函数”这条经验规则的由来。

const nums = [1, 2, 3, 4];

nums.map(n => n * 2);                  // [2, 4, 6, 8]，长度不变
nums.filter(n => n % 2 === 0);         // [2, 4]
nums.reduce((sum, n) => sum + n, 0);   // 10，0 是初始值
nums.some(n => n > 3);                 // true：存在满足条件的元素
nums.every(n => n > 0);                // true：所有元素都满足
[].some(() => true);                   // false
[].every(() => false);                 // true：空数组的 every 恒为 true

// 用 reduce 实现 map，体会“归约”的通用性
const myMap = (arr, fn) => arr.reduce((acc, item, i) => {
  acc.push(fn(item, i, arr));
  return acc;
}, []);
myMap(nums, n => n + 1);               // [2, 3, 4, 5]

[[1, [2]], [3]].flat(Infinity);        // [1, 2, 3]

五、模块化与异步：把脚本写成工程

早期的 JS 没有模块体系，所有脚本共享一个全局作用域，于是开发者用立即执行函数加闭包来“造”模块，把变量藏在函数内部，只暴露必要的接口。后来 Node.js 带来了 CommonJS（require 引入、module.exports 导出，运行时同步加载，只能在 Node 环境用），浏览器端则出现过 AMD（RequireJS）和 CMD 等方案。现在的主流是 ES Module：export 导出、import 引入，它是静态语法，必须写在模块顶层，打包工具能在编译阶段就分析出依赖关系并做 tree-shaking。export default 与具名导出不要在同一个文件里混着乱用，CommonJS 的 require 和 ESM 的 import 也不要塞进同一个文件。webpack 是“静态模块打包器”，负责从入口出发递归构建依赖图并输出 bundle，它本身并不是模块规范。Vue CLI 默认内置 webpack，只是一种工程选择，与 ES Module 语法本身无关。

异步编程经历了回调函数 → Promise → async/await 三代。await 只能等待 Promise（更准确说是 thenable），它会让所在函数暂停，但不阻塞主线程；Promise 的失败状态必须处理，用 try/catch 包住 await，或补上 .catch()，否则会触发 unhandledrejection。最容易写出性能问题的地方，是把彼此独立的请求用 await 一个个串起来，白白累加等待时间；正确做法是用 Promise.all([...]) 并发发起。Promise.all 是“一个失败整体失败”，需要全部结果无论成败时用 Promise.allSettled；Node 里那些 error-first 风格的回调 API（如 fs.readFile）可以用 util.promisify 一键转成 Promise。

六、旧写法到现代写法：一张演进对照表

本章开头提到的那些坑，几乎都能对应一条“老写法 → 新写法”的演进路线。下表先把替换关系集中列出，再逐条解释原因。旧代码不必推倒重写，但要知道它为什么被替代。

旧写法问题现代写法
var函数作用域、声明提升、没有块级约束const 优先，确实要重新赋值才用 let
== / !=隐式类型转换，规则记不全就容易误判=== / !==
for...in 遍历数组拿到的是字符串键，还会枚举到原型链上的可枚举属性for...of、forEach；枚举对象键用 Object.keys()
document.write()解析完成后调用会清空整个文档，并阻塞解析DOM API：createElement 配 appendChild、textContent
用 + 拼接字符串引号与换行易错，多行模板难读模板字符串（反引号 + ${} 插值）
逐个取出对象或数组元素样板代码多，默认值处理啰嗦解构赋值与默认值、展开运算符 ...
XMLHttpRequest 配回调回调嵌套，状态码与错误处理分散fetch() 返回 Promise，配 async/await
手写 prototype 继承链路长，容易漏掉 constructorclass（语法糖，原型链底层不变）

for...in 遍历数组的三个坑

for...in 枚举的是可枚举属性名，不是元素值。用在数组上会连踩三个坑：第一，拿到的是字符串下标 '0'、'1'，参与算术前得先转换；第二，遍历顺序在规范里并不保证，只是现代引擎恰好多按升序输出；第三，只要有人给 Array.prototype 或 Object.prototype 挂过可枚举属性（早期 polyfill 里很常见），循环就会凭空多出几项，这也是它最危险的地方。按值遍历数组请用 ES6 的 for...of（走迭代器，支持 break/continue），只要元素时用 forEach/map。要枚举对象的键，Object.keys()/Object.entries() 更省心；确需 for...in 时用 Object.hasOwn(obj, k)（ES2022，旧环境可退回 Object.prototype.hasOwnProperty.call(obj, k)）过滤掉继承来的键。

const arr = [10, 20, 30];

for (const v of arr) console.log(v);        // 10 20 30：拿的是值
arr.forEach((v, i) => console.log(i, v));   // 需要下标时用 forEach
arr.map(n => n * 2);                        // [20, 40, 60]

// 反例：用 for...in 遍历数组
Array.prototype.extra = 'oops';             // 早期 polyfill 的典型后果
for (const k in arr) {
  console.log(k);                           // '0' '1' '2' 'extra'：字符串键，还多一项
}
delete Array.prototype.extra;               // 演示结束就清理，真实代码不要这样改原型

const user = { name: 'Tom', age: 18 };
Object.keys(user);                          // ['name', 'age']
Object.entries(user);                       // [['name', 'Tom'], ['age', 18]]
for (const k in user) {
  if (Object.hasOwn(user, k)) console.log(k, user[k]);  // 过滤继承属性
}

document.write 为什么不能再用了

document.write() 只在文档解析阶段由内联脚本调用时，才表现为“往当前位置插入内容”。一旦文档解析完成（例如在事件回调、DOMContentLoaded 之后）再调用，浏览器会先清空整个文档再写入，页面直接被冲掉；它还会阻塞 HTML 解析，并让同一份脚本在同步与异步加载下行为不一致——在 async/defer 脚本里调用甚至会被忽略并给出控制台警告。动态添加内容请改用 DOM API：document.createElement() 搭配 appendChild()/insertBefore()，写文本用 textContent。不要用 innerHTML 拼接用户输入，那等于把 XSS 漏洞写进页面；确需渲染结构时用 <template> 元素，或把数据交给 textContent 逐节点设置。

const list = document.querySelector('#list');
const li = document.createElement('li');
li.textContent = userInput;            // 文本按字面处理，不会被当成 HTML 解析
list.appendChild(li);

// 旧写法：解析完成后执行会清空整页，注释掉仅供对照
// document.write('<li>' + userInput + '</li>');

回调 → Promise → async/await：以 fetch 为例

发请求的现代写法是 fetch()：它返回 Promise，天然适配 async/await。三个必须记住的细节：fetch 只在网络层出错时才 reject，HTTP 404、500 依然算“成功”，所以要自己判断 response.ok；响应体是一次性流，response.json() 与 response.text() 只能选一个、且只能调用一次；默认不携带跨域 Cookie，需要时显式写 credentials: 'include'，并让服务端配置好 CORS。旧教程里的 XMLHttpRequest 或 jQuery $.ajax 仍能运行，但嵌套回调、错误处理分散、取消请求麻烦，正是 Promise 与 async/await 要解决的问题。另外，彼此独立的请求不要用 await 逐个串起来，那样等待时间是累加的，应当交给 Promise.all() 并发。

async function loadUser(id) {
  try {
    const res = await fetch(`/api/users/${id}`);
    if (!res.ok) throw new Error(`HTTP ${res.status}`);  // 404/500 不会自动 reject
    return await res.json();                             // 响应体只能读一次
  } catch (err) {
    console.error('请求失败', err);
  }
}

// 并发而不是串行：总等待时间约等于最慢的那个请求
const [a, b] = await Promise.all([loadUser(1), loadUser(2)]);

解构与模板字符串：少写样板代码

取对象字段、给参数默认值、复制并覆盖对象，现代写法都用解构与展开运算符；拼字符串则用反引号模板字符串，${} 直接插值且支持换行。它们由 ES6（ES2015）引入，今天的浏览器和 Node 都原生支持，无需编译即可运行。class 与 ES Module 同理，本章第三节和第五节已经用过。要注意模板字符串里的插值同样是隐式转换：null 与 undefined 会分别变成字符串 'null'、'undefined'，这与 == 的隐式转换是同一类陷阱，该判空还是要判空。

const { name, age = 0 } = user;          // 对象解构 + 默认值
const [first, ...others] = [1, 2, 3];    // 数组解构 + 剩余元素
const merged = { ...user, age: 20 };     // 展开复制并覆盖 age

function greet({ name }, greeting = 'Hi') {
  return `${greeting}, ${name}!`;        // 模板字符串：插值 + 跨行
}
greet(user);                             // 'Hi, Tom!'

小结：本章围绕六个基础点做了梳理。旧写法向现代写法的替换关系同样要记牢：for...in 只用于枚举对象键、遍历数组请用 for...of，document.write 应彻底避免，发请求交给 fetch 配 async/await，取值与拼串用解构和模板字符串。变量声明以 const 优先、let 次之，比较用 ===，类型判断要绕开 typeof null 这个历史坑；函数的 this 看调用方式，箭头函数按词法绑定。闭包既能做私有状态，也会延长变量生命周期，循环配 let 才不会全体指向同一个值。对象靠原型链查找属性，class 只是语法糖，判数组用 Array.isArray；数组高阶函数不改原数组，注意 every 对空数组返回 true、reduce 记得给初始值。模块化统一用 ES Module，异步优先 async/await，并用 Promise.all 并发。执行上下文解释了提升与闭包：函数每调用一次生成一份新上下文，创建阶段先登记形参、函数声明、变量声明（函数声明整个提升，var 只提升声明，let/const 处于暂时性死区），作用域链因此静态固定，闭包是这条链在函数返回后仍可达的结果。this 则只由调用位置决定，按 new 绑定、显式绑定、隐式绑定、默认绑定的优先级判定，箭头函数例外——它词法继承外层 this，无法被 call/apply/bind 改写，也不能 new；方法被取出或解构时用 bind、包装函数或箭头函数保住 this。把这些规则变成肌肉记忆后，再学 Vue、webpack 或 Node，就不会被语言层面的意外绊住。
