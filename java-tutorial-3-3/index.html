JavaScript 基础

Posted on 2026-09-19，9 min read

写 JavaWeb 项目时，服务端的 Servlet、JSP 只管把数据送到浏览器，页面上的表单校验、按钮响应、无刷新请求，最后都要落到 JavaScript 上。很多后端出身的开发者把 JS 当成「能跑就行的脚本语言」，于是反复踩同一批坑：var 提升导致循环里的回调拿到同一个值、this 在回调里莫名变成 undefined、判断数组类型却得到 'object'。这些坑的根源不是语法难，而是 JS 的类型系统、作用域规则和对象模型与 Java 差别很大。本章不追求覆盖全部 API，而是按「类型与变量 → 函数与闭包 → 对象与原型 → 数组与高阶函数 → 模块化与异步」的顺序，把最容易出错的基础讲透。阅读前只需要会写最基本的 <script>，示例可直接粘贴到浏览器控制台或用 Node.js 运行。

一、类型与变量：松散类型不等于没有类型

JavaScript 是动态类型、松散类型的语言：变量本身不绑定类型，类型属于「值」，同一个变量可以先存数字再存字符串。这一点和 Java 的「变量声明即定类型」正相反，但并不意味着 JS 没有类型。原始类型一共七种：undefined、null、boolean、number、string、symbol（ES6）、bigint（ES2020）；除此之外的一切都是对象。注意 number 同时表示整数和浮点数，且没有 int/long 之分，超出安全整数范围要用 bigint 或 Number.MAX_SAFE_INTEGER 之外的手段处理。

判断类型有两个必须记住的结论。第一，用 typeof 时 typeof null === 'object'，这是语言诞生第一版就留下的历史 bug，因为改动会让大量旧代码崩溃，所以永远不会修；判断 null 要写 value === null。第二，typeof 对数组和普通对象都返回 'object'，想准确区分要用 Object.prototype.toString.call(x) 得到形如 '[object Array]' 的字符串，日常判数组则直接用 Array.isArray(x)。另外，判 NaN 请用 Number.isNaN()，全局的 isNaN() 会先做隐式类型转换，isNaN('abc') 也返回 true，容易误判。

变量声明有 var、let、const 三种。老资料（包括不少 JavaWeb 笔记）会说「所有数据类型都用 var 定义」，这是 ES5 时代的写法，现代项目里应当默认 const，只有确实需要重新赋值时才用 let。原因是 var 只有函数作用域、没有块级作用域，并且声明会被提升到作用域顶部且初始值为 undefined，先使用后声明不报错却拿到空值；let/const 是块级作用域，在声明前访问会直接抛 ReferenceError（这段区间叫暂时性死区，TDZ）。const 只约束「绑定不可重新赋值」，对象内部属性照样能改，想彻底冻结要用 Object.freeze()（且只冻结第一层）。最后，比较一律用 ===：== 会做隐式转换，'1' == 1、null == undefined 都为 true，这类规则记不全就干脆别用。

const name = 'Tom';        // 字符串
let age = 18;              // 数字：后面可能变化，所以用 let
const user = { name, age }; // 属性简写

typeof name;               // 'string'
typeof null;               // 'object'  ← 历史遗留问题，判断请用 === null
typeof (() => {});         // 'function'

Object.prototype.toString.call([]);  // '[object Array]'
Array.isArray([]);                   // true（日常推荐）

console.log(age === '18');  // false：=== 不做隐式转换
console.log(age == '18');   // true：== 把字符串转成了数字，别用
console.log(Number.isNaN(NaN)); // true

// console.log(score);      // ReferenceError：let 存在暂时性死区
let score = 90;
user.age = 20;              // 合法：const 只锁定绑定，不冻结对象

二、函数、作用域与闭包

函数在 JS 里是一等公民：可以赋给变量、作为参数传入、作为返回值传出，这正是后面高阶函数和回调式 API 的基础。定义方式有两种，行为并不相同：function f() {} 是函数声明，整个声明会被提升，在定义之前调用也没问题；const f = function () {} 和箭头函数属于表达式，只有变量的提升而没有函数体的提升，赋值之前调用会抛 TypeError: f is not a function。调用时 JS 也不校验参数个数和类型：多传的参数被忽略（可用 arguments 或剩余参数 ...args 取到），少传的参数值是 undefined，因此形参默认值要用 ES6 的 function f(a = 1) {}，不要靠手动判断。

this 是 JS 最反直觉的部分，记住一条：普通函数的 this 由「调用方式」决定，而非定义位置。obj.fn() 中 this 指向 obj；把方法单独取出写成 const g = obj.fn; g()，this 就变成 undefined（严格模式）或全局对象；用 new 调用则指向新创建的对象。箭头函数没有自己的 this 和 arguments，它捕获定义时外层作用域的 this（词法绑定），所以特别适合写回调和 setTimeout，但也因此不能用 call/apply 改变指向，不能当构造函数。

闭包是「函数 + 它定义时所处的作用域」的组合：内层函数引用了外层的变量，即使外层函数已经执行完毕，这些变量依然留在内存中可被访问。它带来两个能力——把变量变成外部拿不到的私有状态，以及把状态在多次调用之间保存下来（函数记忆、防抖节流都依赖它）。代价是对应的变量不会被回收，若闭包长期持有大对象或 DOM 节点，就可能造成内存泄漏，必要时在不再使用后手动把引用置为 null。经典陷阱是循环里的 var：var 没有块级作用域，三个回调捕获的是同一个 i，输出全是 3；换成 let 后每轮迭代都有独立的绑定，输出 0、1、2。

function createCounter() {
  let count = 0;                 // 被闭包记住的私有变量
  return () => ++count;          // 返回的函数仍然能访问 count
}
const next = createCounter();
next();  // 1
next();  // 2
// count;  // ReferenceError：外部无法直接访问

// 经典陷阱：var 没有块级作用域
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);   // 3 3 3
}
for (let j = 0; j < 3; j++) {
  setTimeout(() => console.log(j), 0);   // 0 1 2
}

// 防抖：事件停止触发 delay 毫秒后才真正执行一次
function debounce(fn, delay) {
  let timer = null;
  return function (...args) {
    clearTimeout(timer);                 // 每次触发都重置计时
    timer = setTimeout(() => fn.apply(this, args), delay);
  };
}
// window.onresize = debounce(() => console.log('resize end'), 300);

三、对象、原型与 class

JS 的对象本质是「键值对集合」，键只能是字符串或 symbol，读取时 obj.a 与 obj['a'] 等价（键名含特殊字符或来自变量时必须用后者）。对象字面量 {} 比 new Object() 更简洁常用，同理数组应写 [1, 2] 而不是 new Array(1, 2)——后者的参数语义还很坑：new Array(3) 得到的是长度为 3 的空数组，而不是 [3]。

属性查找靠原型链：每个对象都有一个内部引用 [[Prototype]]（通过 Object.getPrototypeOf() 读取），访问属性时先查自身，找不到就沿着原型链往上找，直到值为 null 为止。要区分两个容易混淆的东西：函数的 prototype 属性是给 new 出来的实例当原型用的，而对象的原型要用 [[Prototype]]/__proto__ 访问，二者不是一回事。老笔记常写「JS 是基于对象的语言」，更准确的说法是：JS 是基于原型的面向对象语言，它没有 Java 那样的类继承，ES6 的 class 只是原型继承的语法糖，底层依旧是构造函数加原型对象。instanceof 判断的也不是「由谁创建」，而是「构造函数的 prototype 是否出现在对象的原型链上」，所以判断数组更可靠的是 Array.isArray()。

用 class 书写时有三点与 Java 不同：类声明不会被提升（存在 TDZ），必须先定义后使用；类体内的代码默认运行在严格模式下；子类必须在构造函数里先调用 super() 才能使用 this。ES2022 起支持 #字段 私有成员，这才是语言层面的真私有——此前只能靠闭包或 WeakMap 模拟，而用「构造函数里保存私有变量」的写法会让每个实例都重新创建一份特权方法，内存开销更大。

function Person(name) {
  this.name = name;
}
Person.prototype.say = function () {
  return 'I am ' + this.name;
};

const p = new Person('Tom');
p.say();                                        // 'I am Tom'
Object.getPrototypeOf(p) === Person.prototype;  // true
p instanceof Person;                            // true

class Student extends Person {          // class 只是原型继承的语法糖
  #score = 0;                           // 私有字段，外部无法访问
  constructor(name, score) {
    super(name);                        // 必须先调用 super 才能用 this
    this.#score = score;
  }
  say() {                               // 重写父类方法
    return super.say() + ', score ' + this.#score;
  }
  static of(name, score) {               // 静态方法属于类本身
    return new Student(name, score);
  }
}
Student.of('Jerry', 90).say();           // 'I am Jerry, score 90'

四、数组与高阶函数

数组是项目里用得最多的结构，真正要熟练的是 map、filter、reduce、some、every、find、flat 这几个高阶方法。它们的回调统一接收 (当前元素, 索引, 原数组) 三个参数，且都不修改原数组，返回新值（会改原数组的是 sort、splice、reverse，用之前要留意）。几个边界值必须记牢：some 对空数组恒返回 false，every 对空数组恒返回 true（逻辑上的「空真」）；reduce 不传初始值时以第一个元素为初始值，对空数组会直接抛 TypeError，所以求和、计数这类场景务必显式传初始值。flat 默认只降一层，传 Infinity 才能彻底拍平——有些笔记把它拼成 Inifity，那是笔误，正确拼写是 Infinity。

另一个常见疑问是 map(callback, thisArg) 的第二个参数：它用来指定回调里的 this，但如果回调写成箭头函数，箭头函数按词法绑定 this，这个参数就完全失效了。这也是「回调优先用箭头函数，但需要自定义 this 时改用普通函数」这条经验规则的由来。

const nums = [1, 2, 3, 4];

nums.map(n => n * 2);                  // [2, 4, 6, 8]，长度不变
nums.filter(n => n % 2 === 0);         // [2, 4]
nums.reduce((sum, n) => sum + n, 0);   // 10，0 是初始值
nums.some(n => n > 3);                 // true：存在满足条件的元素
nums.every(n => n > 0);                // true：所有元素都满足
[].some(() => true);                   // false
[].every(() => false);                 // true：空数组的 every 恒为 true

// 用 reduce 实现 map，体会「归约」的通用性
const myMap = (arr, fn) => arr.reduce((acc, item, i) => {
  acc.push(fn(item, i, arr));
  return acc;
}, []);
myMap(nums, n => n + 1);               // [2, 3, 4, 5]

[[1, [2]], [3]].flat(Infinity);        // [1, 2, 3]

五、模块化与异步：把脚本写成工程

早期的 JS 没有模块体系，所有脚本共享一个全局作用域，于是开发者用立即执行函数加闭包来「造」模块，把变量藏在函数内部只暴露必要的接口。后来 Node.js 带来了 CommonJS（require 引入、module.exports 导出，运行时同步加载，只能在 Node 环境用），浏览器端则出现过 AMD（RequireJS）和 CMD 等方案。现在的主流是 ES Module：export 导出、import 引入，它是静态语法，必须写在模块顶层，打包工具能在编译阶段就分析出依赖关系并做 tree-shaking。export default 与具名导出不要在同一个文件里混着乱用，CommonJS 的 require 和 ESM 的 import 也不要塞进同一个文件。需要强调的是，webpack 是「静态模块打包器」，负责从入口出发递归构建依赖图并输出 bundle；它本身不是模块规范，Vue CLI 默认内置它也只是一种工程选择，与 ES Module 语法本身无关。

异步编程经历了回调函数 → Promise → async/await 三代。await 只能等待 Promise（更准确说是 thenable），它会让所在函数暂停，但不阻塞主线程；Promise 的失败状态必须处理，用 try/catch 包住 await，或补上 .catch()，否则会触发 unhandledrejection。最容易写出性能问题的地方是把彼此独立的请求用 await 一个个串起来，白白累加等待时间，正确做法是 Promise.all([...]) 并发发起。Promise.all 是「一个失败整体失败」，需要全部结果无论成败时用 Promise.allSettled；Node 里那些 error-first 风格的回调 API（如 fs.readFile）可以用 util.promisify 一键转成 Promise。

小结：本章围绕五个基础点做了梳理：变量用 const 优先、let 次之，比较用 ===，类型判断绕开 typeof null 这个历史坑；函数的 this 看调用方式，箭头函数按词法绑定；闭包既能做私有状态也会延长变量生命周期，循环配 let 才不会全体指向同一个值；对象靠原型链查找属性，class 只是语法糖，判数组用 Array.isArray；数组高阶函数不改原数组，注意 every 空数组为 true、reduce 记得给初始值；模块化统一用 ES Module，异步优先 async/await 并用 Promise.all 并发。把这些规则变成肌肉记忆后，再学 Vue、webpack 或 Node，就不会被语言层面的意外绊住。
