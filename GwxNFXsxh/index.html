ClickHouse-2初识

Posted on 2021-11-13，5 min read

一、简介

1.1 ClickHouse 是什么？

ClickHouse 是 Yandex（俄罗斯最大的搜索引擎）开源的一个用于实时数据分析的基于列存储的数据库，其处理数据的速度比传统方法快 100-1000 倍。ClickHouse 的性能超过了目前市场上可比的面向列的 DBMS，每台服务器每秒可处理数亿至十亿多行、数十吉字节的数据。

1.2 ClickHouse的一些特性：

  1. 快速：ClickHouse 会充分利用所有可用的硬件，以尽可能快的速度处理每个查询。单个查询的峰值处理性能超过每秒 2 TB（解压缩后，仅使用的列）。在分布式部署中，读取会在健康副本之间自动平衡，以避免增加延迟。
  2. 容错：ClickHouse 支持多主机异步复制，并且可以跨多个数据中心部署。所有节点地位平等，可以避免出现单点故障。单个节点或整个数据中心的停机不会影响系统的读写可用性。
  3. 可伸缩：ClickHouse 可以在垂直和水平方向上很好地扩展。它既可以在具有数百或数千个节点的集群上运行，也可以在单台服务器甚至小型虚拟机上运行。目前，单节点安装的数据量可以超过数万亿行或数百 TB。
  4. 易用：ClickHouse 简单易用，开箱即用。它简化了所有数据处理：将结构化数据导入系统后，就可以立即用于构建报表。用 SQL 就能表达期望的结果，无需使用某些 DBMS 中的自定义非标准 API。
  5. 充分利用硬件：与具有相同可用 I/O 吞吐量和 CPU 容量的传统面向行系统相比，ClickHouse 处理典型的分析查询要快两到三个数量级。列式存储格式允许在 RAM 中容纳更多热数据，从而缩短响应时间。
  6. 提高 CPU 效率：向量化查询执行会用到相关的 SIMD 处理器指令和运行时代码生成。按列处理数据可以提高 CPU 缓存的命中率。
  7. 优化磁盘访问：ClickHouse 可以最大程度地减少范围查询的次数；由于数据保持连续存储，使用机械硬盘时的效率也更高。
  8. 最小化数据传输：ClickHouse 使公司无需使用专门针对高性能计算的专用网络即可管理其数据。

何时使用 ClickHouse：
适合分析结构良好、不可变的事件流或日志流：建议每一类流都写入一张预先连接好维度的宽表中。
何时不使用 ClickHouse：
不适合事务性工作负载（OLTP）、高价值的键值请求、Blob 或文档存储。

1.3 为什么 ClickHouse 速度这么快？

首先我们了解一下 OLAP 场景的特点：

  1. 读多于写。
  2. 大宽表，读大量行但是少量列，结果集较小。
  3. 数据批量写入，且数据不更新或少更新。

针对分析类查询，通常只需要读取表的一小部分列。在列式数据库中，你可以只读取需要的数据。例如，如果只需要读取 100 列中的 5 列，这将帮助你至少减少 20 倍的 I/O 消耗。

由于数据总是按批打包读取，压缩也就非常容易；同时数据按列分别存储，也更利于压缩。这进一步降低了 I/O 的数据量，从而让更多数据可以被系统缓存。

例如，查询「统计每个广告平台的记录数量」需要读取「广告平台 ID」这一列，它在未压缩的情况下需要 1 个字节进行存储。如果大部分流量不是来自广告平台，那么这一列至少可以获得十倍的压缩率。当采用快速压缩算法时，它的解压速度至少为十亿字节（未压缩数据）每秒。换句话说，这个查询可以在单个服务器上以每秒大约几十亿行的速度进行处理，这实际上就是当前实现的速度。

ClickHouse 从 OLAP 场景需求出发，定制开发了一套全新的高效列式存储引擎。

column-oriented（图片来源见水印）

相比于行式存储，列式存储在分析场景下有着许多优良的特性。

  1. 如前所述，分析场景中往往需要读大量行但是少数几个列。在行存模式下，数据按行连续存储，所有列的数据都存储在一个 block 中，不参与计算的列在 IO 时也要全部读出，读取操作被严重放大。而列存模式下，只需要读取参与计算的列即可，极大的减低了 IO cost，加速了查询。
  2. 同一列中的数据属于同一类型，压缩效果显著。列存往往有着高达十倍甚至更高的压缩比，节省了大量的存储空间，降低了存储成本。
  3. 更高的压缩比意味着更小的 data size，从磁盘中读取相应数据耗时更短。
  4. 自由的压缩算法选择。不同列的数据具有不同的数据类型，适用的压缩算法也就不尽相同。可以针对不同列类型，选择最合适的压缩算法。
  5. 高压缩比，意味着同等大小的内存能够存放更多数据，系统 cache 效果更好。
