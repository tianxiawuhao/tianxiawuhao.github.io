常用工具类

Posted on 2026-09-19，9 min read

写业务代码时，真正占篇幅的往往不是业务逻辑，而是判空、拼接、类型转换、属性拷贝这些重复劳动。一个 Service 里塞进十几个 if (str != null && !"".equals(str.trim()))，代码就变得又长又难读。工具类要解决的正是这个问题：把高频、易错的通用操作收敛成一行调用。

本章梳理 Java 项目里最常用的几类工具库——Apache Commons Lang、Apache Commons Collections、Apache Commons BeanUtils、Spring 的 BeanUtils 与 DigestUtils，以及 JDK 自带的 Objects 和 UUID。如果你已经能写基本的分支循环，但还在手写判空和 get/set 拷贝，这一章会明显提升你的代码质量与阅读速度。

一、StringUtils：判断空字符串的正确姿势

字符串判空是最典型的例子。JDK 的 String.isBlank()（Java 11 起）只判断是否为空或全为空白字符，长度为零才返回 true；Apache Commons Lang3 的 StringUtils 则提供了更符合业务语义的一组方法：

  • isEmpty(CharSequence)：长度为 0 或为 null 时返回 true，不做 trim。
  • isBlank(CharSequence)：null、空串、以及只包含空白字符时都返回 true，等价于先 trim 再判空。
  • isNotBlank / isNotEmpty：对应的取反方法。
  • defaultIfBlank(str, "默认值")：为空时给默认值，比三目运算清晰。
  • join(数组, 分隔符)、split(str, 分隔符)、trimToNull(str)、capitalize(str)：拼接、切分、去空白转 null、首字母大写。

需要注意，Spring 也有一份 org.springframework.util.StringUtils，它没有 isBlank，判断依据是 hasText（非空白）与 hasLength（长度大于 0）。两个同名类经常被同时引入，写代码时务必看清 import 来源，否则会遇到「方法明明存在却编译不通过」的困惑。

import org.apache.commons.lang3.StringUtils;

public class StringDemo {
    public static void main(String[] args) {
        System.out.println(StringUtils.isEmpty("  "));   // false，空格不算空
        System.out.println(StringUtils.isBlank("  "));   // true，trim 后为空
        System.out.println(StringUtils.isBlank(null));   // true，null 安全

        // 业务里更常用的写法：为空就取默认值
        String name = StringUtils.defaultIfBlank("  ", "匿名用户");
        System.out.println(name);                        // 匿名用户

        // 拼接与切分
        String joined = StringUtils.join(new String[]{"a", "b", "c"}, "-");
        System.out.println(joined);                      // a-b-c
        System.out.println(StringUtils.trimToNull("   ") == null); // true
    }
}

另外，org.apache.commons.lang3.StringEscapeUtils 已经废弃，官方建议迁移到 org.apache.commons.text.StringEscapeUtils（即 commons-text 包）。它的 escapeHtml4 用于把 <div> 这类内容转成 HTML 实体以输出到页面，escapeXml、escapeJson、escapeJava 分别对应不同场景；转义方向别记反：escape* 是「原文 → 实体」，unescape* 才是「实体 → 原文」。注意它只做转义，不能替代参数化查询或输出编码等安全手段。

二、集合、数组与 IO 工具

集合工具类里最常用的是 org.apache.commons.collections4.CollectionUtils（Commons Collections 3 的包名是 org.apache.commons.collections，两者 API 包路径不同，别混用）。它解决了 JDK 集合 API 的两处不顺手：判空要写两遍，以及筛选、转换只能靠手写循环。

  • isEmpty / isNotEmpty：一次性处理 null 与空集合，省掉一个 == null 判断。
  • select：按条件筛选，返回新集合，原集合不受影响；filter 语义相近。
  • transform：对每个元素做转换，返回新集合，作用类似 Stream 的 map。
  • isEqualCollection：忽略顺序比较两个集合的元素是否一致。
  • CollectionUtils.emptyIfNull(list)：把 null 换成空集合，避免调用方到处判空。

数组与文件方面，org.apache.commons.lang3.ArrayUtils 提供 contains、add、addAll、subarray、indexOf、isEquals、isEmpty 等方法；org.apache.commons.io.FileUtils 与 IOUtils 负责文件与流的读写、复制、静默关闭，其中 closeQuietly 常放在 finally 块里 closeQuietly，而 FileUtils.deleteQuietly、forceMkdir、readFileToString、writeStringToFile 是使用频率最高的几个。Java 7 之后有 try-with-resources，新代码优先用它管理流，IOUtils 更多用于流拷贝与编码转换。

import org.apache.commons.collections4.CollectionUtils;
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

public class CollectionDemo {
    public static void main(String[] args) {
        List<Integer> nums = Arrays.asList(1, 2, 3, 4, 5, 6);

        // 筛选偶数：无需手写 for 循环和临时集合
        List<Integer> evens = new ArrayList<>(
                CollectionUtils.select(nums, n -> n % 2 == 0));
        System.out.println(evens);                       // [2, 4, 6]

        // 判空与去 null：Controller 接收参数后立刻规整
        List<String> tags = null;
        for (String tag : CollectionUtils.emptyIfNull(tags)) {
            System.out.println(tag);                     // 不会抛 NPE，直接不循环
        }
        System.out.println(CollectionUtils.isEmpty(tags)); // true
    }
}

日期与随机数：别再用过时的 Calendar

日期时间的推荐做法是直接用 java.time（Java 8 起）：LocalDateTime.now()、DateTimeFormatter.ofPattern("yyyy-MM-dd HH:mm:ss")、Duration.between(a, b)。旧项目里常见的 java.util.Date 与 SimpleDateFormat 有两个硬伤：Date 的月份从 0 开始、年份需要减去 1900，极易出错；SimpleDateFormat 不是线程安全的，作为静态字段共享会在并发下产生错乱结果甚至抛异常。

随机数与唯一标识方面，UUID.randomUUID().toString().replace("-", "") 可以生成 32 位十六进制字符串作业务主键或幂等键。安全敏感的随机数（验证码、令牌、盐值）必须用 java.security.SecureRandom，而不是 java.util.Random，因为后者的种子可被推导。org.apache.commons.lang3.RandomStringUtils.randomNumeric(length) 适合生成纯数字串，它不保证首位非 0，需要定长数字编号时记得自行补齐或校验。摘要计算推荐 org.apache.commons.codec.digest.DigestUtils：md5Hex、sha256Hex 返回十六进制字符串，sha512Hex 对应 SHA-512；而 DigestUtils.md5(String) 返回的是 16 字节数组 byte[]，不是「16 位字符串」，需要字符串时请用 md5Hex。

三、BeanUtils：属性拷贝与它的三个坑

实体类（Entity/PO）与展示对象（VO/DTO）字段高度重合，逐个 get/set 赋值既啰嗦又容易漏字段。BeanUtils.copyProperties 利用反射与自省机制按属性名自动拷贝，一行顶十几行。但它的参数顺序是新手最容易踩的坑：

  • org.apache.commons.beanutils.BeanUtils.copyProperties(目标对象, 源对象)：目标在前、源在后。
  • org.springframework.beans.BeanUtils.copyProperties(源对象, 目标对象)：源在前、目标在后。

两个同名方法参数顺序完全相反，写反了不会报错，只会静默地把字段拷成 null，排查起来非常费时。除此之外还有两个坑：一是它只拷贝同名同类型的属性，源和目标字段名不一致时不会自动映射，需要手动赋值或用 MapStruct、Dozer 这类映射框架；二是反射拷贝在批量循环中性能不如直接赋值，同时要注意不要因过度使用而破坏封装，把不该暴露的内部字段带到对外接口上。

public class User {
    private String name;
    private Integer age;
    // 省略 getter / setter
    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
    public Integer getAge() { return age; }
    public void setAge(Integer age) { this.age = age; }
}

public class UserVO {
    private String name;
    private Integer age;
    // 省略 getter / setter
    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
    public Integer getAge() { return age; }
    public void setAge(Integer age) { this.age = age; }
}
import org.springframework.beans.BeanUtils;

public class CopyDemo {
    public static void main(String[] args) {
        User user = new User();
        user.setName("张三");
        user.setAge(20);

        UserVO vo = new UserVO();
        // Spring：源在前、目标在后
        BeanUtils.copyProperties(user, vo);
        System.out.println(vo.getName());   // 张三

        // Commons BeanUtils 的顺序恰好相反，切勿照搬：
        // org.apache.commons.beanutils.BeanUtils.copyProperties(vo, user);
    }
}

如果两个类结构差距很大，用 JSON 中转也很常见：先用 Fastjson 或 Jackson 把源对象序列化成字符串，再反序列化成目标类型（JSON.parseObject(json, UserVO.class)）。这种方式只要求属性名一致、不要求类型继承关系，代价是多一次序列化开销，且字段名不匹配时同样会丢数据。

四、JDK 自带的 Objects 与密码工具

在引入第三方库之前，先看看 JDK 已经提供了什么。java.util.Objects 从 Java 7 起就覆盖了大部分判空与比较场景，无需任何依赖：

  • Objects.equals(a, b)：内存地址相同或 a.equals(b) 为 true 即返回 true，参数可为 null。
  • Objects.deepEquals(a, b)：数组会比较对应下标的值。
  • Objects.hashCode(o)：o 为 null 时返回 0；Objects.hash(values...) 用于重写 hashCode。
  • Objects.toString(o, nullDefault)：null 时返回默认值。
  • Objects.requireNonNull(obj, "message")：为 null 时抛出带信息的 NullPointerException，适合做方法入口的参数校验。

密码存储是另一个必须用工具类而非自研算法的场景。MD5、SHA 系列都是快速摘要算法，加不加盐都扛不住现代硬件的暴力破解和彩虹表。Spring Security 提供的 BCryptPasswordEncoder 内置随机盐与可调计算强度，是更合适的选择：

import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;
import org.springframework.security.crypto.password.PasswordEncoder;
import java.util.Objects;

public class PasswordDemo {
    public static void main(String[] args) {
        PasswordEncoder encoder = new BCryptPasswordEncoder();
        String raw = "111111";

        String hash1 = encoder.encode(raw);
        String hash2 = encoder.encode(raw);
        // 每次 encode 都含随机盐，两次结果不同
        System.out.println(Objects.equals(hash1, hash2)); // false
        // 但用 matches 校验都能通过：数据库只存 hash，不存原文
        System.out.println(encoder.matches(raw, hash1));  // true
        System.out.println(encoder.matches(raw, hash2));  // true
    }
}

所以校验密码只能调用 matches(原文, 密文)，绝不能用「把用户输入重新加密后与数据库字符串做 equals」的方式比对——随机盐会让这种比较永远失败。另外，BCrypt 密文本身就包含盐与强度信息，长度约 60 字符，建库时字段宽度要给足（varchar(100) 更稳妥）。

五、小结

工具类的价值在于把容易写错的细节封装起来：StringUtils.isBlank 区分了「空串」与「空白串」，CollectionUtils 省掉了判空和手写循环，BeanUtils.copyProperties 消灭了成片的 get/set，Objects 与 java.time 让你不必依赖第三方库就能写好判空和日期。选择时优先用 JDK 自带 API，其次用社区活跃、维护正常的库；已经废弃的类（如 commons-lang3 的 StringEscapeUtils）要按官方指引迁移。命名上遵循惯例，工具类放在 util 包下并命名为 XxxUtils，与实体类区分开。

最后提醒两点：工具类都是静态方法，天然无状态，不要在其中保存可变成员，否则会引入并发问题；使用第三方库时务必在构建文件里声明依赖并统一版本（Maven 的 commons-lang3、commons-collections4、commons-beanutils 坐标），避免同一个库出现多个版本导致 NoSuchMethodError。
