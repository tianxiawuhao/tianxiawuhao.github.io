ExecutorCompletionService

Posted on 2022-03-19，9 min read

Future 回顾

Future 模式是多线程设计中常用的一种设计模式：把任务交给一个「凭据」，自己先去忙别的事，之后拿着凭据去取结果。Java 里这个凭据就是 Future。

Future 提供的三种功能

  • isDone() / isCancelled()：判断任务是否完成。
  • cancel(boolean)：尝试中断任务（能否真正停下取决于任务是否响应中断）。
  • get() / get(long, TimeUnit)：获取执行结果，前者会一直阻塞。

关键差异在于：线程池的 submit 不阻塞，而 Future.get() 阻塞。当提交一批任务后按提交顺序逐个 get，只要第一个任务耗时最长，后面已经完成的任务也拿不到结果，整体耗时被拖成「最慢的那个任务」。get(long, TimeUnit) 可以加超时避免无限等待，但依然没有解决顺序问题。

典型的三段式写法是：① 提交多线程任务 → ② 处理其他事 → ③ 收集结果。Future 本身没有完成通知机制，第 ③ 步只能二选一：要么在 get() 处阻塞，异步又退回同步；要么用 isDone() 轮询，白白消耗 CPU。

要「按任务完成的先后顺序拿结果」，有两条路：ExecutorCompletionService 和 CompletableFuture。本文讲前者。

ExecutorService：按提交顺序取结果的写法

下面这段代码模拟「开车依次接人」：三个人上厕所耗时分别是 10 秒、6 秒、3 秒，结果按提交顺序打印，所以必须等最慢的总裁先出来。

public static void test1() throws Exception {
    ExecutorService executorService = Executors.newCachedThreadPool();
    ArrayList<Future<String>> futureArrayList = new ArrayList<>();
    System.out.println("公司让你通知大家聚餐 你开车去接人");

    Future<String> future10 = executorService.submit(() -> {
        System.out.println("总裁：我在家上大号 我最近拉肚子比较慢 要蹲1个小时才能出来 你等会来接我吧");
        TimeUnit.SECONDS.sleep(10);
        System.out.println("总裁：1小时了 我上完大号了。你来接吧");
        return "总裁上完大号了";
    });
    futureArrayList.add(future10);

    Future<String> future6 = executorService.submit(() -> {
        System.out.println("中层管理：我在家上大号  要蹲10分钟就可以出来 你等会来接我吧");
        TimeUnit.SECONDS.sleep(6);
        System.out.println("中层管理：10分钟 我上完大号了。你来接吧");
        return "中层管理上完大号了";
    });
    futureArrayList.add(future6);

    Future<String> future3 = executorService.submit(() -> {
        System.out.println("研发：我在家上大号 我比较快 要蹲3分钟就可以出来 你等会来接我吧");
        TimeUnit.SECONDS.sleep(3);
        System.out.println("研发：3分钟 我上完大号了。你来接吧");
        return "研发上完大号了";
    });
    futureArrayList.add(future3);

    TimeUnit.SECONDS.sleep(1);
    System.out.println("都通知完了,等着接吧。");
    try {
        for (Future<String> future : futureArrayList) {   // 按提交顺序 get
            String returnStr = future.get();
            System.out.println(returnStr + "，你去接他");
        }
    } catch (Exception e) {
        e.printStackTrace();
    } finally {
        executorService.shutdown();
    }
}

ExecutorCompletionService 登场

把线程池包一层 ExecutorCompletionService，用 submit 提交、用 take 取结果，顺序就变成了完成顺序：谁先干完谁先被取走。

public static void test2() throws Exception {
    ExecutorService executorService = Executors.newCachedThreadPool();
    ExecutorCompletionService<String> completionService =
            new ExecutorCompletionService<>(executorService);
    System.out.println("公司让你通知大家聚餐 你开车去接人");

    completionService.submit(() -> {
        System.out.println("总裁：我在家上大号 我最近拉肚子比较慢 要蹲1个小时才能出来 你等会来接我吧");
        TimeUnit.SECONDS.sleep(10);
        System.out.println("总裁：1小时了 我上完大号了。你来接吧");
        return "总裁上完大号了";
    });
    completionService.submit(() -> {
        System.out.println("中层管理：我在家上大号  要蹲10分钟就可以出来 你等会来接我吧");
        TimeUnit.SECONDS.sleep(6);
        System.out.println("中层管理：10分钟 我上完大号了。你来接吧");
        return "中层管理上完大号了";
    });
    completionService.submit(() -> {
        System.out.println("研发：我在家上大号 我比较快 要蹲3分钟就可以出来 你等会来接我吧");
        TimeUnit.SECONDS.sleep(3);
        System.out.println("研发：3分钟 我上完大号了。你来接吧");
        return "研发上完大号了";
    });

    TimeUnit.SECONDS.sleep(1);
    System.out.println("都通知完了,等着接吧。");
    try {
        // 提交了几个任务就取几次；take() 阻塞直到有任务完成
        for (int i = 0; i < 3; i++) {
            String returnStr = completionService.take().get();
            System.out.println(returnStr + "，你去接他");
        }
    } catch (Exception e) {
        e.printStackTrace();
    } finally {
        executorService.shutdown();
    }
}

运行结果：3 秒的研发最先被接走，6 秒的中层第二，10 秒的总裁最后，接人顺序与完成顺序一致。

submit 与 take / poll 的语义

先看类里到底有什么。除了构造方法，ExecutorCompletionService 只暴露两类方法：

public class ExecutorCompletionService<V> implements CompletionService<V> {
    public Future<V> submit(Callable<V> task);           // 提交并返回原任务的 Future
    public Future<V> submit(Runnable task, V result);
    public Future<V> take() throws InterruptedException; // 阻塞取「已完成」任务，队列空则等待
    public Future<V> poll();                             // 非阻塞取，队列空返回 null
    public Future<V> poll(long timeout, TimeUnit unit)   // 限时等待，超时返回 null
            throws InterruptedException;
}

三个取结果方法的行为要分清楚：

  • take()：队列为空时一直阻塞，直到有任务完成或被中断（抛 InterruptedException）。适合「知道自己提交了几个任务，就取几次」的场景。
  • poll()：立即返回，没有已完成的任务时返回 null，不会阻塞。必须判空，否则紧接着的 .get() 会抛 NullPointerException。
  • poll(timeout, unit)：最多等 timeout，超时返回 null。适合「等不到就放弃」的场景。

两点容易忽略的语义：其一，返回的 Future 就是原来那个 FutureTask，get() 拿到的是任务真正的返回值，而不是队列里的什么东西；其二，任务抛异常也算「完成」，同样会被放进队列，此时 get() 会抛出包装后的 ExecutionException（原始异常可用 e.getCause() 取到）。take() 不区分成功与失败，异常必须靠 get() 暴露出来——只 take() 不 get()，异常会被静静吞掉。

异常与超时处理

由于结果可能失败，工程代码里不能只写一个 for 循环就完事。下面是一份可直接编译运行的完整示例，包含任务异常、单个任务超时以及整体退出三类处理。

import java.util.concurrent.*;

public class CompletionServiceDemo {

    static String work(String name, long seconds, boolean fail) throws Exception {
        TimeUnit.SECONDS.sleep(seconds);
        if (fail) {
            throw new IllegalStateException(name + " 拉肚子太严重，去不了");
        }
        return name + " 上完大号了";
    }

    public static void main(String[] args) throws Exception {
        ExecutorService pool = Executors.newFixedThreadPool(4);
        CompletionService<String> cs = new ExecutorCompletionService<>(pool);
        int submitted = 0;

        cs.submit(() -> work("研发", 3, false));      submitted++;
        cs.submit(() -> work("中层管理", 6, false));   submitted++;
        cs.submit(() -> work("总裁", 10, false));      submitted++;
        cs.submit(() -> work("实习生", 1, true));      submitted++;   // 这个会失败

        int finished = 0;
        while (finished < submitted) {
            Future<String> f = cs.poll(12, TimeUnit.SECONDS);   // 整体限时，防无限等待
            if (f == null) {
                System.out.println("超过 12 秒还有任务没回来，放弃等待");
                break;
            }
            finished++;
            try {
                // 单任务超时：已经完成的 Future 会立刻返回，这里只是兜底
                System.out.println("接到：" + f.get(1, TimeUnit.SECONDS));
            } catch (ExecutionException e) {
                System.out.println("任务失败：" + e.getCause().getMessage());
            } catch (TimeoutException e) {
                System.out.println("单任务取结果超时，跳过");
            }
        }

        pool.shutdown();
        if (!pool.awaitTermination(5, TimeUnit.SECONDS)) {
            pool.shutdownNow();
        }
    }
}

预期输出顺序为：实习生失败 → 研发 → 中层管理 → 总裁，失败的任务不会卡住后面的结果回收：

任务失败：实习生 拉肚子太严重，去不了
接到：研发 上完大号了
接到：中层管理 上完大号了
接到：总裁 上完大号了

注意最后两句：shutdown() 只是不再接新任务，awaitTermination() 才负责等待已有任务收尾，超时再 shutdownNow() 打断，这样进程不会因为还有非守护线程而挂着不退出。

源码分析

ExecutorCompletionService 位于 java.util.concurrent 包下，整个类不到 200 行，核心只有两点：一个阻塞队列 + 一个重写了 done() 的内部 FutureTask。

初始化线程池

  1. 构造时同步创建一个完成队列 completionQueue，默认实现是 LinkedBlockingQueue（无界）；同时判断传入的 executor 是否为 AbstractExecutorService，是则缓存下来以复用其 newTaskFor。
public ExecutorCompletionService(Executor executor) {
    if (executor == null)
        throw new NullPointerException();
    this.executor = executor;
    this.aes = (executor instanceof AbstractExecutorService) ?
        (AbstractExecutorService) executor : null;
    this.completionQueue = new LinkedBlockingQueue<Future<V>>();
}

执行 submit 方法

  1. 提交时先用 newTaskFor 把任务包装成 RunnableFuture，再把它包进 QueueingFuture 交给线程池执行。交给线程池的是「包装后的任务」，而返回给调用方的是原来那个 Future，两者共享同一个执行结果。
public Future<V> submit(Callable<V> task) {
    if (task == null) throw new NullPointerException();
    RunnableFuture<V> f = newTaskFor(task);
    executor.execute(new QueueingFuture<V>(f, completionQueue));
    return f;
}
  1. QueueingFuture 继承 FutureTask，构造函数里 super(task, null) 把真正的任务交给父类执行（所以它的泛型是 Void，结果仍存在内部那个 task 上）。关键在于它重写了 done()：任务结束（无论正常结束、异常还是取消）时把 task 放进阻塞队列。
private static class QueueingFuture<V> extends FutureTask<Void> {
    QueueingFuture(RunnableFuture<V> task,
                   BlockingQueue<Future<V>> completionQueue) {
        super(task, null);
        this.task = task;
        this.completionQueue = completionQueue;
    }
    private final Future<V> task;
    private final BlockingQueue<Future<V>> completionQueue;
    protected void done() { completionQueue.add(task); } // 完成后入队
}
  1. done() 由 FutureTask 在状态转为终态时回调。任务提交后线程池执行的是 run()：正常结束走 set(result)，抛异常走 setException(ex)，取消则直接进入终态。
public void run() {
    if (state != NEW ||
        !RUNNER.compareAndSet(this, null, Thread.currentThread()))
        return;
    try {
        Callable<V> c = callable;
        if (c != null && state == NEW) {
            V result;
            boolean ran;
            try {
                result = c.call();
                ran = true;
            } catch (Throwable ex) {
                result = null;
                ran = false;
                setException(ex);
            }
            if (ran)
                set(result);              // 设置值，随后触发 finishCompletion
        }
    } finally {
        runner = null;
        int s = state;
        if (s >= INTERRUPTING)
            handlePossibleCancellationInterrupt(s);
    }
}
  1. set 把状态从 NEW 推到 COMPLETING → NORMAL，写入结果后调用 finishCompletion()。
protected void set(V v) {
    if (STATE.compareAndSet(this, NEW, COMPLETING)) {
        outcome = v;
        STATE.setRelease(this, NORMAL);   // 终态，结果对其它线程可见
        finishCompletion();
    }
}
  1. finishCompletion() 唤醒所有在 get() 上排队的线程，然后调用 done()——这正是 QueueingFuture 把结果送进完成队列的位置。
private void finishCompletion() {
    for (WaitNode q; (q = waiters) != null;) {
        if (WAITERS.weakCompareAndSet(this, q, null)) {
            for (;;) {
                Thread t = q.thread;
                if (t != null) {
                    q.thread = null;
                    LockSupport.unpark(t);      // 唤醒阻塞在 get() 的线程
                }
                WaitNode next = q.next;
                if (next == null)
                    break;
                q.next = null;                  // unlink to help gc
                q = next;
            }
            break;
        }
    }

    done();                 // 执行 done()：completionQueue.add(task)

    callable = null;        // to reduce footprint
}

所以整条链路是：submit → QueueingFuture → 线程池执行 → 任务终态 → finishCompletion → done() → completionQueue.add(task)。每完成一个任务，队列里就多一条记录，take() 从这个队列里按完成顺序取，取出来的 Future 与提交时返回的 Future 是同一个对象。

Future<String> submit = completionService.submit(() -> {
    return "假装有返回";
});
submit.get();   // 直接取返回值，不经过 take()

如上所述，如果使用过程中只需要当前任务的返回值，于是从不调用 take() / poll()，那么 completionQueue 里的记录永远不会被消费（LinkedBlockingQueue 默认无界），已完成的任务对象会持续堆积，任务量大时就会 OOM。凡是用了 ExecutorCompletionService，就必须保证「提交几次、取几次」。

与 invokeAll / invokeAny / CompletableFuture 的取舍

  • ExecutorCompletionService：需要「谁先完成先处理谁」，处理逻辑又比较重（写库、发通知）时最合适。只需一个线程池，取结果的过程天然串行，方便做限流和聚合。缺点是结果必须靠调用方循环取，容易漏取导致队列堆积。
  • invokeAll：一次提交一批任务并阻塞到全部完成，返回的 List 顺序与提交顺序一致，每个 Future 都已完成，get() 不会阻塞。适合「批处理、只要最终结果」。它无法感知完成顺序，中途也拿不到部分结果。
  • invokeAny：只返回第一个成功完成的任务结果，其余任务被取消。适合「多个数据源任取其一」「接口竞速」这类只要一个答案的场景。
  • CompletableFuture：需要编排（thenApply / thenCombine / allOf / anyOf）、串行依赖、异常恢复（exceptionally / handle）时更合适，回调式无需手动循环。代价是错误处理与线程上下文（默认共用 ForkJoinPool.commonPool）需要额外留意；只做 CompletionService 那点事，它偏重。
// 只要一个答案：invokeAny
String fastest = executor.invokeAny(Arrays.asList(
        () -> queryFromPrimary(),
        () -> queryFromBackup()));

// 编排式：CompletableFuture + anyOf（等价于「先完成先要」）
CompletableFuture<String> any = (CompletableFuture<String>) CompletableFuture.anyOf(
        CompletableFuture.supplyAsync(() -> queryFromPrimary(), executor),
        CompletableFuture.supplyAsync(() -> queryFromBackup(), executor));
System.out.println(any.join());

一句话选型：要完成顺序 + 边完成边处理选 ExecutorCompletionService；要全部结果选 invokeAll 或 allOf；只要最快的一个选 invokeAny 或 anyOf；要复杂编排与异步回调选 CompletableFuture。

小结

  • ExecutorCompletionService = 线程池 + 无界 BlockingQueue + 重写 done() 的 QueueingFuture，因此能按完成顺序返回结果。
  • take() 阻塞、poll() 立即返回 null、poll(timeout, unit) 限时等待；poll 系列必须判空。
  • 任务失败也会入队，异常通过 get() 的 ExecutionException 抛出，不能只 take 不 get。
  • 必须「提交几次取几次」，否则队列堆积会导致 OOM。
