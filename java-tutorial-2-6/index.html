Oracle 要点

Posted on 2026-09-19，7 min read

MySQL 学完以后，不少人第一次接手 Oracle 项目会立刻卡住：同样叫“数据库”，Oracle 里却多出了实例、表空间、模式、序列这一整套概念，取第二页数据还要套一层子查询，甚至连自增主键都得自己造。本章不铺开讲 Oracle 的安装与运维，只聚焦后端开发里天天要写的几件事：

  • 序列（Sequence）
  • ROWNUM 分页
  • 常用单行函数与查询执行顺序
  • PL/SQL 与存储过程
  • PL/SQL 块结构、游标、触发器与异常处理
  • 视图 / 索引 / 同义词、decode 与 case、外连接写法

顺带把“实例 / 表空间 / 用户”这组基础概念摆正。本章适合已经会写 SQL、正要上手 Oracle 项目或准备面试的读者。

一、先把概念摆正：实例、表空间、用户与模式

Oracle 的“数据库”和 MySQL 的“数据库”不是一回事。MySQL 里一个实例下可以挂很多个 database，database 基本等于一个命名空间。Oracle 则是一个实例（Instance）对应一个数据库（Database），业务上的隔离靠的是“用户 / 模式（Schema）”。

  • 实例是运行时的东西：一块共享内存（SGA，含共享池、数据缓冲区、日志缓冲区等）加上一组后台进程（DBWn、LGWR、CKPT、SMON、PMON 等）。数据库是磁盘上的文件集合：数据文件、控制文件、重做日志文件、参数文件。
  • 逻辑结构自上而下是“表空间 → 段 → 区 → 数据块”。建表时不写表空间，表就落到该用户的默认表空间里；这也是为什么 Oracle 里“磁盘满了”往往要具体到某个表空间去看。
  • 用户与模式一一对应且同名。表实际属于某个模式，跨模式访问要写 模式名.表名，或者建同义词（synonym）把长名字藏起来，例如 create synonym owners for t_owners; 之后就能直接 select * from owners;。

还有一处容易说错：常见说法是“数据表中存储的数据区分大小写，其他都不区分”。更准确的说法是——SQL 关键字、函数名和未加双引号的标识符不区分大小写；字符串字面量的比较区分大小写；用双引号创建的标识符也区分大小写。'ABC' = 'abc' 在 Oracle 里是 false，需要忽略大小写时用 upper()/lower()，或建函数索引。

二、序列：Oracle 的自增方案

Oracle 的表没有 MySQL 的 AUTO_INCREMENT，主键自增靠序列 + 触发器（12c 起也可以直接用 GENERATED AS IDENTITY）。序列是一个独立于表存在的数据库对象，只负责按规则吐数字，和表是否插入成功毫无关系。

create sequence seq_ownersid
  increment by 1        -- 步长，默认 1
  start with 11         -- 起始值
  maxvalue 999999       -- 最大值
  cache 20              -- 预分配到内存的个数，默认 20
  nocycle;              -- 不循环，达到最大值后报 ORA-08004

select seq_ownersid.nextval from dual;   -- 取下一个值，并推进序列
select seq_ownersid.currval from dual;   -- 取本会话的当前值

alter sequence seq_ownersid cache 50;    -- 改缓存
drop sequence seq_ownersid;

几个必须记住的坑：

  • currval 必须先在本会话执行过一次 nextval 才能用，否则报 ORA-08002: sequence xxx.CURRVAL is not yet defined in this session；而且它返回的是本会话的当前值，别的会话取到哪儿了它并不知道。
  • 只执行 select seq.nextval from dual 而不插入，序列照样往前走，所以序列值天然不连续：事务回滚、实例重启丢缓存都会造成跳号。主键只需要唯一，不要用“有没有断号”来校验业务。
  • cycle（循环）配合 maxvalue/minvalue 时要留神缓存：一轮可取的值是 maxvalue - minvalue，cache × increment 不能超过一轮的容量，否则创建时就会报 ORA-04013: number to CACHE must be less than one cycle。生产上更建议用 nocycle + 足够大的 maxvalue。
  • 如果业务要求“编号必须连续”，序列做不到，只能在事务里 select ... for update 锁住一张单行编号表自己维护，代价是并发能力急剧下降。

三、ROWNUM 与分页：本章最大的坑

ROWNUM 是 Oracle 给查询结果逐行分配的伪列，编号从 1 开始。关键在于它的分配时机：在 WHERE 过滤的过程中就分配好了。所以下面这种写法永远查不出第二页：

-- 错误：结果恒为空
select rownum, t.* from t_account t
where rownum > 10 and rownum <= 20;

-- 正确：内层只限制上界，外层再按别名过滤下界
select * from (
  select rownum rn, t.* from t_account t where rownum <= 20
) where rn > 10;

-- 正确且有序：先排序，再编号
select * from (
  select rownum rn, tt.* from (
    select * from t_account order by usenum desc
  ) tt where rownum <= 20
) where rn > 10;

原因是：第一行取出来时 ROWNUM 是 1，不满足 > 10 被丢掉；第二行取出来时 ROWNUM 仍然是 1（编号是在过滤时按“当前候选行”给的），依旧被丢掉……如此往复，一行都留不下。凡是“ROWNUM > n”的写法都必然为空，只有 <=、< 才能用。正确套路是用子查询把 ROWNUM 变成普通列（取别名 rn）再过滤。

排序场景更要注意：ORDER BY 在 ROWNUM 分配之后才执行，所以“先排序再编号”必须让排序发生在内层子查询里（上面第三段代码）。否则拿到的是“先取 20 行、再把这 20 行排序”，结果完全错乱。另外两点补充：外层 select * 会把辅助列 rn 一起返回，正式代码里应显式列出需要的字段；Oracle 12c 之后可以直接写 order by usenum desc offset 10 rows fetch next 10 rows only，语义更清晰，也是现在推荐的分页写法。至于用 minus 做差集分页的写法，能出结果但代价高，不建议在业务代码里使用。

四、常用单行函数与查询执行顺序

单行函数对每一行返回一个结果，Oracle 里习惯用内置的 dual 表来验证它们——dual 是系统提供的一行一列表，专门用来凑 SELECT 语法。

select length('itheima') from dual;                     -- 7，字符串长度
select 'ABC' || 'DEF' from dual;                        -- ABCDEF，|| 比 concat 更好用
select substr('Jackie', 2, 3) from dual;                -- ack，下标从 1 开始
select replace('ADBCD', 'D', 'd') from dual;            -- AdBCd，按字符串替换
select translate('ADBCD', 'DB', 'db') from dual;        -- AdbCd，按字符一一映射
select round(123.678, 2), trunc(123.678, 2) from dual;  -- 123.68 / 123.67
select trunc(sysdate, 'mm') from dual;                  -- 本月 1 日 00:00:00
select add_months(sysdate, -12), last_day(sysdate) from dual;
select to_char(123456789, '999,999,999') from dual;     -- ' 123,456,789'，注意前导空格
select nvl(null, 0) from dual;                          -- 0，空值处理

细节上有几处容易出错。substr 的下标从 1 开始，没有下标 0 的概念（常说成“没有索引 0”，容易和索引混淆），第二、三个参数建议始终传整数（传小数时的取整行为随版本而异，不要依赖），起始位置传负数表示从右往左数。replace 按整串匹配且区分大小写，所以 replace('ADBCD', 'Db', 'db') 什么也不会替换——把它当成“替换成功”的例子是错的；translate 才是字符级映射，且源串与目标串按位置一一对应。round 四舍五入而 trunc 直接截断，做金额计算时要明确用哪个。to_char 的数字格式串位数不够会返回一串 #，位数够则按格式补前导空格，做报表时通常再套一层 trim()。

查询的书写顺序和执行顺序并不一致，实际执行顺序是：from → where → group by → having → select → order by。这解释了两条常见规则：where 里不能使用 select 中定义的列别名（那时还没算出来），而 order by 可以使用列别名甚至列序号。

关于“优化”，有一句流传很广的口诀：把数据量最少的表放在 from 最后，把过滤性最强的条件放在 where 最后。它属于 Oracle 8i 之前基于规则优化器（RBO）时代的产物。现代 Oracle 用基于代价的优化器（CBO），连接顺序和访问路径由统计信息决定，与书写顺序无关。真正该做的是：保证表和索引有较新的统计信息；从执行计划确认走没走索引；避免在索引列上套函数或做隐式类型转换（例如列是 varchar2 却写 where year = 2012，Oracle 会把列转成数字，索引直接失效，应写成 where year = '2012'）；能连表就别写相关子查询。

五、PL/SQL 与存储过程

PL/SQL 是 Oracle 在 SQL 之上加的过程化扩展，把分支、循环、异常处理带进了 SQL。它的最小单位是块，结构固定为“声明部分 → 可执行部分 → 异常处理部分”：

  • 变量在 declare 里声明，赋值用 :=，也可以用 select 列 into 变量 from ...；后者要求结果恰好一行，零行报 NO_DATA_FOUND，多行报 TOO_MANY_ROWS。
  • 用 %TYPE 引用某列的类型、用 %ROWTYPE 引用整行类型，列类型改了变量跟着改，比硬编码类型更稳。
  • 存储函数必须有返回值，可以写在 SELECT 里；存储过程没有返回值，靠 OUT 参数带回多个结果，只能被应用程序或 PL/SQL 块调用。过程参数只写类型、不写长度（写 varchar2 而不是 varchar2(30)）。
create or replace procedure pro_owners_add2
(
  v_name        varchar2,      -- 默认 IN，只写类型不写长度
  v_addressid   number,
  v_housenumber varchar2,
  v_watermeter  number,
  v_type        number,
  v_id          out number     -- 传出参数：新增后的主键
)
as
begin
  select seq_ownersid.nextval into v_id from dual;
  insert into t_owners(id, name, addressid, housenumber, watermeter, adddate, ownertypeid)
  values(v_id, v_name, v_addressid, v_housenumber, v_watermeter, sysdate, v_type);
  commit;                        -- DML 不会自动提交，别漏
end;
/

-- 用匿名块调用，可以拿到传出参数
declare
  v_id number;
begin
  pro_owners_add2('黑马', 1, '2-209', 123456, 1, v_id);
  dbms_output.put_line('新增业主 ID：' || v_id);
end;
/

在 SQL*Plus 或 PL/SQL Developer 里查看 dbms_output 的输出，要先执行 set serveroutput on。用 call pro_owners_add2(...) 调用时无法直接接收 OUT 参数，所以带传出参数的过程一般用匿名块调用。Java 侧则用 CallableStatement：conn.prepareCall("{call pro_owners_add2(?,?,?,?,?,?)}")，前五个参数用 setXxx 传入，第六个先 registerOutParameter(6, OracleTypes.NUMBER)，执行后用 getLong(6) 取出。

六、PL/SQL 编程基础：块、变量与控制结构

PL/SQL 的最小执行单位是块，结构固定为三段：声明部分（可选）、可执行部分（必需）、异常处理部分（可选）。在 SQL*Plus 或 PL/SQL Developer 里，块的结束用单独一行 / 提交执行。

declare
  -- 1. 声明部分（可选）：变量、常量、游标、自定义异常
begin
  -- 2. 可执行部分（必需）：SQL 语句 + 流程控制
exception
  -- 3. 异常处理部分（可选）
end;
/

变量声明写成「名字 类型 [:= 初值]」，赋值用 :=（= 只用于比较），初值也可以写 default。类型优先用 %type 跟随列定义，列类型变了变量自动跟着变：

declare
  v_ename emp.ename%type;               -- 与 emp.ename 同类型
  v_sal   emp.sal%type := 0;            -- 声明时给初值
  v_rate  constant number := 1.1;       -- 常量，再赋值会报错
  v_note  varchar2(50) default 'ok';    -- default 等价于 :=
begin
  select ename, sal into v_ename, v_sal
  from emp
  where empno = 7369;                   -- 结果必须恰好一行

  dbms_output.put_line(v_ename || ' 调整后 ' || v_sal * v_rate || ' ' || v_note);
end;
/

分支用 if / elsif / else，注意拼写是 elsif 而不是 elseif，结束必须写 end if;：

declare
  v_sal emp.sal%type;
begin
  select sal into v_sal from emp where empno = 7369;

  if v_sal >= 3000 then
    dbms_output.put_line('高薪档');
  elsif v_sal >= 1000 then
    dbms_output.put_line('中薪档');
  else
    dbms_output.put_line('低薪档');
  end if;
end;
/

case 有简单 case（比较一个表达式的值）和搜索 case（直接写条件）两种写法，既可以当赋值表达式，也可以当多分支语句：

declare
  v_deptno dept.deptno%type := 20;
  v_dname  dept.dname%type;
  v_level  varchar2(10);
begin
  -- 简单 case：按等值比较，作为表达式赋值
  v_dname := case v_deptno
               when 10 then 'ACCOUNTING'
               when 20 then 'RESEARCH'
               when 30 then 'SALES'
               else 'OTHER'
             end;

  -- 搜索 case：按条件判断，前一个条件命中就不再往后走
  v_level := case
               when v_deptno = 10 then 'A'
               when v_deptno = 20 then 'B'
               else 'C'
             end;

  dbms_output.put_line(v_dname || ' ' || v_level);
end;
/

循环有三种写法。最省事的是数值 for：循环变量由 Oracle 自动声明，只能在循环体内读、不能改。循环里还可以用 exit 直接退出、continue（11g 起）跳过本轮，两者都能带 when 条件。

declare
  v_i number := 1;
begin
  -- 1. 基础 loop：靠 exit when 跳出，至少执行一次
  loop
    dbms_output.put_line('loop ' || v_i);
    v_i := v_i + 1;
    exit when v_i > 3;
  end loop;

  -- 2. while：先判断后执行
  while v_i <= 5 loop
    dbms_output.put_line('while ' || v_i);
    v_i := v_i + 1;
  end loop;

  -- 3. 数值 for：1 .. 3 含两端；reverse 表示递减
  for i in 1 .. 3 loop
    dbms_output.put_line('for ' || i);
  end loop;

  for i in reverse 1 .. 3 loop
    dbms_output.put_line('reverse ' || i);    -- 输出 3 2 1
  end loop;
end;
/

七、游标：隐式游标与显式游标

游标（Cursor）是 PL/SQL 处理「多行结果集」的手段。Oracle 会为每条 SQL 自动开一个隐式游标，名字固定叫 sql，它的属性用来判断有没有结果、影响了几行：

  • sql%rowcount：最近一条 SQL 影响的行数，insert/update/delete 之后就是实际改动的行数（与是否提交无关）。
  • sql%found / sql%notfound：是否有结果、是否已经没有更多行。
  • sql%isopen：隐式游标执行完即自动关闭，这个值恒为 false，实际很少用到。
begin
  update emp set sal = sal * 1.1 where deptno = 10;

  if sql%found then
    dbms_output.put_line('改动行数：' || sql%rowcount);
  else
    dbms_output.put_line('没有匹配的行');
  end if;

  commit;                     -- DML 不会自动提交
end;
/

要逐行处理时用显式游标，标准四步是「声明 → open → fetch → close」。判断 %notfound 必须紧跟在 fetch 之后，否则会少处理最后一行：

declare
  cursor c_emp is
    select empno, ename, sal from emp where deptno = 20 order by empno;
  v_empno emp.empno%type;
  v_ename emp.ename%type;
  v_sal   emp.sal%type;
begin
  open c_emp;
  loop
    fetch c_emp into v_empno, v_ename, v_sal;
    exit when c_emp%notfound;              -- 一定要紧跟 fetch
    dbms_output.put_line(v_empno || ' ' || v_ename || ' ' || v_sal);
  end loop;
  close c_emp;
end;
/

日常开发更推荐 for rec in 游标 loop 的简化写法：Oracle 自动完成 open / fetch / close，循环变量是 %rowtype 类型，字段直接点出来，也不会忘记关游标。游标还可以带参数，连游标声明都能省成内联子查询：

declare
  cursor c_emp(p_deptno number) is                 -- 带参数的游标
    select empno, ename, sal from emp where deptno = p_deptno;
begin
  for r in c_emp(20) loop                          -- 传参打开，自动关闭
    dbms_output.put_line(r.empno || ' ' || r.ename || ' ' || r.sal);
  end loop;

  -- 直接写子查询，连游标声明都省了
  for r in (select ename, sal from emp where deptno = 10) loop
    dbms_output.put_line(r.ename || ' ' || r.sal);
  end loop;
end;
/

%rowtype 表示「一整行」的类型，常和 select * into 搭配，字段增删不用改声明：

declare
  v_emp emp%rowtype;                               -- 整行类型
begin
  select * into v_emp from emp where empno = 7369;
  dbms_output.put_line(v_emp.ename || ' 属于部门 ' || v_emp.deptno);
end;
/

如果要在遍历的同时改当前行，声明时加 for update，更新时用 where current of 游标名 定位，比再拼一次主键条件更稳妥：

declare
  cursor c_emp is
    select empno, sal from emp where deptno = 10 for update of sal;
begin
  for r in c_emp loop
    update emp set sal = r.sal * 1.1 where current of c_emp;
  end loop;
  commit;
end;
/

八、存储过程、函数与触发器

过程（procedure）和函数（function）都用 create or replace 创建，改逻辑时不必先 drop。区别只有两条：函数必须 return 一个值，所以能出现在 SQL 里；过程没有返回值，靠 OUT 参数带回结果。过程与函数的参数只写类型、不写长度。

-- 函数：算某个部门的工资合计
create or replace function f_dept_sal(p_deptno in number) return number
is
  v_total number;
begin
  select nvl(sum(sal), 0) into v_total from emp where deptno = p_deptno;
  return v_total;
end;
/

-- 函数可以直接写在 SQL 里
select d.deptno, d.dname, f_dept_sal(d.deptno) as total_sal
from dept d
order by d.deptno;

参数方向有三种：默认是 in（只读入），out 只写出、用来带回结果，in out 可读可写。校验失败时不要静默返回，用 raise_application_error 抛出带错误码的异常，Java 侧能通过 SQLException.getErrorCode() 拿到：

create or replace procedure p_raise_sal
(
  p_empno in  emp.empno%type,        -- 传入
  p_rate  in  number,                -- 传入
  p_new   out emp.sal%type           -- 传出：调整后的工资
)
is
begin
  update emp set sal = sal * p_rate where empno = p_empno;

  if sql%rowcount = 0 then
    raise_application_error(-20001, '员工不存在：' || p_empno);
  end if;

  select sal into p_new from emp where empno = p_empno;
  commit;
end;
/

调用方式有三种：SQL*Plus 里用 execute 命令（可简写 exec，OUT 参数用绑定变量接）；call 是 SQL 语句，Java 侧就是 {call ...} 加占位符；在 PL/SQL 里最通用的还是匿名块。

-- 1. SQL*Plus 命令：execute / exec
variable v_new number
execute p_raise_sal(7369, 1.1, :v_new)
print v_new

-- 2. call 是 SQL 语句；JDBC 里写成
--    conn.prepareCall("{call p_raise_sal(?,?,?)}")
call p_raise_sal(7369, 1.1, ?);

-- 3. 匿名块：OUT 参数用局部变量接，最通用
declare
  v_new emp.sal%type;
begin
  p_raise_sal(7369, 1.1, v_new);
  dbms_output.put_line('调整后工资：' || v_new);
end;
/

触发器（trigger）绑在表上，由 DML 自动触发，常用于审计、补默认值、维护冗余字段，它不能被显式调用。按时机分 before/after，按粒度分语句级（一条语句触发一次）和行级（每行触发一次，要写 for each row）。行级触发器里用 :new 取新值、:old 取旧值（:old 在 insert 中不可用，:new 在 delete 中不可用）。

-- 建一张审计小表
create table emp_audit
(
  id      number generated as identity,     -- 12c 起可用，替代「序列 + 默认值」
  empno   number,
  old_sal number,
  new_sal number,
  op_user varchar2(30),
  op_time date
);

-- 行级触发器：工资被改动时记一条审计
create or replace trigger trg_emp_sal_audit
  after update of sal on emp
  for each row
  when (old.sal <> new.sal)                -- when 里不加冒号，也不能调用函数
begin
  insert into emp_audit(empno, old_sal, new_sal, op_user, op_time)
  values(:old.empno, :old.sal, :new.sal, user, sysdate);
end;
/

before 行级触发器还可以直接给 :new 赋值，用来补默认值；语句级触发器没有 :new/:old，只能做整表校验或记录。触发器里有两条硬限制：不能写 commit/rollback（确需独立事务要声明 pragma autonomous_transaction）；逻辑要短，否则排错会很痛苦。临时停用触发器用 alter trigger trg_emp_sal_audit disable;，事后 enable。

-- before 行级触发器：入职时间留空就补当前时间
create or replace trigger trg_emp_before_insert
  before insert on emp
  for each row
begin
  if :new.hiredate is null then
    :new.hiredate := sysdate;
  end if;
end;
/

九、异常处理：when、raise 与自定义异常

异常处理写在块的 exception 段，格式是 when 异常名 then ...。捕获的顺序是自上而下，when others 必须放在最后兜底。Oracle 预定义了一批命名异常，最常用的几个是：

  • no_data_found：select into 一行都没查到。
  • too_many_rows：select into 查到了多行。
  • zero_divide：除数为零。
  • dup_val_on_index：违反唯一约束。
  • value_error：类型转换失败或长度超限。
  • others：未列出的所有异常，只能放最后。
declare
  v_sal emp.sal%type;
begin
  select sal into v_sal from emp where deptno = 10;   -- 部门 10 有多人，会抛异常
  dbms_output.put_line(v_sal);
exception
  when no_data_found then
    dbms_output.put_line('没有这个员工');
  when too_many_rows then
    dbms_output.put_line('结果不止一行，改用游标或聚合函数');
  when others then
    dbms_output.put_line('未预期的错误 ' || sqlcode || '：' || sqlerrm);
    raise;                                            -- 记完日志再抛给上层
end;
/

业务规则不满足时用 raise 主动抛出。自定义异常先在声明段用 异常名 exception; 定义，需要的话再用 pragma exception_init(异常名, 错误号) 把它绑到某个 Oracle 错误号上。抛给应用层的异常建议用 raise_application_error(错误号, 消息)，错误号取 -20000 到 -20999，JDBC 侧用 getErrorCode() 就能读到。

declare
  e_sal_invalid exception;                    -- 1. 自定义异常
  v_sal emp.sal%type;
begin
  select sal into v_sal from emp where empno = 7369;

  if v_sal < 0 then
    raise e_sal_invalid;                      -- 2. 主动抛出
  end if;
exception
  when e_sal_invalid then                     -- 3. 捕获处理
    dbms_output.put_line('工资不能为负');
    raise_application_error(-20002, '工资不能为负：' || v_sal);
end;
/

还有两点要知道：异常会逐层向外传播——内层块没捕获的异常会交给外层块的 exception 段，最外层再没人管就返回给调用方，事务状态也留给调用方决定；异常处理段里的 DML 要自己收尾，写操作出错时不要在过程内部随意 rollback，把提交或回滚交给调用方，避免把别人的事务一起回滚掉。

十、视图、索引、同义词与外连接写法

除了序列，日常最常打交道的对象还有视图、索引和同义词。

  • 视图把复杂查询固化成一张「虚表」，本身不存数据。它能简化调用、控制列级权限；含连接、聚合、distinct、分组的视图通常只能查不能改，单表简单视图才允许直接 DML。
  • 索引用来加速查询，代价是写操作要同步维护。Oracle 会为主键和唯一约束自动建索引，不用重复建；在索引列上套函数会让索引失效，除非建函数索引。
  • 同义词是对象的别名，用来屏蔽真实对象名和模式名，迁移或换 schema 时不用改代码。
-- 视图：把常用的连接查询封装起来
create or replace view v_emp_dept as
select e.empno, e.ename, e.sal, d.deptno, d.dname
from emp e join dept d on e.deptno = d.deptno
with read only;                                      -- 明确只读，避免误更新

select * from v_emp_dept where dname = 'SALES';

-- 索引：普通索引、唯一索引、函数索引
create index idx_emp_deptno on emp(deptno);
create unique index uk_emp_ename on emp(ename);
create index idx_emp_upper_ename on emp(upper(ename));   -- 让 where upper(ename)=... 也能走索引

-- 同义词：私有同义词只有当前用户能用
create synonym e for emp;
select * from e where deptno = 10;
drop synonym e;

第二节讲过的序列，这里补两个细节：currval 必须在当前会话先取过一次 nextval 之后才能用；12c 起更推荐直接建 identity 列，省掉「序列 + 触发器」这一套。

create sequence seq_ownersid start with 1 increment by 1 nocache;
select seq_ownersid.nextval from dual;      -- 先取一次
select seq_ownersid.currval from dual;      -- 本会话内可用

-- 12c 起：自增列，插入时不用管主键
create table t_demo
(
  id   number generated by default as identity (start with 1 increment by 1),
  name varchar2(30)
);
insert into t_demo(name) values ('a');
select * from t_demo;

条件取值有 decode 和 case when 两种写法。decode 是 Oracle 特有的老函数，只能做等值比较；case when 是 SQL 标准写法，支持范围条件、可移植性更好，新代码优先用它。

select ename,
       sal,
       decode(deptno, 10, '财务', 20, '研发', 30, '销售', '其他') as dname_old,
       case deptno
         when 10 then '财务'
         when 20 then '研发'
         when 30 then '销售'
         else '其他'
       end as dname_new,
       case
         when sal >= 3000 then '高'
         when sal >= 1000 then '中'
         else '低'
       end as sal_level
from emp
order by empno;

两者有一个容易踩的区别：decode 把 null 当成相等的值，所以 decode(comm, null, 0, comm) 能直接把空提成 0；而 case comm when null then ... 永远不成立，必须换成 case when comm is null then ...。

最后是外连接。ANSI 标准写法是 left join / right join / full outer join，Oracle 从 9i 起就完整支持，现行代码应优先用标准写法。老代码里更常见的是 (+) 写法：它是 Oracle 特有的旧语法，规则是「把 (+) 加在可能为空的那一侧（被补 null 的表）的列上」，读起来别扭，表一多极易写反，而且 (+) 无法表达 full join，也不能和 or、in 混用。看老项目时要能读懂，写新代码请用标准写法。

-- 需求：列出所有部门及其员工，没有员工的部门也要出现

-- 旧写法：dept 是被补 null 的一侧，加 (+)，因此 dept 全保留
select d.deptno, d.dname, e.ename
from emp e, dept d
where e.deptno(+) = d.deptno;

-- 标准写法（推荐）：语义一目了然
select d.deptno, d.dname, e.ename
from dept d
left join emp e on e.deptno = d.deptno;

-- 反过来：员工全保留、部门信息允许为空
-- 旧写法：这次是 emp 的列加 (+)，等价于 emp 左连接 dept
select e.ename, d.dname
from emp e, dept d
where e.deptno = d.deptno(+);

-- 标准写法（推荐）
select e.ename, d.dname
from emp e
left join dept d on e.deptno = d.deptno;

小结

Oracle 的日常开发可以浓缩成四句话：表空间管存储、用户即模式；自增靠序列，序列不保证连续；分页靠 ROWNUM，必须子查询套一层，排序要先进内层；能连表就不写子查询，把函数和类型转换从索引列上挪开。需要复用业务逻辑时再上 PL/SQL：简单查询封装成函数，带事务的写操作封装成过程。同时记住两个高频失误点——DML 之后手动 commit，过程参数不写长度。把这几件事写熟，从 MySQL 迁到 Oracle 的主要不适感基本就消失了。

再补一句 PL/SQL 的取舍：能用一个 SQL 解决的别写过程，游标优先用 for rec in 游标 loop 的简化写法，异常一律在 exception 段显式处理、别让 others 悄悄吞掉错误；触发器只用来做审计和兜底默认值，业务逻辑留在应用层或存储过程里更好维护。外连接新代码写 left join，只在读老项目时认得 (+) 就够了。
