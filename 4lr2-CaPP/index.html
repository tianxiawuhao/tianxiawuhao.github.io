Go语言学习（简单与Java作比较）

Posted on 2023-01-24，21 min read

序言

之前有一年多的 Java 开发经验，主要学习了 Java 基础（面向对象特点——封装、继承、多态，异常处理、常用类、数组和集合、IO 流）、JVM 内存机制、设计模式、数据库设计，以及工作中用到的一些框架；了解并熟悉别人的框架有助于简化自己的开发。本文较为啰嗦且无侧重点，慎入。

不管是学习C语言、C++、Java还是Go、Python，前面学到的东西并不会白费，有些时候反而能互补，比如有些设计思想。

搭建环境那都是一样的就不说了。下面就主要以Java和Go语言作对比，Java是面向对象的语言，Go语言既不是面向对象的语言也不是面向过程的语言，但Go语言在其他语言的身上能找到自己的影子。

Java 的所有开发都围绕对象展开。虽然 Java 有 char、boolean、byte、short、int、long、float、double 等基本数据类型，但它们都有对应的包装类：Character、Boolean、Byte、Short、Integer、Long、Float、Double。实例化对象只需 new 出来，就会创建在 JVM 堆中；对象用完之后由 JVM 的垃圾回收器自动回收，具体算法可以自行查阅资料。这里需要注意的一个地方就是，基本类型int转换为包装类型Integer时，在[-128,127]内转换的数据相等，在其他范围相同的int数据转换的包装类值不相等。这是由于Integer类为内部整数维护一个内部静态类IntegerCache缓存并保存从-128到127的整数对象，所以在这区间转换出来的是相等的对象。

public static void main(String[] args) {
    System.out.println("实例化相同值对象结果="+(new Integer(127) == new Integer(127))); // false
    System.out.println("实例化相同值对象结果="+(new Integer(128) == new Integer(128))); //false
    System.out.println("将基本类型int转换为包装类型Integer结果="+(Integer.valueOf(127) == Integer.valueOf(127))); //true
    System.out.println("将基本类型int转换为包装类型Integer结果="+(Integer.valueOf(128) == Integer.valueOf(128))); //false
    Integer a1 = 127;
    Integer a2 = 127;
    Integer b1 = 128;
    Integer b2 = 128;
    System.out.println(a1 == a2); //true
    System.out.println(b1 == b2); //false
}

另外要注意，new Integer(int) 这种构造方式从 Java 9 起已被标记为 @Deprecated，实践中应改用 Integer.valueOf() 或直接自动装箱。

Java和Go语言区别

下面按变量与类型、访问控制、执行顺序、循环与条件、函数、数组与指针、结构体、切片、map、接口、异常处理、并发、内存回收、包管理这些维度逐一对比，先给出一张总览表，再展开细节。

数据类型

  • 上面其实也提到过Java的基本数据类型，其实Java除了八大基本数据类型（char，boolean，byte，short，int，long，float，double）外还有引用数据类型，如对象（包含string）、数组。

  • Go语言数据类型包含布尔型（bool），数字型（uint8、uint16、uint32、uint64、int8、int16、int32、int64、float32、float64、complex64、complex128），字符串型，派生类型（指针Pointer、数组、结构化类型、Channel、函数、切片、接口、Map），布尔型、数字型、字符串型的默认值与 Java 类似（数值 0、布尔 false、字符串空串），不过 Java 的引用类型默认是 null，Go 的指针、切片、map、channel、接口等类型的零值是 nil。

  • Java 中占用字节大小：byte-1 字节，short-2 字节，char-2 字节，int-4 字节，long-8 字节，float-4 字节，double-8 字节；boolean 比较特殊，JVM 规范只规定它表示 true/false，单独的 boolean 变量编译后通常用 int（4 字节）代替，而 boolean[] 的读写共用 byte 数组的 baload/bastore 指令，每个元素占 1 字节。Go 中数字类型的宽度有固定约定，直接除以 8 即可，比如 uint16 就是 16/8=2 字节；不过 int、uint、uintptr 的宽度随平台变化（32 位平台 4 字节，64 位平台 8 字节）。

变量、方法的访问控制

  • Java会有访问控制符和非访问控制符，访问控制符可以使类、变量、方法和构造方法具有不同的访问权限，public > protected > default > private（当前类、同包子类、不同包子类、不同包其他类的访问）。而非访问控制符有static修饰符（可修饰类、变量、方法，用来声明独立于对象的静态变量），final修饰符（类——不能被继承、方法——不能被继承类重定义、变量——不可修改），abstract修饰符（创建抽象类和抽象方法，不能与final一起用），synchronized修饰符（保证被修饰的方法线程安全），transient修饰符（实现Serialize接口的类中被修饰的变量JVM不进行序列化，但静态变量不管有没有修饰符都不能被序列化，且实现Externalizable接口的类与transient无关），volatile修饰符（被修饰的变量线程共享，保证线程可见性和禁止指令重排序）

  • Go中不同包下的不同变量和方法只需要通过大小写就可以进行访问控制，大写字母开头的变量和方法是公开的，而小写的是私有的。

代码块执行顺序

  • Java代码块的执行顺序是：父类静态代码块(1次)——>子类静态代码块(1次)——>父类非静态代码块 ——> 父类构造函数 ——> 子类非静态代码块 ——> 子类构造函数

  • Go代码块的执行顺序是：其他包go文件定义变量初始化 ——> 其他包go文件定义的init()函数执行 ——> 本包go文件定义变量初始化 ——> 本包go文件定义的init()函数执行 ——> 本包go文件定义的main()函数执行

循环结构

  • Java循环结构有while循环，do...while循环，for循环，用到的控制语句有break、continue。

  • Go语言中循环结构主要就是for循环以及循环嵌套，里面会用到的控制语句有break、continue、goto，多了一条goto语句，它可以无条件地转移到过程中指定的行，但是在结构化程序设计中一般不主张使用 goto 语句， 以免造成程序流程的混乱，使理解和调试程序都产生困难。
    Go 的 for 循环除了 for init; condition; post { } 这种三段式写法外，还可以用 for key, value := range oldMap { newMap[key] = value } 遍历 slice、map、数组和字符串。需要注意的是 Go 的 for 语句不能加圆括号，但左花括号必须与 for 写在同一行。有兴趣的同学还可以拿 Go 的 for range 和 Java 的 Iterator 迭代器做个比较。

条件语句

  • Java的条件语句主要有if语句，if...else语句以及if嵌套语句。

  • Go的条件语句有if语句，if...else语句，if嵌套语句，switch语句（switch 变量+case分支+default分支，默认匹配后不会执行其他case，使用 fallthrough 会强制执行后面的 case 语句，fallthrough 不会判断下一条 case 的表达式结果是否为 true），select语句（Go的一个控制结构，类似switch，但它会随机执行一个可运行的 case。如果没有 case 可运行，它将阻塞，直到有 case 可运行。一个默认的子句应该总是可运行的。）

函数

  • Java虽然没有函数的概念，但是通常可以用类中的方法去进行实现各个功能模块。

  • Go 的可执行程序必须包含 package main 和 main() 函数，此外还可以定义 init() 初始化函数：一个包甚至一个文件里可以有多个 init()，它们按文件名的字典序依次执行，常用于注册驱动、校验配置。

  • Go 语言的函数参数一律是值传递：在函数内直接修改参数不会影响实参。不过切片、map、channel 的值里含有指向底层数据的指针（切片传参复制的是指针、长度、容量三者组成的结构体），所以在函数内修改元素或 map 键值会影响原数据；而像 append 这类可能更换底层数组的操作，调用方不一定能看到——这与 Java 中“基本类型传值、对象传引用”的效果部分类似，细节上并不等价。

  • Go 语言的函数是一等公民，可以作为另一个函数的实参：下面第一段是工具包中的 go 文件，它声明了函数类型 func(int) int，凡是符合该签名的函数都可以作为 TestCallBack 的第二个参数传入；第二段是调用方的代码。

package util

import "fmt"

//声明一个函数类型
type callBackType func(int) int

func CallBack(x int) int{
	fmt.Printf("我是回调函数，x：%d\n",x)
	return x
}

func TestCallBack(x int, function callBackType){
	function(x)
}

package main

import(
	"fmt"
	"godemo/src/gocode/callbackDemo/util"
)

func main(){
	//CallBack函数作为实参传入到TestCallBack函数
	util.TestCallBack(1, util.CallBack)
	//匿名函数作为实参传入到TestCallBack函数中，类似于Java的匿名内部类
	util.TestCallBack(2, func(x int) int {
        fmt.Printf("我是回调，x：%d\n", x)
        return x
    })
}

Java 中方法不能直接作为另一个方法的实参，但 Java 8 引入的函数式接口可以变相做到这一点：java.util.function.Predicate<T> 被 @FunctionalInterface 标注为函数式接口，它的 test(T t) 方法用来判断对象是否满足某个条件，因此可以把“不同的条件”作为参数传给方法。下面的 eval 方法第二个参数就可以传入不同的条件（Lambda 表达式）。

import java.util.Arrays;
import java.util.List;
import java.util.function.Predicate;

public class PredicateDemo {
    public static void main(String args[]){
        List<Integer> list = Arrays.asList(1, 2, 3, 4, 5, 6, 7, 8, 9);
        /**
         *  Predicate<Integer> predicate = n -> true
         *  n 是一个参数传递到 Predicate 接口的 test 方法
         *  n 如果存在则 test 方法返回 true
         */
        System.out.print("输出所有数:");
        eval(list, n->true);
        /**
         * Predicate<Integer> predicate1 = n -> n%2 == 0
         * n 是一个参数传递到 Predicate 接口的 test 方法
         * 如果 n%2 为 0 test 方法返回 true
         */
        System.out.print("输出所有偶数:");
        eval(list, n-> n%2 == 0 );
 
        // Predicate<Integer> predicate2 = n -> n > 3
        // n 是一个参数传递到 Predicate 接口的 test 方法
        // 如果 n 大于 3 test 方法返回 true
 
        System.out.print("输出大于 3 的所有数字:");
        eval(list, n-> n > 3 );
    }
 
    public static void eval(List<Integer> list, Predicate<Integer> predicate) {
        for(Integer n: list) {
            if(predicate.test(n)) {
                System.out.println(n + " ");
            }
        }
        System.out.println();
    }
}

数组

Java 和 Go 的数组在声明、初始化和下标访问上写法类似，但语义有关键差别：Java 的数组是引用类型，赋值和传参传的是同一个数组，长度用 arr.length；Go 的数组是值类型，长度是类型的一部分（[3]int 与 [4]int 是不同类型），赋值和传参会整体复制一份，长度用内建函数 len(arr)。也正因为数组是值类型，Go 中日常更常用切片。

指针

  • Java 中没有暴露给程序员的指针，语言希望开发者更关注业务：引用变量本身只保存一个引用（64 位 JVM 开启指针压缩后通常是 4 字节），它为 null 时只是不指向任何对象，并不代表这个变量不占空间。对象一旦实例化，其内存地址对上层不可见，而且可能变化——例如使用复制算法的垃圾回收器在整理堆时会把存活对象搬到新地址并更新引用。sun.misc.Unsafe 只能拿到字段相对对象起始地址的偏移量，无法直接得到对象地址，日常开发也不需要关注。

  • Go语言中和C/C++一样也用到了指针，使用指针可以更简单的执行任务，指针也带来了更高的效率。指针被声明后尚未指向任何变量时，其值为 nil。
    Java中对某个对象/数组进行修改时，需要通过方法的返回值的对象/数组来接收新的对象/数组，而Go语言有指针后可以向函数传入指针，直接通过指针修改对应的值。

内存管理与垃圾回收

Java 和 Go 都自带垃圾回收，程序员不需要手动释放内存，但两者的实现取向不同。

  • Java 的堆按代划分（新生代 Eden + Survivor、老年代），对象先分配在新生代，经过多次 Minor GC 仍然存活才晋升到老年代；GC 实现可以在 Serial、Parallel、CMS、G1、ZGC、Shenandoah 中选择，停顿时间、吞吐量、堆大小都能通过参数调节，适合既对延迟敏感、又需要精细调优的场景。
  • Go 的 GC 是不分代的并发三色标记清除：标记阶段与用户 goroutine 并发执行，只在极短的 STW（亚毫秒级）里完成写屏障开启、栈扫描等准备工作，目标是把停顿压到最低，代价是吞吐量和内存占用要让步，而且几乎没有可调参数，只能通过 GOGC（默认 100，即堆增长到上次存活对象的两倍时触发）和 GOMEMLIMIT 影响它的行为。
  • 两者都不保证对象被及时回收，也都不阻止内存泄漏：Go 里最常见的“泄漏”其实是 goroutine 泄漏——向无人接收的 channel 发送数据、忘记 close 导致 goroutine 永久阻塞，这类问题通常用 pprof 排查；Java 则常用堆转储（heap dump）配合 MAT 分析。
  • 另外 Java 对象有对象头（Mark Word 加类型指针，通常 12 到 16 字节）和引用类型带来的额外开销，Go 的结构体没有对象头，值语义的结构体、切片可以分配在栈上，是否上堆由逃逸分析决定——这也是 Go 内存占用通常更小的原因之一。

结构体

Go 的结构体（struct）用于把不同类型的数据聚合成一个整体，语法是 type 结构体名 struct { 成员定义 ... }。它相当于 Java 中只保留字段的类（Java 16 之后的 record 与它最接近，但 record 的字段不可变），区别在于：Go 的结构体本身不包含方法定义，方法通过接收者写在结构体之外；Go 不支持继承，需要复用行为时用匿名字段做组合；结构体的零值是所有字段均为零值，可以直接使用。

package main

import "fmt"

type Person struct {
	Name string // 大写开头，包外可见
	age  int    // 小写开头，仅包内可见
}

// 值接收者：操作的是副本
func (p Person) SayHi() {
	fmt.Printf("我是 %s，今年 %d 岁\n", p.Name, p.age)
}

// 指针接收者：可以修改原对象
func (p *Person) GrowUp() {
	p.age++
}

func main() {
	p := Person{Name: "Tom", age: 18}
	p.SayHi()
	p.GrowUp()
	p.SayHi()
	// 对应 Java：new Person("Tom", 18)，方法写在 class 内部
}

上面这段代码可以直接 go run：值接收者方法操作的是结构体副本，指针接收者方法才能改到调用方的字段，这一点和 Java 中“对象变量都指向同一个堆对象”的直觉不同。

切片

  • Go语言切片是对数组的抽象。数组长度不可变，但切片长度和容量是可变的。

  • 切片包含三个属性：指针（Pointer）、长度（Length）、容量（Capacity），可以使用内建函数make([]type, length, capacity)创建特定类型的切片，也可以从其他切片中进行截取。

  • 这里需要区分一下数组和切片，数组是长度不可变的，而切片是长度可变的。数组的类型是[length] type，切片的类型是[] type。
    创建一个切片事实上是指向一个底层数组，如果对切片进行截取后，修改截取后的切片的元素值实际上改变的是底层数组的元素值，截取前的切片元素值也会发生改变。

  • 切片可以通过内建函数copy()和append()进行切片拷贝以及切片元素追加。

  • 切片元素追加时需要注意，如果原切片的容量大于长度，则直接在原切片的基础上追加，切片容量不变且长度+1；如果原切片的容量等于长度，则会对原切片进行2倍扩容且长度+1，这时将会生成一个新的底层数组，即原切片和扩容后的切片不再是共用一个底层数组，修改扩容后的切片的元素值将不会影响原切片的元素值。示例如下，

old_slice := []int{11,22,33,44,55,66,77,88}
test_slice := old_slice[1:3:3]	//从1开始切，长度3-1，容量3-1，即{22,33}
fmt.Printf("追加前的slice=%v,长度=%v,容量=%v\n",test_slice,len(test_slice),cap(test_slice))
app_slice := append(test_slice, 100)
fmt.Printf("追加后的slice=%v,长度=%v,容量=%v\n",app_slice,len(app_slice),cap(app_slice))
app_slice[0] = 300
fmt.Printf("修改扩容后的切片的第一个元素后，追加前slice=%v, 追加后slice=%v\n",test_slice, app_slice)
  • 还需注意的是底层数组扩容的规则：在文章使用的 go1.15.7 上，元素个数不超过 1024 时按底层数组长度的 2 倍扩容并生成新数组，超过 1024 时按 25% 的比率扩容（1024 个元素时容量扩展为 1280）。从 Go 1.18 起扩容策略改为：容量小于 256 时仍按 2 倍增长，之后逐步过渡到约 1.25 倍，并且新容量还要按内存规格向上取整，所以不一定正好是 2 倍。

Map集合

Go 的 map 是一种键值对集合，底层实现是散列表，主要包含 hmap（map 的头部，记录桶数量、元素个数、哈希种子等）和 bmap（通常也叫 bucket，每个桶默认存放 8 个键值对）两类结构。它的遍历顺序是随机的：运行时会随机选一个起始桶和起始单元格，所以不能依赖遍历顺序；这与 Java 中 HashMap 不保证顺序、LinkedHashMap 保证插入顺序的差别类似。

  • Go中它是数组+链表，使用链表的原因和Java一样是为了避免哈希冲突。

  • 而 Java 在 JDK 1.8 后是数组+链表+红黑树：当链表长度达到 8 且桶数组长度不小于 64 时转为红黑树，红黑树节点数小于 6 时再转回链表；引入红黑树主要是为了提高查询效率。

  • Go map 扩容同样依据负载因子判断：桶的数量是 2^B，B 表示取哈希值低位的位数（而不是桶数组的长度），当元素个数超过 6.5 × 2^B（即平均每个桶 6.5 个键值对）时触发翻倍扩容；如果桶内溢出桶过多，还会触发等量扩容来整理碎片。Java 中 HashMap 的负载因子默认是 0.75f，元素个数超过阈值就把容量扩为原来的 2 倍。

递归函数

递归，就是在运行的过程中调用自己。
不管是Go、Java、还是其他语言都可以实现递归调用，最常见的递归案例就是实现斐波那契数列。

接口

Go 的接口是对其他类型行为的抽象和概括，用 type 接口名 interface { 方法签名 } 定义。它与 Java 接口最大的区别在于实现是隐式的：Go 不要求类型声明“我实现了哪个接口”，只要一个类型定义了接口里的全部方法，编译器就认为它满足该接口，这叫鸭子类型（duck typing）；Java 则必须用 implements 显式绑定接口和实现类，否则编译不通过。

隐式实现的好处是解耦：接口可以由使用方按需定义，已有的类型不用改动就能适配新接口，标准库里的 io.Reader、error、fmt.Stringer 都是这样工作的；代价是没有显式声明，IDE 里不容易一眼看出某个类型实现了哪些接口，而且方法签名差一点（接收者类型、参数、返回值）就不算实现。

package main

import "fmt"

// 接口：只要实现了 Say() 方法，就自动满足 Speaker
type Speaker interface {
	Say() string
}

type Dog struct{ Name string }

// 没有 implements，方法签名匹配即隐式实现
func (d Dog) Say() string { return d.Name + "：汪汪" }

func speak(s Speaker) { fmt.Println(s.Say()) }

func main() {
	speak(Dog{Name: "旺财"}) // 编译期检查 Dog 是否满足 Speaker
}

对应到 Java，则要写成 class Dog implements Speaker { ... } 并在类里用 @Override 标注方法。另外 Java 的接口可以定义 default 方法和静态方法，Go 的接口只能放方法签名（Go 1.18 起接口还可以作为类型约束，包含类型集合，但不能当作值使用）。

异常处理

Java 的异常分为 Error（程序无法处理的严重错误，编译器不做检查，通常会导致线程终止）和 Exception（又分运行时异常与编译期受检异常，以及自定义异常），Exception 通常用 try {} catch (Exception e) {} 捕获处理；异常不需要调用方显式接收，沿着调用栈向上抛即可。

  • Go 没有异常机制，错误是普通的值：函数把 error 作为最后一个返回值交给调用方，调用方用 if err != nil 显式判断；标准库提供 errors.New、fmt.Errorf（用 %w 包装后可用 errors.Is/As 追溯原因）来构造和串联错误。这种写法啰嗦，但错误流向一目了然，也不会出现“忘记 catch 导致程序直接崩掉”的情况。
  • 对于真正无法继续的严重问题（数组越界、空指针、除零等），Go 用 panic 抛出，可以在 defer 中调用 recover() 取回 panic 值并恢复正常执行；defer、panic、recover 都来自 builtin 包。需要注意的是 defer 是后进先出（LIFO）：同一个函数内注册的多个 defer，最后注册的最先执行，并不是 FIFO；defer 的触发时机是所在函数返回（return 或 panic）时，而不是整个程序退出时。若 recover() 不在 defer 的函数里调用，它不会阻止 panic 继续传播。
  • 另外 Go 中 panic 与 error 的定位不同：可预期的失败（文件不存在、参数非法）应该返回 error，只有程序内部逻辑被破坏时才 panic；panic 若不被 recover 会终止整个程序，所以下面示例里“自定义错误后直接 panic”只是演示效果，生产代码更推荐把 error 逐层返回给上层处理。

下面给出一个用 defer+recover() 捕获和处理运行时异常的示例（出现异常后，主函数后面的语句仍会正常执行）：

package main

import (
	"fmt"
)

func test() {
	//使用defer+recover捕获和处理异常
	defer catchError()
	num1 := 10
	num2 := 0
	res := num1/num2
	fmt.Println("res = ",res)
}

//捕获异常
func catchError(){
	err := recover() //recover()也是内建函数
	if err!=nil{	//err!=nil说明捕获到异常
		fmt.Println("异常信息=",err)
	}
}

func main(){
	test()
	fmt.Println("main()下面的代码......")
}

下面给出一个自定义异常的处理，直接使用panic()内建函数终止程序，会输出自定义错误，但后面的代码将不会再执行：

package main

import (
	"fmt"
	"errors"
)

//支持自定义错误，使用errors.New和panic内建函数
func readConf(name string)(err error){
	if name == "config.ini"{
		return nil //读取返回空...
	} else{
		return errors.New("读取文件错误...")
	}
}

func test(){
	err := readConf("confi.ini")
	if err != nil{
		panic(err) //如果读取文件发生错误，输出错误并终止程序
	}
	fmt.Println("test()继续执行...")
}

func main(){
	test()
	fmt.Println("main()下面的代码......")
}

并发

  • Java 中主要和进程、线程打交道：进程是资源分配的最小单位，拥有独立的内存空间；线程是 CPU 调度和分派的基本单位，同一进程内的线程共享堆内存。Java 的线程与内核线程是一对一映射，创建和切换都要陷入内核，栈空间通常为 1MB 左右，所以几千个线程就会带来明显开销。

  • Go 在进程和线程之间加了一层 goroutine（协程）：它是用户态的轻量级执行体，由 Go 运行时调度，初始栈只有 2KB 并且可以按需增长，创建和切换不需要陷入内核，因此很容易支撑几十万个并发任务。代价是 goroutine 由运行时而非操作系统调度，长时间占用 CPU 且不让出的任务会拖住挂在同一个 P 上的其他 goroutine。

  • goroutine 的调度基于 GMP 模型：G 是 goroutine，M 是内核线程，P 是逻辑处理器（数量由 GOMAXPROCS 决定，默认等于 CPU 核数）。P 维护本地运行队列，M 必须绑定一个 P 才能执行 G；本地队列空了会去全局队列或其他 P 那里偷任务（work stealing）。当 G 发生阻塞（网络 IO、通道等待等）时，运行时会交出 M 去执行其他 G，而不是一直占着线程。

  • 用法上，Java 通过 new Thread(...) 或线程池提交任务，Go 只需在函数调用前加 go 关键字就能启动一个 goroutine。go f(x) 会先计算好参数再异步执行 f，因此要注意闭包捕获的是同一个循环变量的问题（Go 1.22 起 for 循环变量每次迭代都是新变量，这个问题才消失）。

  • goroutine 之间推荐用 channel（通道）传递指定类型的值来通信和同步，也就是 Go 常说的“不要通过共享内存来通信，而应该通过通信来共享内存”。默认的通道没有缓冲区：发送和接收必须配对，先到的一方阻塞等待，因此它天然是一个同步点；需要缓冲时用 make(chan T, n) 指定容量，缓冲未满时发送不阻塞、缓冲非空时接收不阻塞。Java 中对应的思路是阻塞队列（BlockingQueue）配合线程池，但关闭与超时都需要自己处理。

  • 最后要注意死锁（fatal error: all goroutines are asleep - deadlock）：无缓冲通道不存储数据，只负责传递，如果在 main goroutine 中向无人接收的无缓冲通道发送数据，或者所有 goroutine 都在等待对方，运行时就会直接报错退出；main 函数本身也是一个 goroutine（main goroutine），它一旦返回，其他 goroutine 会被立刻终止。下面给出一个简单的 demo。

package utils

import(
	"fmt"
	"time"
)

func SaySomething(s string){
	for i:=0;i<5;i++{
		time.Sleep(100 * time.Millisecond)
		fmt.Printf("这是某某第%v次说%v\n",i+1,s)
	}
}

func Sum(s []int, c chan int){
	sum := 0 
	for _,v := range s{
		sum += v
	}
	//把sum发送到通道c
	c <- sum
}

func Fibonacci(n int, c chan int){
	x, y := 0, 1
	for i:=0;i<n;i++{
		//把x发送到通道c中
		c <- x
		x, y = y, x+y
	}
	close(c)
}

package main

import(
	"fmt"
	"goDemo/src/gocode/goroutine/utils"
)

func main(){
	str1 := "hello"
	str2 := "world"
	//输出的 hello 和 world 是没有固定先后顺序。因为它们是两个 goroutine 在执行
	go utils.SaySomething(str1)
	utils.SaySomething(str2)
	fmt.Println("then I can say")

	//通过两个 goroutine 来计算数字之和，在 goroutine 完成计算后，它会计算两个结果的和：
	s := []int{7, 2, 8, -9, 4, 0}
	 
	c := make(chan int)
	fmt.Printf("信道地址=%v,信道容量=%v\n",c, cap(c))
	go utils.Sum(s[:len(s)/2],c)
	go utils.Sum(s[len(s)/2:],c)
	//从通道c接收数据并赋值给x，y
	// 两个 goroutine 谁先发送并不确定，x、y 与前后半段的对应关系不固定，但 x+y 恒为 12
	x, y := <- c , <- c
	fmt.Printf("x=%v,y=%v,总和=%v\n",x,y,x+y)
	 
	// 这里我们定义了一个可以存储整数类型的带缓冲通道，缓冲区大小为2
	ch := make(chan int, 2)
	// 因为 ch 是带缓冲的通道，我们可以同时发送两个数据
	// 而不用立刻需要去同步读取数据
	ch <- 1
	ch <- 2
	// ch <- 3	//如果再发送一个数据则会出现异常 fatal error: all goroutines are asleep - deadlock!
	// 获取这两个数据
	fmt.Println(<-ch)
	fmt.Println(<-ch)
	// 接收了数据之后缓存里才能继续缓冲数据，否则就会出现协程死锁
	ch <- 3
	 
	//go遍历通道和关闭通道
	cc := make(chan int,10)
	go utils.Fibonacci(cap(cc), cc)
	 
	for i := range cc{
		fmt.Printf("%v\t",i)
	}
	 
	//无缓冲信道不会用来存储数据，只负责数据的流通，两个goroutine可以用无缓冲信道传输数据
	go func(){c <- 1}()
	test := <- c
	fmt.Println(test)
	// c <- 1 //无缓冲信道容量为0，不能在main goroutine中传数据，否则会出现deadlock

}

包管理与依赖

Java 的工程一般由 Maven 或 Gradle 管理：依赖写在 pom.xml（或 build.gradle）里，坐标由 groupId、artifactId、version 三段确定，构建工具从中央仓库或私服把 jar 下载到本地仓库，同一份依赖在这台机器上被所有工程共享；版本冲突靠依赖调解规则（如最近优先）解决，需要时用 mvn dependency:tree 排查。

  • Go 早期依赖 GOPATH：所有代码必须放在 $GOPATH/src 下，第三方库没有版本概念，于是出现了 govendor、dep 等第三方工具。
  • Go 1.11 引入模块（module）机制、Go 1.16 起默认开启：在项目根目录执行 go mod init 模块路径 生成 go.mod，依赖由 go get 记录版本，go mod tidy 增删依赖，go.sum 保存所有模块的校验和以保证可复现构建。
  • 与 Maven 的一个明显差别是，Go 使用最小版本选择（MVS）：构建时选用满足所有要求的最低版本，而不是取最新版本，因此升级依赖需要显式执行 go get 模块@版本。
  • 另外 Go 没有私服概念，默认走 proxy.golang.org 或 GOPROXY 指定的模块代理，国内常用 goproxy.cn；Go 的模块路径本身就是 import 路径（比如 github.com/gin-gonic/gin），所以示例里那种 goDemo/src/gocode/... 的写法是 GOPATH 时代的遗留，模块化之后应该改成模块路径。

依赖方式也影响代码组织：Java 用包名区分命名空间，且目录结构必须与包名对应；Go 以目录为包，同一目录下的文件必须属于同一个包，包名可以与目录名不同，但导入路径必须与“模块路径 + 目录结构”保持一致。
