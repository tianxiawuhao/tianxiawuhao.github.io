IO 流与文件操作

Posted on 2026-09-19，5 min read

前面的章节里，数据都活在内存中：程序一结束，列表、对象、计算结果全部消失。本章要解决的是“数据怎么和磁盘、网络打交道”，也就是 Java 的 IO 流与文件操作。

内容从文件字符流讲到缓冲流、转换流与对象序列化，适合已经会写类和方法、但一看到 InputStream / Reader 一大堆类名就发懵的读者。读完应该能独立写出“复制文件”“按行读取配置”“把对象存盘再读回”这类最常用的 IO 代码。

一、先分清字节流与字符流

Java 把 IO 抽象成"流"：数据从一端流向另一端。按方向分为输入流（从设备到内存）与输出流（从内存到设备）；按处理单位分为字节流和字符流，前者的顶层抽象类是 InputStream / OutputStream，后者是 Reader / Writer。

为什么不全部用字节流？因为一个汉字在 GBK 下占 2 个字节、UTF-8 下占 3 个字节，字节流并不知道"哪几个字节该拼成一个字"，用 (char) 强行转换只会得到乱码。字符流 = 字节流 + 编码表，它先读字节，再按编码规则把字节组装成字符，因此拿到的就是正确的字符。

结论很实用：处理纯文本用字符流，处理图片、音频、视频等二进制数据必须用字节流。下面的 FileWriter / FileReader 就是字符流的便捷类，构造时直接传文件路径，写字符串不需要先转成 byte[]。

二、文件的写出与读入

写出文本的标准四步是：关联文件、写数据、刷新缓冲、关闭资源。flush() 把内存缓冲区里的数据真正刷到磁盘，之后流还能继续写；close() 先刷新再释放系统底层资源，关闭后再调用 write() 会抛 IOException: Stream closed。所以 close() 是必须做的，而 flush() 按需调用。

import java.io.FileWriter;
import java.io.IOException;

public class FileWriterDemo {
    public static void main(String[] args) throws IOException {
        // 第二个参数 true 表示追加写入，默认 false 会清空原文件
        try (FileWriter fw = new FileWriter("c.txt", true)) {
            for (int x = 0; x < 10; x++) {
                fw.write("hello" + x);
                fw.write("\r\n");   // Windows 换行；Linux 用 \n
            }
        }   // try-with-resources 会自动 close()
    }
}

读入时，int read() 一次读一个字符，返回的是字符的 int 值，读完返回 -1，这正是循环的结束条件；int read(char[] cbuf) 一次读一批，返回实际读到的字符个数，同样以 -1 表示结束。用数组读能大幅减少系统调用，效率更高。注意读到最后一批时数组往往不会填满，必须用 new String(cbuf, 0, len) 只取有效部分，直接 System.out.println(cbuf) 会把上一轮的残留数据一起打出来。

三、缓冲流与转换流：效率与编码

缓冲流在内存里维护一个数组，真正的读写仍交给普通流完成，从而减少磁盘访问次数。用法就是把原流对象套进去。它还有两个专用方法：readLine() 一次读一行且不含换行符，读完返回 null；newLine() 写出由系统决定的换行符，比手写 \r\n 可移植。

import java.io.BufferedReader;
import java.io.BufferedWriter;
import java.io.FileReader;
import java.io.FileWriter;
import java.io.IOException;

public class CopyFileDemo {
    public static void main(String[] args) throws IOException {
        try (BufferedReader br = new BufferedReader(new FileReader("src.txt"));
             BufferedWriter bw = new BufferedWriter(new FileWriter("dest.txt"))) {
            String line;
            while ((line = br.readLine()) != null) {
                bw.write(line);
                bw.newLine();   // 补回被 readLine 丢掉的换行
            }
        }
    }
}

转换流解决编码问题：InputStreamReader 是字节输入到字符输入的桥梁，OutputStreamWriter 是字符输出到字节输出的桥梁，两者都能在构造时指定编码表。便捷类是它们的子类，FileWriter / FileReader 其实等于用平台默认编码的转换流。新手最容易踩的坑正在这里：平台默认编码随环境变化（早期中文 Windows 是 GBK，现代 JVM 多为 UTF-8），文件编码与默认编码不一致就会乱码，而 FileReader 根本无法指定编码。所以需要指定编码时必须用转换流，例如 new InputStreamReader(new FileInputStream("a.txt"), "UTF-8")。乱码的本质就是"用一种编码表编码、用另一种解码"，保持一致即可。

四、对象序列化

序列化是把内存中的对象转换成字节序列的过程，反序列化则是把字节序列恢复成对象。它的用途很明确：把对象状态持久化到文件或数据库、通过网络传输对象、通过 RMI 调用远程对象。实现方式极其简单——让类实现 java.io.Serializable 接口即可。这个接口没有任何方法或字段，只是一个"标记"，告诉 JVM 这个类允许被序列化。

import java.io.*;

public class SerializableDemo {
    public static void main(String[] args) throws Exception {
        FlyPig pig = new FlyPig();
        pig.setName("naruto");
        pig.setColor("black");

        try (ObjectOutputStream oos =
                     new ObjectOutputStream(new FileOutputStream("d:/flyPig.txt"))) {
            oos.writeObject(pig);          // 序列化
        }

        try (ObjectInputStream ois =
                     new ObjectInputStream(new FileInputStream("d:/flyPig.txt"))) {
            FlyPig read = (FlyPig) ois.readObject();   // 反序列化
            System.out.println(read);
        }
    }
}

class FlyPig implements Serializable {
    private static final long serialVersionUID = 1L;
    private static String AGE = "269";   // static 属于类，不参与序列化
    private String name;
    private String color;
    private transient String car;        // transient 修饰的字段不参与序列化

    public void setName(String name) { this.name = name; }
    public void setColor(String color) { this.color = color; }
}

三个必须记住的细节：static 字段属于类，不参与序列化，读回来是当前类的值；transient 字段被跳过，读回来是 null 或默认值；serialVersionUID 是版本号，反序列化时 JVM 拿文件里的版本号与本地类比对，不一致就抛 InvalidClassException。不显式声明时 JVM 会按类结构自动算一个值，你哪怕只加一个字段版本号也会变，旧数据立刻读不出来，所以建议所有可序列化类都显式声明 private static final long serialVersionUID = 1L;。此外，未实现 Serializable 的类写入对象流会抛 NotSerializableException。

小结

本章的脉络可以压缩成四句话。第一，字节流面向二进制、字符流面向文本，而字符流 = 字节流 + 编码表。第二，FileWriter / FileReader 是便捷类，flush() 刷新后可继续写，close() 关闭后不能再写。第三，缓冲流负责效率、转换流负责编码，需要指定编码表时只能用转换流。第四，序列化让对象可持久化与传输，serialVersionUID 一定要显式声明。

另外要养成一个习惯：所有流都用 try-with-resources 管理，避免异常路径下资源泄漏。
