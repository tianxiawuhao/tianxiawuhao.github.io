Java实现License授权许可和验证

Posted on 2022-11-01，15 min read

TrueLicense

TrueLicense 是一个开源的证书管理引擎，使用场景是：软件交付给客户之后，用数字签名保证授权不被随意复制和篡改。它默认只校验证书的开始/结束时间，也可以扩展增加 MAC 地址、CPU 序列号等硬件校验（本文不涉及 FTP 方式的远程校验，介绍的是本地校验方案）。

我们用到的核心是它的 LicenseManager 类，它负责三件事：生成证书文件、安装证书文件、验证证书文件。

不过要先明确一个前提：License 机制防的是守规矩的客户，而不是铁了心破解的人。它能有效阻止客户私自延长有效期、把软件拷到未授权的机器上运行；但一旦私钥泄露，或者攻击者直接在字节码层面绕过校验，这套机制就失效了。因此校验逻辑要尽量收敛、集中，必要时配合代码混淆。

原理

  • 首先需要生成密钥对，方法有很多，JDK 自带的 keytool 即可完成。
  • 授权者保留私钥，使用私钥对包含授权信息（如截止日期、MAC 地址等）的 license 进行数字签名。这里必须区分清楚：签名不是加密，签名只保证内容完整、来源可信，并不会隐藏内容本身。
  • 公钥随程序交付给使用者（放在验证的代码中使用），用于验证签名确由对应私钥签发，并校验有效期、机器码等授权条件。
  • 使用者拿不到私钥，因此无法伪造或篡改授权信息，这就是整套 License 机制的安全边界。

上图把整条链路串了起来：左侧是发布方（离线环境、持有私钥），右侧是使用方（客户服务器、只有公钥）。有两点需要特别注意：一是私钥只用于签名，绝不随程序交付；二是使用方拿到的是 license.lic 与 publicCerts.store，验签失败、已过期或机器码不匹配时都应当直接抛异常拒绝启动，而不是只打一行日志继续运行。

使用 Keytool 命令生成密钥对

Keytool 是一个 Java 数据证书管理工具，它把密钥（key）和证书（certificates）存放在一个称为 keystore 的文件中。keystore 里包含两种数据：
密钥实体（Key entity）——密钥（secret key）又或者是私钥和配对公钥（采用非对称加密）
可信任的证书实体（trusted certificate entries）——只包含公钥

在接触代码前，我们先来大概熟悉下密钥生成的流程吧

  • 首先用 JDK 自带的 keytool 生成私钥库（-alias 是别名，-validity 3650 表示 10 年有效）：

    keytool -genkeypair -alias privatekey -keystore privateKeys.store -keysize 2048 -validity 3650 -storepass "pri2022key" -keypass "pri2022key" -dname "CN=test, OU=test, O=Space, L=SH, ST=SH, C=CN"

    几个容易踩的坑：

    1. keytool 要求库口令至少 6 位，过短会直接报错，命中弱口令规则时还会给出警告；示例中的口令请务必替换成自己的强口令。
    2. -genkey 在 JDK 9 之后已被标记为废弃，建议改用 -genkeypair。
    3. JDK 9 起默认密钥库类型为 PKCS12，而 PKCS12 不支持 -storepass 与 -keypass 取不同值，此时 keytool 会给出警告并把密钥口令对齐为库口令；若确实需要两个口令不同，请显式指定 -storetype JKS。
    4. 密钥长度建议 2048 位及以上，1024 位 RSA 已不再被认为是安全的。

    执行成功后，会在当前命令行所在目录生成 privateKeys.store。

  • 然后把私钥库内的证书导出到一个文件当中：

    keytool -export -alias privatekey -file certfile.cer -keystore privateKeys.store -storepass "pri2022key"

    生成 certfile.cer（证书）文件，它只包含公钥、不包含私钥，导入公钥库之后这个 cer 文件就没用了。

  • 然后再把这个证书文件导入到公钥库：

    keytool -import -alias publiccert -file certfile.cer -keystore publicCerts.store -storepass "pri2022key" -noprompt

    生成 publicCerts.store。如果不加 -storepass，keytool 会交互式要求设置新库口令；加上 -noprompt 则跳过“是否信任该证书”的确认。

    关于口令一致性（重要）：本文示例中，LicenseCreator 与 LicenseVerify 都用 storePass 构造 DefaultCipherParam，而这个口令正是 license.lic 外层 PBE 保护所使用的口令，因此公钥库口令必须与生成端使用的 storePass 完全一致，否则客户端安装证书时会直接解密失败。把公钥库口令与私钥库口令设成同一个值并不理想，生产环境更推荐在 License / LicenseVerify 中额外引入一个独立的 cipherPass 字段，让“库口令”和“license 保护口令”解耦。

privateKeys.store：私钥库，签发方自己留着，绝不能泄露或随产品交付。
publicCerts.store：公钥库，交付给客户，程序用它配合 license 完成验签与授权信息校验。
certfile.cer：中间产物，导入公钥库之后即可删除。

最后把生成的文件 privateKeys.store、publicCerts.store 拷贝到各自的部署目录备用。

私钥库的安全保管建议（这一条比代码本身更重要）：

  • 私钥库只保存在签发环境，尽量放在离线机器或加密磁盘上，不要提交到 Git、不要打进安装包；一旦随产品发出，整套授权体系即告失效。
  • 库口令与私钥口令不要硬编码在代码或 yml 中，改用环境变量、启动参数或密钥管理服务注入，并限制文件权限（如 600）。
  • 私钥库与口令分开存放、分别备份，签发用的机器不要用于日常办公和上网。
  • 若怀疑私钥泄露，无法只更换公钥——必须重新生成密钥对，并对所有已发出的 license 重新签发。
  • 公钥库的完整性同样需要保护：客户端应防止 publicCerts.store 被替换，否则攻击者可以用自己的密钥对伪造一整套 license 与公钥。

自定义密钥库读取：CustomKeyStoreParam

首先从整个流程上来讲，现在这步是证书生成，证书生成需要私钥库和证书参数
在这个引擎中，公/私钥库默认是存储在项目中的。但是，我们实际生产环境中，都是将配置文件等脱离项目部署的，所以我们需要重写它获取公/私钥库的地方。
CustomKeyStoreParam.java

import de.schlichtherle.license.AbstractKeyStoreParam;
import org.springframework.util.ResourceUtils;

import java.io.*;

/**
 * 自定义KeyStoreParam，用于将公私钥存储文件存放到其他磁盘位置而不是项目中。现场使用的时候公钥大部分都不会放在项目中的
 */
public class CustomKeyStoreParam extends AbstractKeyStoreParam {

    /**
     * 公钥/私钥在磁盘上的存储路径
     */
    private final String storePath;
    private final String alias;
    private final String storePwd;
    private final String keyPwd;

    public CustomKeyStoreParam(Class clazz, String resource, String alias, String storePwd, String keyPwd) {
        super(clazz, resource);
        this.storePath = resource;
        this.alias = alias;
        this.storePwd = storePwd;
        this.keyPwd = keyPwd;
    }


    @Override
    public String getAlias() {
        return alias;
    }

    @Override
    public String getStorePwd() {
        return storePwd;
    }

    @Override
    public String getKeyPwd() {
        return keyPwd;
    }

    /**
     * AbstractKeyStoreParam里面的getStream()方法默认文件是存储的项目中。
     * 用于将公私钥存储文件存放到其他磁盘位置而不是项目中
     */
    @Override
    public InputStream getStream() throws IOException {
//        return new FileInputStream(new File(storePath));
        File file = ResourceUtils.getFile(storePath);
        if (file.exists()) {
            return new FileInputStream(file);
        } else {
            throw new FileNotFoundException(storePath);
        }
    }
}

证书参数可以放在配置文件里，也可以写成类，本示例用的是类的方式。注意 ResourceUtils.getFile() 只能解析文件系统路径（支持 file: 前缀），不支持 classpath:，这正是为了把密钥库移出项目而特意重写的。

扩展校验：自定义 CustomLicenseManager

由于引擎默认只验证有效期，当需要自定义校验逻辑时，可以写一个继承 LicenseManager 的自定义证书管理器。
额外的信息的校验可以加在validate()方法里

CustomLicenseManager.java

import de.schlichtherle.license.*;
import de.schlichtherle.xml.GenericCertificate;
import de.schlichtherle.xml.XMLConstants;
import org.apache.logging.log4j.LogManager;
import org.apache.logging.log4j.Logger;

import java.beans.XMLDecoder;
import java.io.BufferedInputStream;
import java.io.ByteArrayInputStream;
import java.io.UnsupportedEncodingException;
import java.util.Date;

/**
 * 自定义LicenseManager，用于增加额外的信息校验(除了LicenseManager的校验，我们还可以在这个类里面添加额外的校验信息)
 */
public class CustomLicenseManager extends LicenseManager {

    private static Logger logger = LogManager.getLogger(CustomLicenseManager.class);

    public CustomLicenseManager(LicenseParam param) {
        super(param);
    }

    /**
     * 复写create方法
     */
    @Override
    protected synchronized byte[] create(LicenseContent content, LicenseNotary notary) throws Exception {
        initialize(content);
        this.validateCreate(content);
        final GenericCertificate certificate = notary.sign(content);
        return getPrivacyGuard().cert2key(certificate);
    }

    /**
     * 复写install方法，其中validate方法调用本类中的validate方法，校验IP地址、Mac地址等其他信息
     */
    @Override
    protected synchronized LicenseContent install(final byte[] key, final LicenseNotary notary) throws Exception {
        final GenericCertificate certificate = getPrivacyGuard().key2cert(key);
        notary.verify(certificate);
        final LicenseContent content = (LicenseContent) this.load(certificate.getEncoded());
        this.validate(content);
        setLicenseKey(key);
        setCertificate(certificate);

        return content;
    }

    /**
     * 复写verify方法，调用本类中的validate方法，校验IP地址、Mac地址等其他信息
     */
    @Override
    protected synchronized LicenseContent verify(final LicenseNotary notary) throws Exception {

        // Load license key from preferences,
        final byte[] key = getLicenseKey();
        if (null == key) {
            throw new NoLicenseInstalledException(getLicenseParam().getSubject());
        }

        GenericCertificate certificate = getPrivacyGuard().key2cert(key);
        notary.verify(certificate);
        final LicenseContent content = (LicenseContent) this.load(certificate.getEncoded());
        this.validate(content);
        setCertificate(certificate);

        return content;
    }

    /**
     * 校验生成证书的参数信息
     */
    protected synchronized void validateCreate(final LicenseContent content) throws LicenseContentException {
        final LicenseParam param = getLicenseParam();
        final Date now = new Date();
        final Date notBefore = content.getNotBefore();
        final Date notAfter = content.getNotAfter();
        if (null != notAfter && now.after(notAfter)) {
            throw new LicenseContentException("证书失效时间不能早于当前时间");
        }
        if (null != notBefore && null != notAfter && notAfter.before(notBefore)) {
            throw new LicenseContentException("证书生效时间不能晚于证书失效时间");
        }
        final String consumerType = content.getConsumerType();
        if (null == consumerType) {
            throw new LicenseContentException("用户类型不能为空");
        }
    }


    /**
     * 复写validate方法，用于增加我们额外的校验信息
     */
    @Override
    protected synchronized void validate(final LicenseContent content) throws LicenseContentException {
        // 1. 首先调用父类的validate方法，校验有效期（notBefore / notAfter）
        super.validate(content);
        // 2. 再校验自定义的 License 参数，例如机器码绑定
        Object extra = content.getExtra();
        if (!(extra instanceof LicenseExtraModel)) {
            return; // 未启用扩展校验
        }
        LicenseExtraModel expected = (LicenseExtraModel) extra;
        if (expected.getMachineCode() == null || expected.getMachineCode().isEmpty()) {
            return;
        }
        // 需自行实现：采集本机 MAC / CPU 序列号 / 主板序列号并做哈希
        String actual = MachineCodeUtils.getMachineCode();
        if (!expected.getMachineCode().equals(actual)) {
            throw new LicenseContentException("License 未授权当前主机：机器码不匹配");
        }
    }


    /**
     * 重写XMLDecoder解析XML
     */
    private Object load(String encoded) {
        BufferedInputStream inputStream = null;
        XMLDecoder decoder = null;
        try {
            inputStream = new BufferedInputStream(new ByteArrayInputStream(encoded.getBytes(XMLConstants.XML_CHARSET)));
            decoder = new XMLDecoder(new BufferedInputStream(inputStream, XMLConstants.DEFAULT_BUFSIZE), null, null);
            return decoder.readObject();
        } catch (UnsupportedEncodingException e) {
            e.printStackTrace();
        } finally {
            try {
                if (decoder != null) {
                    decoder.close();
                }
                if (inputStream != null) {
                    inputStream.close();
                }
            } catch (Exception e) {
                logger.error("XMLDecoder解析XML失败", e);
            }
        }

        return null;
    }

}

签发入口：LicenseCreator

前面的所有可以说都是为了整个流程在铺垫，现在开始是真正开始生成 License 证书的代码

LicenseCreator.java

import de.schlichtherle.license.*;
import org.apache.logging.log4j.LogManager;
import org.apache.logging.log4j.Logger;

import javax.security.auth.x500.X500Principal;
import java.io.File;
import java.text.MessageFormat;
import java.util.prefs.Preferences;

/**
 * License生成类 -- 用于license生成
 */
public class LicenseCreator {

    private final static X500Principal DEFAULT_HOLDER_AND_ISSUER = new X500Principal("CN=Haier, OU=Haier, O=Space, L=SH, ST=SH, C=CN");

    private static final Logger logger = LogManager.getLogger(LicenseCreator.class);

    private final License license;

    public LicenseCreator(License license) {
        this.license = license;
    }

    /**
     * 生成License证书
     */
    public boolean generateLicense() {
        try {
            LicenseManager licenseManager = new CustomLicenseManager(initLicenseParam());
            LicenseContent licenseContent = initLicenseContent();
            licenseManager.store(licenseContent, new File(license.getLicensePath()));
            return true;
        } catch (Exception e) {
            logger.error(MessageFormat.format("证书生成失败：{0}", license), e);
            return false;
        }
    }

    /**
     * 初始化证书生成参数
     */
    private LicenseParam initLicenseParam() {
        Preferences preferences = Preferences.userNodeForPackage(LicenseCreator.class);

        // 设置 license 文件的保护口令：它并不是对授权内容“加密”，只是给 license.lic 外层加一层
        // PBE 保护；真正的防篡改由私钥签名保证。验证端必须使用同一个口令才能解开。
        CipherParam cipherParam = new DefaultCipherParam(license.getStorePass());

        KeyStoreParam privateStoreParam = new CustomKeyStoreParam(LicenseCreator.class, 
                license.getPrivateKeysStorePath(),
                license.getPrivateAlias(),
                license.getStorePass(),
                license.getKeyPass());

        return new DefaultLicenseParam(license.getSubject(),
                preferences,
                privateStoreParam,
                cipherParam);
    }

    /**
     * 设置证书生成正文信息
     */
    private LicenseContent initLicenseContent() {
        LicenseContent licenseContent = new LicenseContent();
        licenseContent.setHolder(DEFAULT_HOLDER_AND_ISSUER);
        licenseContent.setIssuer(DEFAULT_HOLDER_AND_ISSUER);

        licenseContent.setSubject(license.getSubject());
        licenseContent.setIssued(license.getIssuedTime());
        licenseContent.setNotBefore(license.getIssuedTime());
        licenseContent.setNotAfter(license.getExpiryTime());
        licenseContent.setConsumerType(license.getConsumerType());
        licenseContent.setConsumerAmount(license.getConsumerAmount());
        licenseContent.setInfo(license.getDescription());

        //扩展校验，这里可以自定义一些额外的校验信息(也可以用json字符串保存)
        if (license.getLicenseExtraModel() != null) {
            licenseContent.setExtra(license.getLicenseExtraModel());
        }

        return licenseContent;
    }

}

左侧是 license.lic 的逻辑结构：外层由 CipherParam 提供的口令做 PBE 保护（只能防误改，不能防破解），内层依次是证书条目、序列化后的 LicenseContent 正文、extra 扩展信息和 signature 签名值。右侧是客户端校验的四道串行关卡：是否已安装 → 公钥验签是否通过 → 当前时间是否落在有效期内 → extra 中的机器码是否与当前主机一致。任何一关失败都应直接拒绝启动。

代码实现 - 证书安装和校验

就像证书生成，验证也需要一个专门的类

LicenseVerify.java

import de.schlichtherle.license.*;
import org.apache.logging.log4j.LogManager;
import org.apache.logging.log4j.Logger;

import java.io.File;
import java.text.DateFormat;
import java.text.MessageFormat;
import java.text.SimpleDateFormat;
import java.util.prefs.Preferences;

/**
 * License校验类
 */
public class LicenseVerify {

    private static Logger logger = LogManager.getLogger(LicenseVerify.class);
    /**
     * 证书subject
     */
    private final String subject;
    /**
     * 公钥别称
     */
    private final String publicAlias;
    /**
     * 访问公钥库的密码
     */
    private final String storePass;
    /**
     * 证书生成路径
     */
    private final String licensePath;
    /**
     * 密钥库存储路径
     */
    private final String publicKeysStorePath;
    /**
     * LicenseManager
     */
    private LicenseManager  licenseManager;
    /**
     * 标识证书是否安装成功
     */
    private boolean installSuccess;

    public LicenseVerify(String subject, String publicAlias, String storePass, String licensePath, String publicKeysStorePath) {
        this.subject = subject;
        this.publicAlias = publicAlias;
        this.storePass = storePass;
        this.licensePath = licensePath;
        this.publicKeysStorePath = publicKeysStorePath;
    }

    /**
     * 安装License证书，读取证书相关的信息, 在bean加入容器的时候自动调用
     */
    public void installLicense() {
        try {
            Preferences preferences = Preferences.userNodeForPackage(LicenseVerify.class);

            // 该口令用于解密 license.lic 外层的 PBE 保护，必须与生成端的 storePass 一致
            CipherParam cipherParam = new DefaultCipherParam(storePass);

            KeyStoreParam publicStoreParam = new CustomKeyStoreParam(LicenseVerify.class,
                    publicKeysStorePath,
                    publicAlias,
                    storePass,
                    null);
            LicenseParam licenseParam = new DefaultLicenseParam(subject, preferences, publicStoreParam, cipherParam);

            licenseManager = new CustomLicenseManager(licenseParam);
            licenseManager.uninstall();
            LicenseContent licenseContent = licenseManager.install(new File(licensePath));
            DateFormat format = new SimpleDateFormat("yyyy-MM-dd HH:mm:ss");
            installSuccess = true;
            logger.info("------------------------------- 证书安装成功 -------------------------------");
            logger.info(MessageFormat.format("证书有效期：{0} - {1}", format.format(licenseContent.getNotBefore()), format.format(licenseContent.getNotAfter())));
        } catch (Exception e) {
            installSuccess = false;
            logger.error("------------------------------- 证书安装失败 -------------------------------");
            logger.error(e);
        }
    }

    /**
     * 卸载证书，在bean从容器移除的时候自动调用
     */
    public void unInstallLicense() {
        if (installSuccess) {
            try {
                licenseManager.uninstall();
            } catch (Exception e) {
                // ignore
            }
        }
    }

    /**
     * 校验License证书
     */
    public boolean verify() {
        try {
            licenseManager.verify();
            return true;
        } catch (Exception e) {
            // 失败原因（未安装、签名无效、已过期、机器码不匹配等）都在异常里，务必记录
            logger.error("License 校验失败", e);
            return false;
        }
    }

}

有效期与防篡改的三个要点

关于有效期与防篡改，有三点需要澄清：

  • 防篡改靠签名，不靠加密。license 的内容（含有效期、机器码）是明文可读的，但任何改动都会导致验签失败，客户端无法通过编辑文件来延长授权。
  • 有效期依赖本地系统时间。用户把机器时间改回授权期内，父类的 validate() 是拦不住的。安全性要求高时，应叠加服务端时间校验、记录“最后运行时间”并在检测到时间回拨时告警，或者引入在线激活与心跳校验。
  • 机器码校验要放在 validate() 中并抛异常。校验不通过必须让启动失败（例如抛出异常终止 Spring 容器的启动），只记录日志然后继续运行等于没有校验。

与 Spring Boot 集成

前面提过：除了项目本身的许多配置文件外，一般还需要把公钥库、私钥库以及验证所需的参数，放到服务器上单独的路径下

application.yml

# License 相关配置
license:
  subject: licenseTest        # 主体，必须与生成证书时的 subject 完全一致，否则校验不通过
  publicAlias: publiccert     # 公钥别名，对应 keytool -import 时使用的 -alias
  storePass: pri2022key       # 公钥库口令；同时用于解密 license.lic，需与生成端 storePass 相同
  licensePath: 'E:\license2\license.lic'                # license 文件位置
  publicKeysStorePath: 'E:\license\publicCerts.store'   # 公钥库位置

这里的 publicAlias 要与导入公钥时使用的 -alias 写法保持一致（keystore 别名本身大小写不敏感，但统一写法可以避免困惑）；subject 则必须与生成端 param.setSubject(...) 的值一致，否则会因为主体不匹配而校验失败。

这些参数代码获取如下

LicenseConfig.java

import lombok.Data;
import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.context.annotation.Bean;
import org.springframework.stereotype.Component;

@Data
@Component
@ConfigurationProperties(prefix = "license")
public class LicenseConfig {

    /**
     * 证书subject
     */
    private String subject;

    /**
     * 公钥别称
     */
    private String publicAlias;

    /**
     * 访问公钥库的密码
     */
    private String storePass;

    /**
     * 证书生成路径
     */
    private String licensePath;

    /**
     * 密钥库存储路径
     */
    private String publicKeysStorePath;

    @Bean(initMethod = "installLicense", destroyMethod = "unInstallLicense")
    public LicenseVerify licenseVerify() {
        return new LicenseVerify(subject, publicAlias, storePass, licensePath, publicKeysStorePath);
    }

}

以上代码是读取yml的配置，以及将LicenseConfig加入Spring容器，在加入Spring容器的同时，执行licenseVerify里的安装方法

这样，程序就会在启动时，自动安装证书，校验时就可以用了

还要清楚「安装」到底装到了哪里：DefaultLicenseParam 接收的是 Preferences.userNodeForPackage(...)，安装时 license key 会被写进 Java Preferences（Windows 对应注册表 HKEY_CURRENT_USER\Software\JavaSoft\Prefs，Linux 对应 ~/.java/.userPrefs），verify() 再从这里读回来。因此换运行账户（例如改成以 Windows 服务、SYSTEM 账户启动）会出现「明明装过却读不到」的 NoLicenseInstalledException，排查时先确认运行账户是否一致。

最后再强调三点：一是「签名」不是「加密」，license 内容本身是明文可读的，安全性来自私钥签名不可伪造，而不是把内容藏起来；二是私钥库与口令必须留在签发方，一旦泄露只能更换密钥对并重新签发全部 license；三是校验失败必须让程序起不来，同时把失败原因写进日志，方便现场排查是过期、换了机器还是公钥库被替换。
