目标检测常见算法

Posted on 2024-06-06，22 min read

一、目标检测常见算法

目标检测（Object Detection）指在给定的图片中精确找到物体所在的位置，并标注出物体的类别，即回答“物体在哪里、是什么”的问题。
然而，这个问题并不容易：物体的尺寸变化范围很大，摆放角度与姿态不定，可能出现在图片的任何位置，而且图中还可能包含多个不同类别的物体。

目标检测算法

目前学术和工业界出现的目标检测算法分成3类：

  1. 传统的目标检测算法：Cascade + HOG/DPM + Haar/SVM以及上述方法的诸多改进、优化；

  2. 候选区域/窗 + 深度学习分类：通过提取候选区域，并对相应区域进行以深度学习方法为主的分类的方案，如：
    R-CNN（Selective Search + CNN + SVM）
    SPP-Net（Spatial Pyramid Pooling）
    Fast R-CNN（Selective Search + CNN + RoI Pooling）
    Faster R-CNN（RPN + CNN + RoI Pooling）
    R-FCN

  3. 单阶段（one-stage）回归方法：以 YOLO 系列、SSD、RetinaNet、FCOS 等为代表，直接由整幅图像回归出边框与类别；此外还有把检测建模为集合预测的 DETR 系列。早期还出现过结合 RNN 的 RRC detection、结合 DPM 的 Deformable CNN 等尝试。

传统目标检测流程：

  • 区域选择（穷举策略：采用滑动窗口，且设置不同的大小，不同的长宽比对图像进行遍历，时间复杂度高）

  • 特征提取（SIFT、HOG等；形态多样性、光照变化多样性、背景多样性使得特征鲁棒性差）

  • 分类器分类（主要有SVM、Adaboost等）

二、传统的目标检测算法

从图像识别的任务说起

这里有一个图像任务：既要把图中的物体识别出来，又要用方框框出它的位置。

这个任务本质上就是这两个问题：

  • 图像识别，

  • 定位。

图像识别（classification）：
输入：图片
输出：物体的类别
评估方法：准确率

定位（localization）：
输入：图片
输出：方框在图片中的位置（x,y,w,h）
评估方法：检测评价函数 intersection-over-union

卷积神经网络CNN已经帮我们完成了图像识别（判定是猫还是狗）的任务了，我们只需要添加一些额外的功能来完成定位任务即可。

定位的问题的解决思路

  • 思路一：看做回归问题
    看做回归问题，我们需要预测出（x,y,w,h）四个参数的值，从而得出方框的位置。

    步骤1:
    　　• 先解决简单问题，搭一个识别图像的神经网络
    　　• 在 AlexNet、VGG、GoogLeNet 上做 fine-tuning（微调）

    步骤2:
    　　• 在上述神经网络的尾部展开（也就说CNN前面保持不变，我们对CNN的结尾处作出改进：加了两个头：“分类头”和“回归头”）
    　　• 成为classification + regression模式

    步骤3:
    　　• Regression那个部分用欧氏距离损失
    　　• 使用SGD训练

    步骤4:
    　　• 预测阶段把2个头部拼上
    　　• 完成不同的功能

    这里需要进行两次 fine-tuning：
    第一次在 AlexNet 上做；第二次把网络头部换成 regression head、前面的网络保持不变，再做一次 fine-tuning。

    Regression 的部分加在哪？
    有两种处理方法：
    　　• 加在最后一个卷积层后面（如 VGG）
    　　• 加在最后一个全连接层后面（如 R-CNN）

    回归（regression）太难训练了，应想方设法转换为分类（classification）问题：回归的训练参数收敛需要的时间长得多，所以上面的做法是先训练分类网络得到共享部分的权重，再在其上接回归头。

思路二：取图像窗口
　　• 还是刚才的classification + regression思路
　　• 咱们取不同的大小的“框”
　　• 让框出现在不同的位置，得出这个框的判定得分
　　• 取得分最高的那个框

左上角的黑框：得分0.5

右上角的黑框：得分0.75

左下角的黑框：得分0.6

右下角的黑框：得分0.8

根据得分的高低，我们选择了右下角的黑框作为目标位置的预测。
注：有的时候也会选择得分最高的两个框，然后取两框的交集作为最终的位置预测。

疑惑：框要取多大？
取不同的框，依次从左上角扫到右下角。非常粗暴啊。

总结一下思路：
对一张图片，用各种大小的框（遍历整张图片）将图片截取出来，输入到CNN，然后CNN会输出这个框的得分（classification）以及这个框图片对应的x,y,h,w（regression）。

那任务就变成了：多物体识别+定位多个物体
那把这个任务看做分类问题？

看成分类问题有何不妥？
　　• 你需要找很多位置， 给很多个不同大小的框
　　• 你还需要对框内的图像分类
　　• 当然， 如果你的GPU很强大， 恩， 那加油做吧…

所以，传统目标检测的主要问题是：

  • 基于滑动窗口的区域选择策略没有针对性，时间复杂度高，窗口冗余

  • 手工设计的特征对于多样性的变化没有很好的鲁棒性

看做classification， 有没有办法优化下？我可不想试那么多框那么多位置啊！

候选区域/窗 + 深度学习分类

R-CNN 横空出世

有人想到一个好方法：预先找出图中目标可能出现的位置，即候选区域（Region Proposal）。利用图像中的纹理、边缘、颜色等信息，可以保证在选取较少窗口（几千甚至几百）的情况下保持较高的召回率（Recall）。

所以，问题就转变成找出可能含有物体的区域/框（也就是候选区域/框，比如选2000个候选框），这些框之间是可以互相重叠互相包含的，这样我们就可以避免暴力枚举的所有框了。

大牛们发明了很多选取候选区域（Region Proposal）的方法，比如 Selective Search 和 EdgeBoxes。那提取候选框用到的算法“选择性搜索”到底怎么选出这些候选框的呢？具体可以看一下 PAMI 2015 上的论文 “What Makes for Effective Detection Proposals?”。

以下是各种选定候选框的方法的性能对比。

有了候选区域，剩下的工作实际就是对候选区域进行图像分类的工作（特征提取+分类）。对于图像分类，不得不提的是 2012 年 ImageNet 大规模视觉识别挑战赛（ILSVRC）上，机器学习泰斗 Geoffrey Hinton 教授带领学生 Krizhevsky 等人使用卷积神经网络，将 ILSVRC 分类任务的 Top-5 error 降到了 15.3%，而使用传统方法的第二名 Top-5 error 高达 26.2%。此后，卷积神经网络（CNN）占据了图像分类任务的绝对统治地位。

2014年，RBG（Ross B. Girshick）使用Region Proposal + CNN代替传统目标检测使用的滑动窗口+手工设计特征，设计了R-CNN框架，使得目标检测取得巨大突破，并开启了基于深度学习目标检测的热潮。

R-CNN的简要步骤如下

  • 输入测试图像

  • 利用选择性搜索Selective Search算法在图像中从下到上提取2000个左右的可能包含物体的候选区域Region Proposal

  • 因为取出的区域大小各自不同，所以需要将每个Region Proposal缩放（warp）成统一的227×227的大小并输入到CNN，把 CNN 的输出作为该区域的特征

  • 将每个Region Proposal提取到的CNN特征输入到SVM进行分类

具体步骤则如下
步骤一：训练（或者下载）一个分类模型（比如AlexNet）

步骤二：对该模型做fine-tuning
　　• 将分类数从1000改为20，比如20个物体类别 + 1个背景
　　• 去掉最后一个全连接层

步骤三：特征提取
　　• 提取图像的所有候选框（选择性搜索Selective Search）
　　• 对于每一个区域：修正区域大小以适合CNN的输入，做一次前向运算，把卷积网络输出的特征（R-CNN 论文中用的是 pool5 之后的 4096 维特征）存到硬盘

步骤四：训练一个SVM分类器（二分类）来判断这个候选框里物体的类别
每个类别训练一个 SVM 二分类器，判断候选框是否属于该类别：属于则为 positive，否则为 negative。

比如下图，就是狗分类的SVM

步骤五：使用回归器精细修正候选框位置：对于每一个类，训练一个线性回归模型去判定这个框是否框得完美。

细心的同学可能看出来了问题，R-CNN虽然不再像传统方法那样穷举，但R-CNN流程的第一步中对原始图片通过Selective Search提取的候选框region proposal多达2000个左右，而这2000个候选框每个框都需要进行CNN提特征+SVM分类，计算量很大，导致R-CNN检测速度很慢，一张图都需要47s。

有没有方法提速呢？答案是有的，这2000个region proposal不都是图像的一部分吗，那么我们完全可以对图像提一次卷积层特征，然后只需要将region proposal在原图的位置映射到卷积层特征图上，这样对于一张图像我们只需要提一次卷积层特征，然后将每个region proposal的卷积层特征输入到全连接层做后续操作。

但现在的问题是每个region proposal的尺度不一样，而全连接层输入必须是固定的长度，所以直接这样输入全连接层肯定是不行的。SPP Net恰好可以解决这个问题。

SPP Net

SPP：Spatial Pyramid Pooling（空间金字塔池化）

SPP-Net 出自何恺明（Kaiming He）等人发表在 ECCV 2014 的论文《Spatial Pyramid Pooling in Deep Convolutional Networks for Visual Recognition》。

众所周知，CNN一般都含有卷积部分和全连接部分，其中，卷积层不需要固定尺寸的图像，而全连接层是需要固定大小的输入。

所以当全连接层面对各种尺寸的输入数据时，就需要先对输入数据做 crop 或 warp 等预处理以统一尺寸：crop 是从大图中“抠出”网络输入大小的 patch（如 227×227）；warp 是把一个边界框（bounding box）的内容 resize 成 227×227。经典输入尺寸还有 224×224（ImageNet）、32×32（LeNet）、96×96 等。

所以才如你在上文中看到的，在R-CNN中，“因为取出的区域大小各自不同，所以需要将每个Region Proposal缩放（warp）成统一的227×227的大小并输入到CNN”。

但warp/crop这种预处理，导致的问题要么被拉伸变形、要么物体不全，限制了识别精确度。没太明白？说句人话就是，一张16:9比例的图片你硬是要Resize成1:1的图片，你说图片失真不？

SPP-Net 的作者何恺明（Kaiming He）等人逆向思考：既然是因为全连接（FC）层的存在，普通 CNN 才需要固定输入图片的尺寸、使全连接层的输入保持固定，那借鉴卷积层可以适应任何尺寸的特性，为何不能在卷积层最后加入某种结构，让后面全连接层拿到的输入变成固定的呢？

这个“化腐朽为神奇”的结构就是spatial pyramid pooling layer。下图便是R-CNN和SPP Net检测流程的比较：

它的特点有两个:

  • 结合空间金字塔方法实现CNNs的多尺度输入。
    SPP Net的第一个贡献就是在最后一个卷积层后，接入了金字塔池化层，保证传到下一层全连接层的输入固定。
    换句话说，在普通的 CNN 结构中，输入图像的尺寸往往是固定的（比如 224×224 像素），输出则是一个固定维数的向量。SPP-Net 在普通 CNN 结构中加入了空间金字塔池化层，使得网络可以接受任意尺寸的输入图像，而输出仍然是固定维数的向量。

    简言之，CNN 原本只能固定输入、固定输出，CNN 加上 SPP 之后，便能任意输入、固定输出。神奇吧？

    ROI池化层一般跟在卷积层后面，此时网络的输入可以是任意尺度的，在SPP layer中每一个pooling的filter会根据输入调整大小，而SPP的输出则是固定维数的向量，然后给到全连接FC层。

  • 只对原图提取一次卷积特征
    在R-CNN中，每个候选框先resize到统一大小，然后分别作为CNN的输入，这样是很低效的。
    而SPP Net根据这个缺点做了优化：只对原图进行一次卷积计算，便得到整张图的卷积特征feature map，然后找到每个候选框在feature map上的映射patch，将此 patch 作为每个候选框的卷积特征，送入 SPP layer 及其后的层，完成特征提取工作。

    如此这般，R-CNN要对每个区域计算卷积，而SPPNet只需要计算一次卷积，从而节省了大量的计算时间，比R-CNN有一百倍左右的提速。

Fast R-CNN

SPP Net真是个好方法，R-CNN的进阶版Fast R-CNN就是在R-CNN的基础上采纳了SPP Net方法，对R-CNN作了改进，使得性能进一步提高。

R-CNN与Fast R-CNN的区别有哪些呢？
先说R-CNN的缺点：即使使用了Selective Search等预处理步骤来提取潜在的bounding box作为输入，但是R-CNN仍会有严重的速度瓶颈，原因也很明显，就是计算机对所有region进行特征提取时会有重复计算，而 Fast R-CNN 正是为了解决这个问题诞生的。

与R-CNN框架图对比，可以发现主要有两处不同：一是最后一个卷积层后加了一个ROI pooling layer，二是损失函数使用了多任务损失函数(multi-task loss)，将边框回归Bounding Box Regression直接加入到CNN网络中训练

  • ROI pooling layer 实际上是 SPP-Net 中空间金字塔池化的一个精简版：SPP-Net 对每个 proposal 使用不同大小的金字塔分桶，而 ROI pooling layer 只下采样到一个 7×7 的特征图。对于 VGG16，conv5_3 有 512 个特征图，于是每个 region proposal 都对应一个 7×7×512 维的特征向量，作为全连接层的输入。

    换言之，这个网络层可以把不同大小的输入映射到一个固定尺度的特征向量，而我们知道，conv、pooling、relu等操作都不需要固定size的输入，因此，在原始图片上执行这些操作后，虽然输入图片size不同导致得到的feature map尺寸也不同，不能直接接到一个全连接层进行分类，但是可以加入这个神奇的ROI Pooling层，对每个region都提取一个固定维度的特征表示，再通过正常的softmax进行类型识别。

  • R-CNN训练过程分为了三个阶段，而Fast R-CNN直接使用softmax替代SVM分类，同时利用多任务损失函数边框回归也加入到了网络中，这样整个的训练过程是端到端的(除去Region Proposal提取阶段)。

    也就是说，之前 R-CNN 的处理流程是先提 proposal，再让 CNN 提取特征，之后用 SVM 分类器分类，最后做 bbox regression；而在 Fast R-CNN 中，作者巧妙地把 bbox regression 放进了神经网络内部，与 region 分类合并成一个 multi-task 模型。实验也证明，这两个任务能够共享卷积特征并相互促进。

所以，Fast-RCNN很重要的一个贡献是成功的让人们看到了Region Proposal + CNN这一框架实时检测的希望，原来多类检测真的可以在保证准确率的同时提升处理速度，也为后来的Faster R-CNN做下了铺垫。

画一画重点：
R-CNN有一些相当大的缺点（把这些缺点都改掉了，就成了Fast R-CNN）。

大缺点：由于每一个候选框都要独自经过CNN，这使得花费的时间非常多。
解决：共享卷积层，现在不是每一个候选框都当做输入进入CNN了，而是输入一张完整的图片，在第五个卷积层再得到每个候选框的特征

原来的方法：许多候选框（比如两千个）-->CNN-->得到每个候选框的特征-->分类+回归
现在的方法：一张完整图片-->CNN-->得到每张候选框的特征-->分类+回归

所以容易看出，Fast R-CNN 相对 R-CNN 的提速原因就在于：不再像 R-CNN 那样把每个候选区域分别送进 CNN 提特征，而是对整张图只做一次卷积，得到整图的 feature map，再把各候选框映射到 conv5 的特征图上做后续操作。

在性能上提升也是相当明显的：

Faster R-CNN

Fast R-CNN存在的问题：存在瓶颈：选择性搜索，找出所有的候选框，这个也非常耗时。那我们能不能找出一个更加高效的方法来求出这些候选框呢？

解决：加入一个用于提取候选区域的神经网络，也就是说，把找候选框的工作也交给神经网络来做。

所以，作者在 Faster R-CNN 中引入 Region Proposal Network（RPN）来替代 Selective Search，同时引入 anchor box 以应对目标形状变化的问题（anchor 是位置与大小预先固定的 box，可以理解为预设好的 proposal）。

具体做法：
　　• 将RPN放在最后一个卷积层的后面
　　• RPN直接训练得到候选区域

RPN简介：
　　• 在feature map上滑动窗口
　　• 建一个神经网络用于物体分类+框位置的回归
　　• 滑动窗口的位置提供了物体的大体位置信息
　　• 框的回归提供了框更精确的位置

一个网络，包含四个损失函数：
　　• RPN classification（anchor：good / bad）
　　• RPN regression（anchor → proposal）
　　• Fast R-CNN classification（目标类别分类）
　　• Fast R-CNN regression（proposal → box）

速度对比

Faster R-CNN 的主要贡献就是设计了提取候选区域的网络 RPN，代替了耗时的选择性搜索（Selective Search），使得检测速度大幅提高。

最后总结一下各大算法的步骤：

RCNN
1.在图像中确定约1000-2000个候选框 (使用选择性搜索Selective Search)
2.每个候选框内图像块缩放至相同大小，并输入到CNN内进行特征提取
3.对候选框中提取出的特征，使用分类器判别是否属于一个特定类
4.对于属于某一类别的候选框，用回归器进一步调整其位置

Fast R-CNN
1.在图像中确定约1000-2000个候选框 (使用选择性搜索Selective Search)
2.对整张图片输进CNN，得到feature map
3.找到每个候选框在feature map上的映射patch，将此patch作为每个候选框的卷积特征，送入RoI Pooling层得到固定长度的特征
4.对候选框中提取出的特征，使用分类器判别是否属于一个特定类
5.对于属于某一类别的候选框，用回归器进一步调整其位置

Faster R-CNN
1.对整张图片输进CNN，得到feature map
2.卷积特征输入到RPN，得到候选框的特征信息
3.对候选框中提取出的特征，使用分类器判别是否属于一个特定类
4.对于属于某一类别的候选框，用回归器进一步调整其位置

简言之，即如本文开头所列

R-CNN（Selective Search + CNN + SVM）
SPP-net（ROI Pooling）
Fast R-CNN（Selective Search + CNN + ROI）
Faster R-CNN（RPN + CNN + ROI）

总的来说，从 R-CNN、SPP-Net、Fast R-CNN 到 Faster R-CNN，基于深度学习的目标检测流程变得越来越精简，精度越来越高，速度也越来越快。基于候选区域（Region Proposal）的 R-CNN 系列方法，是目标检测技术中一个重要的分支。

三、基于深度学习的回归方法

YOLO (CVPR2016, oral)

(You Only Look Once: Unified, Real-Time Object Detection)

R-CNN 系列这类两阶段方法精度高，但速度难以满足实时检测的要求。于是，YOLO 一类单阶段回归方法逐渐显现出重要性：这类方法直接使用整张图作为输入，在图像的多个位置上回归出目标边框以及目标所属的类别。

我们直接看上面YOLO的目标检测的流程图：

(1) 给定一个输入图像，首先将其划分成 7×7 的网格；
(2) 对每个网格都预测 2 个边框（包括每个边框包含目标的置信度，以及该边框区域在多个类别上的概率）；
(3) 由前两步可以得到 7×7×2 个候选目标窗口，按阈值去除可能性较低的窗口，最后用 NMS（非极大值抑制）去除冗余窗口。

可以看到整个过程非常简单，不再需要中间的Region Proposal找目标，直接回归便完成了位置和类别的判定。

小结：YOLO 把目标检测任务转换成一个回归问题，大大加快了检测速度，可以每秒处理 45 张图像；并且每个网格预测时都利用了全图信息，使 false positive 比例大幅降低（得益于充分的上下文信息）。

但是 YOLO 也存在问题：没有 Region Proposal 机制，只靠 7×7 的网格回归，目标难以被非常精准地定位，这导致 YOLO 的检测精度并不高。

SSD

(SSD: Single Shot MultiBox Detector)

上面分析了YOLO存在的问题，使用整图特征在7*7的粗糙网格内回归对目标的定位并不是很精准。那是不是可以结合Region Proposal的思想实现精准一些的定位？SSD结合YOLO的回归思想以及Faster R-CNN的anchor机制做到了这点。

上图是SSD的一个框架图，首先SSD获取目标位置和类别的方法跟YOLO一样，都是使用回归，但是YOLO预测某个位置使用的是全图的特征，SSD预测某个位置使用的是这个位置周围的特征（感觉更合理一些）。

那么如何建立某个位置和其特征的对应关系呢？可能你已经想到了：使用 Faster R-CNN 的 anchor 机制。如 SSD 的框架图所示，假如某一层特征图（图 b）大小是 8×8，就使用 3×3 的滑窗提取每个位置的特征，再由这些特征回归得到目标的坐标与类别信息（图 c）。

不同于Faster R-CNN，这个anchor是在多个feature map上，这样可以利用多层的特征并且自然的达到多尺度（不同层的feature map 3*3滑窗感受野不同）。

小结：SSD 结合了 YOLO 中的回归思想和 Faster R-CNN 中的 anchor 机制，使用全图各个位置的多尺度区域特征进行回归，既保持了 YOLO 速度快的特性，也让窗口预测比 YOLO 更精准。SSD300 在 VOC2007 test 上 mAP 可达到 72.1%（SSD512 为 75.1%），在当时的 GPU 上可以跑到 58 FPS 左右。

R-FCN

Faster R-CNN 之后，精度已经不是主要矛盾，速度才是：RoI Pooling 之后每个候选区域都要单独经过若干全连接层，一张图几百个 RoI 就意味着几百次重复计算。R-FCN（Region-based Fully Convolutional Networks，NIPS 2016）的思路是把计算量全部前移到共享的卷积层，让 RoI 之后不再有任何“逐区域”的卷积或全连接。

它的关键设计是位置敏感得分图（position-sensitive score map）：对每个类别生成 \(k^2\) 张得分图（论文中 \(k=3\)），每张图只负责描述“相对该物体位置的一个九宫格分区”。做 RoI Pooling 时，把这 \(k \times k\) 个分区分别池化再投票求和，就得到这个 RoI 属于该类别的得分。因为得分图本身是卷积算出来的整图结果，RoI 阶段只剩下取值与求和，几乎不耗时。

R-FCN 用 ResNet-101 做骨干时，在 VOC 2007 上 mAP 约 83.6%，测试速度约 170 ms/张，比同骨干的 Faster R-CNN 快约 2.5～3 倍。它的位置敏感思想也影响了后来的一些分割与检测工作，不过随着 FPN、单阶段检测器和 Transformer 检测器的成熟，R-FCN 如今更多是作为演进链条上的一环被提及。

单阶段检测器的演进

从 YOLOv1 到 YOLOv3

YOLOv1 的价值在于把检测变成一次回归，速度极快，但召回率和定位精度明显落后于两阶段方法。后续版本沿着“更强骨干 + 更细粒度预测 + 更好损失”的方向迭代：

  • YOLOv2 / YOLO9000（CVPR 2017）：引入 Batch Normalization、高分辨率分类器微调，并用 k-means 在数据集上聚类得到先验框（anchor），同时用 \(13\times13\) 的网格配合 anchor 预测，把 VOC 2007 上的 mAP 从 63.4% 提升到 78.6%，还支持 9000 类联合训练。
  • YOLOv3（2018）：改用 Darknet-53 骨干和类似 FPN 的多尺度预测（\(13\times13\)、\(26\times26\)、\(52\times52\) 三个尺度），每个位置 3 个 anchor，分类损失改用二元交叉熵以支持多标签，小目标检测能力明显改善。

RetinaNet 与 Focal Loss

单阶段检测器长期打不过两阶段方法，一个被忽视的原因是正负样本极端失衡：一张图可能产生十万量级的候选位置，其中真正包含目标的只有几十个，大量易分的负样本会淹没损失、把训练带偏。

RetinaNet（ICCV 2017 最佳学生论文）给出的答案是 Focal Loss。它是在交叉熵前乘上一个调制因子：

\[ FL(p_t) = -\alpha_t (1-p_t)^{\gamma} \log(p_t) \]

其中 \(p_t\) 是模型对真实类别的预测概率，\(\gamma\) 为聚焦参数（论文取 \(\gamma=2\)），\(\alpha_t\) 用于平衡正负样本（论文取 \(\alpha=0.25\)）。当样本已被正确分类（\(p_t \to 1\)）时，\((1-p_t)^{\gamma}\) 趋近于 0，该样本的损失被大幅压低；难分样本则几乎不受影响。这样一来，训练会自动把注意力集中到难例上，无需再靠 OHEM 之类的硬采样。

RetinaNet 的网络结构是 ResNet + FPN 骨干，两个子网分别做分类与边框回归（分类子网较深，回归子网较浅），配合 Focal Loss 在 COCO 上首次让单阶段检测器在精度上超过同期两阶段方法，同时保持较快的推理速度。它也让“单阶段精度天然差”这个印象成为历史。

FCOS 与 anchor-free

anchor 机制带来了一堆需要调的超参：尺度和长宽比怎么设、IoU 阈值取多少、正负样本怎么匹配。FCOS（ICCV 2019）干脆取消了 anchor，改为逐像素预测：对特征图上的每个位置，直接回归它到目标四条边的距离 \((l, t, r, b)\)，并判断该位置是否落在某个目标的中心区域，中心度（center-ness）分支用于抑制离目标中心较远的低质量框。

anchor-free 的好处是超参更少、结构更简单，也更容易与 FPN 的多尺度预测结合。同一时期还有 CornerNet、CenterNet 等基于关键点的做法。此后 YOLOX、YOLOv8 等主流检测器也相继转向 anchor-free。

DETR 系列

2020 年 Facebook AI 提出的 DETR（Detection Transformer，ECCV 2020）是第三条路线：把检测任务建模为集合预测。它用 CNN 骨干提取特征，送入 Transformer 编码器—解码器，解码器输出固定数量（如 100 个）的预测结果，再通过匈牙利算法（Hungarian matching）与真实目标做二分图匹配，实现真正的端到端训练。

DETR 有两大优点：不需要 anchor，也不需要 NMS 后处理；缺点是收敛慢（需要 500 个 epoch）且对小目标不友好。后续工作针对这两点持续改进：

  • Deformable DETR（ICLR 2021）：用可变形注意力只关注参考点附近的少量采样点，收敛轮数降到原来的十分之一左右，小目标性能明显改善；
  • DAB-DETR、DN-DETR、DINO（2022）：改进查询的语义与去噪训练，DINO 在 COCO 上达到 63.3 AP，成为当时最强的检测器之一；
  • RT-DETR（CVPR 2024）：百度提出的实时版本，用高效混合编码器与 IoU 感知的查询选择，把 DETR 推到实时区间，也是第一个在速度和精度上同时超过同期 YOLO 的实时端到端检测器；
  • D-FINE（2025）：把边框回归重新表述为概率分布精化（FDR）与自蒸馏，进一步提升了 DETR 类模型的定位精度。

RoI Pooling 与 RoI Align

这两个层只差一个“取整”的动作，精度差别却很明显。

  • RoI Pooling（Fast R-CNN）：候选框从原图映射到特征图时，坐标要除以步长（stride，例如 16），得到的往往是小数，而实现上会直接四舍五入取整；随后把 RoI 均分成 \(7\times7\) 个格子时，每个格子的边界同样要取整。两次量化误差在小目标上可能占到几个像素，映射回原图就是几十像素的偏移。
  • RoI Align（Mask R-CNN，ICCV 2017）：取消所有量化，保留浮点坐标；把 RoI 均分为 \(7\times7\)（或 \(14\times14\)）个格子后，在每个格子内取 4 个采样点（2×2），用双线性插值从特征图上算出这些点的值，再取最大或平均池化。

实验上，RoI Align 带来的提升在检测上约 0.5～1 个点，在掩膜分割这种对像素级对齐更敏感的任务上提升更大（Mask R-CNN 论文中约 3 个点），因此它已成为后续方法的默认选择。

NMS 与 Soft-NMS

检测器会在同一目标周围产生大量重叠框，需要后处理去冗余。NMS（非极大值抑制）的做法是：按置信度从高到低排序，取出最高分框，把与它 IoU 超过阈值（通常 0.5）的框全部删除，重复直到没有剩余框。

NMS 的缺陷在于“一刀切”：重叠度超过阈值的框无论置信度高低都被直接扔掉，因此两个真实目标挨得很近时，其中一个会被误删（漏检）。Soft-NMS（ICCV 2017）把“删除”换成“降分”：对重叠框按重叠程度连续地衰减其置信度（线性或高斯加权），衰减后的框仍有机会以较低分数参与后续比较，最后再按分数阈值统一过滤。

Soft-NMS 不增加训练成本，只改后处理，在 COCO 上通常能带来约 1 个点左右的提升，代价是计算量略增；在人群、车辆等遮挡密集的场景中收益更明显。此外，YOLOv10、DETR 系列通过一对一匹配实现了 NMS-free 的端到端推理，这也是近年的重要方向之一。

评价指标：IoU、精确率、召回率与 mAP

检测任务既要判对类别，又要框准位置，因此指标是分类指标与定位指标的组合。

IoU 衡量预测框与真实框的重合程度：

\[ \mathrm{IoU} = \frac{\text{预测框} \cap \text{真实框}}{\text{预测框} \cup \text{真实框}} \]

通常把 IoU 大于阈值（如 0.5）的预测视为真正例（TP）。在此基础上定义：

\[ \text{Precision} = \frac{TP}{TP+FP}, \qquad \text{Recall} = \frac{TP}{TP+FN} \]

精确率回答“报出来的框有多少是对的”，召回率回答“真实目标有多少被找到了”。两者随置信度阈值此消彼长，于是用 PR 曲线下的面积 AP（Average Precision）来综合刻画单个类别的性能，对所有类别取平均即得 mAP（mean Average Precision）。

需要特别注意的是不同数据集对 mAP 的定义并不一致：

  • PASCAL VOC：常用 \(\mathrm{mAP@0.5}\)，即 IoU 阈值固定为 0.5 时的 mAP（VOC2010 之后按全点插值计算 PR 面积）；
  • MS COCO：主指标 \(\mathrm{AP@[.5:.95]}\) 是在 IoU 阈值 0.5 到 0.95、步长 0.05 的 10 个阈值上分别算 AP 再平均，对定位精度要求更严格，同一模型在 COCO 上的数值通常比 VOC 口径低十几个点；此外还分 \(\mathrm{AP_S}\)、\(\mathrm{AP_M}\)、\(\mathrm{AP_L}\) 报告小、中、大目标的精度。

因此比较模型时必须说明指标口径：“mAP 72.1%”如果不写清数据集与 IoU 阈值，是没有意义的。工程上还会同时关注推理速度（FPS、ms/图）和参数量、FLOPs。

损失函数：分类损失 + 回归损失

现代检测器普遍使用多任务损失，由分类损失、边框回归损失（有些方法还有目标性损失、中心度损失）加权相加：

\[ L = L_{cls} + \lambda L_{reg} \]

  • 分类损失：早期 R-CNN 用 SVM 的 hinge loss，Fast R-CNN 起改用 softmax 交叉熵；单阶段检测器中每个位置都要判正负，正负样本比例可能达到 1:1000，因此 RetinaNet 引入 Focal Loss（见上文），Faster R-CNN 的 RPN 则通过采样固定比例的正负样本来缓解失衡。

  • 回归损失：直接对 \((x, y, w, h)\) 做 L2 损失对离群点过于敏感（Fast R-CNN 论文指出 L2 需要仔细调学习率才不至于梯度爆炸），因此改用 Smooth L1：

    \[ \mathrm{smooth}_{L_1}(x) = \begin{cases} 0.5x^{2} & |x| < 1 \\ |x| - 0.5 & \text{否则} \end{cases} \]

    它的形式是对预测偏移量做回归，而不是直接回归绝对坐标，训练更稳定。

  • IoU 系损失：Smooth L1 把四个坐标当作相互独立的量，与评价指标 IoU 并不一致。IoU Loss、GIoU Loss、DIoU / CIoU Loss（2020）把重叠面积、中心点距离、长宽比直接写进损失，与指标更对齐，已成为当前主流：YOLO 系列常用 CIoU，其后还有 EIoU、SIoU 等变体。

2023—2025 年的现状

如果今天要在工程里选一个检测器，yolov1 时代的那份清单已经不够用了。当前主流可以概括为三条线：

YOLO 系列的最新版本

  • YOLOv5 / YOLOv7 / YOLOv8：分别来自 Ultralytics 与 YOLOv4 作者团队。YOLOv8（2023）是 anchor-free、解耦检测头的统一框架，同时提供 n/s/m/l/x 五档规模，覆盖从边缘设备到服务器的需求；
  • YOLOv9（2024）：提出可编程梯度信息（PGI）与 GELAN 结构，缓解深网络中的信息丢失；
  • YOLOv10（2024）：由清华大学团队提出，通过一致的双重分配实现无 NMS 的端到端推理，同时做了大量效率优化；
  • YOLOv11（2024 下半年）：Ultralytics 发布的迭代版本，在骨干与检测头上进一步精简，同精度下参数更少、速度更快，并统一支持检测、分割、姿态、分类等任务；
  • YOLOv12（2025）：以注意力机制为中心的版本，把注意力模块重新引入实时检测器（社区对其“官方”血统有争议，选型时应以实测为准）。

实时端到端检测器

RT-DETR 及其后续工作在 COCO 上已能做到 50 AP 以上、百 FPS 级别的推理，且不需要 NMS——这消除了后处理带来的延迟抖动，对部署非常友好。D-FINE（2025）、LW-DETR 等继续沿着“更轻、更准的 Transformer 检测器”推进。总体趋势是：单阶段与 Transformer 两条路线在实时区间正面竞争，anchor-free 与 NMS-free 成为默认选择。

其他值得关注的进展

  • 开放词汇与零样本检测：GLIP、Grounding DINO 把检测与语言对齐，可以用文本提示检测任意类别；
  • 分割一切与检测的结合：SAM 类模型提供通用分割能力，配合检测器构成“检测 + 分割”的流水线，也出现了 FastSAM 这类实时方案；
  • DETR 式端到端训练已从学术概念变成工程常态，成为新一代检测框架的默认范式之一。

七、小结

把全文串起来看，目标检测的演进可以概括成三条并行的线索：

  1. 两阶段：R-CNN 用 Selective Search 找候选区域、用 CNN 提特征、用 SVM 分类，是深度学习检测的开端；SPP-Net 与 Fast R-CNN 通过共享卷积、RoI Pooling 和多任务损失把流程变成端到端（除候选区域提取外）；Faster R-CNN 用 RPN + anchor 把候选区域提取也交给网络；R-FCN 则把逐 RoI 计算彻底消掉。这条线索的主线是不断消除重复计算、把精度做高。
  2. 单阶段：YOLO 把检测变成一次回归，速度快但定位粗；SSD 结合回归与 anchor、在多尺度特征图上预测；RetinaNet 用 Focal Loss 解决正负样本失衡，证明单阶段也能有高精度；FCOS 去掉 anchor；DETR 系列进一步去掉 NMS。这条线索的主线是在保持实时性的同时逼近甚至超过两阶段精度。
  3. 工程现实：今天的选型基本落在 YOLOv8/v11 这类成熟单阶段模型和 RT-DETR 这类实时端到端模型之间。指标上要同时看 \(\mathrm{mAP@[.5:.95]}\) 与延迟，训练上要处理样本失衡与回归损失，后处理上要理解 NMS / Soft-NMS 的取舍。

换句话说，“能不能用”早就不是问题了，“在给定算力下如何取得最好的精度—延迟折中”才是现在真正要回答的问题。
