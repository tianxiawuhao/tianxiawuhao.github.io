java基础之一文件操作

Posted on 2021-05-08，11 min read

一、抽象类：

字节流： InputStream（读入流） OutputStream（写出流）
字符流：Reader（字符读入流） Writer（字符写出流）

字节流读取字符数据的问题 :

汉字等字符往往由多个字节组成，到底哪几个字节应该组成一个汉字呢？字节流并不知道。如果我们自己用字节流读取字节数据再手动转字符，就可能因为对规则不了解而出错，Java 的字符流恰好能帮我们解决这个问题。

Java提供的字符流的底层，它自己会根据读取到的字节数据的特点，然后自动的帮助我们把字节转成字符，最后我们就会自然的得到想要的字符数据。

字符流怎么解决这个问题呢？

字符流 = 字节流 + 编码表

编码表里面定义了字节与字符的转换规则。

字符流在读取数据时，底层仍然是字节流在读取数据，字符流会自动根据编码规则把字节数据转为字符数据，因此不会出错。

编码表的介绍 :

说明：计算机中保存的数据都是二进制（如 1010100101001）。要把生活中的数据存进计算机，就得先把它转成二进制；要让计算机能正确识别这些数据，就必须定义一个固定的转换关系。

为此老美发明了一张表，在表中规定了生活中所有字符与二进制之间的对应关系，这就是 ASCII（美国信息交换标准代码）。

ASCII码表： 它采用的是一个字节表示所有的文字（标点符号，英文字母，其他的特殊符号，数字等）。

生活中的字符 十进制 二进制
A 65 01000001
B 66 01000010

欧洲也定义了一张拉丁码表 ISO-8859-1，它兼容 ASCII 码表，同样用一个字节表示字符数据。

ASCII： 一个字节表示一个字符： 0xxx xxxx 规定二进制的最高位是0，其他的7位表示某个字符的编码值。

ISO-8859-1： 一个字节表示一个字符：把整个字节表示字符，xxxx xxxx 全部用来表示字符数据

中国的编码表： GBK编码表采用2个字节表示一个汉字。
GB2312 ： 它识别六七千的文字。兼容ASCII编码表。

GBK：识别两万多字符，是中文环境下 Windows 的默认编码。

GB18030： 识别更多。

为了统一各国互不兼容的编码，国际标准化组织与业界共同制定了国际通用的字符集：

Unicode 编码表：Unicode 是字符集，为世界上几乎所有字符分配唯一码点（U+0000～U+10FFFF）。最早用固定 2 字节的 UCS-2 表示基本多文种平面，超出范围的字符需要 4 字节（UTF-16 的代理对），因此 Unicode 本身并不规定一个字符占几个字节。

Unicode 的落地编码方案有 UTF-8、UTF-16、UTF-32 等，其中最常用的是 UTF-8。

UTF-8：它是 Unicode 的一种变长编码：能用 1 个字节表示的字符就用 1 个字节，需要 2 个字节的用 2 个字节，需要 3 个字节的用 3 个字节（常用汉字为 3 个字节），辅助平面字符则用 4 个字节。

可以识别汉字的编码表：GB2312、GBK、Unicode、UTF-8

三、缓冲流：

字节缓冲流： BufferedInputStream,BufferedOutputStream
字符缓冲流：BufferedReader ,BufferedWriter
缓冲流是对流的操作的功能的加强，提高了数据的读写效率。既然缓冲流是对流的功能和读写效率的加强和提高，所以在创建缓冲流的对象时应该要传入要加强的流对象。

// 构造方法签名（源码节选，以注释形式给出）
// 缓冲区数组默认大小 8192
// public BufferedInputStream(InputStream in)
// 指定缓冲区大小 size
// public BufferedInputStream(InputStream in, int size)
// public BufferedOutputStream(OutputStream out)
// public BufferedOutputStream(OutputStream out, int size)

BufferedWriter bw = new BufferedWriter(new OutputStreamWriter(new FileOutputStream("demo08_utf8.txt"), "UTF-8"));

BufferedReader br = new BufferedReader(new InputStreamReader(new FileInputStream("demo08_utf8.txt"), "UTF-8"));

//1.指定要读 的文件目录及名称
File file =new File("文件路径");
//2.创建文件读入流对象
FileInputStream fis =new FileInputStream(file);
//3.创建缓冲流对象加强fis功能
BufferedInputStream bis =new BufferedInputStream(fis); 
//4.定义结束标志,可用字节数组读取
int i =0 ;
while((i = bis.read())!=-1){ 
    //i 就是从文件中读取的字节，读完后返回-1
}
//5.关闭流
bis.close();
//6.处理异常

//1.指定要写到的文件目录及名称
File file =new File("文件路径");
//2.创建文件读入流对象
FileOutputStream fos =new FileOutputStream(file);
//3.创建缓冲流对象加强fos功能
BufferedOutputStream bos=new BufferedOutputStream(fos);
//4.向流中写入数据
byte[] data = "要写出的内容".getBytes(StandardCharsets.UTF_8);
bos.write(data);
//5.刷新和关闭流
bos.flush();
bos.close();
//6.处理异常

由以上看出流的操作基本相同，此流与文件流操作几乎一样，只是将文件流作为参数传入缓冲流的构造方法，对文件流读写文件的功能进行加强
注1：在字符读入缓冲流BufferedReader 中还提供了读一行的方法 readLine() 可以读取一行文本
在字符写出缓冲流BufferedWriter 中还提供了写入一个行分隔符的方法 newLine()，用于写出时换行
注2：此处用到的是设计模式中的装饰模式。下图给出节点流、缓冲流与转换流的包装关系：

//装饰的对象只要是抽象类的子类即可
BufferedInputStream bis =new BufferedInputStream(new FileInputStream(new File("文件路径")));

四、转换流：

这类流是用于将字符转换为字节输入输出，用于操作字符文件，属于字符流的子类，所以后缀为reader，writer；前缀inputstream，outputstream；

注：要传入字节流作为参数
InputStreamReader：字节输入流 → 字符输入流（解码，构造时可指定编码表）
OutputStreamWriter：字符输出流 → 字节输出流（编码，构造时可指定编码表）

需求：读取键盘输入的一行文本,再将输入的写到本地磁盘上
//1.获取键盘输入的字节流对象in
InputStream in = System.in;
/*2.用转换流将字节流对象转换为字符流对象，方便调用字符缓冲流的 readLine() 方法*/
InputStreamReader isr =new InputStreamReader(in);
/*5.创建字符转换输出流对象osw，方便把输入的字符流转换为字节输出到本地文件。*/
OutputStreamWriter osw =new OutputStreamWriter(new FileOutputStream(new File("文件名"))); 
/*3.现在isr是字符流，可以作为参数传入字符缓冲流中*/
BufferedReader br =new BufferedReader(isr);
/*4.可以调用字符缓冲流br的readLine()方法度一行输入文本*/
String line =null;
while ((line = br.readLine()) != null) {
    osw.write(line);//osw是字符流对象，可以直接操作字符串
}
//刷新此缓冲的输出流，保证数据全部都能写出
osw.flush();
br.close();
osw.close();

读取数据

下面三种写法演示从字符流读取数据的常见方式，注意用数组读取时只能取 0..len 区间的有效数据。

//读取方式一 : 效率低!
int content = -1;
while ((content = reader.read()) != -1) {
    System.out.print((char)content);
}


//读取方式二 : 数组之后的无用数据都会被读取!
int len = -1;
char[] cbuf = new char[1024];
while ((len = reader.read(cbuf)) != -1) {
    System.out.println(cbuf);
}


// 读取方式三 : 只取数组中有效的 0..len 部分转成字符串
int len2 = -1;
char[] cbuf2 = new char[1024];
while ((len2 = reader.read(cbuf2)) != -1) {
    String str = new String(cbuf2, 0, len2);
    System.out.println(str);
}

转换流 和 操作流 之间的关系 :
转换流 :
1. OutputStreamWriter = OutputStream + 任意编码表
2. InputStreamReader = InputStream + 任意编码表
操作流 :
1. FileWriter = OutputStreamWriter + 默认编码表
2. FileReader = InputStreamReader + 默认编码表
总结 : 一般使用操作流，需要指定编码表时才使用转换流

补充：JDK 18 起 FileReader/FileWriter 的默认字符集已由平台默认改为 UTF-8；JDK 8～17 在中文 Windows 上默认是 GBK，跨平台读写务必显式指定编码。

拆分文件及还原

思路很简单：先用 judge() 遍历文件累加字节数得到总大小，再按份数 n 依次切出 n 个分片文件，最后按分片顺序把字节写回一个新文件即可还原。下面的示例把 somethings/test.flv 切成 6 份再拼成 somethings/jzc.flv。

public class Test {
     public static void main(String[] args) throws IOException {
           int count = judge();
           System.out.println(count);
           BufferedInputStream bis = new BufferedInputStream(new FileInputStream(
                     "somethings\\test.flv"));
           incision(count, bis, 6);
           BufferedOutputStream bos = new BufferedOutputStream(
                     new FileOutputStream("somethings\\jzc.flv"));
           joint(bos,6);
           bos.close();
           bis.close();
     }
     public static void joint( BufferedOutputStream bos,int n)
                throws FileNotFoundException, IOException {
           for (int i = 1; i <= n; i++) {
                BufferedInputStream bis = new BufferedInputStream(
                           new FileInputStream("somethings\\jzc" + i + ".flv"));
                byte[] bys = new byte[1024];
                int len = -1;
                while ((len = bis.read(bys)) != -1) {
                     bos.write(bys, 0, len);
                }
                bis.close();
           }
           bos.close();
           System.out.println("拼接完了");
     }
     public static void incision(int count, BufferedInputStream bis, int n)
                throws FileNotFoundException, IOException {
           byte[] bys = new byte[1024];
           int len = -1;
           
           for (int i = 1; i <= n; i++) {
                int count2 = 0;
                BufferedOutputStream bos = new BufferedOutputStream(
                           new FileOutputStream("somethings\\jzc" + i + ".flv"));
                while ((len = bis.read(bys)) != -1) {
                     count2 += 1024;
                     System.out.println(count2);
                     if (count2 < (count / n)+1024&&count2 > (count / n)-1024) {
                           break;
                     } else {
                           bos.write(bys, 0, len);
                     }
                }
                bos.close();
           }
           System.out.println("切割完了");
     }
     public static int judge() throws FileNotFoundException, IOException {
           BufferedInputStream bis = new BufferedInputStream(new FileInputStream(
                     "somethings\\test.flv"));
           byte[] bys = new byte[1024];
           int len = -1;
           int count = 0;
           while ((len = bis.read(bys)) != -1) {
                count += 1024;
           }
           bis.close();
           return count;
     }
}

说明：分片判断中用 count2 += 1024 累加，是假设每次 read 都读满 1024 字节。若文件长度不是 1024 的整数倍，最后一个分片会略有偏差，实际项目应按真实读取长度 len 累加。
