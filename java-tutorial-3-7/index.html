Vue 基础

Posted on 2026-09-19，6 min read

在上一章我们把页面的骨架（HTML）、样式（CSS）和交互（JavaScript）拼在了一起，但真正写起来会发现：每改一次数据，都要自己找到对应的 DOM 节点，手动改它的 innerHTML 或 value。数据一多，取节点、改节点、再同步回数据的代码就会散落各处。本章要解决的正是这件事——用 Vue 2 把「数据」和「视图」绑在一起，让数据变化自动驱动界面更新。本章覆盖模板语法、常用指令、计算属性、侦听器和生命周期这五块基础，适合已经会写 HTML/CSS/JS、能看懂 document.getElementById 的读者。学完你就能不依赖任何构建工具，用一个 script 标签写出可运行的小应用。

一、为什么需要 Vue：从操作 DOM 到数据驱动

Vue 的核心思想是数据驱动加组件系统。它提供 MVVM 式的双向绑定，把「数据对象」和「DOM 视图」交给框架去同步：你只负责修改数据，视图更新由 Vue 完成。

实现原理上，Vue 2 用 ES5 的 Object.defineProperty 把 data 里的属性改造成存储器属性（getter/setter），这个过程叫「可观察化」。解析模板时，每个依赖数据的指令或插值都会创建一个 watcher，在求值过程中把当前 watcher 注册为所读取数据的订阅者；当数据被赋值触发 setter 时，就通知所有订阅者重新求值并更新对应的 DOM。因为依赖是「按需收集」的，不需要像脏检查那样遍历所有 watcher，效率更高。

这套机制带来两个必须记住的限制：

  • 只能兼容 IE9 及以上浏览器，因为 defineProperty 在更低版本不可用。
  • 在 Vue 2 中，直接给对象新增属性、或通过下标修改数组元素（arr[0] = x）不会触发更新，需要用 Vue.set(obj, key, value)（组件内是 this.$set）以及 push、splice 等被 Vue 包裹过的数组变异方法。

需要说明的是，网上不少旧笔记写的是 obj.$add(key, value)，这是 Vue 1.x 的写法，在 Vue 2 中已被移除，请统一改用 Vue.set / this.$set。另外 Vue 3 改用 Proxy 重写了响应式，新增属性和下标赋值都能被侦测到，且不再支持 IE；本章的结论只适用于 Vue 2。

二、模板语法与常用指令

模板语法分两类：插值和指令。插值就是双大括号 {{ }}，它会把表达式的结果渲染成文本；指令则是带 v- 前缀的特殊属性，用来给元素附加行为。

初学阶段最容易被一个问题绊住：页面加载瞬间会闪一下 {{ msg }} 原文。原因是 JS 还没执行、Vue 还没接管模板。解决办法是用 v-text 渲染文本（它不会显示原始大括号），或者在根元素上加 v-cloak 并配合 CSS 隐藏。渲染 HTML 片段要用 v-html，但内容来自用户输入时存在 XSS 风险，能不用就不用。

常用指令可以按用途记成四组：

  • 绑定属性：v-bind:href，简写 :href。
  • 绑定事件：v-on:click，简写 @click。
  • 双向绑定：v-model，只适用于表单控件和组件，它本质上是 :value 加 @input 的语法糖。配合修饰符使用更省事：.lazy 改成 change 时同步、.number 把输入转成数字、.trim 去掉首尾空格。
  • 条件与循环：v-if/v-else 会真正销毁和重建元素，v-show 只是切换 display；v-for 用于列表渲染，务必写 :key，且 key 要用稳定唯一的值（例如数据 id），用数组下标做 key 在列表增删时会导致复用错乱。

下面这段代码不依赖任何脚手架，直接保存为 .html 用浏览器打开即可运行，它同时用到了插值、v-text、v-model、v-for、v-if 和 @click：

<div id="app">
  <!-- v-text 不会闪现原始大括号，插值会 -->
  <p v-text="msg"></p>
  <p>当前输入：{{ msg }}</p>

  <!-- v-model.trim 双向绑定，并自动去掉首尾空格 -->
  <input v-model.trim="msg">

  <ul>
    <!-- :key 用稳定的 id，不要用 index -->
    <li v-for="(item, index) in list" :key="item.id">
      {{ index }} - {{ item.name }}
    </li>
  </ul>

  <p v-if="list.length === 0">暂无数据</p>
  <button @click="add">添加一条</button>
</div>

<script src="https://cdn.jsdelivr.net/npm/vue@2.7.16/dist/vue.js"></script>
<script>
  new Vue({
    el: '#app',
    data: {
      msg: 'Hello Vue',
      list: [{ id: 1, name: '张三' }]
    },
    methods: {
      add() {
        // 用 push 这类变异方法才能触发视图更新
        this.list.push({ id: Date.now(), name: '新同学' });
      }
    }
  });
</script>

三、计算属性与侦听器

模板里可以写表达式，但只适合简单运算；逻辑一复杂就该搬到 computed 里。计算属性有两个关键特性：一是有缓存，只要它依赖的响应式数据没变，多次访问都直接返回上次的结果，不会重复计算；二是它依赖其他响应式数据，依赖变化时会自动重新求值。相比之下 methods 里的方法每次重新渲染都会被调用一次，没有缓存。所以「由已有数据推导出的值」用 computed，「由事件触发的动作」用 methods。

计算属性默认只有 getter，是只读的；如果确实需要给它赋值，要写成带 get/set 的对象形式。而 watch 用于「数据变化后做一件副作用的事」，典型场景是发异步请求、写本地存储、操作非 Vue 管理的第三方库。侦听对象时可以用 deep: true 深度侦听，用 immediate: true 让它在初始化时先执行一次。

new Vue({
  el: '#app',
  data: {
    price: 100,
    count: 2,
    keyword: ''
  },
  computed: {
    // 有缓存：price 和 count 不变时不会重复计算
    total() {
      return this.price * this.count;
    },
    // 需要赋值时写成 get/set
    amount: {
      get() {
        return this.price * this.count;
      },
      set(value) {
        // 此处把单价按数量反推回去
        this.price = value / this.count;
      }
    }
  },
  watch: {
    // 数据变化后做副作用：适合发请求、写缓存
    keyword(newVal, oldVal) {
      if (newVal === oldVal) return;
      this.search(newVal);
    },
    // 侦听对象的内部变化需要 deep
    form: {
      handler(newVal) {
        console.log('form 变了', newVal);
      },
      deep: true,
      immediate: true
    }
  },
  methods: {
    search(kw) {
      console.log('搜索：' + kw);
    }
  }
});

一句话选择标准：能用 computed 推导出来的，就别用 watch 再去存一份；只有「做事情」而不是「算数值」时才用 watch。

四、生命周期：什么时候能拿到 DOM

每个 Vue 实例从创建到销毁会依次触发若干钩子函数，理解它们能省掉大量「为什么这里取不到元素」的困惑。Vue 2 的八个钩子按顺序是：beforeCreate、created、beforeMount、mounted、beforeUpdate、updated、beforeDestroy、destroyed。

实际使用中真正高频的只有三个：

  • created：实例已创建，data、methods、computed 可用，适合发起初始数据的异步请求；但此时还没有挂载，拿不到真实 DOM。
  • mounted：模板已渲染成真实 DOM 并插入页面，可以访问 this.$refs，适合初始化需要 DOM 的第三方库（如富文本编辑器、图表）。
  • beforeDestroy：实例销毁前调用，用来清理定时器、解绑全局事件、销毁第三方实例，否则容易内存泄漏。

要注意 Vue 1.x 到 2.0 的钩子名称变化很大，旧教程里的 ready 对应现在的 mounted，compiled 对应 beforeMount，attached 已被移除——照着旧笔记写会静默失效，钩子根本不会执行。

new Vue({
  el: '#app',
  data: { list: [] },
  created() {
    // 有 data，没有 DOM：这里发请求最合适
    console.log('created', this.list.length);
    // this.$refs.box 此时是 undefined
  },
  mounted() {
    // 有 DOM：可以操作 $refs
    console.log(this.$refs.box.offsetWidth);
    this.timer = setInterval(() => {
      console.log('轮询中');
    }, 1000);
  },
  beforeDestroy() {
    // 清理副作用，避免内存泄漏
    clearInterval(this.timer);
  }
});

另外，Vue 2 的 DOM 更新是异步批量的：修改数据后立刻读 DOM 拿到的还是旧值。需要等更新完成再操作，用 this.$nextTick(callback)。

五、常见坑与小结

把上面几节的内容收拢成一份避坑清单：

  • 新增对象属性、按下标改数组不会触发更新，用 this.$set 或数组变异方法。
  • 组件的 data 必须是函数并返回新对象，直接写成对象会让多个组件实例共享同一份数据。
  • v-if 和 v-for 不要写在同一个元素上：Vue 2 中 v-for 优先级更高，会先循环再逐个判断，既浪费性能，也无法在 v-if 里访问循环变量；正确做法是用计算属性先过滤出需要的列表。
  • v-for 的 :key 要用稳定唯一值，不要用下标。
  • 想立刻拿到更新后的 DOM，要用 $nextTick。
  • 别把旧版本的钩子名（ready、compiled）当成本章 API，它们在 Vue 2 中已不存在。

小结：本章围绕「数据驱动」讲了五件事——响应式的原理与边界、模板语法与常用指令、计算属性与侦听器的分工、生命周期的关键节点与版本差异。真正需要记住的判断标准只有几条：由数据推导的值放 computed，数据变化后要做的副作用放 watch，发请求放 created，要碰 DOM 放 mounted 或 $nextTick。下一章我们会把这些能力收进组件，讲清楚组件通信与单文件组件的写法。
